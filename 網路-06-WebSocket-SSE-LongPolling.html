連線層 vs 應用層

  • WebSocket 是連線層的雙向通道，本身沒有 topic、QoS、訂閱，要自己造。
  • MQTT 是應用層協定，內建 publish/subscribe、QoS、retain。
  • IoT 裝置動輒上萬，需要 broker 管訂閱與可靠度 → MQTT 勝出。

面試官可能再追

SSE 斷線怎辦？

瀏覽器內建自動重連，並帶 Last-Event-ID 讓 server 知道從哪續傳。

WebSocket 的 proxy 問題？

有些企業 proxy 不支援 ws；nginx 要正確設定 Upgrade / Connection header。

「單向推（通知、進度、即時統計）用 SSE，省事又能自動重連；要雙向互動用 WebSocket；裝置端大量上報用 MQTT 而不是 WebSocket，因為 MQTT 有 broker、topic、QoS 這些 IoT 需要的抽象。MOOVO 我會用 SSE 推車況給 App、MQTT 收車輛 telemetry。」
