邊讀邊處理，
別讓 buffer 爆掉

Stream 像水管：資料一小塊一小塊流過，邊流邊處理，記憶體只放當下那塊。Backpressure 是「下游忙不過來時，叫上游先停一下」的機制。

基本用法

大檔案別整包載進記憶體

// ❌ 壞：整包載進記憶體，1GB 檔案會 OOM
const data = await fs.readFile('big.csv');
res.send(data);

// ✅ 好：邊讀邊送
fs.createReadStream('big.csv').pipe(res);

四種 Stream

類型做什麼例子
Readable讀createReadStream、HTTP request
Writable寫createWriteStream、HTTP response
Duplex可讀可寫TCP socket
Transform邊讀邊轉換gzip 壓縮、加密
背壓重點 & 最佳實踐

用 pipeline 最安全

  • pipe() 會自動處理 backpressure。
  • 手動 write() 要看回傳值：回 false 代表 buffer 滿了，要先暫停讀取，等 drain 事件再繼續。
import { pipeline } from 'node:stream/promises';
await pipeline(
  fs.createReadStream('in.csv'),
  zlib.createGzip(),
  fs.createWriteStream('out.csv.gz')
);  // 自動處理錯誤與資源清理

30 秒版本

「Stream 讓我處理大檔案不用全載進記憶體，分 Readable/Writable/Duplex/Transform 四種。重點是 backpressure —— 寫入端比讀取端慢時 buffer 會堆爆，pipe() 會自動暫停上游、write() 回 false 時要等 drain。實務我用 stream/promises 的 pipeline，它會幫我處理錯誤和清理。」
