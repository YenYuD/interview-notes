Node.js

一個服務生，
跑滿整間餐廳

Node 只有一條 JS 執行緒，靠 Event Loop 不斷輪詢「有沒有完成的非同步工作要處理」。耗時的 I/O 丟給底層 libuv 背景做，JS 大部分時間在「等」，所以單執行緒也能撐高並發。

DEMO — 經典考題

猜這段的輸出順序

面試最愛問。先自己猜，再按「執行」一步步看為什麼：

按執行，逐步揭曉
setTimeout(() => console.log('1'), 0);
setImmediate(() => console.log('2'));
Promise.resolve().then(() => console.log('3'));
process.nextTick(() => console.log('4'));
console.log('5');
輸出：5 → 4 → 3 → 1/2。同步 5 先跑 → nextTick 4 → microtask 3 → timer 1 / setImmediate 2（順序不一定）。
優先順序總結

誰先誰後

同步程式碼 → process.nextTick → microtasks(Promise) → 進入下一階段
  • 每個階段「之間」都會清空一次 microtask queue（Promise.then、queueMicrotask）。
  • process.nextTick 又優先於 microtask（它有自己獨立的 queue）。
六個階段（依序循環）

Event Loop 的巡邏路線

1

Timers

執行到期的 setTimeout / setInterval。

2

Pending callbacks

某些系統操作的 callback（如 TCP 錯誤）。

3

Poll（最主要）

取得新 I/O 事件、執行 I/O callback。

4

Check

執行 setImmediate。

5

Close callbacks

如 socket.on('close', ...)。

為什麼單執行緒能高並發 & 踩雷

擅長 I/O，怕 CPU

I/O boundAPI、DB query → 適合 Node
CPU bound影像、加解密 → 會卡死整條執行緒
✕

把 CPU 密集運算放主執行緒 → 整個 server 卡住、所有請求變慢。要丟給 Worker Threads。

✕

無限遞迴呼叫 process.nextTick → 餓死 I/O，後面階段永遠輪不到。

面試這樣答

30 秒版本

「Node 單執行緒跑 JS，I/O 交給 libuv 背景做，Event Loop 輪巡六個階段（timers→pending→poll→check→close）。每個階段之間清空 microtask，而 process.nextTick 又優先於一般 microtask。所以它擅長 I/O 密集、不擅長 CPU 密集 —— CPU 重活會卡死整條執行緒，要丟給 Worker Threads。」
