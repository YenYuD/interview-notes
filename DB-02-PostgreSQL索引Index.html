代價：索引佔空間，每次寫入都要更新索引 → 寫變慢。所以索引不是越多越好。
索引類型

不同資料用不同索引

類型適用情境
B-tree（預設）等值(=)、範圍(<, >, BETWEEN)、排序(ORDER BY)
Hash只做等值，很少用（B-tree 已夠好）
GINarray、jsonb、全文搜尋（多值欄位）
GiST地理資料（PostGIS）、範圍型別
BRIN超大表且資料天然有序（time-series）
Partial只索引部分（如 WHERE deleted = false），省空間
複合索引的順序（重要）

等值在前、範圍在後

-- 查「某 user 的訂單，依時間新到舊排序」
CREATE INDEX idx_orders_user_time
  ON orders (user_id, created_at DESC);
-- 完美命中：WHERE user_id = ? ORDER BY created_at DESC LIMIT 20

先用 user_id 等值縮小範圍，再用已排好序的 created_at 直接取前 20 筆，不用額外排序。

面試這樣答

30 秒版本

「B-tree 是預設、處理等值/範圍/排序；jsonb 和全文搜尋用 GIN；地理資料用 GiST；超大有序表用 BRIN；只查部分資料用 partial index。複合索引順序是『等值欄位在前、範圍在後』並對齊 ORDER BY，例如 (user_id, created_at DESC)。索引會拖慢寫入、佔空間，所以要針對實際 query 設計，不是亂加。」
