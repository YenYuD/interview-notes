手環 vs 護照

HTTP 無狀態，server 預設不記得你是誰。登入後怎麼證明「我是剛剛登入的人」有兩種思路：Session 把狀態存在 server，JWT 把狀態打包成一張簽章過的票自己帶著走。

Session 像遊樂園手環：server 有一本名冊，每次翻冊確認。JWT 像護照：server 只驗章、不查冊。
兩種比較

優缺點

Session（狀態在 server）JWT（狀態在 token）
怎麼認查名冊（通常放 Redis）只驗簽章，不查任何資料
優點可隨時失效、適合 web無狀態、跨服務、行動友善
缺點多台 server 要共享名冊發出去難收回、payload 較大
B2C App（行動端）→ JWT：access 短效 + refresh 長效
B2B 後台（web）→ Session + httpOnly cookie（要強登出）
重要機制

Refresh Token：短效才安全，但別一直重登

A

Access token（短效，如 15 分鐘）

每次請求帶它。

R

Refresh token（長效，如 30 天）

存 DB 可撤銷，只用來換新的 access token。

↻

流程

access 過期 → 收到 401 → 用 refresh 換新 access → 換失敗才導回登入。

✓

Refresh token rotation

每次換新時把舊的作廢，防止被偷後重放。

延伸追問 & 踩雷

資安重點

JWT 被偷怎辦？

短 TTL + refresh rotation + 異常 IP 偵測 + 重要操作二次驗證。

JWT 放哪？

localStorage 怕 XSS；httpOnly cookie 怕 CSRF（用 SameSite=Lax + CSRF token）；行動端用 secure storage（iOS Keychain / Android Keystore）。

✕

JWT 演算法欄位寫 none 卻不檢查 → 攻擊者可偽造 token（經典 CVE）。一定要在 server 端鎖定允許的演算法。

面試這樣答

30 秒版本

「行動端我用 JWT，access 15 分鐘 + refresh 30 天且存 DB 可撤銷，並做 refresh rotation 防重放。後台管理用 session + httpOnly cookie，因為管理員需要『一鍵踢掉所有登入』這種強登出能力，session 刪一筆就生效。」
