    關鍵詞彙
    
怎麼讀

    
掃描方式

    
    
      
  • Seq Scan：掃全表。大表上出現 → 可能缺索引（警訊）。
    • 
      
  • Index Scan / Index Only Scan：用了索引（後者連表都不回查，最快）。
    • 
      
  • Bitmap Heap Scan：合併多個索引的結果。
    • 
    

    
怎麼讀數字

    
    
      
  • actual time=0.123..5.678：第一個是「找到第一筆」，第二個是「全部完成」。
    • 
      
  • rows=：實際筆數。估計與實際差很多 → 統計過期，跑 ANALYZE 表名。
    • 
      
  • Buffers: shared hit=X read=Y：hit 命中記憶體，read 真的讀了 disk（read 多代表 cache 不夠）。
    • 
    

  


  

    判斷瓶頸四步
    
SOP

    

      
1
找最貴的節點
cost 或 actual time 最高的那個。

      
2
大表 Seq Scan？
考慮加索引。

      
3
估計 rows ≠ 實際？
統計過期，ANALYZE。

      
4
索引後出現 Filter？
索引沒涵蓋這條件，還是掃了很多列。

    

  


  

    面試這樣答
    
30 秒版本

    
「我會用 EXPLAIN ANALYZE 看執行計畫。先看有沒有大表 Seq Scan（通常代表缺索引），再看 actual time 最貴的節點。如果估計 rows 和實際差很多，代表統計過期要 ANALYZE。Buffers 的 read 高代表在讀 disk。理想是看到 Index Scan 甚至 Index Only Scan。」
