API 設計

每人每段時間限打幾次

像遊樂設施「每人每 5 分鐘限玩一次」。沒有限制的話，有人寫腳本狂打你的 API、或暴力嘗試密碼，就會拖垮系統或造成資安問題。Rate limiting 就是擋這個。

DEMO — Token Bucket 桶子

桶裡有代幣才放行

桶子最多裝 5 顆代幣，每 2 秒自動補 1 顆。每次請求花 1 顆。狂點看看，代幣空了就吃 429：

狂點，看代幣消耗與回補
X-RateLimit-Remaining: 5 / 5　·　每 2 秒回補 1 顆
// 請求結果會顯示在這…
Token bucket 的精髓：平常累積代幣，允許短暫突發（一次用掉好幾顆），但長期速率被回補速度綁住。
四種演算法

怎麼算「這段時間幾次」

演算法概念特性
Fixed window每分鐘 60 次，整點重算簡單，但跨整點邊界會爆量（1 秒內可達 120 次）
Sliding window看「過去 60 秒」較準確
Token bucket
常用		定速放代幣，有幣才放行允許短暫突發
Leaky bucket請求像水滴勻速漏出強制平滑、不允許突發
維度與實作

per 什麼？放哪算？

⚠️

要選對維度：解鎖按鈕應該 per user，否則「一家人共用同一支手機（同 IP）」就會互相卡到。

用 Redis 的 INCR + EXPIRE（多台 server 共享狀態，不能用單機記憶體），並在回應加 header 告訴 client 現況：

X-RateLimit-Limit: 60        # 上限
X-RateLimit-Remaining: 23     # 還剩幾次
X-RateLimit-Reset: 1716000000 # 何時重置

超過就回 429 Too Many Requests + Retry-After（幾秒後再試）。

延伸追問

面試官可能再追

DDoS 怎辦？

Rate limit 是應用層的；大規模 DDoS 要在更前面的 Cloudflare / WAF 層擋。

為什麼用 Redis 不用記憶體？

多台 server 要共享同一份計數，記憶體各算各的會破功。

面試這樣答

30 秒版本

「我會用 token bucket 允許合理突發，存在 Redis 讓多台 server 共享計數，維度選 per user（解鎖這種要綁人不綁 IP）。回應帶 X-RateLimit-* header，超過回 429 + Retry-After。」
