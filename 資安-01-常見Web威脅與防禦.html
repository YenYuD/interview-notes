資安專題

四大經典攻擊，
一眼看出風險

全端工程師必須認得這幾種經典攻擊（SQL injection、XSS、CSRF、SSRF）和對應防禦，code review 時要能一眼看出風險。

DEMO — 攻擊 vs 防禦

點一種攻擊，看怎麼打、怎麼防

選攻擊類型
🔴 攻擊
🛡️ 防禦
SQL Injection 的正確寫法

永遠用參數化查詢

// ❌ db.query(`SELECT * FROM users WHERE email = '${email}'`)
// ✅ 參數化：
db.query('SELECT * FROM users WHERE email = $1', [email])
其他散落的資安點

code review 必盯

  • JWT 演算法 none 攻擊：server 一定要鎖定允許的演算法，不能信 token 自報的 alg。
  • mTLS：雙向憑證驗證，B2B 機敏 API 與 IoT 裝置認證常用。
  • Webhook 簽章驗證：收 Stripe webhook 一定要驗 Stripe-Signature，並用 event.id 去重防重送。
  • 錯誤訊息別吐 stack trace 給 client。
  • Rate limiting 防暴力破解。
面試這樣答

30 秒版本

「四大經典：SQL injection 用參數化查詢防；XSS 用輸出跳脫 + CSP + httpOnly cookie 防；CSRF 用 SameSite cookie + CSRF token 防；SSRF 用 URL 白名單防。再加上 JWT 要鎖演算法防 none 攻擊、webhook 要驗簽章、錯誤別吐 stack trace。code review 時我會特別盯有沒有字串拼 SQL、有沒有對使用者輸入做跳脫。」
