核心觀念

HTTP code 和 business code 分兩層

層級例子給誰用
HTTP code402client 的框架（fetch / axios 判斷成功失敗）
business codeBALANCE_INSUFFICIENT前端業務邏輯（顯示哪句 i18n、跳哪頁）
💡

為什麼要分？因為 HTTP code 種類有限，但業務錯誤千百種，需要自己的代碼系統。

  • 一定要回 traceId：出問題時 client 把它給工程師，就能在 server log 對到同一筆請求。
  • 多語（i18n）：訊息文字交給前端用 code 對照，或後端依 Accept-Language 回對應語言。
表單錯誤

多欄位驗證一次全回

{
  "status": 422,
  "code": "VALIDATION_ERROR",
  "errors": [
    { "field": "email", "code": "INVALID_FORMAT" },
    { "field": "age", "code": "OUT_OF_RANGE" }
  ]
}

用 errors 陣列一次回所有欄位問題，而不是一次只回一個 —— 使用者不用一個一個試。
