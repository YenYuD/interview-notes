JAVASCRIPT · 展開運算子

一個 ...，替代掉四種舊寫法

ES6 的展開運算子讓陣列複製、合併、物件淺拷貝從多行變成一行，也讓函式呼叫不再需要 apply()。掌握它是寫出簡潔、不可變風格程式碼的基礎。

新舊對比

展開運算子取代哪些舊寫法

操作舊寫法展開運算子
複製陣列arr.slice()[...arr]
合併陣列arr1.concat(arr2)[...arr1, ...arr2]
複製物件Object.assign({}, obj){ ...obj }
傳陣列給函式fn.apply(null, arr)fn(...arr)
實用範例

在現有陣列或物件基礎上新增內容

// 陣列：在尾端加元素，不改動原始陣列
const arr = [1, 2, 3];
const newArr = [...arr, 4, 5];  // [1, 2, 3, 4, 5]

// 物件：覆蓋某個屬性（後者贏）
const user = { name: 'Alice', age: 25 };
const updated = { ...user, age: 26 };
// { name: 'Alice', age: 26 }
物件展開時，後面的屬性會覆蓋前面同名的屬性。這個特性讓「更新某個欄位」的寫法非常乾淨，Redux reducer 裡很常見。
延伸追問

面試官可能再追

展開和 Object.assign 在屬性覆蓋上有差嗎？

行為相同，後者覆蓋前者。差別在 setter 觸發：Object.assign 會呼叫目標的 setter，展開不會。另外 Object.assign 可以多目標，展開只能建立新物件。

展開後修改巢狀物件會影響原始物件嗎？

會。展開只複製第一層，巢狀物件仍是共享參考。{ ...user, address: { ...user.address, city: 'Taipei' } } 這樣才能安全更新巢狀欄位。

面試這樣答

30 秒版本

「展開運算子讓陣列和物件的複製、合併語法大幅簡化，也取代了 apply() 傳陣列的需求。它是淺層複製，這是最重要的注意點——巢狀物件需要逐層展開才能避免修改原始資料。在 Redux / React state 的 immutable 更新模式中大量使用。」
