for...in 遍歷物件，for...of 遍歷可迭代物件

搞混這兩者是高頻地雷。for...in 走的是「可列舉屬性的鍵」，包含原型鏈；for...of 走的是「迭代器吐出的值」，只能用在可迭代物件（陣列、字串、Map、Set…）。

物件遍歷

四種遍歷物件屬性的方式

方式包含繼承屬性？包含不可列舉？回傳
for...in✅（需 hasOwn 過濾）❌鍵（字串）
Object.keys()❌❌自身可列舉鍵陣列
Object.entries()❌❌[key, value] 陣列
Object.getOwnPropertyNames()❌✅自身所有鍵陣列
 
const obj = { a: 1, b: 2 };

// 安全遍歷（過濾原型鏈）
for (const key in obj) {
  if (Object.hasOwn(obj, key)) console.log(key, obj[key]);
}

// 更推薦：Object.entries() 搭配解構
Object.entries(obj).forEach(([k, v]) => console.log(k, v));
⚠️

直接用 for...in 不過濾，可能會遍歷到原型鏈上的屬性，造成 bug。現代寫法優先用 Object.keys() 或 Object.entries()。

陣列遍歷

for...of 是遍歷陣列的現代首選

const arr = [1, 2, 3];

// for...of：簡潔、可 break
for (const n of arr) console.log(n);

// 同時需要 index
for (const [i, n] of arr.entries()) console.log(i, n);
對陣列用 for...in 是常見錯誤——它會遍歷索引字串 '0' '1' '2'，還可能包含陣列上擴充的屬性，盡量避免。
延伸追問

面試官可能再追

for...in 和 for...of 的本質差異？

for...in 列舉物件的可列舉屬性鍵，適用於任何物件；for...of 依賴可迭代協議（[Symbol.iterator]），只適用於有實作 iterator 的物件（陣列、字串、Map、Set 等）。

Object.entries() 的鍵順序保證嗎？

ES2015+ 規範物件整數鍵按升序、其餘鍵按插入順序排列。Object.entries() 遵循此規則，實務上可視為插入順序。

面試這樣答

30 秒版本

「遍歷物件我優先用 Object.entries()，可以同時拿到 key 和 value，語意清晰又不會踩原型鏈的坑；遍歷陣列用 for...of 或 forEach，需要同時拿 index 時搭配 .entries() 解構。for...in 用在物件時要記得加 Object.hasOwn 過濾。」
