JAVASCRIPT · Map

都是鍵值對，Map 多了普通物件做不到的事

普通物件（POJO）輕量但只能用字串／Symbol 當鍵。Map 的鍵可以是任意類型、保留插入順序、有 size 屬性——換來的代價是無法直接 JSON 序列化。

選擇指南

什麼時候用 Map？什麼時候用物件？

選 Map 非字串鍵 / 需要順序 / 大量增刪
選物件 JSON 傳輸 / 靜態設定 / 簡單字串鍵 
// Map 用物件當鍵
const cache = new Map();
const node = document.getElementById('btn');
cache.set(node, { clickCount: 0 });  // DOM 節點當鍵
⚠️

Map 不能直接用 JSON.stringify()，結果是空物件 {}。需要序列化時，先用 Object.fromEntries(map) 轉換，或改用第三方函式庫。

延伸追問

面試官可能再追

Map 和 Object 的查找效能有多大差異？

對於大量頻繁增刪的情境，Map 的 V8 引擎內部實作通常比 Object 更優化。小型靜態物件兩者差異不大，一般應用無需為效能特別切換。

Map 可以被 for...in 遍歷嗎？

不行。Map 沒有可列舉屬性，for...in 什麼都拿不到。應該用 for...of、map.forEach() 或 map.entries()。

面試這樣答

30 秒版本

「Map 和普通物件都是鍵值對，但 Map 的鍵可以是任意類型、保留插入順序、有 size 屬性，迭代也更直接。普通物件的優勢是可以直接 JSON 序列化、語法更輕量。需要傳輸或存儲時用物件；需要非字串鍵或大量動態增刪時用 Map。」
