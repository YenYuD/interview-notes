JAVASCRIPT · Set / Map

內容一樣不等於同一個，Set/Map 看的是參考

把兩個「內容相同」的物件加入 Set，你會得到兩筆資料。Set 和 Map 使用參考相等（SameValueZero）判斷，只有指向同一記憶體位置才算相同。

踩雷示範

為什麼 Set 還是有兩個「一樣」的物件？

const set = new Set();
const obj1 = { a: 1 };
const obj2 = { a: 1 };  // 內容相同，但是不同物件

set.add(obj1);
set.add(obj2);
console.log(set.size); // 2 ← 兩個都進去了！

// 同一個參考才會被去重
set.add(obj1);
console.log(set.size); // 仍是 2
⚠️

Set 的「去重」對原始值（數字、字串）有效，但對物件只去掉「同一個參考」的重複，不做深度比較。這是最容易誤用的地方。

NaN 特例

SameValueZero vs ===

NaN === NaN false（JavaScript 的奇特設計）
Set 裡的 NaN new Set([NaN, NaN]).size === 1
Set/Map 使用的 SameValueZero 把兩個 NaN 視為相等，所以 Set 只會保留一個 NaN，這是和 === 唯一的差異。
實務解法

需要深度比較怎麼辦？

Set/Map 本身沒有深度比較的選項。常見做法：

  1. 改用字串化的鍵：set.add(JSON.stringify(obj))（有限制，如物件含函式時失效）。
  2. 自行維護陣列 + some(isEqual) 做成員檢查。
  3. 使用 lodash.isEqual 等函式庫實作深度比較邏輯。
延伸追問

面試官可能再追

Map 用物件當鍵時，取值要注意什麼？

必須用同一個參考才能取到值。若你把 { id: 1 } 設為鍵，再用另一個 { id: 1 } 去 get，結果是 undefined。通常需要先把物件存在變數裡再使用。

如何利用 Set 搭配 JSON 快速去重物件陣列？

[...new Set(arr.map(o => JSON.stringify(o)))].map(s => JSON.parse(s))。缺點是序列化有損失（函式、undefined、循環參考都無法處理）。

面試這樣答

30 秒版本

「Set 和 Map 判斷相等用的是 SameValueZero，本質是參考相等。兩個內容完全相同但不同的物件字面量，在 Set 裡會被視為兩個不同元素。唯一和 === 的差別是 NaN：Set 把兩個 NaN 視為相同，只保留一個。需要深度比較時，Set/Map 本身做不到，需要另外實作。」
