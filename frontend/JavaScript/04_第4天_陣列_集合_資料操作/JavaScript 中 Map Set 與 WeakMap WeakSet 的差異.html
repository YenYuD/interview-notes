WeakMap / WeakSet：讓垃圾回收器自己決定

Map/Set 對鍵持有強參考，只要集合存在，鍵就不會被回收。WeakMap/WeakSet 持有弱參考——鍵物件若無其他參考指向它，垃圾回收器可以把它清掉，集合也跟著縮。

Weak 版本的典型用途

WeakMap — 關聯私有資料到物件

把額外資料附加在 DOM 節點或某個物件上，不影響它的生命週期。節點被移除後資料自動清除，不會洩漏記憶體。

WeakSet — 標記已處理的物件

例如遍歷有循環參考的資料結構時，用 WeakSet 記錄已訪問的物件；或追蹤活躍使用者 session 物件，session 結束後自動從集合中消失。

// WeakMap 避免記憶體洩漏
const metadata = new WeakMap();
let dom = document.querySelector('#app');
metadata.set(dom, { init: true });

dom = null;
// dom 的強參考消失 → GC 可以回收它
// metadata 內的那筆資料也跟著消失
✅

WeakMap/WeakSet 因為不可迭代、沒有 size，不適合用來儲存需要遍歷或統計的資料；它們的存在價值就是「讓 GC 自己管理」。

延伸追問

面試官可能再追

WeakMap 為什麼只能用物件當鍵？

弱參考的語意需要 GC 能追蹤物件的存活狀態。原始值（字串、數字）不是 GC 管理的堆積物件，無法建立弱參考，所以只能用物件。

WeakRef 和 WeakMap 有什麼關係？

WeakRef（ES2021）是直接暴露弱參考給開發者的低階 API，讓你持有一個物件的弱參考並在需要時 deref() 取值。WeakMap 是更高階的封裝，自動管理弱鍵的生命週期。
