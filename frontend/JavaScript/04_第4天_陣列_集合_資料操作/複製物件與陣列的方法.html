淺拷貝一行搞定，深拷貝要選對工具

複製物件或陣列時，最重要的問題是：你需要淺拷貝（只複製第一層）還是深拷貝（完整獨立複製）？選錯工具，巢狀資料改了會互相影響。

淺拷貝

展開運算子 vs Object.assign()

推薦：展開運算子 [...arr] / { ...obj }
傳統：Object.assign Object.assign({}, obj) 
const obj = { a: 1, b: { c: 2 } };

const shallow = { ...obj };
shallow.a = 99;        // ✅ 不影響 obj.a
shallow.b.c = 99;      // ❌ 影響 obj.b.c（同參考！）
深拷貝

三種選擇，各有限制

方法支援循環參考支援函式/undefined備註
structuredClone()✅❌原生 API，現代環境推薦
JSON.parse(JSON.stringify())❌（會出錯）❌（被忽略）簡單資料的快速方法
_.cloneDeep()（Lodash）✅✅最完整，需引入函式庫
 
// 現代推薦：structuredClone
const deep = structuredClone(obj);
deep.b.c = 99; // ✅ 完全不影響 obj
⚠️

JSON.parse(JSON.stringify()) 遇到 undefined、函式、Date（轉字串）、循環參考（報錯）會出問題。現代環境優先用 structuredClone()。

延伸追問

面試官可能再追

structuredClone() 有哪些限制？

不能複製函式、DOM 節點、Error 物件（部分）等；支援 Date、RegExp、Map、Set、ArrayBuffer 等。Node.js 17+ 和現代瀏覽器都有原生支援。

陣列有哪些內建的淺拷貝方法？

[...arr]、arr.slice()、Array.from(arr)、[].concat(arr) 都是淺拷貝。arr.slice() 是最傳統的寫法。

30 秒版本

「淺拷貝我用展開運算子 { ...obj } 或 [...arr]，簡潔且語意清晰。深拷貝優先用 structuredClone()，原生 API 支援循環參考；如果要相容舊環境或需要處理函式，用 Lodash 的 _.cloneDeep。JSON.parse(JSON.stringify()) 只在資料純粹（無函式、無循環）時才用。」
