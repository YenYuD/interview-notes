JAVASCRIPT · 展開運算子

不可變操作的最佳拍檔，展開讓程式碼意圖自己說話

展開運算子的優勢不只是「少打幾個字」。它讓你不修改原始資料就能複製、合併、新增——這正是 React state 更新、Redux reducer 所需要的思維方式。

陣列優勢

複製、合併、插入，全部不改原陣列

const base = [1, 2, 3];

// 複製
const copy = [...base];

// 合併（在任意位置插入）
const merged = [...base, ...[4, 5]];   // [1,2,3,4,5]
const prepend = [0, ...base];           // [0,1,2,3]

// 不改 base，base 仍是 [1, 2, 3]
物件優勢

更新單一欄位，而不破壞整個物件

const user = { name: 'Alice', age: 25, role: 'user' };

// 更新 role，其他欄位保持不變
const admin = { ...user, role: 'admin' };

// 合併兩個設定物件（後者優先）
const config = { ...defaults, ...overrides };
✅

這種「展開原物件、覆蓋特定屬性」的模式在 React 的 state 更新中隨處可見：setState(prev => ({ ...prev, loading: false }))。

延伸追問

面試官可能再追

展開運算子是深拷貝還是淺拷貝？

淺拷貝。第一層的原始值會被複製，但第一層的物件或陣列仍是共享參考。更新巢狀資料時需逐層展開，或改用 structuredClone()。

為什麼說展開運算子利於函式式編程？

函式式編程強調不可變性（immutability），避免直接修改資料。展開運算子讓你建立「修改了某個部分的新資料」，而原始資料完全不動，符合純函式的精神。
