修改「副本」卻改到「原本」？你用的是淺拷貝

淺拷貝只複製第一層——巢狀物件還是共享同一個記憶體位置。深拷貝遞迴複製所有層級，副本和原本完全獨立。這個差異在 React state 管理中非常關鍵。

踩雷示範

淺拷貝的陷阱：巢狀物件仍共享

const obj = { a: 1, b: { c: 2 } };
const shallow = { ...obj };

shallow.a = 99;
console.log(obj.a);    // 1 ← 沒影響（原始值）

shallow.b.c = 99;
console.log(obj.b.c); // 99 ← 被改了！（物件共享參考）
第一層的原始值（數字、字串、boolean）是值複製，互不影響；第一層的物件或陣列只複製「指向它的指標」，兩份資料指向同一個東西。
深拷貝

副本完全獨立，改一個不影響另一個

const obj = { a: 1, b: { c: 2 } };

// structuredClone：現代推薦
const deep = structuredClone(obj);
deep.b.c = 99;
console.log(obj.b.c); // 2 ← 完全不受影響

// JSON 方法（僅適用純資料）
const json = JSON.parse(JSON.stringify(obj));
方法類型主要限制
{ ...obj }淺巢狀物件共享參考
Object.assign()淺同上
structuredClone()深不支援函式
JSON.parse(stringify)深函式/循環參考不支援
_.cloneDeep()深需要 Lodash

面試官可能再追

React 中為什麼關心淺拷貝 vs 深拷貝？

React 的 state 比較用的是淺比較（reference equality）。如果你直接改了巢狀物件的屬性但沒有改外層物件的參考，React 會認為 state 沒有改變而不重新渲染。正確做法是每層都建立新物件，讓參考改變。

什麼是 structural sharing（結構共享）？

Immer 等函式庫利用 Proxy 讓你用可變語法寫不可變更新，內部只建立「有修改到的路徑上」的新物件，未修改的部分繼續共享原始參考，兼顧效能與不可變原則。

30 秒版本

「淺拷貝只複製第一層，巢狀物件仍共享參考——改副本的巢狀屬性會改到原本。深拷貝遞迴複製所有層級，副本完全獨立。現代 JavaScript 推薦用 structuredClone() 做深拷貝；需要相容舊環境或處理函式時用 Lodash。在 React 中這個概念很重要，因為 state 更新需要改變物件參考才能觸發重新渲染。」
