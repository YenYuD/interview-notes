放棄 var，從根源杜絕提升帶來的靜默錯誤

提升問題大多源自 var 的不可預測行為。改用 let/const、先宣告後使用、搭配 ESLint，可以從根本上消滅這類 bug。

四個實踐原則

防範策略

1. 用 let/const 取代 var：let/const 有 TDZ，宣告前存取立即拋錯，不會靜默 undefined。
2. 在作用域頂端宣告變數：讓變數宣告集中在上方，一眼看清本作用域用了哪些變數。
3. 先宣告函式再呼叫：即使函式宣告可提升，保持先宣告再使用的習慣可讀性更好。
4. 使用 ESLint no-use-before-define：靜態分析自動捕捉提前使用的問題。
var 的問題示範

為什麼 var 容易踩坑

// var 靜默失敗 — 不好
console.log(x); // undefined（不報錯，容易誤判邏輯）
var x = 10;

// let/const 快速失敗 — 好
console.log(y); // ReferenceError — 立刻知道問題在哪
let y = 20;
💡

「快速失敗（fail fast）」是個好原則：與其靜默地得到 undefined 讓 bug 延遲爆發，不如立即拋出錯誤讓問題可見。

延伸追問

面試官可能再追

ESLint 的 no-use-before-define 怎麼設定？

在 .eslintrc 中加入 "no-use-before-define": "error"，它會在函式、類別、變數被使用在宣告之前時報錯。這是大多數嚴格規則集（如 airbnb）的預設配置。

TypeScript 能解決提升問題嗎？

TypeScript 的編譯器會在型別層面警示，但提升是 JavaScript runtime 行為，TypeScript 無法完全阻止。搭配 strict 模式的 TS + ESLint 才是最完整的防線。

面試這樣答

30 秒版本

「避免提升問題最根本的方法是完全改用 let/const，不用 var。let/const 有 TDZ，宣告前存取立刻 ReferenceError，是快速失敗的行為；var 宣告前存取只是 undefined，bug 會延遲爆發很難追。除此之外，養成先宣告再使用的習慣，並設定 ESLint no-use-before-define 規則，可以從工具層面自動防範。」
