三種宣告都會提升，但初始化的時機完全不同

var、let、const 都會在編譯期被提升，差別在於：var 提升並初始化為 undefined，let/const 提升但不初始化，宣告前存取就踩進 TDZ（暫時性死區）。

var a = 10;

let b = 20;

console.log(c); // ReferenceError（TDZ）
const c = 30;
TDZ 概念

暫時性死區（Temporal Dead Zone）

let/const 的 TDZ 是從區塊開始到宣告行執行完成之間的區段。這個期間變數已存在作用域中（已提升），但處於「未初始化」狀態，任何存取都會拋出 ReferenceError。

ℹ️

TDZ 的設計目的是讓開發者養成「先宣告再使用」的習慣，避免 var 那種宣告前存取得到 undefined 的靜默錯誤。

延伸追問

面試官可能再追

函式宣告的提升和 var 一樣嗎？

不一樣。函式宣告（function declaration）連函式定義一起提升，可在宣告前呼叫；var 只提升宣告，值是 undefined，在宣告前呼叫會得到 TypeError。

const 一定要在宣告時賦值嗎？

是的。const 必須在宣告時初始化，否則 SyntaxError。這與 let 不同，let 可以先宣告不賦值。

面試這樣答

30 秒版本

「三種宣告都會提升，但行為不同。var 提升並初始化為 undefined，所以宣告前存取不會報錯，只會得到 undefined；let/const 提升但不初始化，宣告前存取進入 TDZ 直接 ReferenceError。TDZ 強迫你先宣告再使用，避免了 var 的靜默 bug。實務上我只用 let/const，從根本避開這些提升陷阱。」
