JAVASCRIPT · 提升陷阱

提升讓 var 宣告前使用不報錯，但悄悄埋下 undefined 地雷

提升本身是中性機制，問題出在 var 的靜默 undefined 與函式表達式的 TypeError。了解三種常見陷阱，才能寫出可預測的程式。

三種常見陷阱

提升可能造成的問題

陷阱 1：var 宣告前存取得 undefined
不報錯，但邏輯悄悄錯誤。
陷阱 2：函式表達式在宣告前呼叫 → TypeError
var 版本提升為 undefined，呼叫 undefined 就是 TypeError。
陷阱 3：var 在區塊內重複宣告同名變數
var 沒有區塊作用域，會覆蓋外部同名變數，難以追蹤。
// 陷阱 1
console.log(a); // undefined（靜默！）
var a = 5;

// 陷阱 2
bar(); // TypeError: bar is not a function
var bar = function() {};

// 陷阱 3
var x = 1;
if (true) { var x = 2; } // 覆蓋了外部 x！
console.log(x); // 2
let/const 的改善

TDZ 讓問題立刻浮現

console.log(b); // ReferenceError（立刻知道問題！）
let b = 10;
💡

ReferenceError 比靜默 undefined 好，因為「快速失敗」讓你立即知道哪裡有問題，不讓 bug 潛伏到後面才爆發。

延伸追問

面試官可能再追

有什麼真實世界的例子會踩到提升陷阱？

最常見的是 for 迴圈中的非同步回呼：用 var 時所有回呼共享同一個 i，迴圈結束後 i 已到最大值，全部印出同樣的數字。改用 let 則每次迭代有自己的 i，行為符合直覺。

面試這樣答

30 秒版本

「提升的問題主要出在 var 上，有三個常見陷阱：一是宣告前存取得 undefined 而非報錯，靜默失敗讓 bug 難追蹤；二是函式表達式宣告前呼叫會 TypeError；三是 var 沒有區塊作用域，在 if/for 裡重複宣告同名變數會意外覆蓋。用 let/const 取代 var，讓 TDZ 把問題變成立即可見的 ReferenceError，是根本的解決方式。」
