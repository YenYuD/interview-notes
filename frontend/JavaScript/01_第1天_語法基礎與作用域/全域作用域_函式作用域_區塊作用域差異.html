變數活在哪一層，就只能在那一層被讀到

作用域決定變數的可見範圍。全域作用域無限制、函式作用域限在函式內、區塊作用域限在 {} 內。選錯 var/let/const 就會跨層洩漏。

三層對照

作用域範圍比較

作用域觸發條件適用宣告外部可存取？
全域任何函式/區塊外var/let/const✓ 全域可見
函式在函式內宣告var/let/const✗ 函式外不可見
區塊在 {} 內宣告let/const 才有效，var 會穿透✗ 區塊外不可見
if (true) {
  var   x = 1; // 函式/全域作用域 → 區塊外可讀
  let   y = 2; // 區塊作用域 → 區塊外 ReferenceError
  const z = 3; // 區塊作用域 → 同上
}
console.log(x); // 1 ✓
console.log(y); // ReferenceError ✗
var 的洩漏問題

var 在迴圈中的陷阱

// var：共享同一個 i，迴圈結束後值是 3
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0); // 3, 3, 3
}

// let：每次迭代獨立的區塊作用域
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0); // 0, 1, 2
}
⚠️

這是 var 在非同步回呼中最惡名昭彰的 bug。let 讓每次迭代有自己獨立的作用域，直接解決。

面試官可能再追

IIFE 和區塊作用域有什麼關係？

IIFE（立即執行函式表達式）是 ES6 之前製造函式作用域隔離的方式。ES6 引入 let/const 後，直接用 {} 就能創造區塊作用域，IIFE 的需求大幅減少。

模組系統如何影響作用域？

ES modules 的每個檔案都是獨立的模組作用域，頂層宣告不會洩漏為全域變數。這是現代開發避免全域污染的主要手段。

面試這樣答

30 秒版本

「三種作用域：全域是任何地方都能存取，函式作用域限制在函式內，區塊作用域限制在 {} 內。關鍵是 var 沒有區塊作用域，會從 if/for 等區塊中洩漏出去；let/const 有區塊作用域，在迴圈中特別重要——var 在 for 迴圈裡所有迭代共享同一個變數，let 讓每次迭代有獨立的作用域，這是為什麼現在都用 let 不用 var。」
