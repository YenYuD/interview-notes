都是「沒有值」，但null、undefined、未宣告三者本質不同

null 是有意設定的空、undefined 是宣告了但沒給值、未宣告是根本不存在。混淆這三者是 JavaScript 新手最常踩的坑。

檢查方式

怎麼正確偵測

// 檢查 null → 嚴格相等
const foo = null;
console.log(foo === null);  // true ✓

// 檢查 undefined → typeof 或嚴格相等
let bar;
console.log(typeof bar === 'undefined');  // true ✓

// 檢查未宣告 → 只能用 typeof（否則 ReferenceError）
console.log(typeof undeclaredVar === 'undefined');  // true ✓
⚠️

不要用 == null 來確認是否為 null，因為它對 undefined 也回傳 true，容易誤判。

延伸追問

面試官可能再追

為什麼 typeof null 是 'object'？

這是 JavaScript 早期實作的 bug：物件在底層以 000 開頭的 bit 表示，null 的記憶體表示也恰好是全 0，被誤判為 object。已被確認是 bug 但為保持向下相容而保留至今。

何時用 null，何時讓它保持 undefined？

慣例上，想明確表示「此處沒有值」用 null（例如清空一個 ref）；讓變數保持 undefined 代表「還未賦值」。API 回傳空值通常用 null，可選欄位缺失才用 undefined。

面試這樣答

30 秒版本

「null 是開發者主動設定的空值，typeof 是 'object'（歷史 bug）；undefined 是宣告但未賦值，typeof 是 'undefined'；未宣告的變數則根本不在作用域，任何操作都會 ReferenceError。檢查 null 用嚴格相等 === null，不要用 == null，因為它會把 undefined 也吃進來。
