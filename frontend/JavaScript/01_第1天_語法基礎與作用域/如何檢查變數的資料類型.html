typeof 不夠用：null、陣列、NaN 各有專屬檢查法

typeof 是最常用的類型判斷工具，但它有幾個著名的盲點。null 回傳 'object'、陣列也是 'object'，遇到這些情況需要用對應的專屬方法。

專屬檢查法

特殊值的正確偵測方式

// 檢查 null
value === null

// 檢查陣列
Array.isArray(value)

// 檢查 NaN（Number.isNaN 比 isNaN 精確）
Number.isNaN(value)

// 檢查 undefined（安全，即使未宣告也不報錯）
typeof value === 'undefined'

// 同時檢查 null 和 undefined
value == null // 利用寬鬆相等
⚠️

全域 isNaN('abc') 回傳 true（先強制轉型），但 Number.isNaN('abc') 回傳 false（不轉型）。檢查 NaN 請用 Number.isNaN()。

面試官可能再追

instanceof 和 typeof 的差別？

typeof 回傳原始類型字串；instanceof 檢查物件是否在某個建構函式的原型鏈上（obj instanceof Array）。instanceof 在跨 iframe 環境可能失效，Array.isArray 更可靠。

Object.prototype.toString 能做什麼？

可以得到更精確的類型字串：Object.prototype.toString.call([]) → '[object Array]'，能區分 null、undefined、Array、Date 等，比 typeof 更精細。

面試這樣答

30 秒版本

「typeof 是主要工具，但有幾個例外必須記：typeof null 是 'object'（歷史 bug），陣列的 typeof 也是 'object'。所以 null 要用 === null 判斷，陣列要用 Array.isArray()，NaN 要用 Number.isNaN() 而不是全域 isNaN（因為全域版本會先強制轉型）。需要更精細的類型識別時，可用 Object.prototype.toString.call(value)。」
