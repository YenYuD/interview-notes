function 宣告先呼叫沒問題，function 表達式卻會報錯

函式宣告（function declaration）連定義一起提升，所以可以先呼叫再宣告；函式表達式（function expression）和箭頭函式只有變數名稱提升，定義不提升，先呼叫會噴 TypeError。

核心差異

宣告 vs 表達式的提升

函式宣告定義完整提升，可先呼叫
函式表達式只有變數名提升（undefined），先呼叫 → TypeError
箭頭函式同函式表達式，不完整提升
// 函式宣告 — 可以先呼叫
hoisted(); // ✓ "This function is hoisted"
function hoisted() {
  console.log('This function is hoisted');
}

// 函式表達式 — 先呼叫會 TypeError
notHoisted(); // ✗ TypeError: notHoisted is not a function
var notHoisted = function() {
  console.log('Not hoisted');
};
為何如此

引擎處理的順序

函式宣告在編譯期間連函式本體一起放進作用域。函式表達式只是把函式賦值給一個變數，變數本身（var）會提升，但賦值要等到執行到那一行才發生。

💡

用 let/const 定義函式表達式，在 TDZ 內呼叫會得到 ReferenceError（而非 var 的 TypeError）。

延伸追問

面試官可能再追

function 宣告放在 if 區塊內，還會提升嗎？

行為因環境而異，存在瀏覽器相容性問題。非嚴格模式下各引擎行為不一致；嚴格模式下函式宣告限制在區塊作用域。建議避免在 if/for 等區塊內使用函式宣告。

函式宣告和函式表達式在使用上有什麼最佳實踐？

現代開發通常傾向使用 const + 箭頭函式（const fn = () => {}），可讀性好且不會被提升造成誤解。若需要具名函式（方便除錯 stack trace），則用函式宣告。

面試這樣答

30 秒版本

「函式宣告完整提升，連函式本體都在編譯期進入作用域，所以可以在程式碼前面呼叫。函式表達式不完整提升，只有變數名稱被提升（值是 undefined），在賦值前呼叫會 TypeError 而非 ReferenceError。這是兩者的關鍵差異，也是為什麼說函式宣告可以先用後宣告，表達式不行。」
