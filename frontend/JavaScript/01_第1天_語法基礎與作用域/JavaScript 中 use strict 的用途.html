一行指令讓 JS 引擎從寬容模式切換為嚴格執法

'use strict' 啟用嚴格模式後，靜默失敗變成拋錯，意外全域變數不再被容忍。ES6 模組與 class 內建嚴格模式，但傳統腳本仍需手動聲明。

嚴格模式做了什麼

三大核心限制

禁止未宣告變數賦值（防意外全域）
禁止刪除不可刪除屬性
禁止重複參數名稱
// 不使用嚴格模式
defineNumber() { count = 123; } // count 成為全域變數！

// 啟用嚴格模式
'use strict';
count = 123; // ReferenceError: count is not defined
使用方式

全域 vs 函式層級

用法寫法生效範圍
全域嚴格放在 JS 檔案第一行整個腳本
函式嚴格放在函式體第一行該函式內部
ES6 模組無需聲明自動嚴格
class 內部無需聲明自動嚴格
💡

現代前端幾乎都透過打包工具處理 ES6 模組，天然嚴格模式。但理解其規則仍是面試必備知識。

延伸追問

面試官可能再追

嚴格模式下 this 有什麼不同？

非嚴格模式中，頂層函式的 this 指向全域物件（瀏覽器是 window）；嚴格模式下是 undefined，可避免意外污染全域。

能在執行中途「取消」嚴格模式嗎？

不能。嚴格模式是單向切換，一旦在某個作用域宣告就無法撤銷。

面試這樣答

30 秒版本

「'use strict' 讓 JavaScript 以更嚴格的規則執行。最重要的效果是禁止意外建立全域變數、讓原本靜默失敗的操作改為拋出錯誤。放在檔案最頂端是全域生效，放在函式內只影響該函式。ES6 模組和 class 內部自動啟用嚴格模式，所以現代開發中大部分情況已無需手動宣告。」
