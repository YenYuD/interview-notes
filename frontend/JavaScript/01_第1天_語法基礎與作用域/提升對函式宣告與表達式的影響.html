宣告可以先用後寫，表達式的賦值不一起提升

函式宣告（function declaration）與函式表達式（function expression）的提升行為截然不同。宣告連定義一起提升；表達式只有變數名提升，先呼叫必報錯。

行為對照

三種寫法的提升結果

寫法提升內容宣告前呼叫
function foo(){}宣告＋定義正常執行
var bar = function(){}只有 var bar（值為 undefined）TypeError
let/const baz = function(){}提升但在 TDZReferenceError
// 函式宣告 — 可先呼叫
console.log(foo()); // 'Hello' ✓
function foo() { return 'Hello'; }

// 函式表達式（var）— TypeError
console.log(bar()); // TypeError: bar is not a function
var bar = function() { return 'Hello'; };

// 函式表達式（let）— ReferenceError
console.log(baz()); // ReferenceError: Cannot access 'baz' before initialization
let baz = function() { return 'Hello'; };
底層原因

為什麼有此差異

引擎在執行前先掃描並處理函式宣告，整個函式（名稱＋本體）都被加入作用域。函式表達式本質上是把函式賦值給變數，只有左側的變數名稱被提升，賦值（右側）要等到程式執行到那一行才發生。

ℹ️

var 表達式先呼叫得 TypeError（bar 是 undefined，不是 function）；let/const 表達式先呼叫得 ReferenceError（TDZ），這是另一個 var vs let/const 行為差異的體現。

延伸追問

面試官可能再追

實務上應該優先用函式宣告還是表達式？

各有用途：函式宣告可提升，適合定義工具函式；const + 箭頭函式表達式強制先定義再使用，讀起來更線性。箭頭函式還沒有自己的 this，在回呼中特別方便。現代 React 組件幾乎都用箭頭函式表達式。

面試這樣答

30 秒版本

「提升對兩者的影響不同。函式宣告連本體一起提升，所以可以先呼叫再宣告；函式表達式只有左邊的變數名提升，右邊的函式賦值不提升，在賦值前呼叫會報錯——var 版本是 TypeError（變數是 undefined），let/const 版本是 ReferenceError（TDZ）。實務上建議先定義後使用，避免靠提升來安排程式碼順序。」
