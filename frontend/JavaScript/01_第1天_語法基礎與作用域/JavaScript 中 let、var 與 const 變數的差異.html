同樣都是宣告變數，作用域與提升行為卻天差地遠

var / let / const 三個關鍵字共存多年，讓無數 bug 悄悄潛入。核心差異在作用域、是否可重新賦值，以及宣告前存取的結果。

關鍵概念

作用域：var 跑出 if 區塊

if (true) {
  var bar = 1;   // 函式作用域，if 外仍可存取
  let baz = 2;   // 區塊作用域，if 外 → ReferenceError
}
console.log(bar); // 1
console.log(baz); // ReferenceError
使用 var 宣告的變數會「漏出」區塊，這是最常見的 bug 來源之一。let/const 具備區塊作用域，行為更直覺。
選用原則

現代 JS 的宣告守則

const預設用這個，不可變更好
let需重新賦值時才改用
var別再用，作用域太難預測

const 不代表物件內容不能改，只代表變數綁定不能重新指向另一個值。

延伸追問

面試官可能再追

const 宣告的物件，屬性可以修改嗎？

可以。const 限制的是變數綁定不能重新賦值，但物件本身仍是可變的。若要深度不可變，需搭配 Object.freeze()。

暫時性死區（TDZ）是什麼？

let/const 在被提升後、實際宣告行執行前，變數處於「未初始化」狀態的區間就是 TDZ。這個區間內任何存取都會拋出 ReferenceError。

為什麼 var 允許重複宣告？

歷史設計決策，ES5 及以前沒有區塊作用域。ES6 引入 let/const 修正此問題，重複宣告直接報 SyntaxError。

面試這樣答

30 秒版本

「三者主要差在作用域與提升。var 是函式作用域、宣告前存取得到 undefined；let/const 是區塊作用域、宣告前存取直接 ReferenceError（TDZ）。const 額外限制不能重新賦值。現代開發我預設用 const，需要改變才換 let，完全不用 var，這樣可以避免作用域洩漏與提升陷阱。」
