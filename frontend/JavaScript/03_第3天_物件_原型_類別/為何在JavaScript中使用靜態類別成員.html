屬於類別、不屬於實例：static 成員的三種用途

static 方法和屬性掛在類別本身上，不需要實例化就能呼叫，也不會浪費每個實例的記憶體，最適合工具函式、共用常數和 Singleton 模式。

基本語法

static 只能從類別呼叫

class MathUtils {
  static PI = 3.14159;

  static add(a, b) { return a + b; }
}

console.log(MathUtils.PI);         // 3.14159 ✓
console.log(MathUtils.add(2, 3)); // 5 ✓

const m = new MathUtils();
console.log(m.PI);      // undefined ✗ 實例無法存取
m.add(1, 2);          // TypeError ✗
三種典型用途

為何要用 static？

工具函式（Utility） 不依賴實例狀態的純函式，如 Math.max()、Object.assign()
命名空間常數 把相關常數集中在類別下，如 Config.API_KEY，避免全域汙染
Singleton 模式 用 static 屬性快取唯一實例，getInstance() 保證全程只有一個 
class Singleton {
  static #instance = null; // 私有靜態屬性（ES2022）

  static getInstance() {
    if (!this.#instance) this.#instance = new Singleton();
    return this.#instance;
  }
}
console.log(Singleton.getInstance() === Singleton.getInstance()); // true
延伸追問

面試官可能再追

static 方法裡的 this 指向什麼？

指向類別本身（即建構函式），不是實例。可以用 this.staticProp 存取其他靜態成員，子類別繼承後 this 指向子類別。

靜態屬性和 prototype 上的屬性有何差異？

靜態屬性在類別（建構函式）本身上，不在 prototype 上；prototype 上的屬性所有實例共享存取，但靜態屬性只能透過類別名稱存取。

面試這樣答

30 秒版本

「static 成員屬於類別本身，不屬於任何實例。最常見的用途是工具函式（不依賴 this）和命名空間常數（如 Math.PI），也能實作 Singleton 模式。在 static 方法裡 this 指向類別本身，子類別繼承後 this 則指向子類別。」
