結構鎖死，值還能改：Object.seal()

Object.seal() 封印物件的結構——不能新增也不能刪除屬性；但現有屬性的值仍可修改，這是它和 freeze 的關鍵差異。

封印行為

什麼能做、什麼不能

const person = { name: 'Alice', age: 25 };
Object.seal(person);

person.name = 'Bob';   // ✓ 可修改現有值
person.age = 30;     // ✓

person.city = 'Taipei'; // ✗ 不能新增
delete person.name;   // ✗ 不能刪除

console.log(person);  // { name: 'Bob', age: 30 }
console.log(Object.isSealed(person)); // true
ℹ️

seal 在內部做了兩件事：呼叫 Object.preventExtensions()，並把所有現有屬性的 configurable 設為 false。

延伸追問

面試官可能再追

seal 後還能用 Object.defineProperty 改 writable 嗎？

不行。seal 把所有屬性設為 configurable: false，因此無法再修改描述符，包括 writable。若要讓值不可改，改用 freeze。

什麼情境適合用 seal 而非 freeze？

當你希望物件結構穩定（不被意外新增 / 刪除屬性），但邏輯上值需要更新時。例如一個 config 物件，欄位集合是固定的，但每個欄位的值會根據環境動態設定。

面試這樣答

30 秒版本

「Object.seal() 封印物件結構：不能新增屬性、不能刪除屬性，但現有屬性的值仍可修改。底層它做了 preventExtensions 再把所有屬性的 configurable 設為 false。和 freeze 的差別就是：seal 鎖結構，freeze 連值也鎖。」
