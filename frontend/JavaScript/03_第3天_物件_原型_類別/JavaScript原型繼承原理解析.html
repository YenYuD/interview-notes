物件直接繼承物件：原型繼承的核心邏輯

JavaScript 不靠「類別的複製」，而是讓物件持有一條指向原型物件的連結，讀取屬性時沿鏈查找，這就是原型繼承的本質。

三個關鍵概念

Prototype、[[Prototype]]、prototype 屬性

名稱存在於說明
[[Prototype]]每個物件指向上一層原型，可用 Object.getPrototypeOf(obj) 讀取
__proto__每個物件（非正式）[[Prototype]] 的非標準存取器，理解用，生產避免
.prototype函式（建構子）new 出來的實例的 [[Prototype]] 會指向此物件
建立繼承鏈

讓 Dog 繼承 Animal

function Animal(name) { this.name = name; }
Animal.prototype.makeSound = function() {
  console.log(this.name + ' makes a sound.');
};

function Dog(name) {
  Animal.call(this, name);  // 借用父建構子
}
Object.setPrototypeOf(Dog.prototype, Animal.prototype);

Dog.prototype.bark = function() { console.log('Woof!'); };

const bolt = new Dog('Bolt');
bolt.makeSound();  // 沿鏈找到 Animal.prototype.makeSound
bolt.bark();       // 在 Dog.prototype 上找到
✅

建議用 Object.setPrototypeOf() 設定繼承鏈，而非 Object.create()（後者需額外補回 constructor 屬性）。

延伸追問

面試官可能再追

Object.create(null) 有什麼用？

建立一個完全沒有 [[Prototype]] 的純粹 dictionary 物件，不繼承 Object.prototype，也就沒有 toString、hasOwnProperty 等方法。常用於實作 Map 型態的純查找表，避免原型汙染。

hasOwnProperty 和 in 有何差別？

in 會查找整條原型鏈，hasOwnProperty 只看物件自身屬性，不含繼承屬性。推薦用 Object.hasOwn(obj, key)（ES2022）作為更安全的替代。

面試這樣答

30 秒版本

「JavaScript 的繼承是基於原型：每個物件有一個 [[Prototype]] 指向另一個物件。存取屬性時，引擎先找自身，找不到就沿原型鏈向上查，直到 null。建構函式的 .prototype 屬性就是 new 出來的實例的原型，方法放在這裡能讓所有實例共用，省記憶體。class extends 只是這套機制的語法糖。」
