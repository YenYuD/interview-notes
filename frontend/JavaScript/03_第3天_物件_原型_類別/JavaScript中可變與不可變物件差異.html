const 防不了的事，Object.freeze 才能做

JS 物件預設是可變的（mutable）。const 只鎖住變數的參考，屬性仍可改；真正的不可變需要 Object.freeze()——但它只凍表層，巢狀物件仍然可變。

深層凍結

freeze 是淺的，巢狀要手動遞迴

const obj = Object.freeze({ user: { name: 'Alice' } });
obj.user.name = 'Bob';   // 成功！巢狀物件沒被凍
console.log(obj.user.name); // 'Bob'

// 深凍實作
function deepFreeze(obj) {
  Object.keys(obj).forEach(key => {
    if (typeof obj[key] === 'object' && obj[key] !== null)
      deepFreeze(obj[key]);
  });
  return Object.freeze(obj);
}
ℹ️

實務上大量使用不可變物件時，建議改用 Immer 或 Immutable.js，它們用結構共享避免重複複製的效能問題。

為何需要不可變性

不可變帶來的三個好處

易於比較 React / Redux 靠參考相等（===）快速判斷物件是否變動，不可變讓這個假設成立
可預測 函式接收不可變輸入，不必擔心被呼叫端偷偷改掉，易於推理與測試
防禦性複製 不可變物件可安全共享參考，不必每次傳入都先深複製一份
延伸追問

面試官可能再追

Object.freeze 和 Object.seal 有何差異？

兩者都防止新增 / 刪除屬性；但 freeze 還會把現有屬性設為 writable: false，讓值也不能改。seal 封住結構，但值仍可改。

原始值（string、number）是不可變的嗎？

是的。'hello'.toUpperCase() 不修改原字串，而是回傳新字串。原始值本質上是不可變的。

「JS 物件預設可變，const 只防止變數被重新指派，屬性仍可改。Object.freeze() 才能真正凍結屬性值，防止新增、修改、刪除——但只到第一層，巢狀物件不受影響。React / Redux 大量依賴不可變物件做高效變動偵測，真正需要深層不可變時建議搭配 Immer 等函式庫。」
