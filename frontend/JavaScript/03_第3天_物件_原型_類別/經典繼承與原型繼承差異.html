JAVASCRIPT · 繼承

類別的藍圖 vs 物件的連結：兩種繼承模型的核心差異

Java 的繼承靠「類別複製藍圖」；JavaScript 靠「物件直接連結另一個物件」。同樣叫繼承，底層邏輯截然不同。

模型對比

經典 vs 原型

面向經典繼承（Java / C++）原型繼承（JavaScript）
繼承單位類別（Class）物件（Object）
機制子類別複製父類別定義的藍圖物件持有指向另一物件的連結（原型鏈）
彈性靜態：類別結構在編譯期確定動態：可在執行期修改原型
多繼承多數語言不支援（Java 用 interface 變通）可透過 mixin 模擬
JS class 語法—是原型繼承的語法糖，非真正的類別
JavaScript 的做法

物件繼承物件

// 原型物件
const animal = {
  eat() { console.log('Eating…'); }
};

// dog 的 [[Prototype]] 指向 animal
const dog = Object.create(animal);
dog.bark = function() { console.log('Woof!'); };

dog.eat();  // 沿原型鏈找到 animal.eat
dog.bark(); // 在 dog 自身找到
沒有「複製」這件事——dog 本身沒有 eat，只是原型鏈把它連過去了。
延伸追問

面試官可能再追

JS 的 class 算是經典繼承嗎？

不是。class 在語法上像經典繼承，讓有 Java / C++ 背景的人容易上手，但底層仍是原型繼承。typeof MyClass === 'function'，class 只是建構函式加原型設定的語法糖。

原型繼承的「委派」是什麼意思？

當物件找不到屬性，它不是「有那個屬性的副本」，而是「把查找委派給原型」。這是 Kyle Simpson 在《You Don't Know JS》中強調的觀點：JS 的繼承更像委派（delegation），不像複製（copying）。

面試這樣答

30 秒版本

「經典繼承（Java）是類別繼承類別，子類別拿到父類別定義的複本；JavaScript 的原型繼承是物件連結物件，存取屬性時沿原型鏈查找，沒有複製這件事，更像委派。JS 的 class 語法雖然看起來像 Java，但底層仍是原型鏈，這是兩者本質差異。」
