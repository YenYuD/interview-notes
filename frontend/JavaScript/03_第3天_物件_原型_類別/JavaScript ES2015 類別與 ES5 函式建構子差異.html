同樣的原型，截然不同的可讀性

ES5 函式建構子和 ES2015 class 本質一樣，都是原型繼承。但 class 把繁瑣的 prototype 操作藏起來，讓繼承像其他語言一樣直覺。

繼承對比

同樣的 Student 繼承 Person

// ─── ES5 ──────────────────────────
function Student(name, id) {
  Person.call(this, name);   // 手動呼叫父建構子
  this.id = id;
}
Student.prototype = Object.create(Person.prototype);
Student.prototype.constructor = Student; // 補回 constructor

// ─── ES2015 ───────────────────────
class Student extends Person {
  constructor(name, id) {
    super(name);             // 一行搞定
    this.id = id;
  }
}
✅

ES2015 class 的底層仍是原型鏈。typeof Person 是 "function"，instanceof 行為相同。

延伸追問

面試官可能再追

class 和 function 建構子有什麼行為差異？

最重要的一點：class 定義的函式不可以不帶 new 呼叫（否則拋 TypeError）；ES5 函式建構子可以不帶 new 呼叫（但 this 會出錯）。此外，class 主體自動處於 strict mode。

class 方法是否可列舉（enumerable）？

不可列舉。class 方法定義於 prototype 上，且 enumerable: false；ES5 直接指派到 prototype 的方法預設可列舉。

面試這樣答

30 秒版本

「ES5 函式建構子和 ES2015 class 本質相同，底層都是原型繼承。差異在語法：ES5 繼承需要手動 Object.create() 並重設 constructor，ES2015 只要 extends + super()，程式碼更短、更不易出錯。另外 class 的方法不可列舉、主體自動進入 strict mode，也不能不帶 new 呼叫——這些是少數實際行為差異。」
