new 不只是「建立」：它做了四件事

new 關鍵字呼叫建構函式時，會自動完成「建立空物件 → 設定原型 → 綁定 this → 回傳物件」四個步驟，缺一不可地建立出一個完整的實例。

四步驟拆解

new 運算子的完整流程

① 建立空物件：相當於 const obj = {}
② 設定原型：obj.[[Prototype]] = Constructor.prototype，讓實例能存取原型方法
③ 執行建構函式：以新物件為 this，執行建構子的程式碼，設定實例屬性
④ 回傳物件：若建構子沒有明確 return 物件，自動回傳 this（新建的物件）
一個陷阱

建構子 return 物件會覆蓋 this

function Gadget(name) {
  this.name = name;
  return { type: 'Electronic' }; // 回傳了一個物件
}

const g = new Gadget('Phone');
console.log(g.type); // 'Electronic'
console.log(g.name); // undefined（this 被拋棄了）
⚠️

若建構子 return 的是原始值（數字、字串…），則忽略，仍回傳 this。只有 return 物件才會覆蓋。

延伸追問

面試官可能再追

不加 new 呼叫建構子會怎樣？

非嚴格模式：this 指向 window，屬性會掛到全域，且函式回傳 undefined（沒有明確 return）。嚴格模式：this 是 undefined，立刻 TypeError。ES2015 class 則永遠強制要 new。

如何手動模擬 new 的行為？

const obj = Object.create(Fn.prototype); Fn.call(obj, ...args); return obj;——這正是 new 的底層語意。

30 秒版本

「new 做四件事：建立空物件、把 [[Prototype]] 指向建構函式的 prototype、以這個新物件為 this 執行建構函式、最後回傳這個物件（除非建構函式自己 return 了另一個物件）。沒有 new 就沒有原型設定，也沒有正確的 this 綁定。」
