in vs hasOwnProperty：繼承屬性算不算？

兩種方式都能檢查屬性是否存在，但 in 往上找整條原型鏈，hasOwnProperty 只看物件自身——選哪個取決於你要不要算繼承來的屬性。

兩種方式對比

自身屬性 vs 含繼承屬性

const parent = { inherited: 'yes' };
const child = Object.create(parent);
child.own = 'mine';

// in 運算子：查整條鏈
console.log('inherited' in child);              // true
console.log('own' in child);                    // true

// hasOwnProperty：只查自身
console.log(child.hasOwnProperty('inherited')); // false
console.log(child.hasOwnProperty('own'));       // true
推薦做法

用 Object.hasOwn()（ES2022）

// 比 hasOwnProperty 更安全：即使物件沒有 prototype 也能用
console.log(Object.hasOwn(child, 'own'));       // true
console.log(Object.hasOwn(child, 'inherited')); // false

// 為何比 hasOwnProperty 好？
const dict = Object.create(null); // 無 prototype 的物件
dict.foo = 1;
// dict.hasOwnProperty('foo') → TypeError（沒有這個方法）
// Object.hasOwn(dict, 'foo') → true ✓
✅

新專案建議使用 Object.hasOwn()，舊瀏覽器可 polyfill。避免直接呼叫 obj.hasOwnProperty()，因為 Object.create(null) 建立的物件沒有這個方法。

延伸追問

面試官可能再追

用 obj.key !== undefined 可以判斷屬性存在嗎？

不可靠。若屬性明確設為 undefined（obj.key = undefined），這個判斷會誤判為不存在。應用 'key' in obj 或 Object.hasOwn()。

for...in 遍歷屬性時要注意什麼？

for...in 會列出所有可列舉屬性，包含繼承來的。通常應在迴圈內加 Object.hasOwn(obj, key) 或 obj.hasOwnProperty(key) 過濾，只處理自身屬性。

面試這樣答

30 秒版本

「in 運算子查整條原型鏈，繼承屬性也算；hasOwnProperty 只查物件自身。現代建議用 Object.hasOwn(obj, key)（ES2022），它功能等同 hasOwnProperty，但不會因為物件以 Object.create(null) 建立而報錯。用 obj.key !== undefined 判斷屬性存在是個陷阱，屬性值若本來就是 undefined 就會誤判。」
