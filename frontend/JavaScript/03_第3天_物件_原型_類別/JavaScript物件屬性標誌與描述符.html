屬性不只有值：三個標誌控制它能做什麼

每個物件屬性除了有值，還帶著三個布林標誌，決定它能否被寫入、列舉、重新配置。理解這些標誌，才能真正掌控物件的封裝與不可變性。

三個核心標誌

writable / enumerable / configurable

標誌預設false 時的效果
writabletrue屬性值不可修改；嚴格模式下賦值拋 TypeError
enumerabletrue不出現在 for...in、Object.keys() 中
configurabletrue不可刪除、不可再修改描述符；這個設定本身不可逆
操作方式

讀取與設定描述符

// 讀取描述符
const user = { name: 'John' };
console.log(Object.getOwnPropertyDescriptor(user, 'name'));
// { value: 'John', writable: true, enumerable: true, configurable: true }

// 設定描述符
Object.defineProperty(user, 'id', {
  value: 42,
  writable: false,       // 唯讀
  enumerable: false,    // 隱藏於列舉
  configurable: false  // 鎖死描述符
});

user.id = 99;  // 靜默失敗；strict mode 下拋 TypeError
console.log(user.id); // 42（未變）
⚠️

configurable: false 設定後無法再改回 true，也無法刪除屬性——這是單向門，使用前三思。

延伸追問

面試官可能再追

Object.freeze() 和手動設 writable: false 有何差異？

Object.freeze() 會對所有屬性批次設 writable: false 且 configurable: false，同時讓物件不可擴展（不能加新屬性）。手動 defineProperty 只影響你指定的那個屬性。

enumerable: false 的實際應用？

將工具方法或私有狀態標記為不可列舉，讓它們在 for...in、JSON.stringify、Object.keys() 中消失，保持物件結構乾淨。JS 內建的 prototype 方法（如 toString）就是這樣設計的。

面試這樣答

30 秒版本

「每個 JS 物件屬性除了值之外，還有三個標誌：writable（能否改值）、enumerable（能否在 for-in 或 Object.keys 裡出現）、configurable（能否刪除或再改描述符）。預設全部 true。用 Object.defineProperty() 可以精確控制，Object.freeze() 則是批次把全部屬性鎖死的快捷方式。」
