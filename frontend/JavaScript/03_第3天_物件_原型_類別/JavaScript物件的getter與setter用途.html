屬性背後的守門員：getter 與 setter

getter 和 setter 讓你攔截屬性的讀取與寫入，在不改變呼叫語法的前提下，偷偷加上驗證、轉換或計算邏輯。

核心語法

用 get / set 定義存取器屬性

const person = {
  _name: 'John',

  get name() {              // 讀取時觸發
    return this._name;
  },
  set name(val) {           // 寫入時觸發
    if (val.trim().length > 0) this._name = val;
    else console.log('Invalid name');
  }
};

console.log(person.name);   // 'John'  ← getter
person.name = 'Jane';       // ← setter，帶驗證
person.name = '';          // 'Invalid name'
下劃線 _name 是慣例，暗示「內部屬性，請透過 getter/setter 存取」。
四種典型用途

為何需要 getter / setter？

封裝實作 外界只看 obj.name，內部儲存格式可任意改變
資料驗證 setter 可在賦值前檢查合法性，拒絕無效資料
計算屬性 getter 可根據其他屬性即時計算（如 fullName = 名 + 姓）
副作用 setter 可觸發 log、事件通知、UI 更新等
延伸追問

面試官可能再追

getter / setter 和 Object.defineProperty 的關係？

兩者等效。get name(){} 語法是 Object.defineProperty(obj, 'name', { get(){ … } }) 的語法糖，都定義存取器屬性（accessor property），而非資料屬性（data property）。

getter 只定義不定義 setter，會怎樣？

對該屬性賦值會靜默失敗（非嚴格模式），或在嚴格模式下拋 TypeError。

在 class 裡也能用 getter / setter 嗎？

可以，語法完全相同，寫在 class 主體內即可。它們會定義在類別的 prototype 上。

面試這樣答

30 秒版本

「getter 和 setter 讓我在物件屬性的讀取和寫入之間插入邏輯，外部呼叫語法（點記法）完全不變。getter 適合做計算屬性，setter 適合加驗證或觸發副作用。底層等同 Object.defineProperty 設定存取器屬性。在需要封裝內部狀態、又想保持簡潔 API 時很實用。」
