五種建立物件的方式，選哪個最合適？

從最簡單的物件字面量到 ES2015 class，每種方式有其適用場景。理解各自的原型設定方式，才能選對工具。

五種方法對照

最值得注意

Object.create() 的特殊能力

// 精確設定原型
const proto = {
  greet() { console.log(`Hi, I'm ${this.name}`); }
};
const person = Object.create(proto);
person.name = 'Alice';
person.greet(); // Hi, I'm Alice

// 建立無原型的純 dictionary
const dict = Object.create(null);
// dict.toString → undefined（不繼承任何東西）
✅

日常開發優先選物件字面量或 class；只有需要控制原型時才用 Object.create()。

延伸追問

面試官可能再追

物件字面量和 new Object() 有差嗎？

功能相同，都建立 [[Prototype]] 指向 Object.prototype 的物件。字面量更簡潔，生產環境幾乎都用字面量，new Object() 基本上是歷史遺留。

class 和建構函式建立的實例，原型鏈一樣嗎？

一樣。class Person 的底層就是個函式，new Person() 的實例的 [[Prototype]] 都指向 Person.prototype。

面試這樣答

30 秒版本

「JS 建立物件有五種主要方式。日常最常用的是物件字面量，簡潔直觀；需要多個相似實例就用 class（或舊式建構函式）；需要精確控制原型繼承用 Object.create()，傳入 null 還能建立無原型的純 dictionary。每種方式的核心差異在於：新物件的 [[Prototype]] 指向哪裡。」
