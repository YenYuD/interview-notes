讓子類別站在巨人肩上：extends 與 super

ES2015 的繼承語法讓你用 extends 宣告父子關係，再用 super() 呼叫父類別建構子，比 ES5 手動串原型鏈直覺許多。

核心語法

extends + super 的三個場景

class Animal {
  constructor(name) { this.name = name; }
  speak() { console.log(`${this.name} makes a noise.`); }
}

class Dog extends Animal {
  constructor(name, breed) {
    super(name);        // ① 呼叫父類別建構子，必須在 this 之前
    this.breed = breed;
  }
  speak() {
    super.speak();      // ② 呼叫父類別方法
    console.log(`${this.name} barks.`);
  }
}
super() 必須在子類別建構子使用 this 之前呼叫，否則會拋出 ReferenceError。
三種繼承行為

繼承、擴充、覆寫

繼承 子類別自動擁有父類別的屬性與方法，無需重複定義
擴充 子類別加入父類別沒有的新屬性（如 breed）或新方法
覆寫（Override） 子類別重新定義同名方法，並可選擇是否透過 super.method() 呼叫原版
延伸追問

面試官可能再追

子類別省略 constructor 會怎樣？

若子類別未定義 constructor，JS 會自動插入一個預設版本，內部只做 super(...args)，效果等同繼承父類別的建構子。

class 繼承和 ES5 原型繼承有何本質差異？

沒有本質差異，class extends 只是語法糖，底層仍是把子類別的 prototype 的 [[Prototype]] 指向父類別的 prototype。

可以繼承內建物件（如 Array）嗎？

ES2015 可以，class MyArr extends Array {} 可正常繼承 Array 的方法與行為；但 ES5 手動繼承內建物件有已知的限制與 bug。

面試這樣答

30 秒版本

「ES2015 類別繼承用 extends 宣告父子關係，子類別會自動繼承父類別的所有屬性與方法。建構子裡必須先呼叫 super() 才能用 this，因為 super 負責初始化父類別部分的狀態。想擴充或覆寫父類別方法時，也可以用 super.method() 呼叫原版實作再加工。底層本質仍是原型鏈，class 只是更易讀的語法糖。」
