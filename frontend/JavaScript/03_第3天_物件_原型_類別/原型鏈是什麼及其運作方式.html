物件 · 原型

物件身上沒有的方法，它會「往上」找

存取屬性時，JS 先看物件自己，沒有就沿著原型一層層往上找，直到找到、或到鏈的盡頭 null。這條路徑就是原型鏈，也是 JS 繼承的本質。

每往上一層就是一次查找成本。鏈尾是 Object.prototype，再上去就是 null——找不到就回傳 undefined（或方法呼叫報錯）。
運作方式

三步驟

  1. 先找物件自己的屬性。
  2. 沒有 → 找它的原型（__proto__ / 建構子.prototype）。
  3. 還沒有 → 找原型的原型…一路到 null 為止。
✅

把方法掛在 Person.prototype 上，所有實例共用同一份，不必每個物件各存一份，省記憶體——這就是原型的價值。

延伸追問

面試官可能再追

__proto__ 和 prototype 差在哪？

prototype 是「函式」上的屬性，建立實例時當作它們的原型；__proto__（即 [[Prototype]]）是「物件」實際指向的原型。new Person() 後，實例的 __proto__ === Person.prototype。

怎麼只查自有屬性、不含繼承的？

用 obj.hasOwnProperty(key) 或 Object.hasOwn(obj, key)；for...in 會跑到繼承屬性，要小心。

面試這樣答

30 秒版本

「原型鏈是 JS 的繼承機制。存取屬性時，引擎先找物件自己，沒有就沿原型往上找，直到命中或到 null。把共用方法放在 prototype 上，所有實例共享同一份、省記憶體。實例的 __proto__ 指向建構子的 prototype，這串連起來就是原型鏈。」
