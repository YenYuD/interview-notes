空物件不是 falsy：可靠判斷 {} 的正確方式

if (!obj) 判斷不了空物件——空物件是 truthy！Object.keys(obj).length === 0 才是最通用、最直覺的標準做法。

方法對照

四種做法的差異

方法寫法備註
Object.keys()Object.keys(obj).length === 0最常用；只看自身可列舉屬性
Object.entries()Object.entries(obj).length === 0同上，語意更明確
Object.values()Object.values(obj).length === 0功能等同，選一個一致使用
for...in迴圈沒執行則為空搭配 hasOwnProperty 可排除繼承屬性
 
const isEmpty = (obj) => Object.keys(obj).length === 0;

console.log(isEmpty({}));            // true
console.log(isEmpty({ a: 1 }));      // false
邊界情況

這些情形要注意

⚠️

不可列舉屬性：若物件有用 Object.defineProperty 定義的不可列舉屬性，Object.keys() 不會列出，可能誤判為空。

ℹ️

繼承屬性：以上方法都只看自身屬性，不含從原型繼承的屬性。for...in 加 hasOwnProperty 確保一致行為。

延伸追問

面試官可能再追

JSON.stringify(obj) === '{}' 能判斷空物件嗎？

可以，但不建議：它不處理不可列舉屬性，且效能比 Object.keys 差；若物件有 toJSON 方法，結果也可能被覆蓋。

如何判斷一個值既不是 null/undefined 又是空物件？

obj !== null && typeof obj === 'object' && Object.keys(obj).length === 0——先排除 null（typeof null === 'object' 是 JS 歷史 bug），再檢查 keys。

面試這樣答

30 秒版本

「空物件 {} 是 truthy，不能用 if (!obj) 判斷。最可靠的方式是 Object.keys(obj).length === 0，只看自身可列舉屬性。若需考慮不可列舉屬性，改用 Object.getOwnPropertyNames(obj).length === 0。使用前記得先排除 null，因為 typeof null === 'object' 是個陷阱。」
