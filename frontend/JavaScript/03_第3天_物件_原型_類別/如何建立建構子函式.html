ES5 的「類別」：用建構子函式批次製造物件

建構子函式是 class 語法出現前的主要批次建立物件方式。關鍵在：PascalCase 命名、用 this 設定屬性、方法放在 prototype。

三個要點

建構子函式的標準寫法

// 1. PascalCase：告訴使用者要用 new 呼叫
function Person(name, age) {
  // 2. this 設定實例屬性
  this.name = name;
  this.age = age;
}

// 3. 方法放 prototype，所有實例共用（省記憶體）
Person.prototype.greet = function() {
  console.log(`Hi, I'm ${this.name}`);
};

const alice = new Person('Alice', 28);
alice.greet();                       // Hi, I'm Alice
console.log(alice instanceof Person); // true
✅

方法若直接寫在建構子內（this.greet = function(){}），每個實例都會各存一份函式，浪費記憶體。放在 prototype 上，所有實例共用一份。

方法位置對比

this 內 vs prototype 上

放在 this（記憶體浪費） this.greet = function(){} ← 每個實例各複製一份
放在 prototype（推薦） Person.prototype.greet = function(){} ← 所有實例共用一份
延伸追問

面試官可能再追

建構子函式和 class 哪個比較好？

現代開發幾乎都用 class，可讀性更高、繼承更簡單、強制需要 new。除非維護舊 ES5 程式碼，否則沒有理由不用 class。

如何判斷一個物件是某建構函式的實例？

用 instanceof：alice instanceof Person；或 Object.getPrototypeOf(alice) === Person.prototype。instanceof 會沿原型鏈查找，所以子類別實例也會被父類別的 instanceof 認可。

面試這樣答

30 秒版本

「建構子函式用 PascalCase 命名，以示需搭配 new 使用。在函式內用 this 設定每個實例專屬的屬性，方法放在 prototype 讓所有實例共用以省記憶體。今天大多直接用 class 語法，但底層機制完全相同。」
