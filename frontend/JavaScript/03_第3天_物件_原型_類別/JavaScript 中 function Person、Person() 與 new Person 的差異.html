差一個 new，結果天差地遠

function Person(){}、Person()、new Person() 三個寫法看似相近，卻代表「定義」、「一般呼叫」、「建立實例」三件截然不同的事。少了 new，你只會拿到 undefined。

三者對照

一眼看清差異

寫法意思回傳值常見錯誤
function Person(){}定義函式，不執行無無
Person()一般函式呼叫undefined（沒有 return）誤以為能建立實例
new Person()建構子呼叫新建的物件無（正確用法）
new 做了什麼

new 運算子的四步驟

建立空物件：{}
設定原型：新物件的 [[Prototype]] 指向 Person.prototype
綁定 this：執行建構子，函式內 this 指向新物件
回傳物件：若建構子沒有明確 return 物件，則回傳 this（新物件）
⚠️

若建構子明確 return 一個物件，new 會回傳那個物件而非 this；若 return 的是原始值則忽略，仍回傳 this。

延伸追問

面試官可能再追

忘記 new 呼叫建構子，this 跑到哪去？

在非嚴格模式下，this 會指向全域物件（window），你的屬性會汙染全域；在嚴格模式下會拋 TypeError，因為 this 是 undefined。

如何防止建構子被不帶 new 呼叫？

在函式內加上防護：if (!(this instanceof Person)) return new Person(name); 或改用 ES2015 class（強制需要 new，否則拋錯）。

面試這樣答

30 秒版本

「function Person(){} 只是定義一個函式，Person() 是一般呼叫，沒有 return 就是 undefined。只有 new Person() 才會建立實例——new 會建立空物件、把 [[Prototype]] 指向 Person.prototype、把 this 綁到新物件，最後回傳它。漏了 new，非嚴格模式下 this 會污染全域，嚴格模式直接報錯。」
