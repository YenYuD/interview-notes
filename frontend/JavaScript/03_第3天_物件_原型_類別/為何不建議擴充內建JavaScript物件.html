別動 Array.prototype：擴充內建物件的五個地雷

向 Array.prototype、String.prototype 加方法看似方便，但這等同修改全域狀態——一旦與其他函式庫或未來標準衝突，會是難以追蹤的 bug 溫床。

為什麼危險

五個不擴充的理由

命名衝突 兩個函式庫各自加了 Array.prototype.contains，互相覆蓋，行為不可預測
未來標準衝突 你的 Array.prototype.flatten 可能和 ES2019 原生 flat() 語意不同
for...in 汙染 加到 prototype 的屬性預設可列舉，會出現在 for...in 迴圈裡嚇壞別人
維護困難 其他開發者不知道 [].myMethod 來自哪裡
安全風險 可列舉屬性可被惡意程式碼利用（Prototype Pollution）
正確替代方案

改用工具函式或 Polyfill

// ✗ 危險：汙染全域 prototype
String.prototype.reverseString = function() {
  return this.split('').reverse().join('');
};

// ✓ 安全：純工具函式
function reverseString(str) {
  return str.split('').reverse().join('');
}

// ✓ 唯一合理例外：Polyfill（標準已存在，只是舊瀏覽器缺少）
if (!Array.prototype.includes) {
  Array.prototype.includes = function(val) { /* … */ };
}
✅

polyfill 是擴充內建物件的唯一合理例外：標準規範中已存在的功能，替老舊環境補實作。

延伸追問

面試官可能再追

polyfill 和 monkey-patching 的差別？

polyfill 是補齊「規範中存在但環境尚未實作」的功能，有明確語意；monkey-patching 是任意修改既有物件的行為，通常是不得已的 workaround，風險更高。

如果真的要加方法，有更安全的做法嗎？

可以建立一個繼承自內建物件的子類別：class MyArray extends Array { myMethod(){…} }，影響範圍只在自己的子類別，不汙染全域。

面試這樣答

30 秒版本

「擴充 Array.prototype 等內建物件等同修改全域，有三大風險：與其他函式庫命名衝突、與未來 ECMAScript 標準衝突、以及新增可列舉屬性汙染 for-in。替代方案是寫純工具函式，或繼承建立子類別。唯一合理的例外是 polyfill——為舊環境補齊規範已定義但尚未實作的功能。」
