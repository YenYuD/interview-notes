函式式程式設計・概念辨析

容易搞混的兩個概念：Currying 不等於 Partial Application

兩者都能從通用函式衍生專用函式，但柯里化嚴格每次一個參數、部分套用可一次固定多個。記住這個核心差異，面試就不會答混。

對比

一張表，一次釐清

柯里化（Currying）部分套用（Partial Application）
參數格式嚴格每次一個：f(a)(b)(c)可一次固定多個：f(a, b) 留 c
函式鏈長度等於原函式 arity不固定，視固定了幾個而定
常見實作巢狀箭頭函式 / curry utilbind / 自定義 partial
適合場景函式組合（compose/pipe）一次填多個固定參數
柯里化：f(a)(b)(c) 
const add = (a) => (b) => (c) => a + b + c;
add(1)(2)(3); // 6
// 每次只能一個參數
部分套用：一次固定多個 
const add = (a, b, c) => a + b + c;
const addOne = add.bind(null, 1); // 固定 a=1
addOne(2, 3); // 6
// 剩餘兩個參數一次傳入
關係

柯里化函式天然支援部分套用

const curriedAdd = (a) => (b) => (c) => a + b + c;

// 柯里化同時支援部分套用
const add1 = curriedAdd(1);      // 固定 a=1（這就是部分套用！）
const add1and2 = add1(2);        // 再固定 b=2
add1and2(3); // 6
ℹ️

柯里化後的函式是部分套用的「超集」——你可以對它做部分套用，但未柯里化的函式不一定支援單參數鏈式呼叫。

延伸追問

面試官可能再追

可以把柯里化說成一種特殊的部分套用嗎？

某種程度上可以：柯里化是「每次套用一個參數的部分套用」。但學術定義上兩者是不同的概念——柯里化是函式轉換（結構性改變），部分套用是呼叫策略（使用方式）。

面試這樣答

30 秒版本

「兩者都能預先填入部分參數、衍生出專用函式。核心差異：柯里化嚴格每次只接受一個參數，轉換後的結構是 f(a)(b)(c)；部分套用則可以一次固定多個，更靈活。柯里化的函式天然支援部分套用，因為你可以中途停下來只填一個或幾個參數。柯里化更適合函式組合場景，部分套用用 bind 就夠了。」
