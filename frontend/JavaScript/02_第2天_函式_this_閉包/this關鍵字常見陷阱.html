this・常見錯誤

三種最容易踩的 this 地雷，以及怎麼解

this 的值由呼叫方式決定，而非定義位置。最常見的三個陷阱：方法當回呼傳出、巢狀函式內 this 跳走、誤用箭頭函式當物件方法。

陷阱一

方法作為回呼傳出，this 丟失

問題：脫離物件後 this 不再是 obj 
const obj = { value: 42, get() { return this.value; } };
const fn = obj.get;
fn(); // undefined ← this 變成 global/undefined
解法：bind 固定 this 
const fn = obj.get.bind(obj);
fn(); // 42 ✅
陷阱二

巢狀普通函式裡的 this 指向全域

問題：innerFunction 的 this 不是 obj 
const obj = {
  value: 42,
  get() {
    function inner() { return this.value; }
    return inner(); // undefined
  }
};
解法：改用箭頭函式繼承外層 this 
const obj = {
  value: 42,
  get() {
    const inner = () => this.value;
    return inner(); // 42 ✅
  }
};
陷阱三

箭頭函式當物件方法，this 跑掉

const obj = {
  value: 42,
  getValue: () => this.value  // ❌ this 是外層作用域（通常是 global）
};
obj.getValue(); // undefined
⚠️

物件字面量本身不建立新的 this，箭頭函式繼承的是定義時的外層 this（通常是 global 或 undefined）。物件方法請用普通函式。

延伸追問

面試官可能再追

嚴格模式下，自由函式呼叫的 this 是什麼？

嚴格模式（'use strict'）下，自由函式呼叫的 this 是 undefined，而非全域物件。ES6 class 內部預設為嚴格模式。

self = this 的老做法和箭頭函式哪個好？

現代 JavaScript 應優先選箭頭函式，語意更清晰且不易出錯。self/that/me = this 是 ES6 之前的慣用解法，維護舊代碼時仍常見。

面試這樣答

30 秒版本

「this 最常見的三個陷阱：一、把方法當回呼傳出，this 從物件變成 global——用 bind 或箭頭函式解；二、巢狀普通函式的 this 不繼承外層，改用箭頭函式；三、箭頭函式不該當物件字面量的方法，因為它的 this 不是物件本身。核心原則：this 由呼叫方式決定，不由定義位置決定。」
