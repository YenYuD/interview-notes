函式跑完了，變數卻沒消失

閉包就是：內層函式記住了它出生時的作用域，就算外層函式早已執行完畢，那些變數依然活著、依然可存取。靠的是 JavaScript 的詞法作用域。

DEMO — 私有計數器

外層跑完，count 為什麼還在？

function createCounter() {
  let count = 0;        // 沒人能從外面直接碰到它
  return () => ++count;  // 內層函式抓住了 count
}
const next = createCounter();

createCounter() 早就回傳結束了，但每次呼叫 next()，count 都還記得上次的值：

這個按鈕背後就是一個閉包
count = 0
// 點 next() 看 count 持續累加…
count 完全藏在函式裡，外部存取不到——這就是用閉包做私有變數 / 資料封裝的經典手法。
為什麼能做到

詞法作用域：寫的時候就決定了

函式能存取哪些變數，是由它在原始碼裡的位置決定的，不是執行時。內層函式寫在外層裡面，就永遠握有外層變數的參考——這份參考讓那些變數不會被垃圾回收。

✅

常見用途：私有變數、函式工廠 / 柯里化、事件處理器與回呼記住當下狀態、模組模式。

延伸追問

面試官可能再追

迴圈裡用 var 為什麼都印出同一個值？

因為 var 是函式作用域，三個閉包共用同一個變數。改用 let（區塊作用域，每圈各一份），或用 IIFE 包一層即可。

閉包會造成記憶體洩漏嗎？

會：被閉包抓住的變數無法回收。長期持有大型物件、或忘了移除的事件監聽器，都可能讓記憶體一直長。用完記得解除引用 / removeEventListener。

面試這樣答

30 秒版本

「閉包是函式記住它出生時的詞法作用域，即使外層函式已經執行完，內層函式仍能存取那些變數。它讓我能做私有變數、函式工廠、回呼保存狀態。要注意被閉包抓住的變數不會被回收，所以長期持有大物件或忘了移除監聽器時，可能造成記憶體洩漏。」
