this 是誰，看「怎麼呼叫」而不是怎麼定義

同一個函式，呼叫方式不同，this 就不同。記住四種綁定的優先序，再加上箭頭函式的特例，幾乎所有 this 謎題都能解開。

優先序由高到低

綁定觸發方式this 指向
new 綁定new Fn()新建立的物件
顯式綁定call/apply/bind你指定的物件
隱式綁定obj.fn()呼叫前的那個物件 obj
預設綁定fn()嚴格模式 undefined；否則全域物件
💡

箭頭函式沒有自己的 this，它直接繼承外層的 this，且 call/apply/bind 改不動。所以物件方法不要寫成箭頭函式，否則 this 會抓到外層而非物件本身。

延伸追問

面試官可能再追

把 obj.method 取出來再呼叫，this 跑掉了？

對。const f = obj.method; f() 變成預設綁定（this 不是 obj）。解法：obj.method.bind(obj) 或用箭頭函式包起來。

callback 裡的 this 為什麼不對？

傳給 setTimeout / 事件處理器的函式是被「裸呼叫」的，走預設綁定。用箭頭函式或 bind 鎖定 this。

面試這樣答

30 秒版本

「this 的值看呼叫方式，優先序是 new ＞ 顯式(call/apply/bind) ＞ 隱式(obj.fn) ＞ 預設(fn)。箭頭函式是特例——它沒有自己的 this，繼承外層且綁不動，所以很適合用在 callback 鎖定 this，但不適合當物件方法。」
