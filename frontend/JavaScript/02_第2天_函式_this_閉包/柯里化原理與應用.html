函式式程式設計・Currying

一次只吃一個參數，柯里化讓函式可無限組合

柯里化（Currying）把 f(a, b, c) 轉成 f(a)(b)(c)，每次只接受一個參數並回傳下一個函式。這讓你能輕鬆從通用函式「特化」出專用函式，是函式組合的核心技術。

原理

巢狀函式 + 閉包

// 傳統寫法
function curriedAdd(a) {
  return function(b) {
    return function(c) {
      return a + b + c;
    };
  };
}

// 箭頭函式簡化
const curriedAdd = (a) => (b) => (c) => a + b + c;

curriedAdd(1)(2)(3); // 6

// 部分套用：先填一部分，之後再補
const add1 = curriedAdd(1);       // 固定 a=1
const add1and2 = add1(2);         // 固定 b=2
add1and2(10); // 13
實務應用

從通用函式衍生專用函式

// 通用：含稅計算
const withTax = (rate) => (price) => price * (1 + rate);

// 特化：各地稅率
const tw = withTax(0.05);   // 台灣 5%
const us = withTax(0.08);   // 美國某州 8%

tw(100);  // 105
us(100);  // 108
ℹ️

柯里化是函式組合（compose/pipe）的基礎——每個步驟只接受一個參數，才能直接串接。Ramda、Lodash/fp 等函式庫的 API 設計都以柯里化為前提。

延伸追問

面試官可能再追

如何實作一個通用的 curry 輔助函式？

遞迴版本：比較已收到的參數數量與原函式的 fn.length，未滿就繼續收；達到就執行。const curry = fn => (...args) => args.length >= fn.length ? fn(...args) : curry(fn.bind(null, ...args));

柯里化和部分套用最大的差異？

柯里化嚴格「每次一個參數」，函式鏈長度等於 arity；部分套用則可以一次固定多個參數，較靈活但不那麼純粹。

面試這樣答

30 秒版本

「柯里化把多參數函式轉換成每次只接受一個參數的函式鏈，背後是閉包記住前面的參數。實務好處是可以從通用函式衍生出語意明確的專用函式，例如 withTax(0.05) 產生台灣含稅計算器。柯里化也是函式組合的基礎，Ramda 等 FP 函式庫大量使用。與部分套用的差別：柯里化嚴格每次一個參數，部分套用可以一次固定多個。」
