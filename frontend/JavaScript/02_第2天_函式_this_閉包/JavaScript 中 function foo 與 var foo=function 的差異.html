函式宣告 vs 函式表達式

宣告可以「先呼叫後定義」，表達式不行

function foo(){} 是函式宣告，整個函式體會被 Hoisting（提升）到頂端，可在任何地方呼叫；var foo = function(){} 是函式表達式，只有變數名稱被提升，本體不提升，提前呼叫直接報錯。

關鍵差異

Hoisting 行為完全不同

函式宣告 — 安全 
foo(); // ✅ 'FOOOOO'
function foo() {
  console.log('FOOOOO');
}
函式表達式 — 提前呼叫報錯 
foo(); // ❌ TypeError: foo is not a function
var foo = function() {
  console.log('FOOOOO');
};
⚠️

函式表達式用 var 宣告時，提升的只有 var foo（值為 undefined），並非函式本體，因此呼叫會得到 TypeError: foo is not a function。

具名函式表達式

函式名稱只在函式內部可見

const myFunc = function namedFunc() {
  console.log(namedFunc); // ✅ 函式本身
};

myFunc();
console.log(namedFunc); // ❌ ReferenceError: namedFunc is not defined

具名函式表達式的名稱 namedFunc 僅在函式自己的作用域內存在，常用於遞迴自我呼叫，不污染外部命名空間。

延伸追問

面試官可能再追

用 let / const 定義的函式表達式提升行為？

let/const 雖然也會提升，但進入 TDZ（Temporal Dead Zone），在宣告前存取會拋出 ReferenceError，不同於 var 的 undefined。

實務上何時選函式宣告，何時選表達式？

需要在整個作用域中隨處呼叫，選函式宣告；函式只用一次、作為回呼、或要限制可見範圍，選表達式（搭配 const）。

面試這樣答

30 秒版本

「函式宣告整個函式體會被 Hoisting，可以在宣告之前呼叫；函式表達式只有變數名稱被提升，本體不提升，提前呼叫得到 TypeError。實務上我預設用 const 加函式表達式，因為它明確表示函式不會被重新賦值，行為更可預測；只有需要在模組頂端到處呼叫的輔助函式才考慮函式宣告。」
