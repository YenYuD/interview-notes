把多參數函式拆成鏈式呼叫：Currying vs 部分套用

Currying 每次只吃一個參數，回傳下一關函式；部分套用則先固定幾個參數，剩下的以後再補。兩者都讓你從通用函式「客製」出專用函式。

const add = (a) => (b) => a + b;

部分套用 
function add(a, b) { return a + b; }
const add2 = add.bind(null, 2);
add2(3); // 5
實務場景

為什麼這兩個技巧有用？

當你需要對同一組資料反覆套用「只差一個參數」的函式時，這兩種技巧能大幅減少重複代碼：

// 通用：計算含稅價
const withTax = (rate) => (price) => price * (1 + rate);

// 特化：台灣 5% 營業稅
const twTax = withTax(0.05);
twTax(100); // 105
twTax(200); // 210
✅

Currying 天然適合函式組合（compose/pipe）；部分套用更直覺，適合「先填一部分參數再呼叫」的情境。

延伸追問

面試官可能再追

Currying 和部分套用最大的差別是什麼？

Currying 必須「每次一個參數」，函式鏈長度等於參數數量；部分套用可以一次固定多個參數，較靈活。

如何實作一個通用的 curry 函式？

遞迴檢查收到的參數數量是否達到原函式的 fn.length，未達就繼續回傳等待下一個參數的函式，達到就執行。

bind 實現部分套用的限制是什麼？

只能從左側固定參數；若需要固定中間或右側的參數，要自己寫 partial 輔助函式。

面試這樣答

30 秒版本

「Currying 是把多參數函式拆成每次只接受一個參數的函式鏈，例如 add(a)(b)；部分套用是預先固定部分參數，像 add.bind(null, 2) 回傳一個只需第二個參數的函式。兩者都能從通用函式衍生出更具語意的專用函式，減少重複，提升可組合性。」
