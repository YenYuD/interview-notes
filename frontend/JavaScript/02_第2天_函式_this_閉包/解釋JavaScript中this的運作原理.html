JAVASCRIPT・this

this 不看定義位置，只看怎麼被呼叫

this 是對「當前執行上下文」的動態參考，值由呼叫方式決定。掌握六條規則，就能在任何情境下預測 this 的值。

六條規則（優先順序由高到低）

this 的決定規則

1. 箭頭函式 — 詞法繼承定義時外層的 this，不受其他規則影響
2. new 建構子 — this 是新建立的物件實例 new Foo()
3. 明確綁定 — call(obj) / apply(obj) / bind(obj) 傳入的物件
4. 隱式綁定（方法呼叫） — obj.fn()，this 是 obj
5. 自由呼叫 — 非嚴格模式是全域物件（window）；嚴格模式是 undefined
6. 全域腳本頂層 — 瀏覽器是 window，Node.js 是 module.exports / global
對照程式碼

同一個函式，四種呼叫方式，四種 this

function show() { console.log(this?.name ?? this); }

const obj = { name: 'obj', show };

show();           // window / undefined（自由呼叫）
obj.show();       // { name: 'obj', ... }（隱式）
show.call({name:'explicit'}); // { name: 'explicit' }（明確）
new show();       // show {}（new 建構）

// 箭頭函式：完全忽略以上規則
const arrow = () => console.log(this);
arrow.call({ name: 'ignored' }); // 依然是外層 this
延伸追問

面試官可能再追

class 內部的 this 是哪種規則？

class 方法呼叫屬於「隱式綁定」，但 class 內部預設為嚴格模式，因此方法獨立呼叫時 this 是 undefined，而非全域物件。

事件處理器中 this 是什麼？

使用普通函式作為事件處理器，this 指向觸發事件的 DOM 元素（event.currentTarget）；使用箭頭函式則繼承外層 this，不是 DOM 元素。

面試這樣答

30 秒版本

「this 是動態決定的執行上下文，值由呼叫方式而非定義位置決定。優先順序由高到低：箭頭函式詞法繼承外層、new 建構子、call/apply/bind 明確指定、方法呼叫隱式綁定、最後才是自由呼叫（全域或 undefined）。箭頭函式的 this 完全不受其他規則影響，這是它最重要的特性。」
