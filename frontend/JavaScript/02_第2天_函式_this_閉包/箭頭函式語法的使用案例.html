箭頭函式・ES6

不只是語法糖：箭頭函式的最佳使用場景

箭頭函式（=>）比普通函式更簡潔，但它最關鍵的特性是詞法 this——繼承外層作用域的 this，不建立自己的。這讓它在回呼和事件處理中特別好用，但也有不適合的場合。

語法

三種常見寫法

// 單一表達式：隱式回傳，無須 return 或大括號
const add = (a, b) => a + b;

// 多行：需要大括號和 return
const greet = (name) => {
  const msg = `Hello, ${name}!`;
  return msg;
};

// 無參數：空括號
const getTime = () => Date.now();
最佳場景

什麼時候箭頭函式最合適？

陣列方法回呼 — 短小、一次性，箭頭函式讓程式碼更宣告式 
[1,2,3].map(n => n * 2).filter(n => n > 3);
需要詞法 this 的回呼 — 在 class 或物件方法內，不想 this 跑掉 
class Timer {
  constructor() {
    this.s = 0;
    setInterval(() => this.s++, 1000); // this 是 Timer 實例
  }
}
⚠️

這三種情況不要用箭頭函式：物件字面量方法（this 不是物件）、需要用 arguments 的函式（箭頭函式無 arguments）、作為建構子（箭頭函式無法用 new）。

延伸追問

面試官可能再追

箭頭函式有 prototype 嗎？

沒有。箭頭函式沒有 prototype 屬性，因此無法用 new 呼叫，也不能作為原型鏈的起點。

回傳物件字面量時要注意什麼？

隱式回傳物件需加括號，否則大括號會被解析為函式體：const fn = () => ({ key: 'val' });。忘了括號是常見 bug。

面試這樣答

30 秒版本

「箭頭函式最大的特性不是語法簡潔，而是詞法 this——繼承外層作用域，不建立自己的 this。最適合用在陣列方法回呼和需要保住外層 this 的非同步回呼。反過來，物件字面量的方法不能用箭頭函式，否則 this 不是物件本身；箭頭函式也沒有 arguments 物件，且不能作建構子。」
