箭頭函式・this 綁定

箭頭函式的 this 從出生就固定，普通函式不行

在建構子裡，箭頭函式方法的 this 詞法綁定到當下的實例，call/apply/bind 都無法改變它；普通函式方法的 this 由呼叫方式決定，傳出去就可能丟失。

對比實驗

同一個物件，兩種方法

const Person = function(name) {
  this.firstName = name;

  this.sayName1 = function() {     // 普通函式
    console.log(this.firstName);
  };
  this.sayName2 = () => {          // 箭頭函式
    console.log(this.firstName);
  };
};

const john = new Person('John');
const dave = new Person('Dave');

john.sayName1();              // 'John'
john.sayName2();              // 'John'

john.sayName1.call(dave);     // 'Dave'  ← this 被改掉了
john.sayName2.call(dave);     // 'John'  ← 箭頭函式不受影響

const fn1 = john.sayName1;
fn1();                        // undefined ← 脫離物件，this 變成 global
const fn2 = john.sayName2;
fn2();                        // 'John'   ← 箭頭函式 this 仍是 john
✅

把方法當回呼傳出去（如 setTimeout(john.sayName1, 1000)）時，普通函式的 this 會丟失，箭頭函式則永遠保住實例。

限制

箭頭函式不是萬能的

箭頭函式普通函式
可作建構子 (new)❌ TypeError✅
arguments 物件❌ 無（用 ...args）✅
this 可被 call/bind 改變❌✅
物件字面量方法⚠️ this 不指向物件✅
⚠️

在物件字面量中定義方法時，不要用箭頭函式——{ getValue: () => this.x } 的 this 不是物件本身，而是外層作用域。

延伸追問

面試官可能再追

ES6 class 中的方法和建構子裡的箭頭函式有什麼差？

class 方法定義在原型上，所有實例共用；建構子裡的箭頭函式屬性定義在每個實例上，各自擁有一份函式。後者記憶體消耗較大，但 this 保證固定。

React class component 為什麼要在 constructor 裡 bind(this)？

class 方法是普通函式，傳給 JSX 事件屬性後 this 會丟失。解法一：this.handleClick = this.handleClick.bind(this)；解法二（現代）：直接用箭頭函式定義方法，利用 class fields 語法。

30 秒版本

「在建構子中，箭頭函式方法的 this 在建立時就詞法綁定到當前實例，之後無論怎麼傳遞、call/apply/bind 都無法改變。普通函式方法的 this 則由呼叫方式決定，一旦脫離物件就可能丟失。這讓箭頭函式特別適合當事件處理器或非同步回呼——不用額外 bind 就能安全使用。代價是無法用 new、無 arguments 物件，且每個實例各持一份函式。」
