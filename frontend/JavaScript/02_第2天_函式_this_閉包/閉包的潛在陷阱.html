閉包・陷阱

閉包「記得太多」：記憶體洩漏、var 迴圈陷阱

閉包保留外層變數的參考——這是它的強大之處，也是它的危險所在。記憶體洩漏、迴圈中共用變數、除錯困難是最常見的三個坑。

陷阱一（最高頻）

var 迴圈：所有閉包共用同一個 i

var：全部輸出 3 
function createFns() {
  const fns = [];
  for (var i = 0; i < 3; i++) {
    fns.push(() => console.log(i));
  }
  return fns;
}
createFns()[0](); // 3 ← 不是 0！
let：每次迭代建立獨立綁定 
function createFns() {
  const fns = [];
  for (let i = 0; i < 3; i++) {
    fns.push(() => console.log(i));
  }
  return fns;
}
createFns()[0](); // 0 ✅
✅

let 在每次迴圈迭代都建立新的區塊作用域綁定，各閉包各自持有獨立的 i，是解決此問題的現代方式。

陷阱二

記憶體洩漏：閉包讓大物件無法被 GC

function createClosure() {
  const largeArray = new Array(1_000_000).fill('data');
  return function() {
    // 只用到 largeArray[0]，但整個陣列被閉包保住了
    console.log(largeArray[0]);
  };
}

const fn = createClosure();
// largeArray 無法被垃圾回收，直到 fn 不再被引用
⚠️

若不再需要閉包，明確將變數設為 null（如 fn = null）可切斷參考，讓 GC 釋放記憶體。

延伸追問

面試官可能再追

除了 let，var 迴圈陷阱還有哪些舊解法？

ES6 前常用：IIFE 包住每次迭代的 i，建立新的作用域 —— fns.push((function(i) { return () => console.log(i); })(i))。現在有 let 後已無必要。

WeakRef / FinalizationRegistry 能解決閉包洩漏嗎？

部分能。WeakRef 對目標持弱參考，不妨礙 GC；FinalizationRegistry 可在物件被 GC 後執行清理。但一般情況下正確管理閉包生命週期仍是最佳方式。

面試這樣答

30 秒版本

「閉包的主要陷阱有三個：第一，var 迴圈——所有閉包共用同一個 var 變數，用 let 解決；第二，記憶體洩漏——閉包會持住外層所有引用的變數，不再需要時要手動解除；第三，除錯困難——多層巢狀閉包的作用域鏈很難追蹤。其中 var 迴圈問題最常考，記住 var 是函式作用域，let 是區塊作用域，每次迭代建立新綁定。」
