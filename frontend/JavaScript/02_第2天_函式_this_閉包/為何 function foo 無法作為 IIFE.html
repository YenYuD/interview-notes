函式宣告・IIFE

解析器把它當宣告，加 () 就報錯：function foo 不是 IIFE

IIFE（Immediately Invoked Function Expression） 要求的是函式表達式，不接受函式宣告。解決辦法：用括號把函式包起來，讓解析器把它當表達式。

為什麼會出錯

解析器的判斷規則

JavaScript 解析器在句子開頭看到 function，就把它認定為函式宣告。函式宣告後面直接接 () 是語法錯誤，因為宣告語句不能立即執行。

錯誤：函式宣告無法 IIFE 
function foo(){}(); // ❌ SyntaxError
正確：括號讓它變成表達式 
(function foo(){})();  // ✅ 執行
(function foo(){}());  // ✅ 也可以
ℹ️

兩種括號位置都合法：(fn)() 括號包函式本體；(fn()) 括號包整個呼叫。現代 linter 偏好前者。

為什麼需要 IIFE

封裝作用域，避免污染全域

(function() {
  var secret = '只在這裡可見';
  console.log(secret); // OK
})();

console.log(secret); // ❌ ReferenceError

ES6 模組化（import/export）普及後，IIFE 的封裝需求大幅降低；但在非模組環境（舊版瀏覽器腳本、CDN 引入的 lib）中仍然常見。

延伸追問

面試官可能再追

除了括號，還有其他方式讓函式宣告變成表達式嗎？

可以在 function 前加一元運算子：!function foo(){}() 或 void function foo(){}()，都能讓解析器把它當作表達式。但返回值會被改變，實務上較少見。

ES6 之後 IIFE 還有用嗎？

ES6 模組中每個檔案已是獨立作用域，大部分 IIFE 使用情境被取代。但在需要立即執行的 async IIFE（(async () => { await ... })()）仍有用武之地。

面試這樣答

30 秒版本

「function foo(){} 被解析器視為函式宣告，不能立即執行。要讓它成為 IIFE，需要用括號把它包住，讓解析器把它當成函式表達式，寫成 (function foo(){})()。IIFE 的用途是建立私有作用域，避免變數污染全域——在 ES6 模組普及前是常見的封裝手段。」
