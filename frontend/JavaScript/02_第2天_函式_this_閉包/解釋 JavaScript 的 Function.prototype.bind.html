函式・this 綁定

bind 回傳一個新函式，this 永久鎖定

bind(thisArg, ...args) 不立即執行，而是回傳一個新函式，其 this 永遠固定為 thisArg，且可選擇預先填入部分參數（部分套用）。

核心行為

bind vs call / apply

bindcall / apply
執行時機回傳新函式，不立即執行立即執行
回傳值新函式原函式的回傳值
適合場景事件處理器、回呼立即呼叫並設定 this
const john = { age: 42, getAge() { return this.age; } };

// 直接呼叫正確
john.getAge(); // 42

// 脫離物件，this 丟失
const fn = john.getAge;
fn(); // undefined

// bind 鎖定 this
const bound = john.getAge.bind(john);
bound(); // 42

// 也可以綁到其他物件
const mary = { age: 21 };
john.getAge.bind(mary)(); // 21
部分套用

bind 也能預先填參數

function multiply(a, b) { return a * b; }

// 綁定 this 為 null，同時固定第一個參數為 5
const multiplyBy5 = multiply.bind(null, 5);
multiplyBy5(3); // 15
multiplyBy5(4); // 20
✅

React class component 的慣用寫法：this.handleClick = this.handleClick.bind(this)，讓 handleClick 傳入 JSX 後仍能正確存取 this。現代寫法改用 class field 箭頭函式。

延伸追問

面試官可能再追

可以對箭頭函式使用 bind 嗎？

可以呼叫，但無效。箭頭函式的 this 在定義時已詞法綁定，bind 傳入再多的 thisArg 都不會改變它。

bind 和閉包有什麼關係？

bind 內部本質上是用閉包記住了 thisArg 和預填參數，回傳的新函式在呼叫時再從閉包取出使用。

面試這樣答

30 秒版本

「bind 回傳一個新函式，this 永久鎖定，不立即執行——這是它和 call/apply 最大的差異。主要用在需要「稍後再呼叫」卻又要保住 this 的場景，例如事件處理器或非同步回呼。bind 也支援部分套用，可以預先固定部分參數。注意箭頭函式對 bind 免疫，this 無法被覆蓋。」
