閉包・封裝

外部看不到，只能透過方法操作：閉包私有變數

JavaScript 沒有內建的 private（ES2022 # 之前），但用閉包就能達到同等效果：把狀態藏在外層函式作用域，只暴露受控的操作介面。

核心模式

工廠函式 + 閉包

function createCounter() {
  let count = 0; // 私有變數，外部無法直接存取

  return {
    increment() { count++; return count; },
    decrement() { count--; return count; },
    getCount()  { return count; }
  };
}

const counter = createCounter();
console.log(counter.increment()); // 1
console.log(counter.increment()); // 2
console.log(counter.count);       // undefined ← 外部看不到！
console.log(counter.getCount());  // 2
ℹ️

count 存在 createCounter 的作用域中，回傳的三個方法形成閉包，「記住」了這個作用域，但外部代碼無法直接讀寫 count。

優點

封裝帶來什麼好處？

好處說明
封裝（Encapsulation）狀態不被外部隨意修改
資料完整性只有受控的方法能改變內部狀態，可加入驗證邏輯
避免命名衝突私有變數不在全域作用域，不會和其他代碼衝突
現代替代方案

ES2022 class 私有欄位

class Counter {
  #count = 0;  // # 前綴 = 真正的私有欄位

  increment() { this.#count++; return this.#count; }
  getCount()  { return this.#count; }
}

const c = new Counter();
c.increment(); // 1
c.#count;      // ❌ SyntaxError — 外部無法存取
✅

ES2022 的 #privateField 是語言層面的真私有，比閉包方案更嚴格（無法被 Proxy 攔截）。新代碼優先考慮 class private fields；閉包方案在非 class 場景、或需要 factory 模式時仍然實用。

延伸追問

面試官可能再追

閉包私有變數和 Symbol 作為 key 的「偽私有」有什麼差？

Symbol key 的屬性雖然不可枚舉，但仍可透過 Object.getOwnPropertySymbols 取得，本質上不是真私有。閉包的私有變數才是真正無法從外部存取。

多個 createCounter() 的實例共用同一個 count 嗎？

不共用。每次呼叫 createCounter() 都建立新的執行上下文，產生獨立的 count。每個實例各自擁有自己的閉包環境。
