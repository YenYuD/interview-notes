函式式程式設計・優點

為什麼要柯里化？可重用、可組合、語意清晰

柯里化和部分套用的共同目標：讓函式更模組化。固定不變的邏輯，留下可變的部分；在需要的時候才填入剩餘參數，程式碼自然變得更宣告式、易讀、可測試。

三大優點

柯里化和部分套用帶來什麼？

重用性 — 一個通用函式衍生出多個語意明確的專用函式 
const add = (a) => (b) => a + b;
const add5  = add(5);   // 永遠加 5
const add10 = add(10);  // 永遠加 10
可讀性 — 減少呼叫點的參數雜訊 
// 每次呼叫都要帶 rate，容易漏或填錯
prices.map(p => applyTax(0.05, p));

// 部分套用後，呼叫點乾淨
const applyTW = multiply.bind(null, 1.05);
prices.map(applyTW);
函式組合 — 柯里化後的單參數函式可以直接用 compose/pipe 串接 
const process = pipe(
  filter(isActive),
  map(formatName),
  take(10)
);
適用情境

什麼時候該用？

情境建議
對同一組資料反覆套用「只差一個參數」的函式柯里化 or 部分套用
需要在 pipe/compose 中串接函式柯里化（確保單一引數）
只是想預先填幾個固定參數部分套用（bind 即可）
一次性呼叫、無重用需求不必要，直接呼叫
延伸追問

面試官可能再追

這些技巧在實際工作中常用嗎？

在純函式式風格的代碼庫（Ramda、Lodash/fp）中非常常見；在一般命令式/OOP 風格中，偶爾用部分套用提升可讀性。過度柯里化反而增加理解成本，應視情況使用。

柯里化對效能有影響嗎？

每次呼叫都建立新的閉包和函式物件，有輕微的記憶體開銷。高頻熱路徑中要謹慎；一般邏輯層的可讀性收益遠大於效能損失。

面試這樣答

30 秒版本

「柯里化和部分套用的核心優點是從通用函式衍生出可重用的專用函式，讓呼叫點更簡潔、語意更清晰。柯里化還有一個特別的好處——每個函式只接受一個參數，天然適合函式組合（compose/pipe），可以串接成 pipeline。實務上我在需要對資料集反覆套用同一組邏輯時會用，但避免過度使用，因為增加抽象層也等於增加閱讀成本。」
