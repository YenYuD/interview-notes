this・事件處理器

addEventListener 裡的 this：普通函式是元素，箭頭函式是外層

在 DOM 事件處理器中，普通函式的 this 指向觸發事件的元素（即 event.currentTarget）；箭頭函式的 this 繼承外層定義時的上下文，不是元素。這是一個常見的混淆點。

核心行為

同樣的 addEventListener，不同的 this

普通函式：this 是按鈕元素 
btn.addEventListener('click', function() {
  console.log(this);          // <button> 元素
  console.log(this === btn);  // true
});
箭頭函式：this 是外層（通常是 window） 
btn.addEventListener('click', () => {
  console.log(this);          // window / undefined
  console.log(this === btn);  // false
});
三種解法

需要「既有元素 this 又有物件 this」時怎麼辦？

bind(obj) — 強制把 this 鎖定到物件 
btn.addEventListener('click', handleClick.bind(myObj));
箭頭函式包住物件方法 — 繼承外層 this（myObj） 
const myObj = {
  name: 'Widget',
  init() {
    btn.addEventListener('click', () => {
      console.log(this.name); // 'Widget' ✅
    });
  }
};
用 event.currentTarget — 不依賴 this，直接從事件物件取元素 
btn.addEventListener('click', (e) => {
  console.log(e.currentTarget); // 按鈕元素，箭頭函式也適用
});
✅

現代前端（尤其 React/Vue）幾乎不再直接依賴事件處理器中的 this 來取得 DOM 元素；改用 event.currentTarget 或框架的 ref，語意更明確。

延伸追問

面試官可能再追

event.target 和 event.currentTarget 有什麼不同？

target 是實際觸發事件的元素（可能是子元素）；currentTarget 是目前正在處理該事件的元素（綁定處理器的那個）。普通函式中的 this 等同於 currentTarget。

React 的合成事件（SyntheticEvent）和原生 addEventListener 行為一樣嗎？

React class component 中，方法若不 bind 或用箭頭函式，this 會是 undefined（因為 class 預設嚴格模式）。React 事件物件是合成的，但 this 行為和原生一致——取決於函式類型。

30 秒版本

「在 addEventListener 中，普通函式的 this 指向觸發事件的 DOM 元素；箭頭函式沒有自己的 this，繼承外層上下文，通常是 window 或 undefined。要同時使用物件 this 又要操作元素，可以用 bind 固定，或用箭頭函式包住物件方法。現代實務更推薦直接用 event.currentTarget 取元素，不依賴 this，語意更清晰。」
