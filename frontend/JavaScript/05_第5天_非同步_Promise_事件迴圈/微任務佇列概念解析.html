Promise 為什麼比 setTimeout先跑？微任務的優先權

JS 有兩條非同步佇列：微任務（microtask）優先、巨任務（macrotask）在後。每次同步碼跑完，都要先清空微任務，才做下一個巨任務。

執行順序規則

事件迴圈的三步節奏

① 同步碼全部跑完，呼叫堆疊清空。
② 清空微任務佇列：逐一取出所有微任務執行（若微任務又產生微任務，也一起清）。
③ 取出一個巨任務執行，完成後回到步驟 ②。
console.log('① 同步');

setTimeout(() => console.log('④ 巨任務'), 0);

Promise.resolve()
  .then(() => console.log('② 微任務 1'))
  .then(() => console.log('③ 微任務 2'));

console.log('① 同步（繼續）');
// 輸出順序：① ① ② ③ ④

注意

微任務的潛在風險

⚠️

若微任務執行時又持續加入新微任務（例如在 .then 中無限 resolve），微任務佇列永遠清不完，巨任務（包括畫面更新）會被餓死，導致瀏覽器卡住。

延伸追問

面試官可能再追

queueMicrotask() 和 Promise.resolve().then() 效果一樣嗎？

幾乎一樣——兩者都將回呼排入微任務佇列。queueMicrotask 更語意化且不需建立 Promise 物件，適合直接排程微任務（效能略優）。

Node.js 的 process.nextTick 是微任務嗎？

它比微任務還早——process.nextTick 有自己的佇列（nextTick queue），在微任務佇列之前被清空。優先順序：nextTick → 微任務 → 巨任務。

面試這樣答

30 秒版本

「微任務佇列是事件迴圈中優先級最高的非同步佇列。規則是：每當同步碼執行完畢或一個巨任務完成，就先把微任務佇列全部清空，才取下一個巨任務。所以 Promise.then 永遠比 setTimeout 先執行。常見的微任務來源是 Promise 的回呼和 queueMicrotask()。」
