非同步 · Promise vs Callback

從巢狀地獄到線性鏈結：Promise 值得嗎？

Promise 讓非同步程式碼從「向右」變成「向下」，統一了錯誤處理，也帶來了平行執行的語法糖。代價是一點點學習曲線。

最大優勢

Callback Hell → 扁平鏈結

Callback — 向右巢狀 
getUser(id, (u) => {
  getPosts(u, (p) => {
    getComments(p, (c) => {
      // 越來越右...
    });
  });
});
Promise — 向下鏈結 
getUser(id)
  .then(getPosts)
  .then(getComments)
  .catch(handleError);
四大優點

Promise 帶來了什麼

優點說明
避免 Callback Hell用 .then() 鏈結，程式碼線性可讀
統一錯誤處理整條鏈只要一個 .catch()，不必每層手動檢查 error 參數
平行請求Promise.all() 同時發出多請求，等全部完成
保證清理.finally() 無論成敗都執行，適合關閉 loading spinner
// 統一錯誤處理：任何一步 reject 都到 .catch
step1()
  .then(step2)
  .then(step3)
  .catch((err) => console.error('任一步失敗：', err))
  .finally(() => setLoading(false));
缺點與取捨

Promise 的限制

⚠️

Promise 仍需理解微任務佇列、鏈結中的 return 語意、以及 Promise.all 的失敗快速機制。對於初學者，理解成本比簡單 callback 高；對於進階開發者，async/await 通常比純 Promise 鏈更易讀。

適合 Promise 的情境 多個平行請求（Promise.all）、需要 .finally 清理、與舊有 Promise-based API 整合。
可考慮 async/await 複雜的順序邏輯、需要在迴圈中 await、需要條件式非同步流程。
延伸追問

面試官可能再追

Promise.all 和 Promise.allSettled 有什麼差？

Promise.all 任一失敗就立即 reject，其餘結果丟棄。Promise.allSettled 等全部完成，回傳每個 Promise 的狀態與值/原因，適合「不想因單一失敗而放棄全部結果」的情境。

在 .then() 裡忘記 return 會怎樣？

下一個 .then() 收到的值會是 undefined，而不是你以為的非同步結果。這是 Promise 鏈結中最常見的 bug 之一。

面試這樣答

30 秒版本

「相比 Callback，Promise 最大的優點是把巢狀變成鏈結，讓程式碼線性可讀；同時統一了錯誤處理，整條鏈只需一個 .catch()，不必在每個 callback 裡手動檢查錯誤。用 Promise.all 也能輕鬆處理平行請求。唯一的代價是需要理解 Promise 鏈的 return 語意和微任務機制。」
