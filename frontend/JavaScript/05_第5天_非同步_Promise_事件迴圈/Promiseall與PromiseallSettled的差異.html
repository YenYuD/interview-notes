一個失敗就放棄，還是等全部結算？

Promise.all 奉行「全成功或全失敗」；Promise.allSettled 等所有 Promise 都有結果，無論成敗，再逐一告訴你每個的狀態。

核心差異

一張表看清楚

Promise.allPromise.allSettled
等待策略等全部 fulfilled等全部 settled（含 rejected）
有人 reject立即 reject，其餘結果丟棄繼續等，最後回傳所有結果
回傳值[val1, val2, …][{status, value/reason}, …]
適合情境全成功才有意義（如結帳）想看每個結果（如批次操作）
行為對比

同樣的輸入，不同的輸出

const promises = [
  Promise.resolve(1),
  Promise.reject('失敗了'),
  Promise.resolve(3),
];

// Promise.all → 立即 reject
Promise.all(promises)
  .catch((err) => console.log(err));  // '失敗了'

// Promise.allSettled → 等全部，回傳每個狀態
Promise.allSettled(promises)
  .then((results) => console.log(results));
// [
//   { status: 'fulfilled', value: 1 },
//   { status: 'rejected',  reason: '失敗了' },
//   { status: 'fulfilled', value: 3 },
// ]
選哪個？

決策流程

任何一個失敗就應該整批報錯（例如：前端需要所有資料才能渲染）→ 用 Promise.all。
想收集所有結果、失敗的也要看（例如：批次上傳、並行健康檢查）→ 用 Promise.allSettled。
Promise.allSettled 回傳的物件中，成功的有 value，失敗的有 reason——記得用 result.status === 'fulfilled' 判斷再取值。
延伸追問

面試官可能再追

Promise.any 和 Promise.race 又是什麼？

Promise.race：第一個 settled（不論成敗）就回傳；常用於設超時。Promise.any（ES2021）：第一個 fulfilled 就回傳；全部 rejected 才 reject，適合多個備援來源取最快成功的。

Promise.allSettled 什麼時候才會 reject？

幾乎不會。它本身只有在傳入非 iterable 等程式錯誤時才 reject；輸入的 Promise 就算全部 rejected，它仍然 resolve（帶著全 rejected 的結果陣列）。

面試這樣答

30 秒版本

「兩者都是平行等待多個 Promise。Promise.all 只要有任一個 reject 就立即 reject，適合全部成功才有意義的場景。Promise.allSettled 會等所有 Promise 都有結果，以 {status, value/reason} 的物件陣列回傳每個的狀態，適合需要看到所有結果（包括失敗）的批次操作。」
