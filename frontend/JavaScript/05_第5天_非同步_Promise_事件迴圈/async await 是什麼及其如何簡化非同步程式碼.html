非同步 · async/await

讓非同步程式碼讀起來像同步的語法糖

async/await 是 ES2017 對 Promise 的語法包裝。底層仍是 Promise，但寫起來像同步，用 try/catch 統一錯誤，告別 .then() 鏈結。

核心語意

兩個關鍵字各做什麼

關鍵字放在哪裡效果
async函式宣告前函式自動回傳 Promise；允許在內部使用 await
awaitasync 函式內暫停函式執行直到 Promise settled，回傳 fulfilled 的值；rejected 則拋出例外
async function getUser() {
  const res  = await fetch('/api/user');   // 等 fetch 完成
  const user = await res.json();             // 等 JSON 解析完成
  return user;                                 // 自動包成 fulfilled Promise
}
對比 Promise 鏈

同樣邏輯，兩種寫法

Promise 鏈寫法 
fetch('/api/user')
  .then(res => res.json())
  .then(user => fetch(`/api/posts?uid=${user.id}`))
  .then(res => res.json())
  .then(posts => console.log(posts))
  .catch(err => console.error(err));
async/await 寫法 
async function loadPosts() {
  try {
    const r1   = await fetch('/api/user');
    const user = await r1.json();
    const r2   = await fetch(`/api/posts?uid=${user.id}`);
    const posts = await r2.json();
    console.log(posts);
  } catch (err) {
    console.error(err);
  }
}
async/await 寫法在有條件判斷、迴圈內 await 時優勢最明顯；純線性串接時兩種差異不大。
常見陷阱

新手最容易踩的坑

⚠️

在迴圈中依序 await 沒問題，但如果你用 forEach + async callback，forEach 不會等待 Promise，導致迴圈結束前非同步操作都還沒完成。請改用 for...of 或 Promise.all。

// 錯誤：forEach 不會等 await
items.forEach(async (item) => {
  await process(item); // ← 這些 Promise 全部同時跑，forEach 不 await
});

// 正確：for...of 會等每個 await
for (const item of items) {
  await process(item);
}
延伸追問

面試官可能再追

async 函式一定回傳 Promise 嗎？即使 return 普通值？

是的。return 任何值都會被自動包成 Promise.resolve(value)；拋出例外則成為 Promise.reject(error)。

await 只能等 Promise 嗎？

不是。await 可以接任何值——若傳入非 Promise，會直接回傳該值（等同 await Promise.resolve(value)）。但多此一舉，通常只對 Promise 用 await。

如何用 async/await 做平行請求？

不要依序 await，改成先建立所有 Promise，再用 Promise.all 等待：const [a, b] = await Promise.all([fetchA(), fetchB()]);

面試這樣答

30 秒版本

「async/await 是 ES2017 對 Promise 的語法糖，底層仍是 Promise。在 async 函式內用 await 可以暫停執行直到 Promise 完成，讓非同步程式碼讀起來像同步。最大優點是用 try/catch 統一錯誤處理，以及在條件判斷和迴圈裡的可讀性明顯優於 Promise 鏈。要注意的是 forEach 不支援 await，平行請求要用 Promise.all。」
