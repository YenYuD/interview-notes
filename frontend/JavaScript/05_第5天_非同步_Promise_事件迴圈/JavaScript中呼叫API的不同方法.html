XHR、fetch、Axios：選對工具打 API

從 callback-based 的 XHR，到回傳 Promise 的 fetch，再到功能豐富的 Axios——每種方式有其適用場景。現代開發首選 fetch 或 Axios，理解差異才能回答面試官的追問。

主角：fetch vs Axios

最常被問的關鍵差異

fetch — 原生但需留意 
const res = await fetch('/api/data');
// fetch 不會在 4xx/5xx 時拋錯！
if (!res.ok) throw new Error(res.status);
const data = await res.json();
Axios — 更省心 
const { data } = await axios.get('/api/data');
// 非 2xx 自動拋錯，且自動解析 JSON
// 支援 interceptors、cancelToken 等
⚠️

fetch 的常見陷阱：HTTP 404 / 500 不會讓 Promise reject——只有網路層錯誤（如斷線）才會。必須手動檢查 response.ok，否則 4xx/5xx 會被當作成功處理。

XHR 的歷史地位

了解就好，不推薦新寫

const xhr = new XMLHttpRequest();
xhr.open('GET', '/api/data', true);
xhr.onreadystatechange = function () {
  if (xhr.readyState === 4 && xhr.status === 200) {
    console.log(JSON.parse(xhr.responseText));
  }
};
xhr.send();
XHR 基於事件回呼，程式碼冗長且難以組合。了解它的意義在於：理解 Promise / fetch 解決了什麼問題。
延伸追問

面試官可能再追

fetch 和 Axios 怎麼取消請求？

fetch 用 AbortController：建立 controller，傳 signal 給 fetch，呼叫 controller.abort() 取消。Axios 也支援 AbortController，舊版用 CancelToken（已棄用）。

在 Node.js 環境能用 fetch 嗎？

Node 18+ 內建 fetch（基於 undici）；更早版本需安裝 node-fetch 或直接用 Axios（通用支援 Node 與瀏覽器）。

面試這樣答

30 秒版本

「JS 呼叫 API 主要有三種方式：老式的 XMLHttpRequest 基於事件回呼、較冗長；現代的原生 fetch 回傳 Promise，語法簡潔但要注意它不會對 4xx/5xx 自動拋錯，需手動檢查 response.ok；第三方的 Axios 則自動解析 JSON、非 2xx 自動拋錯，並支援攔截器，是需要更多功能時的選擇。」
