全部成功才算贏：Promise.all 的平行策略

需要同時打三支 API、等全部回來再組裝畫面？Promise.all 讓你一次發出、等待最慢的那個，只要有一個失敗就整批 reject。

核心行為

Promise.all 怎麼運作

傳入 Promise 陣列，所有 Promise 同時開始執行（非依序）。
等最慢的那個完成，回傳 按原陣列順序排列的結果陣列（非完成順序）。
任一 Promise reject → 立即 reject，不等其他人，結果陣列丟棄。
const [user, posts, cart] = await Promise.all([
  fetchUser(id),
  fetchPosts(id),
  fetchCart(id),
]);
// 三支請求平行發出，最慢的決定總等待時間
若三支 API 各需 300ms，依序 await 要等 900ms；Promise.all 只等 300ms（最慢那支）。
失敗快速機制

任一失敗 = 全部放棄

Promise.all([
  Promise.resolve('A'),
  Promise.reject('B 壞了！'),
  Promise.resolve('C'),
]).catch((err) => console.error(err)); // 'B 壞了！'
⚠️

若你希望即使有些請求失敗也能看到其他結果，請改用 Promise.allSettled()——它等所有 Promise 都 settled，回傳每個的狀態與值/原因。

適用情境

用 Promise.all 的時機

適合 多支 API 請求之間沒有依賴關係，且只要有任何一支失敗就應該整批報錯（例如購物車結帳的多步驟 API）。
不適合 需要看到所有結果（包含失敗的）。改用 Promise.allSettled。
不適合 只要有一個 resolve 就繼續。改用 Promise.any 或 Promise.race。
延伸追問

面試官可能再追

Promise.all 傳入空陣列會怎樣？

立即 resolve，回傳空陣列 []。

Promise.all 裡可以混入非 Promise 值嗎？

可以。非 Promise 的值會被自動包成 Promise.resolve(value)，放進結果陣列中對應位置。

面試這樣答

30 秒版本

「Promise.all 接受一個 Promise 陣列，所有請求同時發出，等最慢的完成後，依原陣列順序回傳結果。任一個 reject 就立即 reject 整體，其他結果丟棄。適合多支 API 同時打、結果都需要的場景，可以大幅縮短等待時間。如果需要容忍部分失敗，改用 Promise.allSettled。」
