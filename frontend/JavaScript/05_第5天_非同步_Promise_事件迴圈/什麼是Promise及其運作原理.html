非同步 · Promise

非同步操作的承諾書：三種狀態，只轉換一次

Promise 是一個代表「未來結果」的物件。建立後進入 pending；操作成功轉 fulfilled、失敗轉 rejected——狀態一旦確定，就永遠不變。

三種狀態

Promise 的生命週期

pending — 初始狀態，操作尚未完成。
fulfilled — 呼叫 resolve(value) 後轉入；可用 .then() 取值。
rejected — 呼叫 reject(reason) 後轉入；可用 .catch() 處理。
ℹ️

fulfilled 和 rejected 合稱 settled（已確定）。settled 後再呼叫 resolve/reject 無效，狀態不會再改變。

建立與使用

Promise 的基本語法

const p = new Promise((resolve, reject) => {
  // 非同步操作...
  const ok = true;
  if (ok) resolve('成功！');
  else    reject(new Error('失敗'));
});

p.then((val) => console.log(val))   // '成功！'
 .catch((err) => console.error(err))
 .finally(() => console.log('都會跑'));
方法觸發時機回傳
.then(fn)fulfilled新的 Promise
.catch(fn)rejected新的 Promise
.finally(fn)任何 settled新的 Promise
Promise 鏈結

用 .then() 串接多步驟

每個 .then() 都回傳一個新 Promise，讓你把多步非同步操作攤平成一條線，告別 Callback Hell：

fetch('/api/user')
  .then((res) => res.json())
  .then((user) => fetch(`/api/posts?uid=${user.id}`))
  .then((res) => res.json())
  .then((posts) => console.log(posts))
  .catch((err) => console.error(err)); // 任一步出錯都到這
延伸追問

面試官可能再追

Promise 的 .then() 回呼是同步還是非同步執行？

永遠是非同步——即使 Promise 已是 fulfilled，.then() 的回呼也會進入微任務佇列，等同步程式碼跑完才執行。這確保行為一致性。

Promise.resolve() 和 new Promise(resolve => resolve()) 有差嗎？

功能上等價，但 Promise.resolve(value) 更簡潔。若傳入的值本身就是 Promise，會直接回傳該 Promise；若是 thenable，則會跟隨其狀態。

面試這樣答

30 秒版本

「Promise 是代表非同步操作未來結果的物件，有三種狀態：pending、fulfilled、rejected，一旦確定就不可更改。用 new Promise((resolve, reject) => …) 建立，.then() 接成功、.catch() 接失敗，並且可以鏈結串接多步非同步邏輯，解決 Callback Hell。所有 .then() 回呼都走微任務佇列，保證非同步執行。」
