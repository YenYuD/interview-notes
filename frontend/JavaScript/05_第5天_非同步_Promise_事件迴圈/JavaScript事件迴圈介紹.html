非同步 · 事件迴圈

單執行緒，卻能不卡住地處理非同步

JS 只有一條呼叫堆疊。事件迴圈的工作是：堆疊一空，就先清光微任務（Promise），再做一個巨任務（setTimeout），如此循環。

DEMO — 一步步看執行順序

猜猜這段印出什麼？

console.log('Start');
setTimeout(() => console.log('Timeout'), 0);
Promise.resolve().then(() => console.log('Promise'));
console.log('End');

關鍵規則：每做完一個巨任務，會先把全部微任務清空，才做下一個巨任務。所以 Promise 永遠贏 setTimeout。

誰排哪個佇列

佇列誰會進來優先序
微任務.then/.catch/.finally、await、queueMicrotask高
巨任務setTimeout、I/O、UI 事件低
⚠️

微任務若無限產生微任務，會「餓死」巨任務（畫面更新、計時器都卡住）。別在 .then 裡無止境再 resolve。

延伸追問

面試官可能再追

setTimeout(fn, 0) 真的 0ms 嗎？

不是。它只保證「至少 0ms 後、且堆疊清空、且微任務都清完」才執行，實際常有 ~4ms 最小延遲。

Web API 算在 JS 引擎裡嗎？

不算。計時器、fetch 等由瀏覽器（或 Node 的 C++ API）在別的執行緒處理，完成後才把回呼丟回佇列，所以 JS 單執行緒也不阻塞。

面試這樣答

30 秒版本

「JS 是單執行緒，靠事件迴圈處理非同步。同步碼先在呼叫堆疊跑完，非同步回呼依類型進微任務或巨任務佇列。事件迴圈的規則是：堆疊一空，先清光所有微任務，再執行一個巨任務。所以 Promise 的 then 一定排在 setTimeout 前面。」
