非同步 · 回呼

把「等完成再做什麼」這件事，包成函式傳進去

Callback 是非同步最原始的解法：把後續邏輯當參數塞給呼叫者，等操作完成再叫你。理解它，才能真正懂 Promise 和 async/await 為何出現。

核心概念

什麼是 Callback？

Callback 就是「被當作參數傳入，並在特定時機被呼叫」的函式。兩種模式：

同步 Callback 立即在函式內執行，會阻塞，例如 Array.forEach。
非同步 Callback 等計時器、I/O、網路請求完成後才執行，不阻塞主執行緒。 
// 非同步 Callback 範例：等 1 秒後才叫 callback
function fetchData(callback) {
  setTimeout(() => {
    const data = { name: 'Alice', age: 30 };
    callback(data);
  }, 1000);
}

fetchData((data) => {
  console.log(data); // { name: 'Alice', age: 30 }
});
致命缺陷

Callback Hell — 巢狀地獄

需要串接多步驟非同步時，巢狀越來越深，形成「毀滅金字塔」，難以閱讀與維護：

getUser(id, (user) => {
  getPosts(user, (posts) => {
    getComments(posts[0], (comments) => {
      // 繼續往右... 😱
    });
  });
});
⚠️

Callback Hell 不只是排版問題——更大的麻煩是錯誤處理散落各處，每層都要手動檢查 error 參數。Promise 和 async/await 正是為了解決這兩個痛點而生。

錯誤處理慣例

Node.js 風格：error-first callback

回呼函式的第一個參數留給錯誤物件，沒錯就傳 null，這是 Node.js 生態的標準約定：

fetchData((error, data) => {
  if (error) {
    console.error('出錯了：', error);
    return;
  }
  console.log(data);
});
延伸追問

面試官可能再追

Callback 與 Promise 最大的差別是什麼？

Promise 將「成功/失敗」的狀態封裝成物件，可鏈結 .then().catch()，避免巢狀；且能用 Promise.all 輕鬆處理平行請求。Callback 則沒有標準化的錯誤傳遞，容易產生巢狀與難以組合的問題。

同步 Callback 有什麼例子？

Array.forEach、Array.map、Array.filter 傳入的函式都是同步 Callback——它們在呼叫堆疊中立即執行，執行完才繼續下一行。

為什麼 Callback 難以做錯誤處理？

因為沒有統一的約定：有人用 (err, data)，有人只傳 data。拋出的例外也無法被外層的 try/catch 捕捉，必須在每個 callback 內部自行處理。
