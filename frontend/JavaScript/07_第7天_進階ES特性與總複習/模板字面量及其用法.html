再見了字串串接，
模板字面量讓插值變直覺

ES6 的模板字面量（template literal）用反引號取代引號，讓多行字串和插值（${...}）都能優雅處理。更進階的 tagged templates 還能讓函式接管整個字串的組裝。

基本語法對照

舊寫法 vs 模板字面量

功能ES5 字串串接模板字面量
插值'Hello ' + name + '!'`Hello ${name}!`
多行字串'line1\n' + 'line2'直接換行即可
表達式需先計算存變數`${a + b}` / `${fn()}`
巢狀模板繁瑣`outer ${`inner ${x}`}`
 
const user = { name: 'Alice', age: 30 };

// 舊寫法
'Hi, ' + user.name + '! You are ' + user.age + ' years old.'

// 模板字面量
`Hi, ${user.name}! You are ${user.age} years old.`

// 多行（縮排會計入字串）
const html = `
  <div>
    <p>${user.name}</p>
  </div>
`.trim();
常見進階用法

插值裡能放什麼

運算式`${a + b}` `${x > 0 ? 'pos' : 'neg'}`
函式呼叫`${formatDate(date)}`
巢狀模板`${items.map(i => `<li>${i}</li>`).join('')}`
Tagged template函式接管解析，見另一篇
// 動態產生 HTML 列表（map 回傳模板陣列再 join）
const items = ['Apple', 'Banana', 'Cherry'];
const list = `<ul>${items.map(i => `<li>${i}</li>`).join('')}</ul>`;
✓

${} 內放的是 JavaScript 表達式（有回傳值的東西），不能放陳述式（if/for）。需要條件時用三元運算子，需要迴圈時用 map()/reduce()。

String.raw 與原始字串

不處理跳脫序列的特殊 tag

// 一般模板會解析 \n 為換行
`line1\nline2`.length;     // 11 (有換行字元)

// String.raw 保留原始字元
String.raw`line1\nline2`.length; // 12 (\n 是兩個字元)

// 最常用於正則、Windows 路徑
const re = new RegExp(String.raw`\d+\.\d+`); // 比 '\\d+\\.\\d+' 更易讀

面試官可能再追

模板字面量和字串串接哪個效能更好？

現代 JS 引擎對兩者的優化程度接近，差異可忽略。選用模板字面量的理由是可讀性，而非效能。有大量字串合併時，用 Array.join() 或 StringBuilder 模式反而比反覆串接更快。

模板字面量的縮排問題怎麼解？

多行模板字面量會把縮排空格納入字串。常見解法：用 .trim() 去頭尾空白，或寫一個 dedent tag function 統一去掉公共縮排前綴。ES2025 有提案 String.dedent 但尚未正式落地。

面試這樣答

30 秒版本

「模板字面量用反引號包裹，透過 ${} 嵌入任意 JavaScript 表達式，大幅改善字串插值和多行字串的可讀性。進階用法是標籤模板（tagged template），在反引號前加函式名稱，讓函式接管字串的組裝，styled-components 和 GraphQL 的 gql 都是這個原理。此外，內建的 String.raw tag 可取得不處理跳脫序列的原始字串，常用於正規表達式或路徑字串。」
