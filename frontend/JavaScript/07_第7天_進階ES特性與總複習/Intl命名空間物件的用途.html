JAVASCRIPT / ES 進階

不用寫格式邏輯，
讓瀏覽器替你說當地語言

Intl 是 ECMAScript 國際化 API 的命名空間，內建日期、數字、字串的語系感知格式化，不需 moment.js 也能輸出「2024年1月1日」或「€1.234,56」。

核心四件組

Intl 裡最常用的建構子

建構子用途典型選項
Intl.DateTimeFormat日期／時間格式化year, month, day, hour, minute
Intl.NumberFormat數字／貨幣／百分比style: 'currency', currency: 'TWD'
Intl.Collator語系敏感字串排序比較sensitivity: 'base'
Intl.PluralRules複數形式選擇type: 'ordinal'
✓

所有建構子都接受 locale tag（如 'zh-TW'、'de-DE'）作為第一個參數，第二個是選項物件。建構子建立後可反覆呼叫 .format()，比每次 new 更有效率。

程式碼對照

格式化數字與日期的實際寫法

// 貨幣格式（德式）
const fmt = new Intl.NumberFormat('de-DE', {
  style: 'currency', currency: 'EUR'
});
fmt.format(1234567.89); // "1.234.567,89 €"

// 日期格式（繁中）
const df = new Intl.DateTimeFormat('zh-TW', {
  year: 'numeric', month: 'long', day: 'numeric'
});
df.format(new Date());  // "2024年1月1日"

// 字串排序（忽略大小寫）
['banana', 'Apple', 'cherry'].sort(
  new Intl.Collator('en', { sensitivity: 'base' }).compare
); // ["Apple", "banana", "cherry"]

延伸追問

面試官可能再追

Intl.NumberFormat 和手動用 toLocaleString() 有什麼差？

toLocaleString() 內部實際上呼叫 Intl.NumberFormat；差別在於重複格式化同一 locale 時，建立一個 Intl.NumberFormat 實例並反覆呼叫 .format() 效率更高，因為 locale 資料只解析一次。

Intl.Collator 和直接用 localeCompare() 差在哪？

同理：localeCompare() 底層也用 Intl.Collator。批次排序大量字串時，先建立 Collator 實例、取出 .compare 方法再傳入 .sort() 更快。

如果瀏覽器不支援某 locale，會怎樣？

瀏覽器會自動降級（fallback）到最接近的支援 locale；可用 Intl.DateTimeFormat.supportedLocalesOf(['zh-TW']) 事先查詢支援清單。現代瀏覽器對主要 locale 覆蓋率很高，IE11 以下才是問題。

面試這樣答

30 秒版本

「Intl 是瀏覽器內建的國際化 API，核心有 DateTimeFormat、NumberFormat、Collator 三大建構子，可以根據 locale 格式化日期、貨幣數字、做語系敏感排序。最佳實踐是建立一次 formatter 實例後反覆呼叫 .format()，避免每次都 new 才高效。對於簡單顯示需求，Intl 已夠用；複雜多語系翻譯才需要搭配 i18n 函式庫。」
