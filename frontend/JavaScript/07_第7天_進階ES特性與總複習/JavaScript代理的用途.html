物件操作的攔截層，
Vue 3 反應式的底層秘密

Proxy 在目標物件和外部程式碼之間插入一個「處理器」，可攔截 get、set、apply 等基本操作並插入自訂邏輯。Vue 3 就是用 Proxy 實作響應式系統，取代 Vue 2 的 Object.defineProperty。

基本結構

Proxy = 目標物件 + 攔截器（handler）

const proxy = new Proxy(target, handler);
// handler 是一組「trap」方法

const validator = new Proxy({}, {
  set(target, prop, value) {
    if (prop === 'age' && typeof value !== 'number')
      throw new TypeError('age 必須是數字');
    target[prop] = value;
    return true;
  }
});
validator.age = 25;     // ✓
validator.age = 'old'; // TypeError
handler 裡每個方法叫做 trap（陷阱），名稱對應 Reflect 方法，如 get、set、has、apply、construct 等共 13 種。
三大使用場景

Proxy 在實務中怎麼用

1

資料驗證 / 型別守衛

在 set trap 裡檢查型別、範圍，替代大量手動的 setter 方法。

2

反應式系統（Vue 3 / MobX / Immer）

get 時追蹤依賴，set 時通知訂閱者重繪 UI。這正是 Vue 3 reactive() 的原理。

3

Debug 日誌 / 存取稽核

在 get/set trap 裡加 console.log，追蹤物件被誰讀寫，不需修改原始物件。

// 動態預設值：存取不存在的屬性時自動回傳預設
const withDefault = (target, def) =>
  new Proxy(target, {
    get(t, k) { return k in t ? t[k] : def; }
  });
const cfg = withDefault({}, 'N/A');
cfg.name;  // 'N/A'
Proxy vs Object.defineProperty

為什麼 Vue 3 要換掉 Vue 2 的做法

Object.defineProperty（Vue 2）Proxy（Vue 3）
攔截新增屬性✕ 需手動 Vue.set()✓ 自動追蹤
攔截陣列索引✕ 需 patch 方法✓ 原生支援
攔截刪除屬性✕✓ deleteProperty trap
效能每個屬性個別定義整個物件一個 Proxy
✕

Proxy 無法被 polyfill，IE11 完全不支援。需要支援舊瀏覽器只能退回 Object.defineProperty 的方案。

延伸追問

面試官可能再追

Proxy 和 Reflect 通常一起出現，Reflect 的作用是什麼？

Reflect 提供與每個 trap 對應的靜態方法（如 Reflect.get(target, prop, receiver)）。在 trap 裡用 Reflect 執行原始操作，可正確處理繼承鏈的 receiver 問題，比直接寫 target[prop] 更安全。

Proxy 可以攔截哪些操作？能攔截 === 比較嗎？

共 13 個 trap，涵蓋屬性讀寫、in 運算子、delete、函式呼叫、new、Object.keys() 等。無法攔截 ===、typeof、Object.is()，這些是語言底層的基本操作。

面試這樣答

30 秒版本

「Proxy 讓你在物件外圍包一層攔截層，透過 handler（trap） 攔截 get、set、apply 等基本操作並插入自訂邏輯。實務常見用途是資料驗證、debug 日誌，以及最重要的反應式系統 — Vue 3 的 reactive() 就是用 Proxy 實作的，相較 Vue 2 的 Object.defineProperty，它能自動追蹤新增屬性和陣列變動，不需要 Vue.set()。唯一限制是無法被 polyfill，不支援 IE11。」
