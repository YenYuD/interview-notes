JAVASCRIPT / ES6+

永不重複的 key，
物件裡的隱形屬性

Symbol 是 ES6 新增的原始型別，每次呼叫 Symbol() 都產生全球唯一的值。最常見的用法是當物件屬性鍵，讓第三方程式碼「看不到」你加的屬性，也不怕與其他屬性名稱衝突。

三大核心特性

Symbol 的本質

唯一性Symbol() === Symbol() 永遠是 false
不可列舉不出現在 for...in / Object.keys()
非建構子不能 new Symbol()，只能 Symbol()
const s1 = Symbol('id');
const s2 = Symbol('id');
s1 === s2; // false — 描述相同但值不同

const obj = { name: 'Alice', [s1]: 42 };
Object.keys(obj);      // ['name']  ← Symbol 不出現
obj[s1];               // 42  ← 但還是能直接存取
Object.getOwnPropertySymbols(obj); // [Symbol(id)]
全域登錄表 vs 局部 Symbol

Symbol.for()：跨模組共享

局部 Symbol() 每次都產生新值；Symbol.for(key) 會先查全域登錄表，相同 key 回傳同一個 Symbol。

const a = Symbol.for('app.token');
const b = Symbol.for('app.token');
a === b; // true

Symbol.keyFor(a); // 'app.token'
適合在多個模組或 iframe 之間共享同一個「約定好的」Symbol，例如框架內部的 plugin key。
知名 Symbol

用來自訂語言行為的內建 Symbol

Symbol覆蓋後效果
Symbol.iterator讓物件支援 for...of 與展開運算子
Symbol.toPrimitive控制物件轉換成數字或字串的行為
Symbol.toStringTagObject.prototype.toString.call(obj) 回傳的標籤
Symbol.hasInstance自訂 instanceof 的判斷邏輯
 
// 讓自訂類別支援 for...of
class Range {
  constructor(from, to) { this.from = from; this.to = to; }
  *[Symbol.iterator]() {
    for (let i = this.from; i <= this.to; i++) yield i;
  }
}
[...new Range(1, 3)]; // [1, 2, 3]
延伸追問

面試官可能再追

Symbol 屬性不可列舉，那能被 JSON.stringify 序列化嗎？

不能。JSON.stringify 會完全忽略 Symbol 鍵的屬性。這反而是一個優點：可以在物件上掛「私有」元資料，序列化時自動消失，不會污染 API 回應。

Symbol 和私有類別欄位 #field 有什麼不同？

私有類別欄位（#field，ES2022）是真正的語法層面封裝，在類別外完全無法存取。Symbol 屬性雖然不可列舉，但只要拿得到那個 Symbol reference，外部程式碼仍能讀寫，只是「不易發現」而非真正私有。

面試這樣答

30 秒版本

「Symbol 是 ES6 新增的原始型別，每次呼叫都產生全球唯一的值。主要用途有兩個：一是當物件屬性鍵，利用它不可列舉的特性掛「半私有」的元資料，不會出現在 Object.keys() 和 JSON.stringify 中；二是用知名 Symbol（如 Symbol.iterator）來自訂物件的語言行為，例如讓自訂類別支援 for...of。需要跨模組共享同一個 Symbol 時，用 Symbol.for(key) 查全域登錄表。」
