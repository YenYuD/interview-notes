JavaScript · 錯誤處理

錯誤會往上爬，直到有人接住它

未被捕捉的錯誤沿著呼叫堆疊一層層向上傳播，最終若到達全域就讓程式掛掉。同步、Promise、async/await 三種情境，接錯的方式各不同。

同步傳播

呼叫堆疊向上爬的路徑

function a() {
  throw new Error('出問題了');
}
function b() { a(); }   // 沒 catch，繼續往上傳

try {
  b();
} catch (e) {
  console.error(e.message); // '出問題了'
}
堆疊傳播方向：a → b → try-catch。每一層如果沒有 try…catch，錯誤就繼續往外層呼叫者傳遞。
非同步情境

Promise 與 async/await 的差異

情境拋出方式捕捉方式
同步 throw new Error() try…catch
Promise chain Promise.reject() 或 throw in .then() 鏈結尾 .catch()
async/await throw 在 async 函式內 try…catch 包住 await 
// async/await
async function loadData() {
  try {
    const res = await fetch('/api');
    return await res.json();
  } catch (e) {
    console.error('請求失敗：', e.message);
  }
}
⚠️

未捕捉的 Promise rejection：若 Promise 鏈沒有 .catch()，瀏覽器會觸發 unhandledrejection 事件，Node.js 則可能終止程序。記得全域監聽作為兜底。

延伸追問

面試官可能再追

什麼情況下需要「重新拋出（re-throw）」錯誤？

當 catch 只想處理特定錯誤類型，其他錯誤不應吞掉時。做法：if (e instanceof NetworkError) handleIt(); else throw e;。這樣讓外層能捕捉到真正需要處理的錯誤。

如何全域捕捉未處理的錯誤？

瀏覽器：window.addEventListener('error', handler) 捕同步錯誤；window.addEventListener('unhandledrejection', handler) 捕 Promise。這是錯誤監控（Sentry 等工具）的基礎。

30 秒版本

「JS 的錯誤傳播遵循呼叫堆疊向上冒泡的規則：throw 後若當層沒有 catch，就往呼叫者傳，直到被接住或到達全域。非同步的情況不一樣——Promise 的錯誤要用 .catch() 接，async/await 則用 try…catch 包 await。未捕捉的 rejection 在現代瀏覽器會觸發 unhandledrejection 事件，正式專案裡我會全域監聽它送進錯誤追蹤服務。」
