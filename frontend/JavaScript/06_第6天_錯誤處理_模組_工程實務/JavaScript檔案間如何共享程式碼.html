ESM 與 CommonJS：兩套模組，一張對照表

現代瀏覽器與 Node.js 各有偏好，ES Modules（ESM） 是語言標準，CommonJS 是 Node.js 的傳統格式。面試考的不只是語法，而是你知不知道兩者的差異與選擇時機。

語法對照

ESM vs CommonJS 一眼看清

特性ES Modules (ESM)CommonJS (CJS)
匯出 export / export default module.exports
匯入 import { fn } from './m.js' const fn = require('./m.js')
載入時機 靜態分析，編譯時確定 執行時動態載入
Tree Shaking 支援（未用到的 export 可被移除） 不支援
環境 現代瀏覽器、Node.js（需 .mjs 或 type:module） Node.js 預設
命名匯出 vs 預設匯出

export vs export default

// utils.js — 命名匯出（可多個）
export function add(a, b) { return a + b; }
export const PI = 3.14;

// main.js — 具名匯入（需大括號）
import { add, PI } from './utils.js';

// math.js — 預設匯出（只能一個）
export default function subtract(a, b) { return a - b; }

// 匯入預設匯出（不需大括號，可自訂名稱）
import subtract from './math.js';
命名匯出可 Tree Shake、IDE 自動補全友善
預設匯出匯入端可任意命名，但需自律維持一致
💡

實務建議：函式庫與工具模組優先用命名匯出，讓打包工具可以 Tree Shake；React 元件慣例用預設匯出。

延伸追問

面試官可能再追

為什麼 ESM 支援 Tree Shaking 而 CommonJS 不支援？

ESM 的 import/export 是靜態宣告，打包工具在編譯時就能分析哪些 export 有被引用。CommonJS 的 require 是函式呼叫，可以在 if/loop 裡動態決定，打包工具無法在編譯時確定依賴，因此無法安全移除未用到的程式碼。

ESM 能動態載入模組嗎？

可以，用 import() 函式（Dynamic Import）：const mod = await import('./heavy.js')。回傳 Promise，常用於程式碼分割（Code Splitting）。

面試這樣答

30 秒版本

「JavaScript 有兩套主流模組系統：ES Modules 是語言標準，使用 import/export，靜態分析讓打包工具可以 Tree Shake；CommonJS 是 Node.js 傳統格式，用 require/module.exports，動態載入但無法 Tree Shake。現代前端專案基本都用 ESM，Node.js 則視專案而定，package.json 的 type: "module" 可切換預設行為。命名匯出比預設匯出更適合大型專案維護。」
