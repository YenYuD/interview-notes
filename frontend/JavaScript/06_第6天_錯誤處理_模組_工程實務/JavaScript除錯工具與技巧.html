console.log 之外，專業除錯的工具箱

人人都會 console.log，但面試官想看的是你能否善用 debugger、斷點與 DevTools，有系統地縮小問題範圍，而不是靠猜。

工具層次

從語言內建到瀏覽器工具

1

console API

log / warn / error / table / group / time…timeEnd——快速印值，table 特別適合物件陣列。

2

debugger 陳述式

在原始碼插入 debugger;，DevTools 開啟時會在此暫停執行，可逐行步進、檢查 scope 中所有變數。

3

DevTools 斷點

在 Sources 面板點行號設定斷點，無需修改原始碼。還有條件斷點（右鍵 → Add conditional breakpoint）、XHR 斷點、Event Listener 斷點。

4

Network / Performance 面板

Network 觀察 API 請求與回應；Performance 錄製時間軸找 CPU 瓶頸與長任務（Long Task）。

實用技巧

幾個 console 用法升級

// 物件陣列一眼看清楚
console.table([{ name: 'Alice', age: 30 }, { name: 'Bob', age: 25 }]);

// 測量耗時
console.time('fetch');
await fetch('/api/data');
console.timeEnd('fetch');   // fetch: 123.45ms

// 條件斷言，條件為 false 才印錯誤
console.assert(user.id !== null, 'user.id 不應為 null', user);
💡

Source Maps：打包後的程式碼難以閱讀，確保開發環境有 source map，DevTools 就能顯示原始 TS/JSX 位置，斷點才有意義。

延伸追問

面試官可能再追

debugger 和直接設斷點有什麼差別？何時用哪個？

debugger 寫進程式碼，版本控制可見，適合追蹤特定條件（配合 if）；DevTools 斷點不修改原始碼，適合快速實驗，且有條件斷點、log point 等進階功能。正式程式碼記得移除 debugger。

非同步程式碼的斷點怎麼設？

在 await 那行設斷點，步進時選「Step Over」跨過 async 等待，或「Step Into」進入 async 函式內部。也可在 Sources 面板勾選「Async」讓 call stack 顯示完整非同步鏈。

面試這樣答

30 秒版本

「除錯時我會分層：先用 console.table / time 快速縮小範圍；更複雜的問題在 DevTools 設條件斷點，配合 Scope 面板逐行觀察變數值；效能問題則開 Performance 面板錄製找長任務。我也會確保開發環境啟用 source map，讓 DevTools 顯示原始碼而非打包後的程式碼，這樣斷點才真正有效。」
