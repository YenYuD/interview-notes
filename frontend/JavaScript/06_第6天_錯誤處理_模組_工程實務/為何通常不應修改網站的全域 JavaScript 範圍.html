全域變數是共用廁所：人人能進，誰都可能弄髒

瀏覽器頁面上的所有腳本共用同一個 window 物件。隨意在全域放變數，就是把私人資料放在公共空間——命名衝突、記憶體洩漏、安全風險，三個問題一次到位。

為什麼不能碰

全域範圍的五個陷阱

風險具體情境
命名衝突 你的 window.data 被第三方套件覆蓋，或反過來踩到別人的
記憶體洩漏 全域變數的生命週期等同頁面，永不回收
隱性耦合 函式直接讀全域變數，難以測試（依賴外部狀態）
安全風險 第三方腳本可讀取或竄改 window 上的敏感值
除錯困難 全域狀態在任何地方都可能被修改，追蹤來源極難 
// 危險：count 跑進 window，任何腳本可改
var count = 0;

// 安全：用 IIFE 封裝，只暴露必要介面
(function () {
  let count = 0;              // 外部無法直接存取
  window.increment = () => count++;
  window.getCount  = () => count;
})();
解法

四種避免全域污染的方式

1

ES Modules

每個 module 有獨立作用域，import/export 明確控制對外介面，是現代前端的首選。

2

let / const + 區塊作用域

宣告在函式或區塊內，生命週期有限，不掛在 window 上。

3

IIFE（即使不用模組系統）

(function(){...})() 建立獨立作用域，老舊專案無模組打包時的常用手法。

✓

'use strict' 嚴格模式

防止意外建立全域變數（未宣告直接賦值會拋 ReferenceError）。

延伸追問

面試官可能再追

有時候就是需要跨腳本共用資料，正確做法是什麼？

用一個命名空間物件（namespace object）：window.MyApp = window.MyApp || {}，所有共用資料掛在 MyApp 下，只佔一個全域名稱。更現代的做法是 ESM 模組化後用全域狀態管理（Zustand/Redux）。

var 和 let/const 在全域行為有什麼差？

在頂層宣告時：var x = 1 會把 x 加到 window；let x = 1 和 const x = 1 建立在腳本作用域，不加到 window，但在 module 裡更是各自獨立。

面試這樣答

30 秒版本

「不污染全域範圍是基本工程紀律。全域變數的問題在於：所有腳本共用 window，命名衝突難以避免，且全域狀態可被任意修改，導致除錯困難與潛在安全風險。現代解法是用 ES Modules——每個模組有獨立作用域，明確 export 才對外可見。舊專案可用 IIFE 封裝，或開啟 'use strict' 讓未宣告的賦值直接拋錯，至少能防止最低級的意外全域污染。」
