繼承 Error，讓錯誤有身份，catch 才精準

自訂錯誤類別讓你可以用 instanceof 判斷錯誤類型，不再靠字串比對 message。API 層的 NetworkError、驗證層的 ValidationError——名字清楚，處理才清楚。

基本寫法

繼承 Error 類別

class ValidationError extends Error {
  constructor(message, field) {
    super(message);          // 設定 this.message
    this.name = 'ValidationError';
    this.field = field;       // 自訂屬性：哪個欄位有問題
  }
}

try {
  throw new ValidationError('Email 格式錯誤', 'email');
} catch (e) {
  if (e instanceof ValidationError) {
    console.log(`欄位 ${e.field}：${e.message}`);
  } else {
    throw e; // 不認識的錯誤往上傳
  }
}
實務分類

按錯誤來源建立錯誤層次

NetworkErrorHTTP / 連線失敗
ValidationError使用者輸入格式錯誤
AuthError401 / 403 未授權
AppError業務邏輯錯誤基底類別
class NetworkError extends Error {
  constructor(message, statusCode) {
    super(message);
    this.name = 'NetworkError';
    this.statusCode = statusCode;
  }
  logError() {
    console.error(`[${this.name}] ${this.statusCode}: ${this.message}`);
  }
}

// 使用時
if (!res.ok) throw new NetworkError('Not Found', 404);
💡

記得設 this.name：繼承 Error 後 this.name 仍然是 'Error'，不設的話 error.name 會誤導，也讓 stack trace 顯示錯誤。

延伸追問

面試官可能再追

為什麼要在 constructor 呼叫 super(message)？

因為 Error 的建構子負責設定 this.message 與 this.stack。若不呼叫 super，這些屬性就不會被設定，堆疊追蹤也會指向錯誤的位置。在繼承內建類別時，super() 必須在存取 this 之前呼叫。

instanceof 在跨 iframe 或多個 realms 時會失效，怎麼辦？

在不同的執行環境（realm）下，各自有獨立的 Error 建構子，跨 realm 的 instanceof 比對會失敗。解法：改用 error.name === 'ValidationError' 字串比對；或使用 Symbol 標記（error[Symbol.for('errorType')] = 'ValidationError'）。
