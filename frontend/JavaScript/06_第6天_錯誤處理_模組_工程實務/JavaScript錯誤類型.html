JavaScript · 錯誤處理

三種錯誤，只有一種會讓引擎拒絕執行

面試官問「JS 有哪些錯誤類型」，多數人只說 TypeError，其實分三層：語法錯誤在解析期就掛掉，Runtime 錯誤在執行中爆炸，邏輯錯誤最狡猾——程式跑完但結果是錯的。

核心概念

三種錯誤各自的生命週期

類型 何時發生 典型例子 能 catch？
語法錯誤 SyntaxError 解析（Parse）階段，程式碼未執行 少了括號、引號不成對 不能（程式根本跑不起來）
執行時錯誤 Runtime Error 執行期間，邏輯觸發 null.property（TypeError） 可以，用 try…catch
邏輯錯誤 Logic Error 執行完成，但結果有誤 if (x = 1) 寫成賦值 無錯誤可 catch，靠測試/debugger
常見 Runtime Error 子類型

ReferenceError、TypeError、RangeError

TypeError存取 null/undefined 的屬性
ReferenceError變數未宣告就使用
RangeError陣列長度為負數、遞迴爆棧
SyntaxErrorJSON.parse 格式不合法
⚠️

邏輯錯誤最難發現：例如 if ((isAdmin = true))，引擎不會報錯，但每次都會進 if 區塊，因為賦值的結果是 true。

// Runtime Error：可被 catch
try {
  let obj = null;
  console.log(obj.property);
} catch (e) {
  console.log(e instanceof TypeError); // true
}

// 邏輯錯誤：不報錯但結果錯
let isAdmin = false;
if ((isAdmin = true)) {  // 應為 ===，不是 =
  console.log('Access granted'); // 永遠執行
}
延伸追問

面試官可能再追

SyntaxError 能用 try…catch 包住嗎？

不行。SyntaxError 在 parse 階段就發生，程式根本沒機會跑到 try 那行。唯一例外是 eval() 或 JSON.parse() 執行時產生的 SyntaxError，那時已進入 runtime，可以 catch。

instanceof TypeError vs error.name === 'TypeError' 有什麼差？

instanceof 在跨 iframe/realm 時可能失效（不同的 Error 建構子）；error.name 是字串比對，不受此限。實務上優先用 instanceof，跨 realm 場景再改用 name。

如何找出邏輯錯誤？

三招：(1) debugger 加中斷點逐行追蹤值；(2) 撰寫單元測試，讓預期結果不符合時紅燈；(3) console.assert() 在條件不符時印錯誤訊息。

面試這樣答

30 秒版本

「JavaScript 的錯誤分三類：語法錯誤在解析期發生，程式無法執行，例如括號沒配對；執行時錯誤（Runtime Error）在執行過程中拋出，例如存取 null 的屬性，可以用 try…catch 捕捉；邏輯錯誤最棘手，程式跑完但結果不對，不會有任何例外，需要靠測試與 debugger 才能找出來。」
