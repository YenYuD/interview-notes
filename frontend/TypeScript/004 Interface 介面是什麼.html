Interface 是資料結構的契約，不是實作

Interface 描述一個物件「應該長什麼樣子」，不包含任何執行邏輯。它是 TypeScript 最常用的結構化型別工具，讓函式、class、物件之間能共享同一份形狀定義。

01

基本語法與可選屬性

interface User {
  name: string;
  age: number;
  email?: string; // ? 表示 optional
}

const user: User = {
  name: "Bob",
  age: 20,
  // email 省略也 OK
};

// Interface 也能描述函式形狀
interface Formatter {
  (value: string): string;
}
const toUpper: Formatter = (v) => v.toUpperCase();

一般規則：物件形狀用 interface，需要 union 或複雜組合用 type。兩者在大多數場景可互換，但 interface 的 Declaration Merging 特性在定義公開 API 時非常有用。

// Declaration Merging — 兩個同名 interface 自動合併
interface User { name: string; }
interface User { age: number; }
// 結果等同 { name: string; age: number }
延伸追問

面試官可能再追

interface 的 extends 可以擴充多個嗎？

可以，interface Admin extends User, Serializable { ... }，這是 interface 比 class extends 更靈活的地方——class 只能單繼承，interface 可以多 extends。

什麼是 Declaration Merging？實際用在哪？

同名 interface 宣告會自動合併。常見用途：擴充第三方套件的型別定義（如為 Express 的 Request 加上自訂欄位），不需要修改原始定義。

面試這樣答

30 秒版本

「Interface 是 TypeScript 用來描述物件形狀的契約，只定義有哪些屬性和型別，不包含實作。它的核心優勢是 Declaration Merging——同名 interface 自動合併，適合定義公開 API 或擴充第三方套件型別。與 type alias 的差異在於：物件形狀優先用 interface，需要 union 或 primitive 才用 type。」
