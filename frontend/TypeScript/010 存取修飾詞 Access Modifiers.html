存取修飾詞是編譯期的封裝機制，不是執行期保護

TypeScript 的 public、protected、private 控制「誰可以存取這個屬性」。它們在編譯時強制執行——但要注意，編譯成 JS 後這些限制消失了；若要真正的執行期私有，要用 ES2022 的 # 語法。

01

三種修飾詞的存取範圍

修飾詞同一 class 內子類別外部
public（預設）✅✅✅
protected✅✅❌
private✅❌❌
02

完整範例與建構子簡寫

class User {
  // 建構子簡寫：直接在參數宣告屬性
  constructor(
    public name: string,
    protected email: string,
    private password: string,
  ) {}

  getInfo() {
    return `${this.name} / ${this.password}`; // ✅ 內部可用 private
  }
}

class AdminUser extends User {
  show() {
    console.log(this.email);    // ✅ protected 子類別可用
    console.log(this.password); // ❌ private 子類別不能用
  }
}

const u = new User("Bob", "bob@x.com", "secret");
console.log(u.name);     // ✅ public
console.log(u.email);    // ❌ protected
console.log(u.password); // ❌ private
⚠️

TypeScript 的 private 是編譯期保護，編譯成 JS 後屬性仍然可被存取。若需要真正的執行期私有，使用 ES2022 的 #password（hard private）。

延伸追問

面試官可能再追

TypeScript private 和 ES2022 # 有什麼差別？

TypeScript private 只在編譯期檢查，JS 執行時仍可存取。ES2022 #name 是真正的執行期私有，即使在 JS 中也無法從外部存取，且子類別也不能繼承。

readonly 和 private 的差別？

readonly 控制的是「可否修改值」（防止重新賦值）；private 控制的是「誰可以存取」。兩者可以同時使用：private readonly id: string。

面試這樣答

30 秒版本

「TypeScript 有三種存取修飾詞：public 任何地方都能存取、protected 僅限同一 class 及子類別、private 只有同一 class 內部。它們是物件導向封裝的核心，在編譯期強制執行。值得注意的是，TypeScript private 編譯成 JS 後保護消失；若需要真正的執行期私有屬性，要改用 ES2022 的 # 語法。」
