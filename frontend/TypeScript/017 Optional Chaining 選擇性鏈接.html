Optional Chaining ?. 讓深層存取遇到 null 就短路，不拋錯

深層物件存取最怕中間某層是 null 或 undefined，一路 && && 又醜又長。?. 讓鏈中任何一環為 null/undefined 時，整個表達式回傳 undefined，乾淨不炸。

01

傳統寫法 vs Optional Chaining

const user = { personalInfo: { name: "John", address: undefined } };

// 傳統：繁瑣且難讀
const city = user && user.personalInfo && user.personalInfo.address
  ? user.personalInfo.address.city
  : undefined;

// Optional Chaining：簡潔
const city = user?.personalInfo?.address?.city;
// address 是 undefined → 整個表達式回傳 undefined（不拋錯）
02

三種用法

// 1. 存取屬性
const name = user?.profile?.name;

// 2. 呼叫方法
const result = user?.getProfile?.();

// 3. 存取陣列元素
const first = arr?.[0];
03

搭配 Nullish Coalescing ?? 提供預設值

// ?? 只對 null / undefined 走右側（不像 || 對所有 falsy 都走）
const name  = user?.profile?.name ?? "Anonymous";
const count = data?.count ?? 0; // count 是 0 時，?? 不會換成 0（|| 會）
💡

??（Nullish Coalescing）比 || 更精準：|| 遇到任何 falsy（0、""、false）都走右側；?? 只對 null 和 undefined 走右側。兩者搭配 ?. 是處理可選值的最佳組合。

延伸追問

面試官可能再追

Optional Chaining 和 Optional Parameter（?）有什麼不同？

Optional Parameter（name?: string）是在型別定義中標記某個參數/屬性是可選的（可能為 undefined）。Optional Chaining（?.）是在存取時安全處理可能為 null/undefined 的值。前者是型別宣告，後者是存取語法。

什麼情況下不適合用 Optional Chaining？

當你確定某個值一定存在（如必填欄位）時，用 ?. 會掩蓋潛在的 bug——原本應該報錯的情況變成靜默回傳 undefined。這種情況用非空斷言 ! 或直接存取更合適，讓問題早點爆出來。

面試這樣答

30 秒版本

「Optional Chaining（?.）讓你安全地存取深層物件屬性——鏈中任何一環是 null 或 undefined，整個表達式立即回傳 undefined 而不拋出錯誤。常搭配 ??（Nullish Coalescing）提供預設值，它比 || 更精準，只對 null/undefined 走右側，不會誤判 0 或空字串。兩者都是 ES2020 / TypeScript 3.7 加入的特性。」
