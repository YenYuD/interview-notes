Enum 是具名常數集合，但現代 TS 常用 as const 取代

Enum 讓你用有意義的名稱代替裸數字或字串。字串型 Enum 比數字型更易讀，但它會編譯出額外的 JS 程式碼——這是為何現代專案偏好用 as const 物件替代的原因。

01

數字型 vs 字串型 Enum

數字型（預設）debug 時只看到數字
字串型（推薦）debug 時看到有意義的字串
// 字串型（推薦）
enum Status {
  Active   = "ACTIVE",
  Inactive = "INACTIVE",
  Pending  = "PENDING",
}

const s: Status = Status.Active;
console.log(s); // "ACTIVE"（不是 0）
02

Enum vs as const：bundle size 的考量

enumas const 物件
Tree-shaking❌ 會生成 IIFE，較難搖掉✅ 純物件，易 tree-shake
型別安全✅✅（搭配 typeof）
執行期存取✅✅
 
// as const 替代方案
const Status = {
  Active: "ACTIVE",
  Inactive: "INACTIVE",
} as const;

type StatusValue = typeof Status[keyof typeof Status];
// "ACTIVE" | "INACTIVE"
ℹ️

TypeScript 把 enum 編譯成 IIFE 物件，這是它比 as const 多生成程式碼的原因。回答時主動提到這個 bundle size 考量，展示實務意識。

延伸追問

面試官可能再追

const enum 和普通 enum 有什麼差別？

const enum 在編譯時會被內聯（inline）成字面值，不產生 IIFE，bundle size 更小。但它與 isolatedModules（如 Babel 轉換 TS）不相容，使用前要確認工具鏈支援。

數字型 enum 為什麼有反向對映？

數字型 enum 編譯後，TypeScript 同時建立 name→value 和 value→name 的對映（Status[0] === "Active"）。字串型沒有這個特性，這也是字串型較推薦的原因之一（行為更單純）。

面試這樣答

30 秒版本

「Enum 是一組具名常數的集合，用來避免魔法數字或字串散落在程式碼中。字串型 Enum 比數字型更推薦，因為 debug 時可以直接看到有意義的字串。不過，現代 TypeScript 有時偏好用 as const 物件替代 enum，因為 enum 會編譯成 IIFE，bundle size 較大且 tree-shaking 較差。兩種做法型別安全性相同，選擇依團隊規範。」
