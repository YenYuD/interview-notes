TYPESCRIPT

unknown 是「型別安全版的 any」——用之前先確認

兩者都能接受任何值，但 unknown 強制你在操作前做型別檢查。這正是 TypeScript 的精神：承認「我不知道型別」，同時不放棄安全性。

01

any vs unknown：一個允許亂來，一個要求確認

// any — TS 完全不管（危險）
let a: any = "hello";
a.toFixed(2);    // ✅ 編譯過，但 runtime 炸

// unknown — 使用前必須 narrowing（安全）
let b: unknown = "hello";
b.toUpperCase(); // ❌ 編譯錯誤

if (typeof b === "string") {
  b.toUpperCase(); // ✅ narrowing 後才能操作
}
02

三個常見使用場景

外部 API 回傳 / JSON.parse 
async function fetchData(): Promise<unknown> {
  const res = await fetch("/api/user");
  return res.json();
}
// 呼叫端必須自行 narrow 才能使用
catch block 的 error 
try { ... } catch (error: unknown) {
  if (error instanceof Error) {
    console.log(error.message); // ✅
  }
}
泛用 callback 
function invoke(cb: unknown): void {
  if (typeof cb === "function") cb();
}

延伸追問

面試官可能再追

unknown 是什麼時候加入 TypeScript 的？

TypeScript 3.0（2018）加入，目的就是提供「型別安全版的 any」。在此之前，社群的做法是用 any 再加手動 narrowing，或用泛型約束。

unknown 和 never 都是特殊型別，差在哪？

unknown 是 top type（所有型別都是它的子型別，任何值都可以賦給它）；never 是 bottom type（它是所有型別的子型別，沒有任何值屬於它）。兩者在型別層級上是兩個極端。

面試這樣答

30 秒版本

「unknown 是型別安全版的 any。兩者都接受任何值，但 any 讓你直接操作而放棄型別檢查；unknown 強制你在操作前先做 narrowing（typeof、instanceof 等），才能存取屬性或呼叫方法。實務上，接收外部 API 回傳、JSON.parse 結果、catch block 的 error 都應用 unknown。幾乎所有「不確定型別」的場景都應優先選 unknown，而不是 any。」
