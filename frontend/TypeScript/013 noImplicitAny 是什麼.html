noImplicitAny 把「偷偷變成 any」的情況全部揪出來

TypeScript 遇到無法推斷的型別，預設會悄悄標為 any。開啟 noImplicitAny 讓這些「隱式 any」在編譯時就報錯，強制你明確標注型別，是邁向嚴格型別安全的第一步。

01

開啟前後的行為差異

關閉（預設） TypeScript 遇到無法推斷的型別 → 自動變 any，不報錯
開啟（建議） 遇到無法推斷的型別 → 編譯錯誤，強制你明確標注 
// noImplicitAny: false（預設）
function print(x) {
  console.log(x); // x 隱式變 any，不報錯
}

// noImplicitAny: true
function print(x) {
  // ❌ Parameter 'x' implicitly has an 'any' type
}

function print(x: string): void {
  console.log(x); // ✅ 明確標注後 OK
}
ℹ️

無論設定如何，你都可以手動明確標注 any（x: any），這個設定只影響「隱式」的 any——你沒寫型別、TS 也推不出來的情況。

02

tsconfig.json 設定與 strict 模式

{
  "compilerOptions": {
    "noImplicitAny": true,
    // 或者直接開啟 strict（包含 noImplicitAny）
    "strict": true
  }
}
情境建議
新 TypeScript 專案✅ 開啟（配合 strict: true）

延伸追問

面試官可能再追

strict: true 包含哪些選項？

strict: true 是一個組合選項，包含 noImplicitAny、strictNullChecks、strictFunctionTypes、strictBindCallApply、strictPropertyInitialization、noImplicitThis 等。現代 TypeScript 最佳實踐是開啟 strict: true。

strictNullChecks 和 noImplicitAny 有什麼關係？

兩者獨立但互補。noImplicitAny 防止型別被隱式標為 any；strictNullChecks 讓 null 和 undefined 成為獨立型別，不能隨便賦值給其他型別。兩個都開啟才能發揮最大的型別安全效益。

面試這樣答

30 秒版本

「noImplicitAny 是 tsconfig 的編譯器選項，控制 TypeScript 遇到無法推斷的型別時是否報錯。關閉時，TS 會悄悄把推不出型別的地方標為 any；開啟後，這些「隱式 any」在編譯時就會報錯，強制你明確標注。它是 strict: true 的一部分，現代 TS 專案通常直接開啟 strict 模式，涵蓋 noImplicitAny 和其他嚴格設定。」
