從 any / unknown / never 到 Mapped Types：型別系統的四個核心地基

TypeScript 不只是「加了型別的 JavaScript」。any 是逃生口，unknown 是安全門，never 是永遠不存在的值——搞懂這三個特殊型別，再搭配 Mapped Types，你就掌握了 TS 的精髓。

01

any vs unknown：都能接受任何值，差在能否操作

anyunknown
賦值給它✅ 任何值✅ 任何值
直接操作（呼叫方法等）✅ 隨便用，TS 不管❌ 必須先 narrowing
型別安全🚫 完全放棄✅ 保留
一句話逃生口安全門
 
// unknown — 使用前必須 narrowing
let b: unknown = "hello";
// b.toUpperCase(); ❌ 編譯錯誤
if (typeof b === "string") {
  b.toUpperCase(); // ✅ narrowing 後才能操作
}
💡

unknown 是 top type（所有型別是它的子型別），never 是 bottom type（它是所有型別的子型別），any 則同時是 top 也是 bottom——這讓它「繞過」了整個型別系統。

02

never：永遠不存在的值，exhaustive check 的利器

// 場景 1：一定拋錯 / 無窮迴圈
function throwError(msg: string): never {
  throw new Error(msg);
}

// 場景 2：Exhaustive Check — 新增 case 忘了處理就編譯報錯
type Shape = "circle" | "square";
function getArea(shape: Shape) {
  switch (shape) {
    case "circle": return Math.PI * 100;
    case "square": return 100;
    default:
      const _check: never = shape; // 若漏掉新 case 就報錯
      return _check;
  }
}
never 在 union 中會自動消失：string | never → string。這是 Exclude utility type 的核心機制。
03

Type Narrowing 與 Discriminated Unions

typeof原始型別判斷
instanceofclass 實例
in屬性存在性
discriminant共同辨識欄位
type ApiResponse = { status: "success"; data: string }
                  | { status: "error"; message: string };

function handle(res: ApiResponse) {
  switch (res.status) {
    case "success": console.log(res.data);    break;
    case "error":   console.log(res.message); break;
  }
}
ℹ️

Discriminated Union 靠共同的「辨識欄位」（status）讓 TS 自動 narrow，不需要手動 as 斷言。

04

Mapped Types：遍歷並轉換型別的語法

// 自製 Readonly
type MyReadonly<T> = {
  readonly [K in keyof T]: T[K];
};

// 內建 Utility Types 都是 Mapped Type
// Partial<T> → [K in keyof T]?: T[K]
// Required<T> → [K in keyof T]-?: T[K]
// Record<K,V> → [P in K]: V
延伸追問

面試官可能再追

什麼情況下應該用 unknown 而不是 any？

幾乎任何「真的不知道型別」的場景都應該用 unknown：接收外部 API 回傳、JSON.parse、catch block 的 error 物件。any 只在漸進式 JS→TS 遷移時暫時過渡。

never 在 Exclude 底層怎麼運作？

type Exclude<T, U> = T extends U ? never : T。對 union 分配運算時，命中條件的成員被換成 never，而 never 在 union 中會自動消失，結果就是被排除了。

Mapped Type 的 key remapping（as）怎麼用？

TS 4.1+ 支援 [K in keyof T as \`get${Capitalize<string & K>}\`]，可在遍歷時重命名 key，用來建 getter/setter 型別非常方便。
