TYPESCRIPT

函式多載讓「傳什麼型別進去，就精確知道回傳什麼型別」

用 Union 型別時，傳 string 進去，回傳型別還是 string | number，不夠精確。函式多載讓每種輸入對應獨立的型別簽名，讓 TypeScript 根據你傳入的參數精確推斷回傳型別。

01

語法結構：多載簽名 + 實作簽名

// 1. 多載簽名（只有型別定義，沒有實作）
function print(message: string): void;
function print(messages: string[]): void;

// 2. 實作簽名（實際邏輯，外部不能直接以此簽名呼叫）
function print(message: string | string[]): void {
  if (typeof message === "string") {
    console.log(message);
  } else {
    message.forEach(m => console.log(m));
  }
}

print("Single");             // ✅
print(["First", "Second"]); // ✅
print(42);                  // ❌ 沒有符合 number 的多載
02

多載 vs Union：精確程度不同

// Union — 回傳型別不夠精確
function parse(input: string | number): string | number { ... }
const r = parse("hello"); // 型別：string | number（還要 narrowing）

// 多載 — 傳 string 回傳 string，精確
function parse(input: string): string;
function parse(input: number): number;
function parse(input: string | number): string | number { ... }
const r = parse("hello"); // 型別：string（精確！不需 narrowing）
03

不同回傳型別的多載（DOM 實際案例）

function createElement(tag: "div"): HTMLDivElement;
function createElement(tag: "span"): HTMLSpanElement;
function createElement(tag: "input"): HTMLInputElement;
function createElement(tag: string): HTMLElement {
  return document.createElement(tag);
}

const div = createElement("div"); // 型別：HTMLDivElement（精確）
ℹ️

重要限制：實作簽名對外不可見，呼叫端只能使用多載簽名列出的形式，不能以實作簽名的 union 型別直接呼叫。

延伸追問

面試官可能再追

什麼時候應該用泛型，什麼時候用多載？

優先考慮泛型——如果不同輸入輸出的型別關係是「傳什麼進去，回傳相同型別」，用泛型更簡潔（identity<T>(x: T): T）。只有「不同輸入對應截然不同型別的輸出」時，才用多載，如 createElement("div")→HTMLDivElement。

為什麼實作簽名的型別對外不可見？

設計上的考量：實作簽名通常是較寬鬆的 union 型別（用來容納所有情況），直接暴露會讓呼叫端的型別推斷變得模糊。TypeScript 強制你寫明確的多載簽名，是為了保證呼叫端的型別精確。

面試這樣答

30 秒版本

「函式多載讓同一個函式對不同輸入提供不同的精確型別簽名。語法分兩部分：多載簽名只定義型別，實作簽名才有邏輯，且實作簽名對外不可見。相較於 Union 型別，多載的優勢是傳入什麼型別，TypeScript 就推斷出對應的精確回傳型別，不需要呼叫端再做 narrowing。使用順序：先考慮泛型，不同輸入對應不同型別輸出時才用多載。」
