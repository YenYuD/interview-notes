預設用 const，需要重新賦值才改 let，幾乎不用 var

var 的函式作用域與 hoisting 是歷史遺毒。let 和 const 帶來區塊作用域，讓變數範圍更可預期；而暫時死區（TDZ）讓錯誤在編譯期就爆出來。

02

var 的問題：作用域洩漏 + 靜默的 undefined

// var hoisting：宣告前用回傳 undefined，不報錯（危險）
console.log(x); // undefined（不是錯誤！）
var x = 5;

// var 不受 {} 限制
if (true) {
  var leaked = "I escape the block";
}
console.log(leaked); // ✅ 竟然可以存取
⚠️

let 和 const 也有 hoisting，但進入的是「暫時死區（TDZ）」，宣告前存取會直接報錯，而不是默默回傳 undefined——錯誤更早被發現。

03

const 只保護「綁定」，不保護物件內容

const user = { name: "Bob" };
user.name = "Alice"; // ✅ 修改屬性沒問題
user = {};           // ❌ 重新賦值才報錯
想要深層不可變，需要 Object.freeze() 或 TypeScript 的 Readonly<T>。

什麼是暫時死區（TDZ）？

從進入區塊到 let/const 宣告那行之間的範圍，變數存在但不可存取。這段就是 TDZ。目的是消除 var hoisting 帶來的「宣告前存取回傳 undefined」的混亂行為。

var 的 hoisting 具體怎麼運作？

JavaScript 引擎在執行前先掃描所有 var 宣告，把「宣告」提升到作用域頂端（但初始化值不提升）。所以宣告前存取得到 undefined 而非報錯。
