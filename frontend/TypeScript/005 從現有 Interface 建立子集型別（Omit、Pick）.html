用 Omit 和 Pick 從現有型別裁出子集，不重複定義

同一個 User 介面，列表頁只需要部分欄位、表單頁需要去掉某幾個欄位。Omit 和 Pick 讓你複用既有型別、零重複定義，改一處就全部同步更新。

01

Omit vs Pick：思考方式不同，結果互補

Pick<T, K>Omit<T, K>
做什麼只保留指定欄位去掉指定欄位，其餘保留
適合場景只需要少數欄位只有少數欄位要排除
思考方式「只要 X」「除了 X 都要」
 
interface User {
  id: number; name: string; email: string; age: number;
}

// Pick — 只拿 id 和 name
type UserCard = Pick<User, "id" | "name">;
// { id: number; name: string }

// Omit — 去掉 email
type PublicUser = Omit<User, "email">;
// { id: number; name: string; age: number }
02

底層實作：Omit 其實是 Pick + Exclude

// Omit 的底層
type MyOmit<T, K extends keyof T> = Pick<T, Exclude<keyof T, K>>;

// Exclude 把 K 從 union 中去掉，剩下的再 Pick 出來
ℹ️

面試時能說出 Omit 底層是 Pick<T, Exclude<keyof T, K>>，展示你理解 Utility Types 不是魔法，而是 Mapped Types + Conditional Types 組合出來的。

延伸追問

面試官可能再追

Partial、Required 和 Pick 的差別是什麼？

Pick 改變的是「哪些欄位存在」；Partial 把所有欄位變 optional（適合「更新」場景）；Required 是 Partial 的反向。三者正交，可以組合使用，如 Partial<Pick<User, "name" | "email">>。

為什麼不直接重新寫一個新的型別就好？

重複定義會造成維護問題——改 User 欄位名稱時，所有手刻的子集型別都要同步更新。用 Pick/Omit 則自動跟著 User 更新，且 IDE 能追蹤來源。

面試這樣答

30 秒版本

「Pick 讓你從型別中挑選少數欄位，Omit 讓你去掉少數欄位、保留其餘——選哪個取決於「需要的欄位少」還是「要排除的欄位少」。它們的核心價值是複用型別定義、避免重複：改動原型別時，所有衍生型別自動同步。底層實作上，Omit 就是 Pick 搭配 Exclude 的組合。」
