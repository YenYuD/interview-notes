extends 是繼承實作，implements 是簽約履行形狀

extends 讓子類別「繼承」父類別的所有屬性和方法；implements 讓 class「承諾」自己符合某個型別的形狀，但不繼承任何實作，所有成員要自己寫。

02

extends：繼承，子類別獲得父類別的實作

class Animal {
  constructor(public name: string) {}
  speak(): void { console.log(`${this.name} makes a sound.`); }
}

class Dog extends Animal {
  speak(): void { console.log(`${this.name} barks.`); } // 覆寫
  fetch(): void { console.log("Fetching!"); } // 新增
}
03

implements：簽約，所有成員要自己提供

interface Serializable {
  serialize(): string;
}

class User implements Serializable {
  name = "Bob";
  serialize() { return JSON.stringify({ name: this.name }); } // 必須自己實作
}

// 同時 extends + implements
class Admin extends User implements Serializable, Loggable {
  // 繼承 User 的屬性，同時實作兩個 interface
}
💡

implements 像「簽約」——class 向 TypeScript 承諾自己符合某個形狀，但不拿到任何實作。這是依賴注入（DI）和多型設計的基礎。

延伸追問

面試官可能再追

interface 自己的 extends 和 class 的 extends 一樣嗎？

interface 用 extends 來擴充另一個 interface，可以多繼承（interface Dog extends Animal, Pet）；class 的 extends 只能繼承一個 class。語法相同但語義稍有差異。

為什麼有時候 class implements class（而不是 interface）？

當你想用一個 class 當作「型別契約」（只借用其形狀），同時讓另一個 class 承諾符合它，可以這樣做。但這僅檢查形狀，不繼承實作，實務上較少見，通常更清晰的做法是定義一個 interface。

面試這樣答

30 秒版本

「extends 是繼承，子類別取得父類別的屬性和方法，可以覆寫或新增；implements 是實作契約，class 承諾自己符合某個 interface 或型別的形狀，但不繼承任何實作，所有成員要自己提供。兩者可以同時使用：class Admin extends User implements Serializable。implements 是多型和依賴注入設計的核心工具。」
