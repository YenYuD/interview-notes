箭頭函式最重要的特性是 lexical this，不是簡短語法

很多人把箭頭函式當「短一點的寫法」，但它最關鍵的差異是 this 的綁定方式：箭頭函式的 this 在定義當下就固定了，不會被呼叫方式改變。

01

語法對比：從完整到精簡

// 一般函式
function add(x: number, y: number): number {
  return x + y;
}

// 箭頭函式
const add = (x: number, y: number): number => x + y;

// 常見用途：陣列操作
const doubled = [1,2,3].map(n => n * 2);    // [2, 4, 6]
const evens   = [1,2,3].filter(n => n % 2 === 0); // [2]
02

lexical this：class 裡的 callback 最常踩的坑

class Timer {
  seconds = 0;

  // ✅ 箭頭函式：this 固定指向 Timer 實例
  startWithArrow() {
    setInterval(() => {
      this.seconds++;
    }, 1000);
  }

  // ❌ 一般函式：this 被 setInterval 改變了
  startWithRegular() {
    setInterval(function() {
      this.seconds++; // undefined（strict mode）或 window
    }, 1000);
  }
}
⚠️

一般函式的 this 由「誰呼叫它」決定（動態綁定）；箭頭函式的 this 由「在哪裡定義它」決定（靜態 / 詞法綁定）。

延伸追問

面試官可能再追

箭頭函式可以用 call/apply/bind 改變 this 嗎？

不行。箭頭函式的 this 在定義時就固定了，call/apply/bind 傳入的 this 會被忽略。這是它的設計意圖：確保 this 永遠可預測。

什麼情況下不該用箭頭函式？

物件的 method 定義（this 應指向物件本身）、需要 arguments 物件、需要作為建構子（new）時，應使用一般函式。

30 秒版本

「箭頭函式和一般函式最重要的差異是 this 的綁定方式。一般函式的 this 是動態的，由呼叫方式決定；箭頭函式是 lexical this，在定義時就固定繼承外層的 this。這讓它特別適合 class 裡的 callback——像是傳給 setTimeout 或陣列操作的函式，不怕 this 被偷走。除了 this，箭頭函式也沒有 arguments 物件且不能當建構子。」
