Abstract Class：樣板方法模式的 TypeScript 實作

抽象類別不能被直接實例化，它的目的是同時做兩件事：提供子類別共用的具體實作，以及強制子類別自己實作某些方法。Interface 只能定義形狀，Abstract Class 還能夾帶邏輯。

01

核心特性：兩種成員並存

abstract class Vehicle {
  // 抽象方法：只有簽名，子類別必須實作
  abstract drive(): void;

  // 具體方法：共用邏輯，子類別直接繼承
  startEngine(): void {
    console.log("Engine starting...");
  }
}

class Car extends Vehicle {
  drive(): void { console.log("Driving a car"); } // ✅ 必須實作
}

// const v = new Vehicle(); ❌ 不能直接實例化抽象類別
const car = new Car();
car.startEngine(); // ✅ 繼承具體方法
car.drive();       // ✅ 自己的實作
02

Abstract Class vs Interface：怎麼選

abstract classinterface
可以有具體實作✅❌
可以有 constructor✅❌
存取修飾詞✅❌（全 public）
一個 class 能繼承幾個只能一個可 implements 多個
用途共用邏輯 + 強制實作純粹定義形狀契約
💡

選擇依據：只需要定義形狀 → interface；需要共用邏輯同時強制子類別行為 → abstract class。

03

實際應用：Repository 模式

abstract class BaseRepository<T> {
  abstract findById(id: string): Promise<T | null>;
  abstract save(entity: T): Promise<void>;

  // 共用邏輯：子類別免費繼承
  async findOrThrow(id: string): Promise<T> {
    const entity = await this.findById(id);
    if (!entity) throw new Error(`Not found: ${id}`);
    return entity;
  }
}
延伸追問

面試官可能再追

什麼是樣板方法模式（Template Method Pattern）？

在父類別定義演算法的骨架（步驟），但把部分步驟留給子類別實作。Abstract Class 天然支援這個模式：具體方法定義「什麼時候」呼叫，抽象方法讓子類別決定「怎麼」實作。

可以在 abstract class 裡用 abstract 修飾 property 嗎？

可以，abstract name: string 讓子類別必須宣告這個屬性。但要注意，抽象屬性沒有值（不能有初始值），子類別需要在 constructor 或直接宣告中提供值。

30 秒版本

「Abstract Class 是不能直接實例化的類別，用途是同時做兩件事：提供子類別可以繼承的共用邏輯（具體方法），以及強制子類別必須自己實作的方法（抽象方法）。它和 interface 的差別是：interface 只定義形狀、沒有實作；abstract class 可以包含實際邏輯、constructor 和存取修飾詞。當多個子類別需要共用部分邏輯但各自有獨特行為時，就用 abstract class。」
