srcset：讓瀏覽器選最合適的圖，不是你來選

srcset 屬性提供多個解析度版本的圖片，讓瀏覽器根據裝置 DPR 和視口寬度自動選擇最合適的版本——節省行動裝置流量，同時讓高 DPI 螢幕清晰顯示。

核心語法

w 描述符 + sizes

<img
  src="/img/photo-800.jpg"  <!-- 備用圖 -->
  srcset="/img/photo-400.jpg 400w,
          /img/photo-800.jpg 800w,
          /img/photo-1200.jpg 1200w"
  sizes="(min-width: 768px) 50vw,
         100vw"
  alt="示範圖"
/>
w 描述符是圖片的實際像素寬度（非 CSS px），配合 sizes 讓瀏覽器計算「這張圖在當前視口下要顯示多大」，再選最合適的版本。
瀏覽器如何計算

選圖公式

瀏覽器計算「圖片實際像素寬度 ÷ 當前 CSS 寬度」，選出比值最接近 DPR 的版本。

ℹ️

範例：視口 320px，sizes="100vw"，DPR=1
400÷320=1.5625 → 最接近 DPR 1 且剛好夠大 → 選 400w（small.jpg）

同樣 320px 視口，但 DPR=2（Retina）
需要比值 ≥ 2 → 400w(1.56)不夠 → 選 800w（3.125，最接近 2）

w 描述符（彈性） 提供圖片實際像素寬，配合 sizes，瀏覽器根據視口和 DPR 綜合選擇
x 描述符（固定尺寸） 直接對應 DPR：icon.png 1x, icon@2x.png 2x，適合固定大小的圖示
延伸追問

面試官可能再追

<picture> 和 srcset 應該怎麼選？

srcset 適合「同一張圖的不同解析度」，讓瀏覽器自動選最省流量的版本。<picture> 適合「Art Direction」——針對不同視口顯示完全不同的圖片（如手機顯示裁切版），或提供 WebP 格式備援 JPEG。

如果不提供 sizes 屬性，瀏覽器怎麼選？

若省略 sizes，瀏覽器預設假設圖片寬度等於視口寬度（100vw），再根據此計算選擇版本。這可能選到不必要的大圖，所以有響應式需求時應明確寫 sizes。

面試這樣答

30 秒版本

「srcset 讓我提供同一圖片的多個解析度版本，瀏覽器自動根據裝置 DPR 和視口寬度選最合適的。搭配 sizes 告訴瀏覽器「這張圖在不同視口下顯示多寬」，瀏覽器就能算出需要幾個像素，再選最接近且不超出的版本。好處是高 DPI 螢幕清晰顯示，行動裝置不必下載桌機大圖，節省流量。這比我手動判斷 DPR 更可靠，因為瀏覽器還會考慮網路狀況等因素。」
