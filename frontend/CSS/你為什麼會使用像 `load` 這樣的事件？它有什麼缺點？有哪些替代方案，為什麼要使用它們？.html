load 等太久了——先用 DOMContentLoaded

load 事件要等圖片、CSS、字體、iframe 全部載入才觸發，DOMContentLoaded 只等 DOM 建好就觸發。大多數初始化邏輯只需要 DOM，不需要等到圖片載完。

關鍵差異

兩個事件的觸發時機

HTML 下載並解析完成 → DOMContentLoaded 觸發（DOM 可用）
圖片、CSS、字體、iframe 等子資源全部載入完成 → load 觸發
// 大多數情況：DOM 建好就夠了
document.addEventListener('DOMContentLoaded', () => {
  // 操作 DOM、初始化元件
});

// 需要等所有資源（如計算圖片尺寸）
window.addEventListener('load', () => {
  // 此時所有 img、iframe、css 都載入完畢
});
選擇原則

何時用哪個？

DOMContentLoaded（大多數場景） DOM 操作、事件綁定、元件初始化、Ajax 請求啟動
load（特定場景） 需要圖片真實尺寸（naturalWidth）、Lightbox 需要計算圖片大小、需要確保所有字體渲染完成
⚠️

如果頁面有大圖或慢速載入的資源，使用 load 初始化 JavaScript 會讓使用者等很久才能互動——這是常見的效能陷阱。

延伸追問

面試官可能再追

defer 腳本和 DOMContentLoaded 有什麼關係？

帶有 defer 屬性的 script 會在 DOM 解析完成後、DOMContentLoaded 觸發前執行。所以如果把初始化邏輯寫在 defer 腳本裡，不需要另外監聽 DOMContentLoaded——腳本執行時 DOM 已就緒。

async 腳本什麼時候執行？

async 腳本下載完就立即執行，不等 DOM 解析完成。如果需要操作 DOM，不要用 async，應用 defer 或放在 </body> 前。async 適合不依賴 DOM 的獨立腳本（如 GA、廣告）。

面試這樣答

30 秒版本

「load 事件要等頁面所有資源（圖片、CSS、iframe）都載入完才觸發，缺點是等待時間長，使用者可能等很久才能互動。大多數 JavaScript 初始化只需要 DOM 就緒，應改用 DOMContentLoaded——HTML 解析完即觸發，不需等子資源。只有需要圖片實際尺寸或確保字體渲染完成等特定場景，才真的需要 load。」
