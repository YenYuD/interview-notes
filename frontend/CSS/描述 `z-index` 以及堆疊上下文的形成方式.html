z-index:9999 還是蓋不過去？

不是數字不夠大——是元素被困在父層的「堆疊上下文」裡。子元素的 z-index 再高，也跳不出父層的層級。

DEMO — 9999 為什麼輸給 2

子元素能爬到別人上面嗎？

紅卡 A（含子元素 C，z-index:9999）和藍卡 B（z-index:2）。切換 A 有沒有自己的堆疊上下文：

A 是否形成堆疊上下文
A (z:1)
C z:9999
B z:2
兩個前提

z-index 生效的條件

  • 元素必須是已定位的（position 不為 static），或是 flex/grid 子項。
  • z-index 只在同一個堆疊上下文內互相比較。跨上下文時，先比父層的層級。
✕

常見雷：給某層加了 opacity、transform 或 filter，它就悄悄形成新的堆疊上下文，導致裡面的 z-index:9999 怎麼調都蓋不出去。

延伸追問

面試官可能再追

哪些屬性會建立新的堆疊上下文？

根元素、position 為 absolute/relative 且有 z-index、position:fixed/sticky、opacity < 1、transform/filter/will-change 不為 none、flex/grid 子項有 z-index 等。

沒設 z-index 時誰在上面？

按 DOM 順序，後出現的蓋在前面的上面；已定位元素一律蓋過 static 元素。

面試這樣答

30 秒版本

「z-index 只對已定位元素有效，而且只在同一個堆疊上下文內比較。一旦父層因為 opacity、transform 等形成了獨立的堆疊上下文，子元素的 z-index 再大也跳不出去——這就是『9999 還蓋不過去』的原因。debug 時我會先找是哪一層意外建立了堆疊上下文。」
