HTML / DOM

data- 屬性：DOM 的自訂資料口袋，現在還有人用嗎？

data-* 屬性讓開發者在 HTML 元素上儲存自訂資料，不污染語意標記。在 JavaScript 框架流行前被廣泛使用，如今最合理的用途是作為測試選擇器。

核心概念

data- 屬性的三種用途

儲存私有資料（過時做法） — 在框架出現前，常用於在 DOM 上掛載頁面私有資料，現在資料應存在 JavaScript 狀態中。
第三方函式庫的觸發器 — Bootstrap 仍使用 data-bs-toggle、data-bs-target 等屬性控制元件行為。
E2E 測試選擇器（現代最佳用途） — 用 data-testid 或 data-cy 標記元素，讓 Playwright/Cypress 穩定選取，不污染 class 或 id 的語意。 
// Bootstrap 用法
<button data-bs-toggle="modal" data-bs-target="#myModal">
  開啟 Modal
</button>

// E2E 測試用法
<button data-testid="submit-btn">送出</button>
// Playwright: await page.getByTestId('submit-btn').click()
注意事項

為什麼不推薦儲存業務資料

⚠️

data- 屬性的值可以被使用者在開發者工具中直接修改，不應存放敏感或影響業務邏輯的資料。業務資料應存在 JavaScript 狀態（React state、Vuex 等），透過虛擬 DOM 或響應式系統同步到 DOM。

延伸追問

面試官可能再追

如何在 JavaScript 中讀取 data- 屬性？

透過 element.dataset API：el.dataset.testid 讀取 data-testid。屬性名稱中的 kebab-case 會自動轉為 camelCase（如 data-user-id → el.dataset.userId）。也可用 el.getAttribute('data-testid')。

data- 屬性可以用 CSS 選取嗎？

可以，用屬性選擇器：[data-active="true"] { color: red; }。這是一種不依賴 class 的條件樣式技巧，常見於元件庫。

面試這樣答

30 秒版本

「data-* 屬性讓我們在 HTML 元素上附加自訂資料而不破壞語意。在框架流行前它常用來在 DOM 上儲存業務資料，但現在不建議這樣做——因為使用者可以輕易在開發者工具中修改它，資料應存在 JS 狀態中。目前我認為最合理的用途是為 E2E 測試（如 Playwright、Cypress）提供穩定的選取點，用 data-testid 標記，不污染 class 或 id 的語意用途。」
