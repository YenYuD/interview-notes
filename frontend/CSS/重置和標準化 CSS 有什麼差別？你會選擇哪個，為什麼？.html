CSS / 基礎設定

Reset 清空一切，Normalize 修正異常——策略不同

CSS Reset 移除所有瀏覽器預設樣式，讓你從零開始；Normalize.css 保留有用的預設值，只修正各瀏覽器之間的不一致。兩者目標都是跨瀏覽器一致性，但出發點截然不同。

核心對比

Reset vs Normalize

CSS ResetNormalize.css
策略清除所有預設樣式保留有用預設，修正異常
適合場景高度客製化設計、不需要任何預設需保留部分語意預設（標題大小、清單縮排等）

如何選擇

決策框架

選 Reset 設計稿非常客製化；不希望任何瀏覽器預設干擾；有完整的設計系統定義所有樣式
選 Normalize 希望保留語意化 HTML 的視覺預設；需要在現有設計上快速修正跨瀏覽器問題；使用 Tailwind 以外的框架
💡

現代專案如果用 Tailwind CSS，其 Preflight（基於 modern-normalize）已內建，不需另外加 reset 或 normalize。

延伸追問

面試官可能再追

CSS Reset 後為什麼連 h1-h6 的大小都一樣了？

Reset 把所有元素的 margin、padding、font-size 都歸零或設為統一值，包含標題元素。你必須在 Reset 之後手動定義所有標題的大小、粗細、間距，這正是 Reset 帶來的「額外工作」。

box-sizing: border-box 和 CSS Reset 有什麼關係？

兩者都是「全域基礎樣式設定」，通常一起寫在專案的 base CSS 或 reset.css 裡。它們不衝突，box-sizing: border-box 改變盒模型計算，reset/normalize 處理跨瀏覽器一致性，現代 reset 通常都包含 box-sizing: border-box。

30 秒版本

「CSS Reset 把所有瀏覽器預設樣式清零，讓我們從空白畫布開始；Normalize.css 則是保留有用的預設、只修正各瀏覽器之間的差異。選擇取決於專案需求：設計高度客製化、不需要任何預設時選 Reset；希望保留語意 HTML 的視覺預設、只修正瀏覽器差異時選 Normalize。現代我多用 Tailwind 的 Preflight，或 modern-normalize，比老式 Reset 更現代、副作用更少。」
