CSS / 響應式設計

響應式是目標，行動優先是撰寫策略

響應式設計讓網站在不同裝置都能正常顯示；行動優先（Mobile First）是撰寫媒體查詢的策略——先定義行動端樣式，再用 min-width 往上覆蓋。兩者互補，不互斥。

核心差異

桌機優先 vs 行動優先的寫法差異

桌機優先（Desktop First） 先寫桌機樣式，用 max-width 針對小螢幕覆蓋——行動端需要「撤銷」許多桌機樣式
行動優先（Mobile First） 先寫行動端樣式作為預設，用 min-width 往上「增加」桌機功能——更乾淨 
/* 行動優先：預設是行動端樣式 */
.title {
  font-size: 1.2rem;  /* 行動端預設 */
}

@media (min-width: 768px) {
  .title {
    font-size: 2rem;  /* 平板/桌機覆蓋 */
  }
}
優點分析

為什麼行動優先更好

維度行動優先桌機優先
行動效能行動端只解析需要的 CSS，不觸發多餘媒體查詢行動端需要解析桌機 CSS 再被覆蓋
可用性降級無論視口多大，基礎內容都可用小視口可能遺漏重要功能
CSS 複雜度往上「加功能」，邏輯清晰往下「撤銷功能」，容易出現殘留樣式
延伸追問

面試官可能再追

行動優先的缺點是什麼？

如果網站確實以桌機為主要使用場景（如複雜的企業管理工具），強制從行動端思考可能讓設計更複雜。此外，部分桌機功能（如 hover 效果、多欄版面）難以用「漸進增加」的方式表達。在確定主要使用場景是桌機時，桌機優先可能更直觀。

面試這樣答

30 秒版本

「響應式設計是目標——網站在各種裝置上都能正常顯示；行動優先是達成這個目標的撰寫策略——用 min-width 媒體查詢，以行動端樣式為預設，往上疊加桌機功能。相比桌機優先，行動優先的好處是行動端只解析必要的 CSS，效能更好；而且往上「增加」功能比往下「撤銷」更乾淨。現在幾乎所有框架（Tailwind、Bootstrap 4+）都採用行動優先策略。」
