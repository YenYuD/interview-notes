CSS / 頁面效能

資源擺放順序直接影響首次渲染速度

CSS <link> 放 <head> 確保樣式在渲染前就緒，避免無樣式閃爍（FOUC）；JS <script> 放 </body> 前避免阻塞 HTML 解析。搞清楚原理，才能在有快取、有 defer/async 時做出正確判斷。

核心原理

CSS 要盡早，JS 要最後

CSS <link> 放 <head> HTML 解析 DOM 的同時並行下載 CSS 建立 CSSOM；兩者都完成後才渲染，確保首次渲染不閃爍
CSS 放底部的問題 部分瀏覽器阻塞漸進式渲染；或先顯示無樣式內容，再套用樣式——產生 FOUC
JS <script> 放 </body> 前 避免阻塞 HTML 解析；DOM 完整後才執行，不會找不到目標元素
或在 <head> 加 defer defer 讓瀏覽器更早發起下載，同時 DOM 解析完後才執行，空快取更快
script 載入策略

defer vs async vs 放底部

方式下載時機執行時機阻塞 HTML 解析
放 </body> 前HTML 解析完後立即不阻塞（已結束）
defer（放 head）並行下載DOM 解析完後，按順序不阻塞
async並行下載下載完立即執行執行時阻塞
無屬性（放 head）遇到就下載立即執行阻塞！
💡

有快取時，defer 在 <head> 比放 </body> 更快，因為可以更早發起下載請求。現代推薦：主要腳本用 defer，不依賴 DOM 的第三方腳本（GA、廣告）用 async。

延伸追問

面試官可能再追

什麼是 FOUC（無樣式內容閃爍）？

Floating Of Unstyled Content。CSS 未載入前，瀏覽器先以預設樣式渲染 HTML，CSS 載入後瞬間重繪，使用者會看到版面短暫「閃一下」。CSS 放 <head> 可確保 CSSOM 在首次渲染前就緒，避免此問題。

defer 和 async 在模組（type="module"）腳本中的行為？

ES Module（type="module"）預設行為就像 defer——並行下載、DOM 解析完後執行。可以再加 async 使其變成下載完立即執行（適合不依賴 DOM 的模組）。

面試這樣答

30 秒版本

「CSS <link> 放 <head> 是因為瀏覽器需要 DOM + CSSOM 才能渲染，盡早下載 CSS 確保首次渲染時樣式就緒，避免無樣式閃爍（FOUC）。JS 放 </body> 前是因為 script 標籤會阻塞 HTML 解析，放底部讓 DOM 先建完，腳本執行時也能找到所有元素。現代推薦改用 defer 放在 head——可以更早觸發下載，DOM 解析完後才執行，有快取時頁面更快。」
