CSS / 瀏覽器相容

當瀏覽器「跟不上」，你有幾套降落策略？

面對功能受限的舊版瀏覽器，核心策略是優雅降級與漸進增強。搭配功能偵測工具，讓所有使用者都能獲得基本可用的體驗。

核心策略

兩種設計哲學

漸進增強（Progressive Enhancement） 先建構最基礎可用的體驗，瀏覽器支援時再疊加進階功能。由下而上。
優雅降級（Graceful Degradation） 先為現代瀏覽器打造完整功能，再確保舊版瀏覽器有基本可用的版本。由上而下。
💡

漸進增強被認為更健全，因為你從「必定能用」的基礎出發，而不是事後打補丁。

實用工具

四種常見技術

caniuse.com — 查詢 CSS/JS 功能在各瀏覽器的支援率，評估是否需要備用方案。
Autoprefixer — 自動為 CSS 加入 -webkit-、-moz- 等廠商前綴，解決前綴問題。
Modernizr — JavaScript 功能偵測函式庫，根據支援情況在 <html> 加 class，讓 CSS 條件樣式更簡單。
CSS @supports — 原生 CSS 功能查詢，不支援某屬性時可套用備用樣式。 
@supports (display: grid) {
  .layout { display: grid; }
}
/* 不支援 grid 的瀏覽器，此區塊直接跳過 */
延伸追問

面試官可能再追

漸進增強和優雅降級哪個更好？

多數情況下漸進增強更推薦：從最低可用基礎出發，確保所有使用者都有可接受的體驗；現代功能作為「加分項」疊加。優雅降級則常見於改版既有系統或需要快速支援新功能時。

@supports 和 Modernizr 如何選擇？

@supports 是原生 CSS，針對 CSS 功能偵測最優先使用，無需額外函式庫。Modernizr 適合需要偵測 JavaScript API（如 WebGL、ServiceWorker）或需要在舊版瀏覽器中使用 CSS class 做條件樣式的情境。

面試這樣答

30 秒版本

「面對功能受限的瀏覽器，我主要採用漸進增強策略——先確保基礎體驗可用，再用 CSS @supports 功能查詢為現代瀏覽器加入進階樣式。建置工具層面，Autoprefixer 自動處理廠商前綴；在評估是否要支援某功能前，我會先查 caniuse.com 確認支援率，再決定是否需要 polyfill 或降級方案。」
