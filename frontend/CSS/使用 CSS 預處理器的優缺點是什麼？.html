CSS / 工具鏈

Sass/Less 帶來了可維護性，但 CSS 原生能力正在追上

CSS 預處理器（Sass、Less、Stylus）用變數、巢狀、Mixin 解決了原生 CSS 的重複與維護問題。但原生 CSS 變數和 CSS Modules 已能替代許多場景，選擇需評估收益與成本。

核心評估

優缺點對照

優點
  • 巢狀選擇器，結構更清晰
  • 變數統一管理主題色彩
  • Mixin 消除重複 CSS
  • 迴圈/映射處理批量樣式
  • 多檔案拆分，建置時合併
缺點
  • 需要額外編譯步驟，增加建置時間
  • Sass 的 node-sass 跨 Node 版本常需重編
  • Less 的 @ 前綴與 CSS @media 等關鍵字容易混淆
  • 可能撰寫「超前」語法，卻非未來原生 CSS
ℹ️

原生 CSS 自訂屬性（CSS Variables） 已能在執行時動態更新（預處理器變數只是靜態替換），且支援 JavaScript 互動，部分場景比 Sass 變數更強大。

延伸追問

面試官可能再追

CSS 變數和 Sass 變數有什麼本質差異？

Sass 變數在編譯時靜態替換，最終輸出的 CSS 中已是固定值。CSS 自訂屬性在執行時存在，可以用 JavaScript 動態修改（el.style.setProperty('--color', 'red')），支援繼承和作用域覆蓋，是真正的動態變數。

PostCSS 和 Sass 有什麼不同？

Sass 是有固定語法的預處理器。PostCSS 是轉換工具鏈，透過外掛（plugin）處理 CSS：可自動加前綴（Autoprefixer）、支援未來語法（postcss-preset-env）、甚至做 CSS Modules。兩者可以並存，PostCSS 更靈活但需自行組合外掛。

30 秒版本

「CSS 預處理器帶來的核心優點是變數、巢狀、Mixin，讓大型 CSS 可維護。缺點是需要編譯步驟，且 Sass 的 node-sass 跨 Node 版本時常需重新建置。現在我會先評估：原生 CSS 變數已能取代 Sass 變數，原生 Nesting 也已普及；複雜的迴圈或設計 token 系統，Sass 還是有價值。新專案我傾向搭配 CSS Modules 或 Tailwind，減少對預處理器的依賴。」
