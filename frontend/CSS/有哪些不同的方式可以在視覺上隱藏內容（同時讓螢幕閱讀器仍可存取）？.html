CSS / 無障礙（a11y）

視覺隱藏不等於無障礙隱藏——要分清楚用哪個

有時需要視覺上隱藏內容，但讓螢幕閱讀器仍能讀到（如圖示的文字說明）。常見的 display:none、visibility:hidden 會同時對螢幕閱讀器隱藏，用錯會造成無障礙問題。

方法比較

各種隱藏方式的無障礙影響

方法視覺隱藏螢幕閱讀器推薦度
display: none✓也隱藏 ✗❌ 若需無障礙不可用
visibility: hidden✓也隱藏 ✗❌ 若需無障礙不可用
hidden 屬性✓也隱藏 ✗❌ 若需無障礙不可用
.sr-only class✓（縮到 1px）可存取 ✓✅ 推薦
position: absolute; left: -99999px✓通常可存取△ 可導覽元素不建議
text-indent: -9999px✓（僅文字）通常可存取△ 只適用 block 文字
最佳實踐

標準的 sr-only class 寫法

/* Tailwind 的 sr-only（業界標準） */
.sr-only {
  position: absolute;
  width: 1px;
  height: 1px;
  padding: 0;
  margin: -1px;
  overflow: hidden;
  clip: rect(0, 0, 0, 0);
  white-space: nowrap;
  border-width: 0;
}

/* 使用範例：圖示按鈕的螢幕閱讀器文字 */
<button>
  <svg aria-hidden="true">...</svg>
  <span class="sr-only">關閉對話框</span>
</button>
💡

直接使用 Tailwind 的 sr-only class 或 Bootstrap 的 visually-hidden，這些都是經過實戰驗證的實作，不需要自己手寫。

延伸追問

面試官可能再追

aria-hidden 和 sr-only 有什麼差別？

aria-hidden="true" 從無障礙樹中移除元素，螢幕閱讀器看不到，但視覺上仍顯示（適合裝飾性圖示）。.sr-only 視覺隱藏但無障礙樹可存取（適合補充說明文字）。兩者方向相反，根據需求選擇。

focus-visible 和 sr-only 可以怎麼搭配？

Bootstrap 的 visually-hidden-focusable class：元素平時用 sr-only 隱藏，但當獲得鍵盤 focus 時變為可見（:focus-within）。常見用途是「跳至主要內容」的 skip link，供鍵盤使用者快速跳過導覽列。

面試這樣答

30 秒版本

「要視覺隱藏但讓螢幕閱讀器仍能存取，不能用 display:none 或 visibility:hidden，因為這兩者也會對螢幕閱讀器隱藏。標準做法是 .sr-only class——把元素縮到 1px、clip 裁切、加負 margin，視覺上不可見但仍在無障礙樹中。我直接用 Tailwind 的 sr-only 或 Bootstrap 的 visually-hidden，這些都是經過實戰驗證的實作。典型用途是圖示按鈕加文字說明，讓螢幕閱讀器知道按鈕的用途。」
