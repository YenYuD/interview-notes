CSS / 盒模型

一行全域宣告，消滅尺寸計算地獄

* { box-sizing: border-box; } 讓元素的 width/height 包含 padding 和 border，所見即所得。這是現代 CSS 的標準起手式，幾乎所有框架都預設採用。

核心差異

content-box vs border-box

計入尺寸的項目content-box（預設）border-box
Content✓✓
Padding✗（額外增加）✓（包含在內）
Border✗（額外增加）✓（包含在內）
Margin✗✗
實例：設 width: 100px; padding: 10px; border: 5px
content-box → 實際寬 130px（100 + 20 + 10）
border-box → 實際寬 100px，content 縮為 70px
最佳實踐

推薦的全域寫法

html {
  box-sizing: border-box;
}
*,
*::before,
*::after {
  box-sizing: inherit; /* 允許特定元素覆蓋為 content-box */
}
💡

Bootstrap 4+、Tailwind CSS 等主流框架都預設使用 border-box。在響應式版面中，它能防止 padding/border 導致元素溢出容器。

延伸追問

面試官可能再追

border-box 的 content 大小如何計算？

content 寬度 = 設定的 width − 左 padding − 右 padding − 左 border − 右 border。如果 padding + border 已超過設定的 width，content 會縮為 0（不會為負值）。

什麼情況下仍要用 content-box？

需要 content 本身有精確尺寸時（如 canvas、某些圖片展示）；或整合未使用 border-box 的第三方元件時，可能需要局部覆蓋。

margin 不論哪種 box-sizing 都不計入寬高，為什麼？

margin 是元素「外部空間」，不屬於盒子本身的尺寸，它影響的是元素與相鄰元素的間距，兩種 box-sizing 模型均不將 margin 納入 width/height 計算。

面試這樣答

30 秒版本

「* { box-sizing: border-box; } 將元素的 padding 和 border 納入 width/height 計算，而不是額外增加尺寸。這讓設定 width: 100% 的元素即使加了 padding 也不會溢出容器，版面更好預測。預設的 content-box 只計算 content，加了 padding 和 border 後實際尺寸會超出設定值，容易引發版面問題。現代框架都預設 border-box，在專案初始就全域套用是標準做法。」
