HTML / 國際化

多語言頁面的技術基礎：Accept-Language、lang 屬性、hreflang

提供多語言頁面是國際化（i18n）的核心。瀏覽器透過 Accept-Language 標頭傳遞語言偏好；HTML 需宣告 lang 屬性；搜尋引擎則靠 hreflang 連結找到各語言版本。

技術實作

三個必要元素

Accept-Language 標頭 瀏覽器發送 HTTP 請求時自動帶上使用者語言偏好，伺服器依此回傳對應語言版本
<html lang="zh-Hant"> 在 HTML 標籤宣告語言，螢幕閱讀器和搜尋引擎需要此資訊
hreflang 連結 告訴搜尋引擎各語言版本的 URL： 
<link rel="alternate" hreflang="en" href="https://example.com/en" />
<link rel="alternate" hreflang="zh-TW" href="https://example.com/zh-tw" />
<link rel="alternate" hreflang="x-default" href="https://example.com/" />
渲染方式

伺服器端 vs 客戶端渲染

伺服器端渲染（SSR） HTML 中放字串佔位符，伺服器根據語言替換後輸出完整 HTML；SEO 效果好
客戶端渲染（CSR） JavaScript 初始化時載入對應語系的翻譯 JSON，動態替換 UI 字串；React-i18next、Vue-i18n 等框架支援
延伸追問

面試官可能再追

Accept-Language 標頭可靠嗎？

不完全可靠。使用 VPN 或瀏覽器語言設定不準確時，推測語言可能有誤。因此伺服器可自動偵測後預選語言，但必須提供手動切換語言的選項，不能強制使用者使用偵測到的語言。

URL 中應該包含語言資訊嗎？

推薦包含，常見方式：/en/page（路徑前綴）或 en.example.com（子網域）。這讓使用者可以分享特定語言版本的 URL，搜尋引擎也更容易索引不同語言版本。

面試這樣答

30 秒版本

「提供多語言頁面，技術上有幾個要點：瀏覽器的 Accept-Language 標頭傳達使用者語言偏好，伺服器依此回傳對應版本；HTML 需在 <html> 宣告 lang 屬性（如 lang="zh-Hant"），供螢幕閱讀器和 SEO 使用；搜尋引擎需要 hreflang 連結才知道各語言版本的 URL 對應關係。渲染方式上，SSR 由伺服器替換語言字串後輸出 HTML；CSR 則在客戶端用 i18n 函式庫（如 react-i18next）動態替換。」
