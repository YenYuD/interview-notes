CSS / 動畫效能

移動元素時用 translate()，不用 absolute——除非版面真的需要

translate() 移動元素不觸發 reflow，由 GPU 處理，動畫更流暢；absolute 定位改 top/left 會觸發 reflow，讓整個頁面重新計算版面。兩者的使用場景根本不同。

效能關鍵差異

為什麼 translate() 更快

translate()改變 top/left
觸發渲染階段只觸發 Composite（合成）觸發 Reflow → Repaint → Composite
計算單位GPU（合成層）CPU（版面計算）
對其他元素影響不影響（仍佔原空間）影響（元素離開原位）
動畫流暢度60fps 流暢可能掉幀
 
/* 動畫：用 translate，不用 top/left */
.slide-in {
  transform: translateX(-100%);
  transition: transform 0.3s ease;
}
.slide-in.active {
  transform: translateX(0);  /* GPU 合成，流暢 */
}
使用情境

各自適合的場景

用 translate() 動畫效果（滑入滑出、Hover 位移）；不需改變文件流；效能優先場景
用 absolute 定位 元素需要脫離文件流（如 tooltip、dropdown、modal）；定位相對於某個容器；靜態位置不需動畫
補充：translate() 移動後元素「仍佔原始空間」，周圍元素不受影響（類似 position: relative）。absolute 則讓元素完全脫離文件流。
延伸追問

面試官可能再追

什麼時候用 will-change: transform？

在動畫開始前告知瀏覽器提前建立合成層，讓動畫更流暢。但不要過早或過廣設置——過多合成層消耗大量記憶體，只在確認有效能問題的元素上用。動畫結束後可移除 will-change。

translate() 和 translateZ(0) 的 GPU 加速有什麼關係？

設置 transform: translateZ(0) 是老式「hack」，強制建立 GPU 合成層。現代瀏覽器只要設置任何 transform 就會建立合成層，不需要這個 hack。直接用 translate() 即可，或用 will-change: transform 更語意清晰。

面試這樣答

30 秒版本

「用 translate() 移動元素只觸發 Composite（GPU 合成），不影響文件流，動畫可以跑在 GPU 上保持 60fps 流暢；改變 top/left 則觸發 Reflow，整個頁面版面需要重新計算，效能差很多。所以動畫效果和位移一律用 transform: translate()。反之，元素需要脫離文件流（tooltip、modal、dropdown）才用 absolute 定位，這是版面的考量而不是動畫。」
