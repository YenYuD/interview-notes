Sass 和 Less 的真實痛點——用過才知道

CSS 預處理器帶來了真實的開發效率提升，但也有令人頭疼的相依性問題。這題考的是你有沒有真正用過、有沒有獨立的技術判斷。

喜歡的部分

主要價值點

Sass 優點
  • 巢狀選擇器讓 BEM 結構可讀性高
  • @mixin / @include 消除大量重複 CSS
  • @each、@for 批量生成樣式
  • 模組化 @use、@forward 管理設計 token
Less 優點 以 JavaScript 撰寫，與 Node.js 生態配合良好，可在瀏覽器端直接編譯
不滿的部分

真實踩過的雷

⚠️

Sass + node-sass：node-sass 是 C++ 綁定套件，每次切換 Node.js 版本就需要重新 npm rebuild，在 CI/CD 環境中特別痛苦。建議改用純 JavaScript 實作的 Dart Sass（即現在官方推薦的 sass 套件）。

⚠️

Less 的 @ 前綴：Less 變數用 @my-color，但 @media、@import、@keyframes 也用 @，容易造成視覺混淆，也讓工具分析更複雜。

延伸追問

面試官可能再追

node-sass 和 sass（Dart Sass）有什麼差別？

node-sass 是 LibSass（C++）的 Node 綁定，速度快但維護已停止，且跨平台建置問題多。sass 是官方 Dart Sass 的 Node 實作，純 JS 安裝簡單、支援最新語法（@use、@forward），是現在推薦的選擇。

Sass 的 @import 和 @use 有什麼差別？

@import（舊版）全域匯入，所有變數/mixin 進入全域作用域，容易名稱衝突，已被棄用。@use（新版）有命名空間，使用時需加前綴（如 vars.$primary），避免污染，是現在的標準寫法。

面試這樣答

30 秒版本

「我主要用過 Sass。喜歡的是巢狀結構配合 BEM 可讀性很高，Mixin 消除重複，@each 批量生成 utility class 很方便。最大的痛點是 node-sass 的跨 Node 版本問題——每次升級 Node 就要重新建置，CI 上特別麻煩；現在我改用 Dart Sass（npm install sass），純 JS 安裝，完全沒有這個問題。」
