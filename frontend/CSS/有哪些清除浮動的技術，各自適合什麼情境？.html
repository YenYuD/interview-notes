浮動元素讓父容器高度塌陷——三種清除技術各有適用場景

float 元素不被父容器計入高度，導致「高度塌陷」問題。有三種清除方法，各有取捨；現代開發更好的解法是直接改用 Flexbox 或 Grid，從根本避免問題。

三種技術

清除浮動的方法比較

方法寫法適用情境缺點
空 div 法 <div style="clear:both"></div> 快速修復，不想動 CSS 污染 HTML，增加無語意標記
Clearfix（::after） 見下方程式碼 大型專案，可複用的 utility class 需要加 class，不影響 HTML 結構
overflow: hidden 父元素加 overflow: hidden/auto 快速、無需額外 class 子元素若超出父元素邊界會被裁切 
/* Clearfix：推薦方式 */
.clearfix::after {
  content: '';
  display: block;
  clear: both;
}
ℹ️

overflow: hidden/auto 能清除浮動的原因：它建立了新的區塊格式化上下文（BFC），BFC 會包含其浮動子元素。

現代建議

最好的清除浮動就是不用 float

💡

在現代專案中，用 Flexbox 或 Grid 替換 float 版面，不會有高度塌陷問題，也不需要 clearfix。float 保留給「文字環繞圖片」這個真正需要它的場景。

延伸追問

面試官可能再追

為什麼 overflow: hidden 能清除浮動？

設置 overflow: hidden（或 auto、scroll）會讓父元素建立新的區塊格式化上下文（BFC）。根據 BFC 規範，BFC 容器必須包含其內部的浮動元素，因此父容器的高度會展開以包住浮動子元素。

現代瀏覽器支援 display: flow-root 嗎？

display: flow-root 是現代建立 BFC 的正確方式，不像 overflow: hidden 有裁切副作用，語意也更清晰。現代瀏覽器支援良好，但在需要支援較舊瀏覽器時需要確認。

面試這樣答

30 秒版本

「清除浮動主要有三種方法：空 div（污染 HTML，不推薦）、Clearfix（在父元素加 ::after { clear: both }，適合可複用場景）、overflow: hidden（建立新 BFC，快速但子元素會被裁切）。不過在現代專案中，最好的解法是改用 Flexbox 或 Grid，根本不需要 float 排版，也就不存在高度塌陷問題。float 現在只保留給「文字環繞圖片」這種特定場景。」
