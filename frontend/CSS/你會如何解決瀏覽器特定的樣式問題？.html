CSS / 跨瀏覽器

瀏覽器特定 CSS 問題的系統化解法

遇到瀏覽器特定樣式問題，解法有從治本到治標的多個層次：優先選擇工具自動處理，再考慮框架/重置，最後才用針對性 hack。

解決策略

由通用到針對性的解法

Autoprefixer（建置工具層） 自動加入 -webkit-、-moz- 等廠商前綴，不需要手動追蹤各屬性的前綴需求
Normalize.css / CSS Reset（基礎樣式層） 消除瀏覽器預設樣式差異，是最廣泛的防範手段
Bootstrap 等框架 已在內部處理大量跨瀏覽器問題，使用框架可直接繼承這些修正
PostCSS + 轉換外掛 使用現代 CSS 語法，PostCSS 自動轉換為各目標瀏覽器的相容語法
瀏覽器特定樣式表（最後手段） 確認問題所在瀏覽器後，用伺服器端渲染針對該瀏覽器載入特定樣式表
現代工作流

建置工具層自動化

/* 你寫的 CSS */
.box {
  display: flex;
  user-select: none;
}

/* Autoprefixer 輸出 */
.box {
  display: -webkit-flex;
  display: flex;
  -webkit-user-select: none;
  user-select: none;
}
💡

現代工作流配合 .browserslistrc 或 package.json 的 "browserslist" 設定，Autoprefixer 和 Babel 都會根據目標瀏覽器範圍自動決定需要哪些轉換，不需要手動管理。

延伸追問

面試官可能再追

如何確認是哪個瀏覽器的問題？

1. 在各瀏覽器開發者工具中比較元素的計算樣式（Computed Styles）；2. 用 BrowserStack 或 LambdaTest 做跨瀏覽器測試；3. 查 caniuse.com 確認該屬性在問題瀏覽器的支援狀況；4. 搜尋「CSS 屬性名 + 瀏覽器名 + bug」通常能找到已知問題。

面試這樣答

30 秒版本

「解決瀏覽器特定樣式問題，我會先從通用工具開始：Autoprefixer 自動加廠商前綴、Normalize.css 消除預設樣式差異，這兩層能防範大多數常見問題。已知問題可以查 caniuse.com 確認支援情況，再決定是否需要 polyfill 或備用寫法。必要時用 CSS @supports 功能查詢做條件樣式，比 UA 偵測可靠。只有在非常特殊的瀏覽器專屬 bug 時，才考慮針對性樣式表。」
