HTML / 國際化

多語言網站的陷阱比你想的多得多

多語言網站（i18n）不只是翻譯文字。文字長度差異、閱讀方向、日期格式、文字不能放圖片——每一項都是實際踩過才知道的坑。

技術實作

SEO 與語言宣告

<html lang="zh-TW"> — 宣告頁面語言，影響螢幕閱讀器和搜尋引擎
URL 包含語系（/en-us/page 或 en.example.com）
<link rel="alternate" hreflang="..."> — 告知搜尋引擎各語言版本 URL
hreflang="x-default" — 指定無法匹配語言時的備用頁面
設計踩坑

翻譯後版面常出的問題

問題說明解法
文字長度差異德語/法語比英語長 20-40%，按鈕、標籤可能超出避免固定寬度，用 min-width + padding
閱讀方向（RTL）阿拉伯語、希伯來語從右到左書寫用 dir="rtl" 和 CSS logical properties
字串串接"The date is " + date 在不同語言語順不同使用 i18n 翻譯函式 t('date_msg', {date})
文字放圖片每種語言需要不同版本的圖片改用 CSS 疊加文字，或純文字排版
日期/貨幣格式美式 May 31, 2024 vs 歐式 31 May 2024用 Intl.DateTimeFormat 依語系格式化
進階注意

語系 vs 語言的差異

ℹ️

注意區分語言（language）和語系（locale）：同一種語言在不同國家有差異。en-US（美式英語）和 en-GB（英式英語）拼法不同；zh-TW（繁體中文）和 zh-CN（簡體中文）字形完全不同，不能混用。

延伸追問

面試官可能再追

CSS Logical Properties 是什麼？為什麼 RTL 需要它？

傳統 CSS 用 margin-left、padding-right 等方向性屬性，RTL 語言時需要寫大量覆蓋。CSS Logical Properties（如 margin-inline-start、padding-block-end）用邏輯方向（block/inline）而非物理方向，自動隨 dir 屬性切換，讓 LTR/RTL 共用一套 CSS。

面試這樣答

30 秒版本

「多語言網站有幾個容易踩的坑：首先是文字長度差異——德文比英文長很多，按鈕、標籤要避免固定寬度；其次是不要串接翻譯字串（語順不同的語言會出錯），要用帶參數的翻譯函式；閱讀方向（RTL）要用 dir="rtl" 和 CSS Logical Properties；日期、貨幣要用 Intl API 依語系格式化；文字絕對不能放在點陣圖裡。SEO 面要設 hreflang，lang 屬性也要正確設定。」
