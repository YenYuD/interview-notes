CSS / 版面設計

一顆球還是換一顆球——響應式與自適應的本質差異

響應式設計（Responsive Design）是彈性流動的：同一套版面根據視口大小連續變化。自適應設計（Adaptive Design）則是針對特定斷點偵測裝置，切換預先定義的版型。

核心對比

兩種策略的本質差異

響應式設計自適應設計
核心思路流動版面，連續變形偵測裝置，切換固定版型
主要技術媒體查詢、彈性格線、響應式圖片User-Agent 偵測、DPI 偵測
維護成本一套程式碼多套版型（通常 3-6 組）
偵測可靠性高（純 CSS 寬度判斷）較低（UA/DPI 可能偽造或不準）
設計挑戰斷點策略難以抉擇新裝置尺寸出現時需更新版型
類比：響應式像是一顆橡皮球，能通過任何大小的圈；自適應像是根據圈環大小更換不同的球。
選擇指南

什麼時候用哪個？

響應式（現代首選） 新專案、內容型網站、需長期維護、團隊熟悉 CSS Flexbox/Grid
自適應（適合特殊情境） 桌機與行動功能差異極大、需針對特定裝置深度優化的 Web App
⚠️

自適應設計依賴 UA 偵測，而 UA 字串可被偽造且解析困難；現代開發通常優先選擇響應式。

延伸追問

面試官可能再追

行動優先（Mobile First）和響應式設計是同一回事嗎？

不完全是。行動優先是一種撰寫媒體查詢的策略——先寫行動端樣式作為預設，再用 min-width 媒體查詢覆蓋桌機樣式。響應式設計是更廣的概念，可以用行動優先也可以用桌機優先寫法。現代推薦採用行動優先的響應式設計。

響應式設計如何設定斷點？

有兩派：一是用標準斷點（如 Bootstrap 的 576/768/992/1200px）；二是依版面自然斷裂點決定（版面「撐壞」時才加斷點）。後者更優雅，不依賴特定裝置尺寸。

面試這樣答

30 秒版本

「響應式設計用媒體查詢與流動格線讓同一套版面在任意視口下連續調整，一套程式碼通吃所有裝置。自適應設計則是偵測裝置類型後切換預先定義的版型，維護多套但各版型可深度優化。現代專案我會優先選響應式搭配行動優先策略，UA 偵測不可靠且維護成本高，不推薦。」
