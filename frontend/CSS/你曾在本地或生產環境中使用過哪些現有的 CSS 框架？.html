不只說「用過」——說出優缺點與取捨才有說服力

CSS 框架面試題考的不是你用過哪些，而是你有沒有獨立的技術判斷——能評估框架的取捨、知道什麼情境適合哪個工具。

主流框架評比

三大框架的真實問題

框架優點痛點
Bootstrap 生態成熟、元件豐富、跨瀏覽器已處理好 版本更新慢（v4 alpha 拖了近 2 年）；未客製化時視覺辨識度高，看起來「很 Bootstrap」
Tailwind CSS Utility-first 極度靈活；JIT 模式按需產出 CSS 體積極小；設計系統化 初期學習曲線；HTML class 繁多，可讀性見仁見智；需要建置工具
Semantic UI / Bulma 語意化 class 名稱直觀 Semantic UI 主題系統複雜難以自訂；Bulma 不向下相容，升版常悄悄 breaking change
選擇框架

什麼情境選什麼

Tailwind（現代首選） 新專案、有設計系統需求、React/Vue 等元件架構、需要高度客製化視覺
Bootstrap（成熟穩健） 企業內部工具、需要豐富現成元件（modal、datepicker）、團隊不熟悉 Utility-first
不用框架 設計師主導、設計稿完全獨特、或已有內部設計系統
延伸追問

面試官可能再追

Tailwind 的「Utility-first」和傳統語意化 class 哪個更好？

各有權衡。Utility-first 讓樣式和 HTML 結合，避免了 CSS 命名和特異性問題，元件本地化也更好維護；但 class 繁多影響可讀性，且需要抽取元件來複用。語意化 class（.btn、.card）直觀但容易導致 CSS 全域污染、特異性衝突。大型專案用 Tailwind + 元件化通常是好選擇。

面試這樣答

30 秒版本

「我主要用過 Bootstrap 和 Tailwind。Bootstrap 元件豐富、生態成熟，但視覺客製化困難，不同專案看起來很相似。Tailwind 的 Utility-first 非常靈活，JIT 模式讓 CSS 體積極小，設計系統化也做得好；缺點是 HTML class 繁多，需要習慣。現在新專案我優先選 Tailwind，有豐富預製元件需求的企業工具才考慮 Bootstrap。能說出框架的具體取捨比只說「用過」更重要。」
