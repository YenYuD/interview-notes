MODULE & BUILD

打包前先搖一搖，沒用到的程式碼自動掉

Tree Shaking 是打包工具的靜態分析魔法：只保留真正被 import 的程式碼，讓最終 bundle 瘦身、瀏覽器少解析、使用者少等待。

核心概念

「搖樹」到底搖什麼？

想像程式碼是一棵樹，根節點是你的 main.js，枝葉是各模組匯出的函式與變數。Tree Shaking 沿著 import 依賴圖追蹤，凡是沒有從根節點可達的枝葉一律剪掉，最終產出的 bundle 只含被用到的節點。

⚠️

必要條件：ES 模組語法。CommonJS 的 require() 是執行時動態決定，無法靜態分析，打包工具看不出哪些匯出真的被用到。ESM 的 import/export 是頂層靜態宣告，讓編譯期分析成為可能。

// utils.js — 匯出兩個函式
export function add(a, b) { return a + b; }
export function subtract(a, b) { return a - b; }

// main.js — 只用了 add
import { add } from './utils';
console.log(add(2, 3));

Webpack / Rollup 在生產模式下分析後，subtract 從未被引用，因此不會出現在 bundle 中。

生效條件

三件事都對，才能搖起來

1

使用 ES 模組語法

以 import / export 撰寫；CommonJS require() 無法靜態分析。

2

打包工具支援 Tree Shaking

Webpack 設 mode: 'production'；Rollup 預設啟用；Vite 底層用 Rollup。

3

標記無副作用（sideEffects）

在 package.json 加 "sideEffects": false，告訴打包器整個套件都可安全搖。有副作用的檔案（如 polyfill）需列出排除。

💡

Vite 使用者：開發模式用原生 ESM 不打包，生產模式自動用 Rollup Tree Shaking，幾乎零設定。

延伸追問

面試官可能再追

為什麼 CommonJS 不支援 Tree Shaking？

require() 是函式呼叫，可在任何地方執行（條件、迴圈、動態字串路徑），打包器在編譯時不知道最終會載入哪個模組，無法靜態推斷哪些匯出用到了。ESM 的 import 只能放頂層，路徑必須是字串常數，讓靜態分析成為可能。

sideEffects: false 設錯了會怎樣？

若有副作用的模組（如「直接修改全域、注入 polyfill」的 CSS / JS）被標記 false，打包器可能把它們也搖掉，造成 polyfill 消失或全域樣式不見等執行時 bug。應在陣列中列出有副作用的檔案路徑，或保守地不設此欄位。

動態 import() 能被 Tree Shaking 嗎？

動態 import() 產生的 chunk 本身會被單獨打包，chunk 內部仍可 Tree Shaking；但動態路徑（import(variable)）無法分析，整個可能的模組都會被保留。
