MODULE & BUILD

export 與 import：模組進出的所有姿勢

命名匯出、預設匯出、命名空間匯入、動態 import——每種寫法都有適合的場景，一次搞懂全部組合才不會在 code review 卡關。

匯出方式

命名匯出 vs 預設匯出

命名匯出可多個，用 { }
預設匯出每模組一個，不用 { }
// ── 命名匯出（Named Export） ──
export const PI = 3.14;
export function add(a, b) { return a + b; }
export class Calculator { /* … */ }

// 也可以一次打包匯出
export { PI, add, Calculator };

// ── 預設匯出（Default Export） ──
export default function greet(name) {
  return `Hello, ${name}!`;
}
匯入方式

四種匯入組合

// 1. 匯入命名匯出
import { add, PI } from './math';

// 2. 匯入並重新命名
import { add as sum } from './math';

// 3. 匯入預設匯出（名稱自訂）
import greet from './greeting';

// 4. 匯入全部（命名空間）
import * as Math from './math';
Math.add(1, 2); // 2
⚠️

命名空間匯入（import *）會破壞 Tree Shaking：打包器無法確定你實際用了哪些匯出，傾向保留全部。除非需要動態存取，否則建議明確列出需要的項目。

動態匯入

import() — 用到才載入

靜態 import 必須在頂層，動態 import() 回傳 Promise，可在條件判斷或事件觸發時才載入，是 Code Splitting 的基礎。

// 按需載入（Code Splitting）
async function loadChart() {
  const { Chart } = await import('./chart');
  return new Chart();
}

// React lazy 底層就是這樣運作
const HeavyComponent = React.lazy(
  () => import('./HeavyComponent')
);
延伸追問

面試官可能再追

預設匯出和命名匯出各自適合什麼場景？

預設匯出適合「這個模組就是一個主要東西」的情境，如 React 元件檔案（一個檔案一個元件）。命名匯出適合工具函式庫、常數集合等「一個模組多個相關功能」的情境，而且對 Tree Shaking 更友善。

import 能在條件式裡用嗎？

靜態 import 只能在模組頂層，不能放在 if、函式或迴圈裡。若需要條件載入，使用動態 import()，它回傳 Promise，可搭配 async/await 使用。

面試這樣答

30 秒版本

「ESM 有兩種匯出：命名匯出可以多個，用 { } 匯入，對 Tree Shaking 友善；預設匯出每個模組只能有一個，匯入時可自訂名稱。此外還有動態 import()，回傳 Promise，可在用到時才載入，是打包器做 Code Splitting 的基礎，React.lazy 就是這樣實作的。實務上我盡量用命名匯出，除非是 React 元件這類一檔一主體的場景才用預設匯出。」
