MODULE & BUILD

Webpack、Rollup、Vite——打包工具幫你做了哪些苦工？

從依賴管理到效能優化，模組打包工具把散落的 JS/CSS/圖片整合成瀏覽器最愛的輸出格式，讓現代前端開發成為可能。

核心優點

打包工具解決了什麼問題

1

依賴管理

分析 import 依賴圖，自動解析模組順序，不用手動管理 <script> 載入順序。

2

效能優化 — 減少 HTTP 請求

把數百個 JS 模組合併成少數幾個 bundle，大幅減少瀏覽器發出的請求數（HTTP/1.1 下尤其重要）。

3

Code Splitting — 按需載入

把程式碼拆成多個 chunk，使用者訪問哪個路由才下載對應 chunk，縮短首屏時間。

4

Tree Shaking — 剔除死碼

靜態分析移除未使用的匯出，bundle 只含實際需要的程式碼。

5

資產處理

CSS、圖片、字型都可以透過 import 引入，打包器統一處理壓縮、hash 命名、CDN 上傳。

工具比較

Webpack vs Rollup vs Vite

工具定位亮點適合場景
Webpack 全能型打包器 生態最豐富、Loader/Plugin 最多 大型複雜應用、舊專案
Rollup 函式庫打包器 Tree Shaking 最佳、輸出乾淨 發布 npm 套件
Vite 開發優先工具 開發用原生 ESM（無打包）、生產用 Rollup 現代應用開發首選
esbuild 極速 transpiler Go 寫成，比 JS 工具快 10-100x Vite 底層、CI 快速建置
💡

熱模組替換（HMR）：Vite 開發模式只更新改動的模組，不重新整理整頁，配合 React Fast Refresh 能在保留元件狀態下即時看到修改結果。

延伸追問

面試官可能再追

Code Splitting 的策略有哪些？

主要三種：路由分割（每個頁面一個 chunk，React.lazy + Suspense）；元件分割（按需載入的大元件或功能模組）；廠商分割（vendor split）（將 node_modules 抽成獨立 chunk，利用瀏覽器快取——業務代碼常改但 vendor 較穩定）。

為什麼 Vite 開發模式比 Webpack 快那麼多？

Webpack 開發時仍需將所有模組打包成一個 bundle，每次修改都重新打包（即便有快取）。Vite 開發時利用瀏覽器原生 ESM，只在請求時才即時轉換被請求的模組（按需編譯），配合 esbuild 的極速轉換，啟動和 HMR 速度不受專案規模影響。
