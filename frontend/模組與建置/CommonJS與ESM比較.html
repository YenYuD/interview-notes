require 還是 import？兩套模組系統一次搞清楚

CommonJS 是 Node.js 的歷史遺產，同步、動態；ESM 是官方標準，靜態、可 Tree Shaking。知道差異才能在面試與實務中做對選擇。

一張表看懂關鍵差異

特性 CommonJS (CJS) ES Modules (ESM)
語法 require() / module.exports import / export
載入方式 同步（阻塞執行） 非同步（非阻塞）
分析時機 執行時（動態） 編譯時（靜態）
Tree Shaking ❌ 不支援 ✅ 支援
瀏覽器原生支援 ❌ 需打包 ✅ 現代瀏覽器直接支援
Node.js 支援 ✅ 預設（.js） ✅ 需 .mjs 或 "type":"module"
語法比較

寫法長什麼樣？

CommonJS動態 · 同步
ESM靜態 · 可搖樹
// ── CommonJS ──
const dep = require('./dep');
module.exports = { doSomething };

// ── ES Modules ──
import dep from './dep';
export function doSomething() { /* … */ }
動態 require 的副作用：因為 require(variable) 合法，打包工具無法在編譯時確定哪些模組會被載入，所以 CommonJS 無法做 Tree Shaking。

延伸追問

面試官可能再追

ESM 與 CJS 能混用嗎？

可以，但有限制。在 ESM 中可用動態 import() 載入 CJS 模組；但 CJS 的 require() 無法直接載入 ESM（因為 ESM 是非同步的）。打包工具通常會自動處理互操作（interop），但直接在 Node.js 裡混用需要注意副檔名與 type 設定。

Node.js 怎麼判斷要用哪種模組系統？

副檔名 .cjs 強制 CommonJS；.mjs 強制 ESM；.js 則看最近的 package.json 中 "type" 欄位——"module" 為 ESM，"commonjs"（預設）為 CJS。

面試這樣答

30 秒版本

「CommonJS 用 require / module.exports，是 Node.js 的歷史預設，同步載入、執行時動態分析，所以無法 Tree Shaking。ESM 用 import / export，是 ES2015 的官方標準，靜態結構讓打包器在編譯時就能移除未使用的程式碼。現代新專案我會優先選 ESM；若要發布 npm 套件，則在 package.json exports 欄位同時提供 CJS 與 ESM 雙入口，相容舊環境。」
