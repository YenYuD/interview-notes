MODULE & BUILD

同樣是模組，CJS 與 ESM 骨子裡差在哪？

不只是語法不同——兩者在載入時機、綁定方式、與打包器的關係上有根本差異，這些細節決定了你選擇模組系統的理由。

本質差異

值的拷貝 vs 活的綁定

這是最常被忽略的差異：CommonJS 匯出的是值的快照（拷貝），匯出後若原模組修改，引用端不會更新。ESM 匯出的是活綁定（live binding），原模組的值改變，所有引用者都會看到最新值。

// CJS — 匯出值的拷貝
let count = 0;
module.exports = { count, increment: () => count++ };
// 引用端 counter.count 永遠是 0（拷貝時的值）

// ESM — 活綁定
export let count = 0;
export const increment = () => count++;
// import { count } 會隨 increment() 更新
載入機制

同步執行 vs 三階段解析

CJS 執行到 require() 才去載入並執行目標模組，是完全同步阻塞的，適合伺服器端（本地 I/O 快）。

ESM 採三階段處理：

1

Construction（建構）

靜態解析所有 import，建立模組依賴圖，此時還沒執行任何程式碼。

2

Instantiation（實例化）

為每個匯出分配記憶體位置，但尚未賦值（所有值為 undefined）。

3

Evaluation（求值）

實際執行程式碼並填入值。深度優先，依賴模組先執行。

💡

為什麼 ESM 更適合瀏覽器：靜態分析讓瀏覽器可以並行抓取依賴模組（不用等上一個模組執行完才知道下一個），大幅提升網路利用率。

延伸追問

面試官可能再追

ESM 的頂層 await 是什麼？

ES2022 起，ESM 模組頂層可直接使用 await，不需包在 async 函式裡。CJS 因同步載入機制無法支援此特性。這讓 ESM 非常適合做資料初始化或條件載入。

兩套系統的循環依賴（circular dependency）處理有什麼差異？

CJS 遇到循環依賴時，回傳目前已執行完畢的部分模組物件（不完整），容易導致 undefined 值。ESM 用活綁定，循環依賴在 Instantiation 階段就建立好記憶體位址，Evaluation 完成後自動填值，更能安全處理循環。

面試這樣答

30 秒版本

「CJS 和 ESM 最根本的差別有兩點：一是 載入時機——CJS 是同步執行時載入，ESM 是編譯時靜態分析；二是 匯出的本質——CJS 匯出值的拷貝，ESM 匯出活綁定，原模組改值引用端會同步更新。靜態分析帶來的好處是讓打包器能做 Tree Shaking，而且瀏覽器可以並行下載依賴，不必等序列執行。新專案我會選 ESM，舊 Node.js 系統則視遷移成本決定。」
