MODULE & BUILD

package.json：不只是版本號，是模組的身份證

package.json 裡每個欄位都有意義：name、version、exports、sideEffects……寫對了讓 npm、打包器、IDE 都能正確理解你的套件。

核心欄位

這幾個一定要會

欄位用途範例值
name 套件識別名稱（npm 唯一 ID） "my-utils"
version 語義化版本（semver） "1.2.3"
main CJS 入口點 "./dist/index.cjs"
module ESM 入口點（非官方但廣泛支援） "./dist/index.mjs"
exports 現代多入口設定（優先於 main/module） 見下方
sideEffects 告訴打包器是否可安全 Tree Shaking false 或檔案路徑陣列
進階設定

exports 欄位：同時發布 CJS + ESM

現代套件應在 exports 欄位提供條件式入口，讓 Node.js 和打包器自動選擇正確的模組格式：

{
  "name": "my-utils",
  "version": "1.0.0",
  "exports": {
    ".": {
      "import": "./dist/index.mjs",   // ESM
      "require": "./dist/index.cjs",  // CJS
      "types": "./dist/index.d.ts"   // TypeScript
    }
  },
  "sideEffects": false
}
💡

sideEffects: false 讓打包器知道此套件所有匯出都是「純函式」，未使用的可以安全搖掉。若有 CSS 或會修改全域的 JS，需列出例外："sideEffects": ["./src/styles.css"]。

相依性管理

dependencies vs devDependencies vs peerDependencies

dependencies生產環境必需
devDependencies僅開發時需要
peerDependencies宿主環境提供
peerDependencies 常見於套件開發：宣告「我需要 React 18+，但請宿主專案自己提供」，避免在使用者的 bundle 裡出現多份 React。
延伸追問

面試官可能再追

語義化版本（semver）怎麼解讀 ^1.2.3 和 ~1.2.3？

^1.2.3（caret）：相容最新的 minor 版本，等同 >=1.2.3 <2.0.0，允許 1.3.0、1.99.0，但不允許 2.0.0。~1.2.3（tilde）：只允許 patch 更新，等同 >=1.2.3 <1.3.0，適合對 API 穩定性要求高的場景。

scripts 欄位的 pre/post 鉤子是什麼？

npm 會自動在執行 npm run build 前尋找 prebuild，執行後尋找 postbuild。例如設 "prebuild": "npm run clean"，每次 build 前都自動清除舊產物，無需手動串接指令。

面試這樣答

30 秒版本

「package.json 的核心欄位是 name、version 識別套件身份；exports 定義模組入口，可以同時提供 CJS 和 ESM 讓不同環境自動選擇；sideEffects 告訴打包器是否可做 Tree Shaking。相依性分三類：dependencies 是生產需要的、devDependencies 是開發工具、peerDependencies 是套件開發時宣告宿主環境應自行提供的，避免重複打包。」
