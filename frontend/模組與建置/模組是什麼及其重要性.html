MODULE & BUILD

把程式碼拆成模組，才能駕馭複雜度

模組是 JavaScript 組織程式碼的基本單位：封裝作用域、明確依賴、可重複使用。沒有模組系統，大型應用很快就會變成全域污染的噩夢。

為什麼需要模組

沒有模組的世界長什麼樣？

早期 JavaScript 所有程式碼共享同一個全域作用域：兩個函式庫都叫 utils，後載入的直接覆蓋前一個，bug 難以追蹤。模組透過封閉自己的作用域解決這個問題。

無模組全域污染・依賴隱式
有模組作用域隔離・依賴明確
核心好處

模組帶來的四大收益

好處解決的問題
作用域隔離 模組內的變數不外洩到全域，消滅命名衝突
依賴明確 透過 import 宣告需要什麼，一眼看出依賴關係
可重複使用 同一個模組可在多個專案引用，遵循 DRY 原則
可維護性 改動限縮在模組邊界內，不易影響無關程式碼
基本語法

一個最小的模組範例

// math.js — 只做數學運算，不管外部
export const PI = 3.14159;

export function circle(r) {
  return PI * r * r;
}

// app.js — 明確宣告需要什麼
import { circle } from './math.js';

console.log(circle(5)); // 78.53975
模組是嚴格模式：ESM 模組預設在 strict mode 下執行，不需要寫 "use strict"，也不能用 var 宣告全域變數。
延伸追問

面試官可能再追

模組和 IIFE（立即執行函式）有什麼關係？

ESM 出現前，開發者用 IIFE 模擬模組作用域隔離：(function(){ var private = 1; })();。IIFE 建立了獨立作用域，防止內部變數污染全域。ESM 原生提供更好的機制：每個模組有獨立作用域，而且有明確的 import/export 語義，不需要 IIFE 這個 workaround。

模組的單例（singleton）特性是什麼？

在 ESM 中，同一個模組路徑不管被 import 幾次，只會執行一次，之後都回傳同一份快取。這表示模組天然是「單例」——如果模組裡有個計數器，所有引用它的地方共享同一個值。這在設計全域狀態（如 store）時很重要。
