Web 安全 · Clickjacking

你以為在點「領獎」，其實在點轉帳確認

Clickjacking 把目標網站藏在透明的 iframe 裡，誘使用戶在不知情的情況下點擊。防禦極簡單：一行 header 告訴瀏覽器不准被 iframe 嵌入，就能完全阻斷這類攻擊。

攻擊原理

三步劫持你的點擊

1

建一個惡意網頁

放上「點我領獎」之類的誘餌按鈕。

2

把目標站藏在透明 iframe 裡

opacity: 0 或 z-index 高層疊，讓真正的按鈕（如「確認轉帳」）精準對齊誘餌按鈕。

3

用戶點下去

以為點誘餌，實際觸發了目標站的敏感操作（轉帳、修改設定、刪除帳號）。

防禦方法

Header 二選一（建議並用）

# 方法一：X-Frame-Options（舊，但相容性好）
X-Frame-Options: DENY           # 完全禁止被 iframe 嵌入
X-Frame-Options: SAMEORIGIN     # 只允許同源 iframe

# 方法二：CSP frame-ancestors（新，更彈性）
Content-Security-Policy: frame-ancestors 'none'
Content-Security-Policy: frame-ancestors 'self' https://trusted.example.com
X-Frame-Options: ALLOW-FROM已廢棄，現代瀏覽器不支援
CSP frame-ancestors現代標準，可指定多個允許來源
並用兩者最高相容性：舊瀏覽器吃 X-Frame-Options，新瀏覽器吃 CSP
✅

在 Express.js 可用 Helmet.js（helmet()）一次設好所有安全 header，包含 frameguard（預設 SAMEORIGIN）。

延伸追問

面試官可能再追

JavaScript frame-busting 腳本有用嗎？

曾流行（if(top !== self) top.location = self.location），但攻擊者可在 iframe 上加 sandbox="allow-forms" 禁用 JS 輕鬆繞過。應優先用 header，不要依賴 JS。

電商結帳頁嵌入第三方 iframe，但又要防 Clickjacking，怎麼辦？

用 CSP frame-ancestors 精準白名單允許那個來源，而不是設 DENY。注意不同子頁可設不同 CSP。

面試這樣答

30 秒版本

「Clickjacking 是把目標站藏在透明 iframe 裡騙用戶點擊，防禦是在 response header 設 X-Frame-Options: DENY 或 CSP 的 frame-ancestors 'none'，讓瀏覽器拒絕被 iframe 嵌入。我會兩個並設以兼容舊瀏覽器，用 Helmet.js 的話 frameguard 一行搞定。JS frame-busting 不可靠，不該依賴。」
