密碼、金鑰、Token——不該出現在 client 的東西

前端 JavaScript 是完全公開的代碼。任何寫在前端的密鑰、寫進 localStorage 的 token，攻擊者都能讀到。敏感資料的安全取決於你把它放在哪裡、怎麼傳輸。

四大原則

敏感資料怎麼處理

1

不放前端

API 金鑰、DB 密碼、私鑰 → 只存環境變數（process.env），不進 git，不寫進 bundle。

2

傳輸加密

所有 API 都走 HTTPS。用 Strict-Transport-Security header 強制讓瀏覽器不降級。

3

Cookie 優於 localStorage

token 存 HttpOnly + Secure + SameSite cookie，JS 讀不到，降低 XSS 偷竊風險。

4

最小暴露

Log 不輸出密碼和完整 token；error response 不洩漏 stack trace 和資料庫細節。

程式碼對照

實作細節

// ❌ 危險：API key 寫死在前端
const apiKey = 'sk-live-abc123';  // 任何人都能在 DevTools 看到

// ✅ 安全：金鑰只在 server 端，前端透過自己的 API 呼叫
// server.js
const apiKey = process.env.STRIPE_SECRET_KEY;

// ✅ 設安全 cookie（server side）
res.cookie('session', token, {
  httpOnly: true,
  secure: true,
  sameSite: 'Lax',
  maxAge: 3600 * 1000,
});
⚠

Vite / CRA 的 REACT_APP_ / VITE_ 前綴變數會被打包進前端 bundle，只放可公開的設定（API endpoint、public key）。私密金鑰永遠只在 server 端。

延伸追問

面試官可能再追

前端需要用到第三方 API key（如地圖 API），怎麼辦？

用限制式的 public key（在服務商後台設定只允許特定 domain 呼叫），而不是 secret key。或者把呼叫代理到自己的 server，前端只打自己的 API。

git 不小心 commit 了密鑰怎麼辦？

立刻 rotate（換掉那個金鑰），假設它已洩漏。用 git-secrets、truffleHog 或 GitHub Secret Scanning 設 pre-commit hook 防止重蹈覆轍。

30 秒版本
