Web 安全

使用者輸入被當成程式碼執行

XSS 是攻擊者把惡意腳本注入網頁，在其他使用者的瀏覽器裡執行——偷 cookie、劫持 session、記錄按鍵。根因只有一個：把不可信資料當 HTML/JS 渲染。

三種類型

注入點在哪

類型惡意腳本來源
儲存型 Stored存進資料庫（留言、貼文），每個讀者都中招
反射型 Reflected從 URL／請求參數反射回頁面（釣魚連結）
DOM 型純前端，JS 把不可信資料寫進 DOM
✅

防禦三層：① 輸出跳脫（最關鍵，框架如 React 預設會做）② CSP 限制可執行的腳本來源 ③ HttpOnly cookie 讓 JS 偷不到 session。

延伸追問

面試官可能再追

React 就完全免疫 XSS 嗎？

預設安全（JSX 會跳脫）。但 dangerouslySetInnerHTML、把使用者資料塞進 href="javascript:" 或直接操作 DOM，仍會中招。

CSP 怎麼擋 XSS？

用 Content-Security-Policy 標頭限制只能載入白名單來源的腳本、禁止 inline script，就算注入成功也跑不起來。

面試這樣答

30 秒版本

「XSS 是攻擊者把腳本注入網頁、在他人瀏覽器執行，可偷 cookie、劫持 session。分儲存型、反射型、DOM 型。根因是把不可信資料當 HTML/JS 渲染。我的防禦是：輸出一律跳脫（React 預設會做，慎用 dangerouslySetInnerHTML）、設 CSP、cookie 設 HttpOnly。」
