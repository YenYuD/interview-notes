Web 安全 · HTTP Headers

六行 Header，擋掉大半常見攻擊

安全 HTTP header 是部署成本最低、效益最高的防禦手段。加幾行設定就能讓瀏覽器主動阻擋 XSS、Clickjacking、MIME 嗅探、降級攻擊。上線前核對清單，確保一個都不少。

六大安全標頭

各司其職，分層防禦

Header防什麼推薦設定
Content-Security-Policy XSS、資料注入 default-src 'self'; script-src 'self'
Strict-Transport-Security HTTP 降級、中間人攻擊 max-age=31536000; includeSubDomains; preload
X-Frame-Options Clickjacking（iframe 劫持） DENY 或 SAMEORIGIN
X-Content-Type-Options MIME 嗅探攻擊 nosniff（固定這一個值）
Referrer-Policy 敏感 URL 資訊外洩 strict-origin-when-cross-origin
X-XSS-Protection 舊瀏覽器 XSS 過濾（已過時） 0（現代 app 建議關掉，改用 CSP）
⚠

HSTS 要謹慎：max-age 一旦設高、加進 preload 清單後，就算你想改回 HTTP 也需要等 cache 到期。先從小 max-age（如 86400）測試，確認 HTTPS 穩定再調高。

重點細說

HSTS 與 MIME Sniffing

HSTS（Strict-Transport-Security）讓瀏覽器記住「這個網域只准 HTTPS」，往後連 HTTP request 都不會發出，直接在客戶端升級。preload 讓瀏覽器出廠就知道。
# HSTS — 強制 HTTPS 一年，含子網域，申請 preload
Strict-Transport-Security: max-age=31536000; includeSubDomains; preload

# 防 MIME 嗅探：瀏覽器不猜 Content-Type，只信宣告的
X-Content-Type-Options: nosniff

# 控制 Referer 資訊洩漏程度
Referrer-Policy: strict-origin-when-cross-origin
ℹ

MIME 嗅探攻擊：攻擊者上傳偽裝成圖片的 HTML 檔，瀏覽器「猜」出是 HTML 後執行。nosniff 告訴瀏覽器：別猜，照宣告的 Content-Type 處理。

延伸追問

面試官可能再追

X-Frame-Options 跟 CSP frame-ancestors 差在哪？

X-Frame-Options 較舊但瀏覽器支援廣；CSP frame-ancestors 更彈性（可指定多個允許來源）。建議兩者並設以確保相容性。

怎麼快速檢查線上站台的安全 header？

用 securityheaders.com 掃描，或 curl -I https://your-domain.com 直接看 response headers。
