AJAX 完整解析：非同步資料交換如何讓頁面不再閃爍重載

AJAX 讓網頁在背景和伺服器交換資料，現在幾乎都用 fetch() API 實作。理解整個流程——從請求到事件迴圈——能讓你在面試中展現深度。

AJAX 運作流程

fetch() 的六個步驟

發出請求：fetch(url, options) 啟動非同步 HTTP 請求
回傳 Promise：主執行緒繼續執行，不阻塞 UI
收到回應：resolve 後得到 Response 物件
解析資料：response.json() / response.text() 等
更新 UI：操作 DOM 顯示資料
錯誤處理：.catch() 處理網路失敗（注意 HTTP 錯誤不會 reject）
fetch() 完整範例

包含正確錯誤處理

async function loadUser(id) {
  try {
    const res = await fetch(`/api/users/${id}`);

    if (!res.ok) {             // 必須手動檢查 HTTP 狀態
      throw new Error(`Error: ${res.status}`);
    }

    const user = await res.json();
    renderUser(user);          // 更新 UI
  } catch (err) {
    console.error('Failed:', err);
  }
}

fetch() 的 then/catch 回調在事件迴圈的微任務佇列中執行，優先於 setTimeout 等巨任務，保證回應後及時更新 UI。

延伸追問

面試官可能再追

AJAX 如何處理競態條件（Race Condition）？

使用者快速連點觸發多次請求時，舊請求的回應可能比新請求晚到。解法：AbortController 取消舊請求，或用變數追蹤最新請求的 ID，只處理最新的回應。

AJAX 和 SPA（單頁應用程式）有什麼關係？

SPA 的核心就是 AJAX——頁面載入一次後，所有資料都透過 AJAX 取得，再由前端路由（pushState）管理 URL，完全不重新載入頁面。

30 秒版本

「AJAX 是讓頁面在背景和伺服器交換資料的技術，現代實作用 fetch()。流程是：呼叫 fetch() 回傳 Promise，主執行緒不阻塞，回應後解析資料再更新 DOM。兩個重點：fetch() 在 HTTP 錯誤時不會 reject，要手動檢查 response.ok；多個並發請求要考慮競態條件，必要時用 AbortController 取消過期的請求。」
