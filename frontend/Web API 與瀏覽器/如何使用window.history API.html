window.history API：不重新載入頁面就能操控瀏覽器歷史紀錄

History API 是 SPA 路由的核心。pushState 新增歷史、replaceState 取代當前——這兩個方法讓前端框架能在不發送 HTTP 請求的情況下改變 URL。

核心方法

五個方法涵蓋完整歷史操作

方法效果歷史堆疊
pushState(state, title, url)更新 URL，不重新載入新增一筆
replaceState(state, title, url)更新 URL，不重新載入取代當前
back()等同點「上一頁」按鈕往後移一步
forward()等同點「下一頁」按鈕往前移一步
go(n)移動 n 步（可為負數）移動 n 步
SPA 路由核心

pushState 怎麼讓 URL 改變但頁面不刷新

// 點擊連結時攔截，不跳頁
document.getElementById('nav-about').addEventListener('click', (e) => {
  e.preventDefault();                                        // 不走預設跳頁
  history.pushState({ page: 'about' }, '', '/about');  // 改 URL
  renderAboutPage();                                         // 自己渲染內容
});

// 使用者點「上一頁」時接收通知
window.addEventListener('popstate', (e) => {
  console.log('State:', e.state); // pushState 傳入的 state 物件
  renderPageFor(e.state);
});
ℹ

pushState 和 replaceState 不會觸發 popstate；只有使用者點擊上一頁/下一頁按鈕，或程式呼叫 back()/forward()/go() 才會觸發 popstate。

延伸追問

面試官可能再追

pushState 和 hash 路由（#）有什麼差別？

Hash 路由（/#/about）利用 URL hash 不觸發頁面重載的特性，不需要伺服器配合；pushState 路由（/about）URL 更乾淨，但需要伺服器設定將所有路由導向 index.html（SPA fallback）。

面試這樣答

30 秒版本

「History API 的核心是 pushState 和 replaceState，能在不重新載入頁面的情況下修改 URL 和歷史堆疊。前端路由框架（React Router、Vue Router）底層就是用這個機制實現 SPA 路由。pushState 新增歷史，replaceState 取代當前；使用者點返回時會觸發 popstate 事件，SPA 監聽這個事件來渲染對應頁面。」
