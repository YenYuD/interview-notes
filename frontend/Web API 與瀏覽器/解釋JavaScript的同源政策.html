WEB API 與瀏覽器

同源政策：瀏覽器阻止跨域請求的核心安全機制

同源政策是瀏覽器的安全基石，限制不同來源的頁面互相存取資料，防範 XSS 和 CSRF 攻擊。理解它才能正確設定 CORS 或選擇跨域替代方案。

什麼是「同源」

協定 + 主機 + 埠號，三個都要完全一樣

URL 比較與 http://example.com:80 同源？原因
http://example.com/page2✅ 同源協定/主機/埠號相同
https://example.com❌ 不同源協定不同（https vs http）
http://sub.example.com❌ 不同源主機不同（子域名不同）
http://example.com:8080❌ 不同源埠號不同（8080 vs 80）
繞過限制的方式

三種合法的跨域解法

CORS（推薦）

伺服器在回應加上 Access-Control-Allow-Origin header，明確允許跨域請求

代理伺服器

前端請求同源的後端代理，由後端轉發到目標 API，瀏覽器不知道有跨域

JSONP（舊方案）

利用 script 標籤不受同源限制，現代已不建議

💡

同源政策只限制瀏覽器端的腳本。伺服器之間的通訊不受此限制，這就是為什麼代理伺服器是一個有效解法。

延伸追問

面試官可能再追

CORS 的 preflight 請求是什麼？

對於複雜請求（非簡單請求，如 PUT/DELETE 或帶自訂 header），瀏覽器會先發一個 OPTIONS 請求詢問伺服器是否允許，伺服器確認後才發送實際請求。

同源政策限制的是什麼？不限制什麼？

限制：fetch()/XHR 請求、讀取 Cookie/localStorage、讀取 iframe 的 DOM。不限制：載入 img/script/CSS、a 標籤導向、form submit（但 JS 無法讀回應）。

面試這樣答

30 秒版本

「同源政策是瀏覽器的安全機制，規定頁面只能向相同協定、主機、埠號的來源發出請求，防止惡意網站竊取其他網站的資料。跨域解法主要有三種：最常用的是 CORS（伺服器在 header 明確允許）；其次是代理伺服器（前端打同源 API，後端代轉）；舊技術 JSONP 現已不建議使用。」
