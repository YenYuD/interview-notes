WebSocket：建立持久雙向連線，伺服器也能主動推送

HTTP 是單次請求-回應，每次都要重新建立連線。WebSocket 在一次握手後保持持久連線，客戶端與伺服器可以任意時刻互相發送訊息，延遲極低。

WebSocket vs HTTP

為什麼聊天室不用普通的 HTTP 請求？

面向HTTPWebSocket
連線模式請求-回應，每次新連線持久連線，一次握手
誰能主動發送只有客戶端客戶端與伺服器都可以
延遲較高（每次建立連線的 overhead）極低
協定http:// / https://ws:// / wss://
適合場景一般頁面請求即時聊天、遊戲、協作工具
基本用法

四個事件涵蓋完整生命週期

const socket = new WebSocket('wss://example.com/ws');

socket.addEventListener('open', () => {
  socket.send('Hello Server!');  // 連線建立後送訊息
});

socket.addEventListener('message', (e) => {
  console.log('收到：', e.data);     // 接收伺服器推送
});

socket.addEventListener('close', () => {
  console.log('連線關閉');
});

socket.addEventListener('error', (e) => {
  console.error('錯誤：', e);
});
💡

生產環境用 wss://（WebSocket Secure），就像 HTTPS 加密 HTTP 請求一樣，加密 WebSocket 通訊。

延伸追問

面試官可能再追

WebSocket 和 SSE 怎麼選？

需要雙向通訊（如聊天、遊戲）用 WebSocket；只需要伺服器單向推送（如通知、即時數據更新）用 SSE，SSE 基於 HTTP，更簡單且支援自動重連。

WebSocket 連線斷掉怎麼辦？

需要自己實作重連機制（監聽 close 事件後 setTimeout 重連），或使用 Socket.io 等函式庫，它內建重連、心跳偵測（heartbeat）和降級機制。
