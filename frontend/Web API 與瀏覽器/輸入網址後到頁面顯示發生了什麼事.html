WEB API 與瀏覽器

輸入網址按 Enter：DNS → TCP → HTTP → Render 七個步驟

這是最常被問到的系統設計題之一。從網址到頁面顯示，涵蓋網路層（DNS、TCP、TLS）和瀏覽器渲染層（DOM、CSSOM、Layout）的完整流程。

完整流程

七個步驟從 URL 到畫面

DNS 查詢：把網域名稱解析成 IP 位址。查詢順序：本機 hosts → 瀏覽器快取 → ISP DNS → 根 DNS
TCP 三向握手：SYN → SYN-ACK → ACK，建立可靠連線
TLS 握手（HTTPS）：驗證憑證、協商加密演算法
HTTP 請求：GET / HTTP/1.1，附帶 Cookie、Accept 等 header
伺服器回應：回傳 HTML（狀態碼 200 OK）
解析 HTML → DOM Tree：遇到 CSS 載入樣式、遇到 script 暫停解析（除非 async/defer）
渲染：DOM + CSSOM → Render Tree → Layout（計算位置）→ Paint（繪製）→ Composite（合成）
渲染關鍵路徑

影響首屏速度的渲染流程

步驟說明
Render TreeDOM + CSSOM 合併，濾掉 display:none 的節點
Layout（Reflow）計算每個元素的位置和大小
Paint（Repaint）把元素繪製成像素
Composite把各層合成最終畫面（GPU 加速的部分）
💡

script 標籤的阻塞問題：預設 script 會暫停 HTML 解析；加 defer 等 HTML 解析完後執行（保持順序）；加 async 下載完就執行（不保證順序）。

延伸追問

面試官可能再追

如何優化這個流程加速頁面載入？

DNS 預解析（dns-prefetch）、HTTP/2 多路復用、CDN 縮短網路距離、壓縮資源（gzip/Brotli）、減少重排觸發、Critical CSS 內嵌加快首次渲染、script 加 defer/async。

Reflow 和 Repaint 的觸發時機和代價？

Reflow（Layout 重新計算）代價最大，修改寬高、位置、字型大小時觸發；Repaint 代價次之，修改顏色、背景等視覺屬性時觸發；只修改 transform/opacity 只觸發 Composite，代價最小。

面試這樣答

30 秒版本

「流程分兩大階段：網路層是 DNS 查詢 → TCP 三向握手（HTTPS 加 TLS）→ HTTP 請求與回應；渲染層是解析 HTML 建 DOM Tree、解析 CSS 建 CSSOM、兩者合併成 Render Tree、計算 Layout → Paint → Composite。關鍵點：script 標籤預設阻塞 HTML 解析，應加 defer 或 async；減少 Reflow 是效能優化的重要方向。」
