WEB API 與瀏覽器

preventDefault 阻止預設行為，stopPropagation 阻止傳播

兩個方法解決不同的問題：preventDefault() 讓瀏覽器不執行元素的預設動作；stopPropagation() 讓事件不再往上（或往下）傳播。

差異對照

一個管「預設行為」，一個管「事件傳播」

方法作用常見使用情境
preventDefault()阻止瀏覽器的預設行為阻止表單送出、阻止連結跳轉、阻止右鍵選單
stopPropagation()阻止事件繼續冒泡（或捕獲）防止父元素的監聽器被意外觸發
範例對比

分別處理不同問題

// preventDefault：阻止表單送出，自行處理
form.addEventListener('submit', (e) => {
  e.preventDefault();       // 不送出，自己用 fetch() 處理
  sendData(new FormData(form));
});

// stopPropagation：阻止點擊事件冒泡到父層
modal.addEventListener('click', (e) => {
  e.stopPropagation();      // 防止觸發外層的「點擊關閉 modal」邏輯
});

document.addEventListener('click', () => closeModal());
ℹ

兩個方法可以同時呼叫，各自獨立不互相影響。另有 stopImmediatePropagation()，連同層的其他監聽器也一併阻止。

延伸追問

面試官可能再追

return false 等同於什麼？

在 jQuery 的事件處理中，return false 同時執行 preventDefault() 和 stopPropagation()。但在原生 addEventListener 中，return false 沒有任何效果，要明確呼叫方法。

passive 事件監聽器是什麼？

加上 { passive: true } 告知瀏覽器此監聽器不會呼叫 preventDefault()，讓瀏覽器可以提前進行捲動優化，改善滾動效能。
