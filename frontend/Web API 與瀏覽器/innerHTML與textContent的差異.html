WEB API 與瀏覽器

innerHTML 解析 HTML 標記，textContent 只處理純文字

innerHTML 功能強大但有 XSS 風險；textContent 更安全、更快，適合插入使用者輸入的內容。選對方法是防範 XSS 的第一步。

核心差異

同一段內容，兩種結果

const el = document.getElementById('demo');
const userInput = '<strong>Bold Text</strong>';

el.innerHTML    = userInput; // 渲染成粗體文字（解析 HTML）
el.textContent  = userInput; // 顯示原始字串 <strong>Bold Text</strong>
面向innerHTMLtextContent
解析 HTML是，會渲染標籤否，當純文字顯示
XSS 風險有（插入不信任內容時）無（自動轉義）
效能較慢（需解析 HTML）較快
適用情境動態插入 HTML 結構插入使用者文字內容
安全警告

innerHTML 的 XSS 陷阱

⚠

使用者輸入的字串如果直接放入 innerHTML，攻擊者可以注入 <script> 或 onerror 屬性執行惡意程式碼。

// 危險：XSS
el.innerHTML = userComment; // 若 userComment 含 <script>...

// 安全：插入使用者文字用 textContent
el.textContent = userComment;

// 必須插入 HTML 時，先消毒（sanitize）
el.innerHTML = DOMPurify.sanitize(userComment);

面試官可能再追

innerText 和 textContent 有什麼不同？

textContent 回傳所有文字（包含隱藏元素的文字），速度更快；innerText 只回傳「可見」的文字，並考慮 CSS 樣式，速度較慢但結果更符合視覺呈現。

除了 DOMPurify，還有什麼方式安全插入 HTML？

使用 DOM API（createElement、appendChild、setAttribute）逐一建構元素，不需要解析 HTML 字串，天然避免 XSS。

面試這樣答

30 秒版本

「innerHTML 會解析並渲染 HTML 標記，適合動態插入結構，但用在使用者輸入時有 XSS 風險；textContent 把內容當純文字處理，自動轉義 HTML 字符，更安全也更快。原則是：插入使用者輸入的內容一律用 textContent，必須插入 HTML 時用 DOMPurify 等函式庫先做消毒。」
