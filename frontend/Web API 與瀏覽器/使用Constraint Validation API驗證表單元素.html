WEB API 與瀏覽器

Constraint Validation API：瀏覽器內建的表單驗證機制

不需要自己寫驗證邏輯，HTML5 內建的 Constraint Validation API 讓你用 checkValidity() 和 setCustomValidity() 輕鬆實現表單驗證，搭配原生 required、pattern 等屬性更強大。

核心方法

四個最常用的 API

方法 / 屬性用途
checkValidity()驗證元素，回傳 true/false，不顯示提示
reportValidity()驗證並顯示瀏覽器內建錯誤提示
setCustomValidity(msg)設定自訂錯誤訊息，空字串表示有效
validity物件，含 valueMissing、typeMismatch 等布林屬性
validationMessage回傳目前的驗證錯誤訊息
實作範例

攔截送出 + 自訂驗證邏輯

const form = document.getElementById('myForm');
const username = document.getElementById('username');

form.addEventListener('submit', (e) => {
  // 自訂驗證：帳號不能包含空白
  if (username.value.includes(' ')) {
    username.setCustomValidity('帳號不能包含空白');
  } else {
    username.setCustomValidity(''); // 清除自訂訊息
  }

  if (!form.checkValidity()) {
    e.preventDefault();
    form.reportValidity(); // 顯示瀏覽器內建提示
  }
});
⚠

呼叫 setCustomValidity('訊息') 後，元素就會變成無效狀態。驗證通過時務必用 setCustomValidity('')（空字串）清除，否則表單永遠送不出去。

延伸追問

面試官可能再追

validity 物件有哪些屬性？

常用的有：valueMissing（required 但空值）、typeMismatch（格式錯誤如 email）、patternMismatch（不符合 pattern）、tooShort/tooLong（長度）、valid（整體是否有效）。

原生驗證 vs 自訂 JS 驗證，怎麼選？

簡單的格式驗證（required、email、min/max）優先用原生 HTML 屬性；需要非同步驗證（如後端確認帳號是否重複）或複雜業務邏輯，才用 JS 搭配 setCustomValidity。
