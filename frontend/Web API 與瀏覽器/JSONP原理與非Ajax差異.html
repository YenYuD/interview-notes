WEB API 與瀏覽器

JSONP：用 <script> 標籤繞過同源政策的古老技巧

JSONP 是 CORS 出現前跨域取資料的常見手法，利用 script 標籤不受同源限制的特性。了解它有助於讀懂舊程式碼，也是面試考點。

運作原理

JSONP 怎麼繞過同源政策？

客戶端動態建立 <script src="https://api.example.com/data?callback=handleData">
伺服器回傳 handleData({"name":"John"})——一段呼叫回調函式的 JS 程式碼
瀏覽器執行該腳本，觸發預先定義的 handleData() 函式，取得資料
function handleData(data) {
  console.log(data); // { name: "John" }
}

const script = document.createElement('script');
script.src = 'https://api.example.com/data?callback=handleData';
document.body.appendChild(script);
JSONP vs AJAX

兩者有什麼本質上的差別？

面向JSONPAJAX（fetch/XHR）
傳輸機制<script> 標籤XMLHttpRequest / fetch()
HTTP 方法僅限 GETGET、POST、PUT、DELETE…
同源政策天然繞過需要 CORS 許可
錯誤處理非常有限完整 catch/onerror
安全性有 XSS 風險可搭配 CORS 安全控管
⚠

現代開發不建議使用 JSONP。CORS 是更安全、更彈性的跨域解法；若需跨域，優先用 CORS。

延伸追問

面試官可能再追

JSONP 為什麼有 XSS 風險？

伺服器回傳的是可執行的 JavaScript，若外部伺服器遭入侵或被替換成惡意腳本，瀏覽器會直接執行，攻擊者可竊取 Cookie 或操作 DOM。

CORS 和 JSONP 如何選擇？

能控制伺服器端就用 CORS：在回應標頭加 Access-Control-Allow-Origin，安全且支援所有 HTTP 方法。JSONP 只在維護無法修改的舊 API 時才考慮。

面試這樣答

30 秒版本

「JSONP 是利用 <script> 標籤不受同源政策限制的特性來跨域取資料。流程是：動態插入一個 script 標籤，src 帶上 callback 函式名稱，伺服器回傳呼叫該函式的 JS，瀏覽器執行後就拿到資料了。但它只支援 GET、沒有錯誤處理、有 XSS 安全風險，現代開發應改用 CORS。」
