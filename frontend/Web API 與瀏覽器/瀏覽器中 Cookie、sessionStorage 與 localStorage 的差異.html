WEB API 與瀏覽器

瀏覽器儲存三劍客：Cookie、localStorage、sessionStorage 選哪個？

三者都是客戶端儲存，但生命週期、容量、安全性截然不同。Cookie 會隨 HTTP 請求自動送到伺服器，其他兩個不會。選錯可能讓 token 被偷或資料在關分頁後消失。

選擇指南

什麼資料放哪裡

Cookie（HttpOnly）

session ID、refresh token——需要伺服器驗證，HttpOnly 讓 JS 碰不到，防 XSS

localStorage

主題偏好、語言設定、購物車——不需要伺服器讀取，長期保存

sessionStorage

多步驟表單進度、結帳流程暫存——只在當次瀏覽有效，關閉自動清除

⚠

常見誤解：Cookie 是客戶端儲存，不是伺服器端儲存！特別的是瀏覽器每次 HTTP 請求都會自動帶上，所以伺服器才看得到它。

延伸追問

面試官可能再追

HttpOnly Cookie 是什麼？為什麼更安全？

設定 HttpOnly 後，JavaScript 無法透過 document.cookie 讀取該 Cookie。即使頁面有 XSS 漏洞，攻擊者也無法透過 JS 竊取 token，大幅降低 XSS 攻擊面。

為什麼不把所有資料都存 localStorage？

localStorage 的資料不會隨請求送到伺服器，SSR 首次渲染時無法取得（如使用者語言偏好）。認證資訊更不能放，因為 JS 都能讀到，有 XSS 風險。

面試這樣答

30 秒版本

「三者都是客戶端儲存，差在生命週期和安全性：Cookie 容量小但會自動隨 HTTP 請求送出，適合認證 token（HttpOnly 可防 XSS）；localStorage 5MB 永久保存，適合使用者偏好；sessionStorage 關分頁就清除，適合單次流程暫存。記住 Cookie 是客戶端儲存，不是伺服器端的。」
