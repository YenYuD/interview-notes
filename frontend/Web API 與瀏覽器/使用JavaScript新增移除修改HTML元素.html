DOM 操作三部曲：新增、移除、修改 HTML 元素

JavaScript 透過 DOM API 動態控制頁面結構。掌握 createElement、appendChild、remove 和 classList 這幾個核心方法，就能應付大多數 DOM 操作需求。

新增元素

createElement + appendChild

// 建立 → 設定內容 → 插入
const div = document.createElement('div');
div.textContent = 'Hello World';
div.className = 'card';
document.body.appendChild(div);

// 插入到特定位置（某元素之前）
const ref = document.getElementById('target');
ref.parentNode.insertBefore(div, ref);

// 現代寫法：更靈活的 insertAdjacentHTML
ref.insertAdjacentHTML('beforebegin', '<p>New paragraph</p>');
移除與修改

直接移除 + classList 切換樣式

// 移除元素
el.remove();  // 現代寫法，直接呼叫
el.parentNode.removeChild(el);  // 舊寫法

// 修改類別
el.classList.add('active');
el.classList.remove('hidden');
el.classList.toggle('open');    // 有就移除，沒有就新增
el.classList.contains('active'); // 回傳 boolean

// 修改屬性
el.setAttribute('data-id', '42');
el.style.backgroundColor = '#f0f0f0';
💡

修改樣式時，優先用 classList 切換 CSS 類別，而不是直接改 style 屬性。這樣樣式定義留在 CSS，JavaScript 只做邏輯控制，更易維護。

延伸追問

面試官可能再追

大量 DOM 操作時如何避免效能問題？

用 DocumentFragment 批次建立元素，最後一次性插入 DOM：const frag = document.createDocumentFragment(); // 把所有元素加到 frag; container.appendChild(frag);。這樣只觸發一次 reflow/repaint。

innerHTML 和 createElement 有什麼效能差異？

innerHTML 插入少量簡單 HTML 時較快且方便，但有 XSS 風險且會重建子樹（破壞事件監聽器）；createElement 更安全、更可控，適合動態新增需要綁定事件的元素。

面試這樣答

30 秒版本

「DOM 操作三個核心動作：新增用 createElement + appendChild；移除用 element.remove()；修改樣式優先用 classList.add/remove/toggle，修改屬性用 setAttribute 或直接存取屬性。批次插入時用 DocumentFragment 可以減少 reflow 次數。插入使用者內容記得用 textContent 而非 innerHTML，避免 XSS。」
