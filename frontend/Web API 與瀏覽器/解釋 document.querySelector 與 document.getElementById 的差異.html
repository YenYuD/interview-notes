WEB API 與瀏覽器

querySelector 支援任何 CSS 選擇器，getElementById 速度更快

兩者都用來從 DOM 選取元素，但 querySelector 靈活性遠勝，可用類別、屬性、偽類等；getElementById 只認 ID，但效能更好。

彈性展示

querySelector 能做更多

// getElementById — 只能選 ID
document.getElementById('header');

// querySelector — 支援所有 CSS 選擇器
document.querySelector('#header');           // 同上（加 # 前綴）
document.querySelector('.btn.primary');       // 多重類別
document.querySelector('input[type="email"]'); // 屬性選擇器
document.querySelector('li:first-child');    // 偽類
document.querySelector('nav > ul > li');     // 後代選擇
💡

用 ID 選取時，若效能要求高（如在迴圈中大量選取），優先用 getElementById；一般情況 querySelector 的可讀性更好。

延伸追問

面試官可能再追

querySelectorAll 回傳的是什麼？可以直接用 forEach 嗎？

回傳 NodeList，不是 Array。現代瀏覽器的 NodeList 支援 forEach，但若需要 map/filter 等方法，要先用 Array.from() 或展開運算子 [...nodes] 轉成陣列。

querySelector 找不到元素時回傳什麼？存取它的屬性會怎樣？

回傳 null。存取 null.textContent 等屬性會拋出 TypeError。要養成習慣在操作前先確認元素不為 null：if (el) el.textContent = '...'。

30 秒版本

「querySelector 接受任何 CSS 選擇器，可以選類別、屬性、偽類等，靈活性高；getElementById 只能用 ID 選取，但直接查找內部索引，效能更好。一般開發用 querySelector 可讀性更好，效能敏感的場景（如大量 DOM 操作）才特別用 getElementById。兩者找不到元素都回傳 null。」
