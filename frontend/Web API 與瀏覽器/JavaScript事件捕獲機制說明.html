事件捕獲：事件從根節點向下傳播，冒泡的相反方向

DOM 事件傳播分三階段：捕獲（由上而下）→ 目標 → 冒泡（由下而上）。捕獲階段預設不啟用，加上 { capture: true } 才會在事件到達目標前先攔截。

三個傳播階段

完整事件流程

捕獲階段（Capture）：事件從 document root 向下傳遞到目標元素，路徑上設定 capture: true 的監聽器依序觸發
目標階段（Target）：事件到達目標元素，capture 和 bubble 監聽器依綁定順序觸發
冒泡階段（Bubble）：事件從目標元素向上傳遞，路徑上設定 capture: false（預設）的監聽器依序觸發
啟用方式

addEventListener 第三個參數控制捕獲

const parent = document.getElementById('parent');
const child  = document.getElementById('child');

// 捕獲階段觸發（事件往下傳時）
parent.addEventListener('click', () => {
  console.log('1. Parent 捕獲');
}, true);  // 或 { capture: true }

// 冒泡階段觸發（預設，事件往上傳時）
parent.addEventListener('click', () => {
  console.log('3. Parent 冒泡');
});  // 預設 capture: false

child.addEventListener('click', () => {
  console.log('2. Child 目標');
});

// 點擊 child 的輸出順序：
// 1. Parent 捕獲  ← 捕獲先觸發
// 2. Child 目標
// 3. Parent 冒泡  ← 冒泡後觸發

延伸追問

面試官可能再追

捕獲和冒泡哪個先觸發？

捕獲先。事件從根節點往下捕獲 → 到達目標元素 → 再往上冒泡。同一元素上若同時有捕獲和冒泡監聽器，目標元素上按綁定順序觸發，其他元素則捕獲優先。

什麼場景真的需要用事件捕獲？

需要在事件抵達目標前攔截的場景：例如「點擊下拉選單外部關閉」可在 document 用捕獲監聽；或阻止某些子元素收到特定事件（在父層捕獲後 stopPropagation）。

面試這樣答

30 秒版本

「DOM 事件傳播有三個階段：捕獲（從 document root 向下到目標）→ 目標（到達點擊的元素）→ 冒泡（從目標向上回到根節點）。預設 addEventListener 在冒泡階段觸發；加 capture: true 才在捕獲階段觸發，優先於冒泡。實務上冒泡比較常用，捕獲用在需要在事件到達目標前先攔截的特殊場景。」
