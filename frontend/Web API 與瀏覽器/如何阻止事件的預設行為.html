WEB API 與瀏覽器

用 event.preventDefault() 接管瀏覽器的預設行為

瀏覽器對某些事件有預設行為：表單送出、連結跳轉、右鍵選單。preventDefault() 讓你取消這些預設動作，完全由 JavaScript 自訂處理邏輯。

三個常見場景

什麼時候需要阻止預設行為

// 1. 阻止表單送出（SPA 用 AJAX 送出時）
form.addEventListener('submit', (e) => {
  e.preventDefault();
  sendFormWithFetch(new FormData(form));
});

// 2. 阻止連結跳轉（SPA 路由攔截）
link.addEventListener('click', (e) => {
  e.preventDefault();
  router.navigate(link.href);
});

// 3. 阻止右鍵選單（自訂 context menu）
document.addEventListener('contextmenu', (e) => {
  e.preventDefault();
  showCustomMenu(e.clientX, e.clientY);
});
ℹ

可以用 event.cancelable 屬性檢查該事件是否支援取消。自訂事件預設不可取消，scroll 事件預設也不行。

注意事項

preventDefault vs stopPropagation

方法作用影響範圍
preventDefault()阻止瀏覽器預設行為不影響事件傳播
stopPropagation()阻止事件繼續冒泡不影響預設行為
延伸追問

面試官可能再追

哪些事件的預設行為無法取消？

像是 scroll（加了 passive 監聽器的）、某些瀏覽器安全事件（如 Ctrl+T 開新分頁）。可以用 event.cancelable 檢查是否可取消。

passive 監聽器和 preventDefault 有什麼衝突？

加了 { passive: true } 的監聽器內呼叫 preventDefault() 會被忽略（並在 console 產生警告）。passive 意思就是「保證不會取消預設行為」，所以才能讓瀏覽器提前執行捲動。

面試這樣答

30 秒版本

「event.preventDefault() 取消瀏覽器對事件的預設處理，例如阻止表單送出後用 fetch 自行處理、阻止連結跳轉讓前端路由接管。它只影響預設行為，不影響事件傳播；stopPropagation() 才是阻止冒泡的方法。要注意 passive 監聽器內呼叫 preventDefault 無效，因為兩者互斥。」
