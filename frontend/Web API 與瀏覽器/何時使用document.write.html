document.write()：幾乎從不使用，但要知道為什麼

document.write() 是最古老的 DOM 操作方式，現代開發幾乎完全避免使用。了解它的危險性，以及為什麼有更好的替代方案，這本身就是面試的考點。

最大問題

頁面載入完成後呼叫會覆蓋整個文件

⚠

如果在頁面載入完成後呼叫 document.write()，瀏覽器會清空整個頁面重新開始，所有現有內容都會消失。

// 危險：頁面載入完成後才執行
window.addEventListener('load', () => {
  document.write('<h1>New Content</h1>');
  // 原本所有頁面內容都消失了！
});
場景用 document.write 的問題更好的替代方案
動態插入內容可能覆蓋整頁、阻塞渲染innerHTML 或 createElement
輸出偵錯訊息影響頁面結構console.log()
插入腳本同步阻塞解析器動態建立 script 元素
何時可以用？

幾乎只剩教學和舊程式碼維護

不建議

生產環境的任何動態內容插入

不建議

第三方廣告腳本（現代廣告服務已改用其他方式）

可接受

教學示範 JS 基礎概念（舊版教材）

可接受

維護無法修改的舊有程式碼時理解它

面試官可能再追

Chrome 為什麼會封鎖 document.write()？

Chrome 在慢速連線（2G）時會介入封鎖 document.write()，因為它同步阻塞 HTML 解析器，會大幅延遲首次內容繪製（FCP）。這是 Google 效能優化的政策。

面試這樣答

30 秒版本

「document.write() 在現代開發中幾乎不使用。主要問題是：頁面載入完成後呼叫會清空整個文件；它同步阻塞 HTML 解析器，影響頁面效能；Chrome 在慢速連線下甚至會主動封鎖它。替代方案：動態插入內容用 innerHTML 或 createElement；偵錯用 console.log。唯一接觸它的情況是維護很舊的程式碼。」
