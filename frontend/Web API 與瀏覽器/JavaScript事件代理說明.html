DOM 事件

一個監聽器，管住一整串子元素

不要給每個 <li> 各掛一個監聽器。把一個監聽器掛在父層，靠事件冒泡把子元素的點擊送上來，再用 event.target 認是誰。

DEMO — 動態新增也能被監聽

父層一個監聽器搞定全部

監聽器只掛在 <ul> 上。點任何一項都會被接到；按「新增」加進來的項目，不必重新綁定也能用：

<ul> 上唯一的監聽器
  • Item 1
  • Item 2
  • Item 3
// 點上面任一項…
監聽器數量永遠是 1。新增的項目自動被覆蓋——因為事件是冒泡到 <ul> 才處理，跟子元素何時加入無關。
為什麼值得

三個好處

  • 省記憶體 / 高效能：1 個監聽器 vs N 個。
  • 支援動態元素：之後才加入的子元素也自動生效。
  • 邏輯集中：處理程式只寫一次，好維護。
⚠️

注意：有些事件不冒泡，沒辦法代理——focus、blur、scroll、mouseenter/leave。（focus 可用會冒泡的 focusin 代替。）

延伸追問

面試官可能再追

target 和 currentTarget 差在哪？

event.target 是實際被點的元素（可能是深層子元素）；event.currentTarget 是監聽器所在的元素（這裡是 ul）。代理時常配 target.closest('li') 來鎖定目標。

事件代理的原理是什麼？

就是事件冒泡：子元素事件會沿 DOM 往上傳到祖先，所以祖先的監聽器能攔截到。

面試這樣答

30 秒版本

「事件代理是把單一監聽器掛在共同父層，利用事件冒泡接住子元素的事件，再用 event.target 判斷是誰觸發。好處是省記憶體、自動支援動態新增的元素、邏輯集中。要注意 focus、scroll 等不冒泡的事件無法直接代理。」
