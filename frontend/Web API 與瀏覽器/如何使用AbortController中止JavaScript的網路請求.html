非同步 · Fetch

請求送出去了，還能反悔

AbortController 給你一個 signal 交給 fetch，之後呼叫 abort() 就能取消這個還在飛的請求——使用者離開頁面、或只想要最新一筆結果時超實用。

DEMO — 送出後按取消

模擬一個 3 秒的請求

const controller = new AbortController();
fetch(url, { signal: controller.signal })
  .catch(e => { if (e.name === 'AbortError') /* 被取消 */ });
controller.abort(); // 反悔！
送出請求後可中途取消
// 按「送出請求」…
取消後 fetch 的 promise 會 reject，錯誤的 name 是 AbortError——要在 catch 裡和真正的網路錯誤分開處理。
三步驟

怎麼用

  1. 建立 const controller = new AbortController()。
  2. 把 controller.signal 傳進 fetch 選項。
  3. 需要取消時呼叫 controller.abort()。
✅

典型場景：搜尋輸入框 debounce 後，取消前一筆未完成的請求只留最新一筆（避免 race condition 顯示舊結果）；以及元件卸載時取消，防止記憶體洩漏與 setState 警告。

延伸追問

面試官可能再追

一個 controller 能取消多個請求嗎？

可以。把同一個 signal 傳給多個 fetch，abort() 一次全部取消。但一個 controller 只能用一次，abort 後要重建。

signal 只能用在 fetch 嗎？

不只。addEventListener 也接受 { signal }，abort 時自動移除監聽器；setTimeout 等也有相容寫法。它是通用的取消信號。

面試這樣答

30 秒版本

「AbortController 用來取消進行中的非同步操作。建立後把它的 signal 傳進 fetch，需要時呼叫 abort()，fetch 就會以 AbortError reject。我常用在搜尋輸入取消舊請求只留最新、以及元件卸載時取消避免洩漏。同一 signal 也能一次取消多個請求或移除事件監聽器。」
