DOMContentLoaded 先、load 後：兩個事件的時機差異

DOMContentLoaded 在 HTML 解析完成後立即觸發，不等圖片和樣式；load 要等所有資源都載入完才觸發。選錯事件會讓初始化腳本在元素不存在時執行。

觸發時機

頁面載入的時間軸

瀏覽器開始解析 HTML
DOMContentLoaded 觸發 — HTML 解析完成，DOM 樹建立，但圖片/CSS 可能還在載入
圖片、樣式表、iframe 等資源全部載入完成
window load 觸發 — 頁面所有資源就緒
用法與選擇

什麼情況用哪個？

// DOM 準備好就能執行 → 用 DOMContentLoaded
document.addEventListener('DOMContentLoaded', () => {
  document.getElementById('btn').addEventListener('click', handleClick);
});

// 需要圖片尺寸才能計算版面 → 用 load
window.addEventListener('load', () => {
  const img = document.querySelector('img');
  console.log(img.naturalWidth, img.naturalHeight); // 此時才有值
});
任務用哪個
綁定事件監聽器、操作 DOMDOMContentLoaded（較早，UX 更好）
依賴圖片尺寸的版面計算load
初始化輪播、幻燈片load（圖片載完才有意義）
💡

現代實務通常把 <script> 放在 </body> 前，或加 defer 屬性，這樣 DOM 已解析完畢，不需要監聽 DOMContentLoaded。

延伸追問

面試官可能再追

script 標籤的 async 和 defer 與這兩個事件有何關係？

defer 腳本在 DOMContentLoaded 之前執行；async 腳本載入完即執行，不保證順序。若有 async 腳本尚未執行，DOMContentLoaded 可能被延遲。

可以用 jQuery 的 $(document).ready() 替代 DOMContentLoaded 嗎？

是的，$(document).ready() 在底層就是監聽 DOMContentLoaded（現代瀏覽器），等價於原生寫法。
