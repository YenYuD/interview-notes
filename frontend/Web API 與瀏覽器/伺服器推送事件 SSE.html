WEB API 與瀏覽器

SSE：伺服器單向推送，比 WebSocket 更簡單的即時方案

Server-Sent Events 讓伺服器透過持久 HTTP 連線主動推送資料給瀏覽器。不需要雙向通訊時，SSE 比 WebSocket 更輕巧，且支援自動重連。

SSE vs WebSocket

場景決定選哪個

屬性SSE (EventSource)WebSocket
通訊方向單向：僅伺服器 → 客戶端雙向：兩端都能主動發送
協定普通 HTTPws:// / wss://
資料格式僅文字文字 + 二進位
自動重連✅ 內建❌ 需自行實作
使用難度簡單（EventSource API）較複雜
適合場景通知、即時數據、日誌串流聊天、遊戲、協作工具
客戶端用法

三行程式碼建立即時串流

const source = new EventSource('/api/notifications');

source.addEventListener('message', (e) => {
  console.log('推送：', e.data);   // 接收訊息
});

source.addEventListener('error', () => {
  // EventSource 會自動重連，通常不需額外處理
});

// 關閉連線
source.close();
💡

SSE 支援自訂事件類型，伺服器發送 event: notification，客戶端就監聽 'notification' 而非 'message'，方便分類處理。

延伸追問

面試官可能再追

SSE 有什麼限制？

只能傳文字資料；瀏覽器對同一網域的 SSE 連線有上限（約 6 條，HTTP/2 可緩解）；只能伺服器 → 客戶端單向，需要客戶端發送時要另外用 fetch/XHR。

ChatGPT 的串流輸出是用什麼技術？

正是 SSE！伺服器把 AI 生成的內容一段段推送過來，客戶端的 EventSource 接收並即時顯示，形成逐字輸出的效果。也有些實作用 fetch() 的 ReadableStream。
