WEB API 與瀏覽器

用 window.location 控制頁面導向：四種方法的差異

JavaScript 提供多種導向頁面的方式，核心差異在是否保留瀏覽器歷史紀錄。選錯方法會讓使用者按「上一頁」回不去，或是跳轉到不預期的頁面。

四種方法比較

選哪個取決於你要不要讓使用者按返回鍵

方法行為歷史紀錄使用情境
location.href = url導向新頁面新增一筆一般頁面跳轉
location.replace(url)導向新頁面取代當前（無法返回）登入後重導、防止返回到登入頁
location.assign(url)導向新頁面新增一筆同 href，更語義化
location.reload()重新載入不變手動刷新頁面
SPA 場景

不重新載入頁面的 URL 更新：history.pushState

// 不觸發頁面載入，只改 URL + 新增歷史
history.pushState({ page: 'about' }, '', '/about');

// 取代當前歷史，不新增
history.replaceState({ page: 'home' }, '', '/home');
💡

React Router、Vue Router 等前端路由庫底層就是用 history.pushState 實現 SPA 路由，讓 URL 變化但頁面不重新載入。

延伸追問

面試官可能再追

replace() 和 href 最大的差異是什麼？

replace() 會取代歷史堆疊中的當前頁面，使用者點「上一頁」時不會回到這一頁；href 則保留，使用者可以返回。登入後重導通常用 replace()，避免使用者返回到登入頁。

pushState 和直接修改 location 有何差異？

pushState 不觸發頁面重新載入，只改 URL 和歷史紀錄；直接設定 location.href 會觸發完整的頁面導向（發送新的 HTTP 請求）。

面試這樣答

30 秒版本

「導向新頁面最常用 location.href = url，它會新增一筆瀏覽器歷史。如果不想讓使用者返回（例如登入後跳轉），用 location.replace()，它會取代而非新增歷史。SPA 框架用的是 history.pushState()，可以改變 URL 但不重新載入頁面，這是前端路由的核心機制。」
