mouseenter 不冒泡，mouseover 會冒泡——差一個字，行為完全不同

兩者都在滑鼠進入元素時觸發，但 mouseover 進入子元素時也會再次觸發，容易造成意外的多次回調。選錯了可能讓 hover 效果閃爍不停。

行為示意

滑鼠從父元素移入子元素時各自的反應

ℹ

情境：父元素 div 內有一個子元素 span，滑鼠移入父元素再移入子元素。

滑鼠進入父元素 → mouseenter 與 mouseover 都在父元素觸發一次
滑鼠移入子元素 → mouseover 再次觸發（子元素冒泡到父元素）；mouseenter 不觸發
💡

有多個子元素時，mouseover 在每次進入子元素時都會觸發，可能造成效能問題或閃爍。偏好用 mouseenter 做 hover 效果。

延伸追問

面試官可能再追

什麼情況下反而需要 mouseover？

想用事件代理在父元素統一處理所有子元素的 hover 時，需要 mouseover（因為它會冒泡）。搭配 event.target 判斷是哪個子元素觸發。

CSS :hover 和 JavaScript mouseenter 有差嗎？

CSS :hover 更簡單高效，不需要 JS，瀏覽器直接處理。JavaScript 的 mouseenter/mouseover 適合需要做複雜邏輯（如計算、資料更新）的場景。

面試這樣答

30 秒版本

「主要差異在冒泡：mouseenter 不冒泡，只在滑鼠進入綁定元素本身時觸發一次，適合簡單 hover 效果；mouseover 會冒泡，每次進入任何子元素都會再次觸發，容易造成多次回調。有巢狀子元素的場景，通常用 mouseenter/mouseleave 更可預測，避免閃爍問題。」
