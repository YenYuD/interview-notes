WEB API 與瀏覽器

XMLHttpRequest 的事件回調 vs fetch() 的 Promise 鏈

兩者都能發 HTTP 請求，但 fetch() 語法更簡潔、基於 Promise、支援 async/await。XHR 在上傳進度追蹤上仍有優勢。現代開發預設選 fetch()。

關鍵差異

語法對比

相同的 GET 請求，兩種寫法

// XMLHttpRequest — 事件驅動，較繁瑣
const xhr = new XMLHttpRequest();
xhr.open('GET', '/api/data');
xhr.responseType = 'json';
xhr.onload = () => console.log(xhr.response);
xhr.onerror = () => console.error('Error');
xhr.send();

// fetch() — Promise 鏈，更現代
const data = await fetch('/api/data')
  .then(res => {
    if (!res.ok) throw new Error('HTTP error');
    return res.json();
  });
⚠

fetch() 的 HTTP 4xx/5xx 不會觸發 reject，需自行檢查 response.ok。這是最常見的踩雷點。

延伸追問

面試官可能再追

fetch() 什麼時候才會 reject（進 catch）？

只有網路完全失敗（DNS 錯誤、離線）或被 AbortController 中止時才 reject。HTTP 404、500 等狀態碼仍然 resolve，要用 response.ok 或 response.status 判斷。

什麼場景還是需要用 XHR？

需要追蹤大型檔案上傳進度時，XHR 的 upload.onprogress 比 fetch() 更方便。其他場景通常 fetch() 更好用。

面試這樣答

30 秒版本

「fetch() 是更現代的 HTTP 請求 API，基於 Promise，支援 async/await，語法比 XHR 簡潔很多。主要差異：XHR 用事件回調、有內建上傳進度追蹤；fetch() 用 Promise、需要 AbortController 才能取消。要注意 fetch() 在 HTTP 錯誤狀態時不會自動 reject，要手動檢查 response.ok。現代開發幾乎都用 fetch()。」
