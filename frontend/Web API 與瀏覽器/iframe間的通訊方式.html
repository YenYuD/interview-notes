iframe 跨框架通訊：postMessage 是唯一安全選項

iframe 與父頁面可能來自不同網域，受同源政策限制，無法直接存取彼此的 DOM。postMessage API 提供安全的跨來源訊息傳遞機制，是業界標準解法。

postMessage 用法

發送方指定目標來源，接收方驗證來源

// 父頁面 → 發送給 iframe
const iframe = document.querySelector('iframe');
iframe.contentWindow.postMessage(
  { type: 'UPDATE', data: 42 },
  'https://iframe.example.com'  // 指定目標來源（不要用 '*'）
);

// iframe 內部 → 接收訊息
window.addEventListener('message', (event) => {
  // 驗證來源！防止惡意頁面注入
  if (event.origin !== 'https://parent.example.com') return;
  console.log(event.data); // { type: 'UPDATE', data: 42 }
});
安全要點

兩個必做的安全檢查

發送時

第二個參數指定確切來源，不要用 '*'，否則任何頁面都能收到訊息

接收時

驗證 event.origin，確保訊息來自預期的可信來源

⚠

不驗證 event.origin 是嚴重的安全漏洞，惡意網站可以嵌入你的 iframe 並注入偽造訊息。

延伸追問

面試官可能再追

同源的 iframe 有什麼捷徑？

同源時可以直接用 iframe.contentDocument 或 iframe.contentWindow 存取 iframe 的 DOM 和 JS，不需要 postMessage。但跨來源就只能用 postMessage。

除了 postMessage，還有其他跨框架通訊方式嗎？

可以用 URL hash（讀取 location.hash）做單向傳遞，但功能有限且不安全。現代開發幾乎只用 postMessage。

30 秒版本

「iframe 和父頁面跨域通訊的標準方式是 window.postMessage()。父頁面用 iframe.contentWindow.postMessage(data, targetOrigin) 發送，目標方監聽 message 事件接收。安全關鍵是：發送時指定精確的 targetOrigin，接收時驗證 event.origin，兩步缺一不可，否則會有跨站訊息注入的風險。」
