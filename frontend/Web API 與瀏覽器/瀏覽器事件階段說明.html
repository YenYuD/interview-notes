DOM 事件

一次點擊，事件先往下、再往上

事件傳播分三段：捕獲（root → 目標）→ 目標 → 冒泡（目標 → root）。預設監聽器跑在冒泡階段；加 true 才在捕獲階段。

三層巢狀，誰先誰後？

三個巢狀的 div 都掛了監聽器。先選監聽階段，再點最內層的「target」：

監聽階段
grandparent
parent
target（點我）
// 點上面的 target…
捕獲：grandparent → parent → target。冒泡：target → parent → grandparent。事件代理靠的就是冒泡這一段。
三階段

傳播路線

1

捕獲 Capturing

從 root 往下傳到目標。addEventListener(type, fn, true) 註冊。

2

目標 Target

抵達被點的元素本身。

3

冒泡 Bubbling

從目標往上傳回 root。預設（false）就在這跑。

💡

用 stopPropagation() 可中止後續傳播；stopImmediatePropagation() 連同元素上其他監聽器也一起擋掉。

延伸追問

面試官可能再追

preventDefault 和 stopPropagation 差在哪？

preventDefault 取消瀏覽器預設行為（如連結跳轉）；stopPropagation 阻止事件繼續傳播。兩者互不相干。

為什麼預設在冒泡階段？

歷史相容（IE 只有冒泡），且冒泡對事件代理最直覺。需要在外層先攔截時才用捕獲。

面試這樣答

30 秒版本

「事件傳播有三階段：捕獲（root→目標）、目標、冒泡（目標→root）。addEventListener 預設在冒泡階段觸發，第三參數傳 true 則改在捕獲階段。事件代理就是利用冒泡。要中止傳播用 stopPropagation，取消預設行為用 preventDefault，兩者不同。」
