Workers：讓 JavaScript 脫離單執行緒限制的背景執行機制

JavaScript 預設單執行緒，耗時運算會凍結 UI。Workers 讓你把重度任務移到背景執行緒，主執行緒保持回應，面試必考三種 Worker 的差異。

三種 Workers

Web Worker、Service Worker、Shared Worker 怎麼選

類型用途存活週期DOM 存取
Web WorkerCPU 密集運算（圖像處理、資料壓縮）主腳本卸載即終止❌
Service Worker網路代理、離線快取、推播通知瀏覽器管理，頁面關閉仍在❌
Shared Worker多分頁共享狀態所有連線關閉才終止❌
ℹ

所有 Workers 都無法直接操作 DOM，需透過 postMessage() 與主執行緒溝通。

Web Worker 範例

主執行緒與 Worker 互傳訊息

// main.js
const worker = new Worker('worker.js');
worker.postMessage('開始計算');
worker.onmessage = (e) => console.log('結果：', e.data);

// worker.js
onmessage = (e) => {
  const result = heavyComputation(e.data);
  postMessage(result);
};
💡

Service Worker 是 PWA 離線功能的基礎，它可以攔截 fetch 請求並回傳快取資源，讓網頁在無網路時也能運作。

延伸追問

面試官可能再追

Web Worker 和 Service Worker 最大的差別是什麼？

Web Worker 是給頁面用的背景執行緒，頁面關閉就消失；Service Worker 是網路代理，由瀏覽器管理生命週期，即使頁面關閉也能接收推播、處理快取。

Worker 能使用哪些 Web API？

可以用 fetch()、IndexedDB、Web Storage、setTimeout，但不能用 document、window、DOM 相關 API。

什麼情境真的值得用 Web Worker？

當主執行緒因運算卡頓時（如解析大型 JSON、影像濾鏡、加密演算法），才值得加入 Worker 的複雜度。一般 AJAX 請求本身就是非同步的，不需要 Worker。

30 秒版本

「Workers 是讓 JavaScript 在主執行緒之外平行執行的機制。三種主要類型：Web Worker 用於 CPU 密集運算（如影像處理）、Service Worker 作為網路代理實現離線快取與推播通知、Shared Worker 讓多個分頁共享狀態。它們都無法直接操作 DOM，透過 postMessage 與主執行緒通訊。」
