事件冒泡：事件從子元素向上傳播到根節點的機制

點擊子元素時，事件會沿 DOM 樹向上冒泡，觸發所有祖先元素的監聽器。這是事件代理技術的基礎，也是最容易產生意外行為的源頭。

冒泡行為

點擊子元素，父元素的處理器也會被觸發

const parent = document.getElementById('parent');
const child  = document.getElementById('child');

parent.addEventListener('click', () => console.log('Parent 被點到了'));
child.addEventListener( 'click', () => console.log('Child 被點到了'));

// 點擊 child → 印出：
// "Child 被點到了"
// "Parent 被點到了"  ← 冒泡

用 event.stopPropagation() 可在任意層停止冒泡，阻止事件繼續往上傳。

實際應用

事件代理：用一個監聽器管理所有子元素

// 傳統：每個項目各自綁定 → 效能差
items.forEach(item => item.addEventListener('click', handleClick));

// 事件代理：只在父層綁定一個 → 效能好，動態新增的子元素也適用
document.getElementById('list').addEventListener('click', (e) => {
  if (e.target.matches('li')) {
    handleClick(e.target);
  }
});
💡

event.target 是實際被點擊的元素；event.currentTarget 是綁定監聽器的元素。事件代理時需區分兩者。

延伸追問

面試官可能再追

stopPropagation 和 preventDefault 有什麼不同？

stopPropagation() 阻止事件繼續冒泡（或捕獲）；preventDefault() 阻止瀏覽器的預設行為（如表單送出、連結跳轉）。兩者互相獨立，可同時呼叫。

哪些事件不會冒泡？

focus、blur、mouseenter、mouseleave 不會冒泡。對應的冒泡版本是 focusin/focusout 和 mouseover/mouseout。

面試這樣答

30 秒版本

「事件冒泡是指事件從觸發的目標元素開始，沿 DOM 樹向上依序觸發每個祖先元素的事件處理器。這個機制讓事件代理成為可能——只在父層綁定一個監聽器，利用 event.target 判斷是哪個子元素觸發的，既省記憶體也方便管理動態生成的元素。需要阻止時用 stopPropagation()。」
