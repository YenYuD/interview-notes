前端效能

用到才載，初始下載只給最必要的

延遲加載（Lazy Loading）把資源的載入推遲到真正需要時。圖片進入視窗才下載、程式碼路由才載入——初始束縮小、互動更快。

三種常見應用

哪些資源可以延遲？

圖片 / 影片loading="lazy" 或 IntersectionObserver
JS 模組動態 import() 拆分 code bundle
React 元件React.lazy + Suspense
圖片延遲加載

HTML 原生 vs JavaScript

<!-- 方法 1：HTML 原生，瀏覽器自動處理 -->
<img src="photo.webp" loading="lazy" alt="..." />

// 方法 2：IntersectionObserver，更靈活
const observer = new IntersectionObserver(entries => {
  entries.forEach(entry => {
    if (entry.isIntersecting) {
      const img = entry.target;
      img.src = img.dataset.src; // 用 data-src 存真實 URL
      observer.unobserve(img);
    }
  });
});
document.querySelectorAll('img.lazy').forEach(img => observer.observe(img));
原生 loading="lazy" 最省事，IE 不支援但可接受。IntersectionObserver 控制更細（自定義觸發時機），也可用於無限捲動。
程式碼分割

React.lazy 路由切割

import React, { lazy, Suspense } from 'react';

const Dashboard = lazy(() => import('./Dashboard')); // 路由進入才下載

function App() {
  return (
    <Suspense fallback={<div>載入中...</div>}>
      <Dashboard />
    </Suspense>
  );
}
💡

程式碼分割搭配路由，每個頁面只下載自己需要的 JS。結合 prefetch 可在背景預載即將要訪問的路由，讓切換更流暢。

延伸追問

面試官可能再追

lazy loading 圖片會影響 CLS（累積版面偏移）嗎？

會。圖片延遲載入、尺寸未預定，載入後會撐開頁面造成 CLS。解法：一定要在 img 上設 width/height 屬性，或用 CSS aspect-ratio 預留空間。

動態 import() 和靜態 import 的差別？

靜態 import 在模組解析時就載入，打包工具會將其打進同一個 bundle；動態 import() 回傳 Promise，打包工具自動將其切割為獨立 chunk，僅在執行到該行時才下載。

面試這樣答

30 秒版本

「延遲加載的核心是只在需要時才下載資源，縮短初始載入時間。圖片用 loading="lazy" 最簡單，或用 IntersectionObserver 自定義觸發；JS 模組用動態 import() 做 code splitting，搭配 React.lazy 按路由分割。要注意圖片 lazy loading 要設好寬高，避免載入後跳動影響 CLS 分數。」
