前端效能

把重活交出去，主執行緒只管畫面

JS 是單執行緒的，一旦主執行緒被大計算佔滿，頁面就凍結。Web Worker 讓你開背景執行緒——運算不擋 UI，兩邊用 postMessage 溝通。

核心概念

主執行緒 vs Worker 執行緒

Worker 能做大量計算、資料解析、加密、圖像處理
Worker 不能做存取 DOM、讀 window、操作 UI
主執行緒：new Worker('worker.js') → worker.postMessage(data) 送出任務
Worker 執行緒：onmessage 接收，處理完用 postMessage(result) 回傳
主執行緒：worker.onmessage 接收結果，更新 UI
程式碼範例

最小可運作結構

// main.js — 主執行緒
const worker = new Worker('worker.js');
worker.postMessage([1, 2, 3, /*...大陣列*/]);
worker.onmessage = (e) => {
  console.log('結果：', e.data);  // 更新 UI
};

// worker.js — 背景執行緒
onmessage = (e) => {
  const result = e.data.map(x => x * x); // 重度計算
  postMessage(result);
};
Transferable Objects（如 ArrayBuffer）可用「轉移所有權」而非複製傳送，零成本跨執行緒傳大型資料。
限制與取捨

什麼時候不適合用

⚠️

Worker 建立有開銷，任務量太小時反而比直接執行慢。另外資料傳遞是「複製」，大物件頻繁傳送也有代價（除非用 Transferable）。

適合不適合
任務大量計算、影像/資料處理小量邏輯、需要同步存取 DOM
通訊Transferable（大緩衝區）頻繁傳送小物件
延伸追問

面試官可能再追

Service Worker 和 Web Worker 的差別？

Web Worker 是輔助主執行緒做計算；Service Worker 是網路代理，可攔截 fetch、控制快取，讓 PWA 離線運作。兩者都跑在背景執行緒但目的完全不同。

SharedArrayBuffer 是什麼？

讓主執行緒與 Worker 共用同一塊記憶體（不需複製），搭配 Atomics 處理競爭條件。因安全疑慮（Spectre）需開啟 COOP/COEP 標頭才能使用。

面試這樣答

30 秒版本

「Web Worker 把重度計算搬到背景執行緒，主執行緒繼續回應使用者操作。用 new Worker() 建立，透過 postMessage 雙向溝通。限制是無法碰 DOM，且資料傳遞預設是複製，大型資料要用 Transferable 傳所有權才有效率。適合圖像處理、大量運算、資料解析這類任務。」
