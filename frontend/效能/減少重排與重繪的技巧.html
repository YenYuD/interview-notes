前端效能

改個樣式，瀏覽器可能重算整頁版面

重排（reflow）＝重新計算幾何位置，最貴；重繪（repaint）＝只重畫外觀，較便宜。減少觸發次數、批次處理，是前端流暢的關鍵。

實戰技巧

怎麼少觸發

  • 批次 DOM 變更：用 documentFragment 或一次 innerHTML，別在迴圈裡逐筆改。
  • 改 class 而非逐條 style：一次套用一組樣式。
  • 分開讀寫：先讀完所有版面數值（offsetTop…）再統一寫，避免「layout thrashing」。
  • 動畫用 transform/opacity + requestAnimationFrame 對齊重繪週期。
  • 頻繁變動的元素酌用 will-change 提示瀏覽器。
⚠️

Layout thrashing：在迴圈裡「讀一下版面、寫一下樣式」反覆交錯，會強迫瀏覽器一直同步重排，效能直接崩。

延伸追問

面試官可能再追

哪些操作會強制同步重排？

寫了樣式後立刻讀 offsetWidth、getBoundingClientRect、scrollTop 等，會逼瀏覽器立即重算版面。要把讀取集中在寫入之前。

requestAnimationFrame 為什麼比 setTimeout 適合動畫？

它在每次重繪前被呼叫、和螢幕更新（約 60fps）同步，不會掉影格或多做無用更新，分頁隱藏時還會自動暫停。

面試這樣答

30 秒版本

「重排是重算版面幾何（最貴），重繪是重畫外觀。我會：批次 DOM 變更（fragment）、用 class 取代逐條 style、把讀取和寫入分開避免 layout thrashing、動畫只改 transform/opacity 並配 requestAnimationFrame。核心是減少觸發次數、避免強制同步重排。」
