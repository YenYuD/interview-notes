前端效能

不重複請求，是最快的網路優化

快取把資源副本存在更近的地方，下次直接取用。對前端而言，掌握瀏覽器快取和 HTTP 標頭的運作，是讓重複訪客秒開的關鍵。

三層快取

從近到遠的快取層級

Memory Cache：同一分頁內已下載的資源（最快，關分頁即消失）
Disk Cache（瀏覽器快取）：跨分頁、跨會話持久快取，受 HTTP 標頭控制
Service Worker Cache：攔截 fetch、可離線提供，開發者完全可控
HTTP 快取標頭

幾個最常用的設定

標頭用途範例值
Cache-Control主要控制指令max-age=3600, public
ETag資源指紋，驗證是否變更"abc123"
Last-Modified最後修改時間Mon, 26 May 2025 10:00:00 GMT
no-cache每次都驗證（非不快取）Cache-Control: no-cache
no-store完全不快取（敏感資料）Cache-Control: no-store
no-cache 不等於「不快取」，它的意思是「每次使用前先向伺服器驗證 ETag」。真的不要快取要用 no-store。
Service Worker 快取

可離線運作的快取策略

// install：預先快取靜態資源
self.addEventListener('install', e => {
  e.waitUntil(caches.open('v1').then(c =>
    c.addAll(['/index.html', '/app.js', '/style.css'])
  ));
});

// fetch：cache-first 策略
self.addEventListener('fetch', e => {
  e.respondWith(
    caches.match(e.request).then(r => r || fetch(e.request))
  );
});
延伸追問

面試官可能再追

部署新版本時怎麼讓快取失效？

最常見做法是在靜態檔名加 hash（如 app.a1b2c3.js）——每次內容變動檔名就變，舊快取自然失效。這稱為 Cache Busting。

Cache-Control: public 和 private 差在哪？

public 允許 CDN 和代理伺服器快取；private 只允許瀏覽器快取，不讓中間層快取（適合含個人資料的回應）。

面試這樣答

30 秒版本

「快取的核心是減少重複的網路請求。瀏覽器快取靠 HTTP 標頭控制：Cache-Control: max-age 設新鮮期、ETag 負責驗證是否變更。靜態資源加 content hash 做 cache busting 讓更新立即生效。需要離線能力就用 Service Worker 攔截請求、自定義快取策略。no-cache 和 no-store 是兩回事，前者每次驗證，後者才是真的不存。」
