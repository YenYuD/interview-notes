SPA 流暢，但搜尋引擎看不到你的內容

單頁應用靠 JavaScript 動態渲染，爬蟲若不執行 JS 就看到空殼。SSR（伺服器端渲染）和 SSG（靜態生成）是讓 SPA 兼顧體驗與 SEO 的兩條路。

問題根源

SPA 為什麼對 SEO 不友善？

傳統 SPA：伺服器只送一個幾乎空白的 HTML，所有內容靠 JS 跑完才出現。搜尋引擎爬蟲可能在 JS 執行前就離開，索引到空頁面。

⚠️

Googlebot 雖然可以執行 JS，但爬取優先級低於靜態 HTML，且 JS 渲染需等待排程，可能導致索引延遲數天。

兩種解法

SSR vs SSG：選哪個？

SSR（伺服器端渲染）SSG（靜態生成）
何時產生 HTML每次請求時在伺服器建置時預先產生
內容即時性每次最新建置時快照
效能TTFB 可能稍慢（需伺服器計算）最快（靜態檔直接 CDN）
適合場景電商、個人化頁面部落格、文件、行銷頁
React 方案Next.js getServerSidePropsNext.js getStaticProps
現代框架多數採 Hybrid（混合）：靜態頁 SSG、動態頁 SSR，搭配 ISR（增量靜態再生）在背景更新靜態頁。
SEO 輔助手段

除了 SSR/SSG 還能做什麼

Meta tags<title>、og:description 等
Canonical URL防止重複內容
Sitemap幫爬蟲找到所有頁面
Structured DataJSON-LD 讓 Google 顯示 Rich Results

面試官可能再追

ISR（增量靜態再生）是什麼？

Next.js 的 ISR 允許你設定 revalidate 秒數，靜態頁在背景定期重新生成，讓你兼得 SSG 的速度和動態更新能力，不需完整重新建置。

React Router 的 SPA 怎麼做 SEO？

純 CSR 方案可用 React Helmet 管理 meta tags，但根本解法是改用 Next.js / Remix。若無法遷移，可用 Prerender.io 等服務為爬蟲提供預渲染的靜態 HTML。

面試這樣答

30 秒版本

「SPA 的 SEO 問題在於內容由 JS 動態產生，爬蟲可能看到空殼。解法有兩種：SSR 每次請求都在伺服器渲染完整 HTML，適合動態內容；SSG 建置時預產生靜態 HTML，適合內容較固定的頁面，部署到 CDN 速度最快。Next.js 可以混用這兩種模式，搭配 ISR 做到靜態頁的定期更新。」
