前端效能

script 放哪、加什麼屬性，決定頁面能多快渲染

預設 <script> 會阻塞 HTML 解析，讓頁面「凍住」等腳本跑完。async 和 defer 讓下載和解析平行進行，差別在於執行時機。

三種行為對照

一圖勝千言

屬性下載時機執行時機執行順序
<script>遇到立即下載（阻塞解析）下載完立即執行（阻塞解析）按出現順序
async與 HTML 解析並行下載完立即執行（可能中斷解析）不保證順序
defer與 HTML 解析並行HTML 解析完成後（DOMContentLoaded 前）按出現順序
<script>：HTML ▓▓▓ — 等下載 — 執行 — HTML 繼續。每次都凍住。
async：HTML ▓▓▓▓▓▓▓▓ 同時下載，下載完就插進來執行，順序不定。
defer：HTML ▓▓▓▓▓▓▓▓ 同時下載，HTML 全部解析完才按順序執行。
選哪個

場景決定屬性

預設 <script>需要立即執行且無法移動位置時
async獨立腳本：Analytics、廣告
defer依賴 DOM 或需要順序的主程式
💡

現代做法：大多數腳本用 defer，放在 <head> 或 <body> 底部皆可。獨立的第三方腳本（GA、廣告）用 async。不依賴 DOM、需要最快執行的關鍵腳本用預設 script 但盡量精簡。

⚠️

async 和 defer 只對有 src 的外部腳本有效，行內腳本（inline script）會被忽略這兩個屬性。

延伸追問

面試官可能再追

type="module" 的腳本預設行為是？

模組腳本預設就是 defer 行為——非同步下載、HTML 解析完才依序執行，且模組腳本只執行一次。加 async 的話會變成下載完立即執行（類似 async 行為）。

defer 腳本保證在 DOMContentLoaded 前執行，對嗎？

對。defer 腳本全部執行完畢後，才觸發 DOMContentLoaded 事件，所以可以安全操作 DOM。

面試這樣答

30 秒版本

「三種屬性決定腳本的下載和執行時機。預設 script 阻塞 HTML 解析，遇到就停下來等；async 和 defer 都跟 HTML 並行下載，差別在執行：async 下載完立即執行、順序不固定，適合獨立腳本；defer 等 HTML 解析完再依序執行，適合需要 DOM 的主程式。現代專案大部分腳本我都用 defer。」
