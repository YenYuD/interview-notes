前端效能

事件狂噴，但你不必每次都處理

輸入、捲動、resize 會在短時間觸發上百次。防抖＝等你停下來再做一次；節流＝固定間隔最多做一次。

防抖 Debounce節流 Throttle
行為停止觸發後延遲執行一次固定間隔最多執行一次
適用搜尋輸入、自動儲存、表單驗證捲動、resize、滑鼠移動、無限載入
關鍵字「等你說完」「定期回報」
// 防抖：每次呼叫都重設計時器
function debounce(fn, d){ let t; return (...a)=>{ clearTimeout(t); t=setTimeout(()=>fn(...a), d); }; }
// 節流：時間窗內只放行一次
function throttle(fn, l){ let on; return (...a)=>{ if(!on){ fn(...a); on=true; setTimeout(()=>on=false, l); } }; }
延伸追問

面試官可能再追

防抖要不要 leading edge？

可加參數：leading 在第一次立即執行、trailing 在停止後執行。搜尋常用 trailing；按鈕防連點常用 leading。

React 裡怎麼用？

用 useMemo/useRef 保住同一個 debounced 函式（別每次渲染重建），或用 lodash 的 debounce/throttle，卸載時記得 cancel。

面試這樣答

30 秒版本

「兩者都在限制函式執行頻率。防抖是停止觸發後延遲執行一次，適合搜尋輸入這種『等使用者說完再發 API』；節流是固定間隔最多執行一次，適合捲動、resize 這種要『定期回應但別太頻繁』。實作上防抖每次重設計時器，節流則設時間窗放行。」
