行為面試考的是你怎麼思考，不是你做過什麼

軟實力題沒有標準答案，但有結構。STAR 原則（Situation → Task → Action → Result）讓你把每個經歷轉成有說服力的故事。準備 3~5 個可複用的故事，面對大多數行為面題都能從容應答。

STAR 框架

把每個經歷轉成面試故事

S

Situation — 背景

一句話交代當時的情境，讓面試官快速理解脈絡。不要過度鋪陳，20 秒內說完。

T

Task — 任務

你的角色是什麼？需要達成什麼目標？面試官想知道你的責任範圍。

A

Action — 行動

這是核心：你具體做了什麼？要說「我」，不是「我們」。展示你的思考過程和決策依據。

R

Result — 結果

量化成果最有力（「減少 40% 首屏時間」、「提升轉換率 15%」）。說不出數字時，描述質性影響也可以。

高頻題目解析

四題拆解與答題原則

題目答題重點避免
遇過最棘手的問題 強調分析過程：怎麼定位問題？試了哪些方案？最終帶來什麼效益？ 選太小的問題，或說「我沒遇過什麼大問題」
為什麼離職 聚焦「追求成長」：更大挑戰、貴公司的產品方向、不同的技術棧 抱怨前公司文化、主管或待遇
資深工程師需要什麼 技術深度 + 解題能力 + Mentorship + 商業思維，至少說三個維度 只說「技術強」，沒有提到協作與影響力
多專案同時 deadline 優先級評估 → 拆解 → 快速完成簡單任務 → 及早溝通風險 只說「努力完成全部」，沒有提到溝通
💡

面對多專案優先級題：先快速交付最小的（拿掉心理負擔）→ 再並行推進中等難度 → 難的任務早點拆解、早點同步風險給主管。

資深工程師定義

四個維度，不只是「技術強」

維度 1 技術深度與廣度：能設計架構，也能快速學習新技術
維度 2 解決問題的能力：面對未知錯誤有系統性的分析與定位方法
維度 3 Mentorship：帶領新人、做 Code Review、提升團隊整體代碼品質
維度 4 商業思維：理解技術決策如何影響產品目標，能說出 ROI
延伸追問

面試官可能再追

如果和 PM 或設計師意見不合，你怎麼處理？

用 STAR 說一個真實故事，重點放在：先理解對方的出發點（用戶需求？時程壓力？）→ 用數據或技術可行性提出替代方案 → 最終達成共識的過程。展示你的溝通方式是協作而非對抗。

你如何讓自己持續成長？

具體說出你的學習習慣：訂閱哪些技術 newsletter、看哪些 conference talk、有沒有 side project 或開源貢獻、如何反思每個 sprint 的學習。具體比空泛的「喜歡學習」有力。

面試這樣答

30 秒版本（資深工程師定義）

「我認為資深工程師要有四個維度：技術深度能設計可擴展的架構、解題能力能系統性定位未知問題、Mentorship能提升團隊整體的代碼品質與開發速度，還有商業思維——能把技術決策和產品目標連結起來，說出為什麼現在做這件事比做別的事更有價值。」
