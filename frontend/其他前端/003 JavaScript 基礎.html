async/await 是語法糖，但底下是整個 Promise 機制

JavaScript 基礎面試最常考 async/await 與錯誤處理。理解它是 Promise 的包裝，才能回答「為什麼不能在頂層直接 await」和「如何同時發多個請求」。

核心概念

async/await 是什麼

問題答案
本質Promise 的語法糖，讓非同步程式碼讀起來像同步
限制await 只能在 async 函式（或 Top-level await ESM）內使用
錯誤捕捉用 try…catch 包住，等同 .catch()
並行寫法Promise.all([a(), b()]) 同時發起，不要連續 await
// ❌ 連續 await（a 完成才發 b，慢）
const a = await fetchA();
const b = await fetchB();

// ✅ 並行（同時發）
const [a, b] = await Promise.all([fetchA(), fetchB()]);
易錯點

三個常見誤區

誤區 1 連續 await 當作並行——實際上是串行，浪費等待時間
誤區 2 忘記 try/catch——未捕捉的 rejected Promise 會變成 UnhandledRejection
誤區 3 在非 async 函式裡用 await——SyntaxError，直接編譯失敗
⚠️

Promise.all 有一個 reject 就整批失敗。若需要「有幾個成功就算幾個」，改用 Promise.allSettled。

延伸追問

面試官可能再追

async 函式回傳什麼？

永遠回傳一個 Promise。就算你 return 42，呼叫方收到的是 Promise.resolve(42)。

Promise.all vs Promise.allSettled vs Promise.race 差在哪？

all：全部成功才 resolve，任一失敗立刻 reject。allSettled：等全部結束，不管成敗，回傳每筆狀態。race：第一個結束（不管成敗）就決定結果。

什麼是 microtask queue？和 async/await 有何關係？

Promise 的 .then callback（包含 await 後面的程式碼）進 microtask queue，比 setTimeout（macrotask）早執行。所以 await 之後的程式碼，在當前同步執行完後立即執行，早於 setTimeout(fn, 0)。

面試這樣答

30 秒版本

「async/await 是 Promise 的語法糖，讓非同步程式碼讀起來像同步。await 必須在 async 函式內，用 try/catch 捕捉錯誤。需要同時發多個請求時，我會用 Promise.all 而不是連續 await，避免不必要的串行等待。底層來說，await 之後的程式碼進入 microtask queue，比 setTimeout 更早執行。」
