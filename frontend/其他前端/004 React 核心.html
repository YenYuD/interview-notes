Virtual DOM 不是魔法，是精準的差異比對

React 的效能核心是 Reconciliation：先在記憶體裡算出新舊差異，再最小化操作真實 DOM。理解這個機制，key / state / props / refs 的設計就全說得通了。

核心機制

Virtual DOM 運作流程

1

State 改變

元件呼叫 setState 或 hook 更新，觸發重新渲染。

2

產生新 Virtual DOM

React 在記憶體中建立新的 JS 物件樹，代表預期的 UI 狀態。

3

Diffing 演算法

新舊 Virtual DOM 逐節點比較，同層比較、不同 type 直接替換、列表靠 key 識別。

4

Commit — 更新真實 DOM

只操作有差異的節點，最小化 DOM 操作成本。

四大常考題

key、state、props、refs 一次搞清楚

概念一句話踩雷提醒
key Diffing 的唯一識別，幫 React 判斷哪筆新增/刪除/移動 別用 index 當 key——重排時會導致狀態錯亂
props 父傳子的唯讀資料，元件不能自己改 過深的 props drilling 改用 Context 或狀態管理
state 元件內部的可變資料，改動觸發重新渲染 不要直接 mutate state（arr.push），要產生新物件
useRef 直接訪問 DOM 節點，或存不觸發 re-render 的可變值 計時器 ID、第三方插件操作點 — 不要拿來存顯示用的狀態
⚠️

把 index 當 key 是常見的效能陷阱：列表重排時，React 會以為每個元素「沒變」，導致輸入框等有 state 的子元件狀態出錯。

延伸追問

面試官可能再追

React 的 Diffing 演算法有哪些假設前提？

1. 不同 type 的元素產生不同的樹（直接拆掉重建）。2. 列表元素靠 key 識別。這讓複雜度從 O(n³) 降到 O(n)。

什麼時候用 useRef 而不是 useState？

當你要存的值「變了也不想觸發 re-render」時，例如計時器 ID、前一次 props 值、第三方 DOM 插件的實例。若值變動需要更新畫面，才用 useState。

Controlled vs Uncontrolled component 差在哪？

Controlled：input value 由 React state 控制，每次輸入都觸發 setState。Uncontrolled：用 ref 直接讀 DOM 值，表單提交時才讀取。Controlled 更易於驗證與聯動，Uncontrolled 適合簡單表單。

面試這樣答

30 秒版本

「React 在 state 改變時，先產生新的 Virtual DOM，透過 Diffing 演算法和舊的比較差異，最後只更新有變動的真實 DOM 節點。key 是 Diffing 在列表中的識別標誌，用 index 當 key 會在重排時導致狀態錯亂。props 是唯讀的父傳子資料，state 是元件內部可變狀態，而 useRef 用來直接存取 DOM 或儲存不需觸發 re-render 的值。」
