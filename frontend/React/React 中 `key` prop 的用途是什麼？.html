React 核心

key 是清單項目的身分證

它讓 React 在清單變動時，認得「誰是誰」——哪些被新增、刪除、移動。用陣列索引當 key 在重排時會出 bug，要用穩定的唯一 id。

DEMO — 用 index 當 key 的災難

在清單最前面插入一筆，會怎樣？

每個項目有自己的輸入框（未受控狀態）。在最前面插入「新項目」，比較兩種 key 策略下，輸入內容跟不跟對：

key 策略
用 index：插入後每個項目的 index 全部位移，React 以為「內容變了」，把舊的 DOM 狀態錯配到不同資料 → 輸入框內容跑掉。用穩定 id：React 認得每筆，正確地只插入新節點。
為什麼需要 key

它幫 React diff 清單

  • 高效更新：靠 key 快速判斷誰新增、刪除、移動，最小化 DOM 操作。
  • 避免 bug：key 對應到正確的元件實例與其內部 state。
✕

兩個常見錯誤：①用 index 當 key（清單會重排/增刪時出錯）；②重複的 key（同一清單裡 key 必須唯一）。

延伸追問

面試官可能再追

什麼情況下 index 當 key 可以接受？

清單是靜態、不重排、不增刪、且項目沒有自身 state 時，用 index 沒問題。一旦會動，就要用穩定 id。

key 要全域唯一嗎？

不用，只要在同一個清單（兄弟之間）唯一即可。

可以用 key 強制重置組件嗎？

可以。改變一個組件的 key 會讓 React 視為全新組件、卸載重建，常用來重置表單狀態。
