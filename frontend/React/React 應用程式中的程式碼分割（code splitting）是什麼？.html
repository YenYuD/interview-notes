程式碼分割：讓使用者只下載當前用到的程式碼

打包後的 bundle 越大，初始載入越慢。Code Splitting 把 bundle 拆成多個 chunk，用到時才按需載入（lazy load）。React 內建 React.lazy + Suspense 讓這件事變得極簡。

實作

React.lazy + Suspense：三行搞定懶載入

import { lazy, Suspense } from 'react';

// 動態 import → Webpack/Vite 自動拆成獨立 chunk
const Analytics = lazy(() => import('./Analytics'));
const Settings  = lazy(() => import('./Settings'));

function App() {
  return (
    <Suspense fallback={<Spinner />}>
      <Routes>
        <Route path="/analytics" element={<Analytics />} />
        <Route path="/settings" element={<Settings />} />
      </Routes>
    </Suspense>
  );
}
✅

最佳分割點是路由層級：每個頁面一個 chunk，使用者導航到哪裡才載入哪個頁面的程式碼。

分割策略

什麼時候分割、分割多細

適合分割路由頁面、只在特定場景出現的重型組件（圖表庫、富文字編輯器）
不值得分割極小的組件、首屏必須立即顯示的 UI
過度分割反而增加 HTTP 請求數，網路延遲的成本可能超過節省的 JS 解析時間。用 Chrome DevTools 的 Coverage 分析才能找出真正值得分割的位置。
延伸追問

面試官可能再追

React.lazy 和動態 import() 有什麼關係？

React.lazy 接受一個回傳 import() 的函式。動態 import() 是 ES 標準，讓打包工具（Webpack/Vite）自動拆分程式碼；React.lazy 則把非同步載入的模組包裝成可在 JSX 使用的組件。

預取（Prefetch）和懶載入有什麼差別？

懶載入是「用到時才載入」；預取是「目前不需要，但預判快要用到，提前在背景下載」。可以在 import() 加 webpack magic comment：/* webpackPrefetch: true */。
