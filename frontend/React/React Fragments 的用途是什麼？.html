Fragment：回傳多個元素，卻不污染 DOM

React 組件只能回傳一個根元素，但加多餘的 <div> 包裹會破壞 CSS 結構、增加 DOM 節點。Fragment 讓你把多個元素組成一組，不產生任何實際 DOM 節點。

兩種寫法

簡寫 vs 完整語法

簡寫（99% 情況） <>...</>
完整語法（需要 key 時） <React.Fragment key={id}>...</React.Fragment> 
// 渲染清單時需要 key，必須用完整語法
{items.map(item => (
  <React.Fragment key={item.id}>
    <dt>{item.term}</dt>
    <dd>{item.desc}</dd>
  </React.Fragment>
))}
⚠️

簡寫 <> 不支援 key 屬性，在列表渲染時必須改用 <React.Fragment key={...}>。

為什麼重要

三個不多包 div 的理由

  • 保持語義：在 <table>、<dl>、<ul> 等結構中，多餘的 <div> 會讓 HTML 不合法。
  • CSS 不受干擾：Flexbox/Grid 計算子元素時，多餘的包裹層會破壞排版。
  • 效能微幅提升：更少的 DOM 節點 = 更少的記憶體和渲染時間。
延伸追問

面試官可能再追

Fragment 和空 div 在效能上差多少？

Fragment 完全不產生 DOM 節點，大型清單中節省的節點數可觀。但對一般小型組件而言差距極小，主要價值在語義正確性而非效能。

可以在 Fragment 上加 className 或 style 嗎？

不行，Fragment 不產生 DOM 元素，因此無法附加任何 CSS 屬性。需要樣式時還是得用真實的 HTML 標籤。

面試這樣答

30 秒版本

「Fragment 讓組件可以回傳多個同層元素，不產生額外的 DOM 節點。這在渲染 table 列、dl 術語等需要嚴格 HTML 結構的場景特別重要——多包一層 div 會讓 HTML 不合法。日常用簡寫 <></>，需要 key 的清單則用 React.Fragment 完整語法。」
