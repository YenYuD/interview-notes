REACT 基礎

State 是組件的記憶，Props 是外部傳入的命令

這是 React 資料流最核心的區分：state 由組件自己管理、可以改變；props 由父組件決定、子組件唯讀。搞清楚「誰擁有這筆資料」，就知道該用哪個。

決策法則

這筆資料該放 state 還是 props？

這筆資料會隨時間改變嗎？不會 → 不需要 state，直接用 props 或常數。
有多個組件需要這筆資料嗎？有 → 提升 state 到共同祖先（state lifting），透過 props 傳下去。
只有這個組件自己用？是 → 放在這個組件的 state 裡。
延伸追問

面試官可能再追

子組件能修改自己的 props 嗎？

不行，props 是唯讀的。如果子組件需要「通知父組件更新」，父組件應傳一個 callback 函式（如 onChange）給子組件，子組件呼叫它。

State 和 Context 有什麼關係？

Context 是「跨層傳遞的 props」，讓你不用每層手動傳。Context 的值通常仍是某個組件的 state，只是透過 Context API 廣播給後代組件。

30 秒版本

「State 是組件自己管理的可變資料，更新時觸發重渲染；Props 是父組件傳入的唯讀屬性，子組件不能直接修改。判斷該用哪個的關鍵是：這筆資料的擁有者是誰？若只有這個組件需要，放 state；若需要跨組件共享或由父組件控制，用 props。子組件需要影響父組件時，透過父傳下來的 callback 函式溝通。」
