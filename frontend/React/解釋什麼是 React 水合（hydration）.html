水合（Hydration）：靜態 HTML 「活過來」的接管過程

SSR 把 HTML 傳給瀏覽器，頁面可以立即顯示——但還不能互動。Hydration 是 React 在客戶端「認出」伺服器生成的 HTML、附加事件處理器、初始化 state 的過程，讓頁面從靜態變為可互動。

水合流程

三個階段

伺服器生成 HTML：含完整內容，瀏覽器接收後立即顯示（可見但不可互動）
載入並執行 JavaScript：React bundle 下載並解析
水合：React 「認出」已有的 DOM 節點，附加事件監聽器，不重新建立節點 → 頁面可互動
// React 18 的 SSR 入口
import { hydrateRoot } from 'react-dom/client';
hydrateRoot(document.getElementById('root'), <App />);
水合不匹配

最常見的 SSR 陷阱

⚠️

如果伺服器和客戶端渲染的 HTML 不同，React 會警告 Hydration Mismatch。常見原因：typeof window 判斷、Date.now()、Math.random()、瀏覽器特有的狀態。解法：確保 SSR 和 CSR 邏輯完全一致，或用 useEffect 把客戶端專屬邏輯延後。

延伸追問

面試官可能再追

水合期間頁面可以互動嗎？

不能。這段時間叫做「hydration gap」——使用者看得到內容，但事件處理器尚未附加。使用者的互動（點擊、輸入）不會有反應，這是 SSR 的已知 UX 問題。React 18 的 Selective Hydration 和 Streaming SSR 在緩解這個問題。

React 18 的 Selective Hydration 是什麼？

React 18 允許把 SSR 輸出串流（streaming）傳給瀏覽器，並且優先水合使用者正在互動的區域。搭配 <Suspense> 邊界，重要區域先水合，其他區域延後，改善互動延遲。

面試這樣答

30 秒版本

「水合是 SSR 的後半段：瀏覽器接收到伺服器的靜態 HTML 後，React 在客戶端載入並認出現有 DOM 節點，附加事件處理器，不重新建立節點，讓頁面從可見變為可互動。最常見的問題是水合不匹配——伺服器和客戶端渲染結果不同時 React 會警告。React 18 的 Selective Hydration 讓重要區域優先水合，改善互動延遲。」
