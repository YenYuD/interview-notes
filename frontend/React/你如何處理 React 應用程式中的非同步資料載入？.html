REACT 資料獲取

非同步資料載入：useEffect + 三個 state 是基礎，Custom Hook 是最佳實踐

React 的資料獲取核心模式是在 useEffect 內發起請求，用三個 state 管理 data / loading / error。把這個模式封裝成 Custom Hook，讓多組件共用並減少重複程式碼。

基礎模式

useEffect + 三個 state

function DataFetchingComponent() {
  const [data, setData]       = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError]     = useState(null);

  useEffect(() => {
    async function fetchData() {
      try {
        const res    = await fetch('https://api.example.com/data');
        const result = await res.json();
        setData(result);
      } catch (err) {
        setError(err);
      } finally {
        setLoading(false);
      }
    }
    fetchData();
  }, []);   // 空陣列 = 只在 mount 時執行一次

  if (loading) return <div>載入中...</div>;
  if (error)   return <div>錯誤：{error.message}</div>;
  return <div>{JSON.stringify(data)}</div>;
}
⚠️

不能直接在 useEffect 的回呼函式宣告為 async——因為 async 函式回傳 Promise，而 useEffect 的回傳值必須是清除函式或 undefined。改在裡面定義並呼叫一個 async 函式。

最佳實踐

封裝成 useFetch Custom Hook

// useFetch.js - 可跨組件重用
function useFetch(url) {
  const [data, setData]       = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError]     = useState(null);

  useEffect(() => {
    let cancelled = false;   // 防止 race condition
    async function fetchData() {
      try {
        const res = await fetch(url);
        if (!cancelled) setData(await res.json());
      } catch (err) {
        if (!cancelled) setError(err);
      } finally {
        if (!cancelled) setLoading(false);
      }
    }
    fetchData();
    return () => { cancelled = true; };   // 清除：取消舊請求的 state 更新
  }, [url]);

  return { data, loading, error };
}

// 組件使用方式
const { data, loading, error } = useFetch('https://api.example.com/data');
生產環境建議考慮 TanStack Query（React Query） 或 SWR：自動快取、去重複請求、背景重新驗證、stale-while-revalidate 策略，遠比手寫 Custom Hook 完善。

什麼是 Race Condition？如何防止？

當 URL 快速切換時，後發出的請求可能比先發出的更早回應，導致舊資料覆蓋新資料。防止方式：在 useEffect 的清除函式（cleanup）設一個 cancelled flag，若 effect 已被清除則不更新 state；或用 AbortController 取消前一個請求。

React Query / SWR 解決了哪些手寫 useFetch 沒有解決的問題？

自動的快取管理（相同 key 的請求不重複發）、背景重新驗證（視窗 focus 時自動 refetch）、分頁與無限捲動、樂觀更新（optimistic update）、請求去重複、全域 loading/error 狀態。這些手寫都要從零處理。
