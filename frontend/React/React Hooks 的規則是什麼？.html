REACT HOOKS

Hooks 有兩條鐵律——違反就壞掉，且 lint 會抓到你

React 用呼叫順序追蹤每個 Hook 的狀態，若順序在不同渲染間改變，狀態就會對應到錯的 Hook。兩條規則確保順序永遠穩定。

規則一

只在最頂層呼叫 Hook

不要在迴圈、條件判斷或巢狀函式裡呼叫 Hook。

正確 // 始終在函式最上層
const [x, setX] = useState(0);
useEffect(() => {}, []);
錯誤 — 在 if 裡 if (condition) {
  const [x] = useState(0); // ✗
}
⚠️

如果某次渲染 condition 為 false，這個 Hook 被跳過，後面所有 Hook 的索引位移，狀態全部亂掉。

規則二

只在 React 函式中呼叫 Hook

有效的呼叫場所只有兩個：

  • 功能組件（Function Component）的函式主體
  • 自定義 Hook（Custom Hook）的函式主體（函式名稱必須以 use 開頭）
✅

安裝 eslint-plugin-react-hooks 並開啟 rules-of-hooks: error，lint 會在 CI 就擋下違規，不需靠記憶。

延伸追問

面試官可能再追

為什麼 React 用呼叫順序追蹤 Hook，而不是名稱或 key？

設計決策：用順序讓 API 更簡潔（不需傳 key）。代價就是順序必須穩定，因此有了這兩條規則。

自定義 Hook 一定要以 use 開頭嗎？

是的。這是 eslint-plugin-react-hooks 辨識自定義 Hook 的依據。不以 use 開頭的函式，lint 不會檢查裡面的 Hook 呼叫。

面試這樣答

30 秒版本

「React Hooks 有兩條規則：第一，只在最頂層呼叫，不能在迴圈或條件裡，因為 React 靠呼叫順序追蹤每個 Hook 的狀態，順序若不穩定狀態就會錯位；第二，只在功能組件或自定義 Hook 內呼叫，確保 React 能管理生命週期。實務上裝 eslint-plugin-react-hooks 就能自動檢查。」
