Render Props：把「渲染決定權」交給呼叫者

Render Props 是一種共享邏輯的模式：把值為函式的 prop 傳給組件，由該函式決定要渲染什麼。邏輯封裝在組件裡，UI 由外部決定，做到關注點分離。

核心概念

「你給我資料，我決定怎麼畫」

// MouseTracker 封裝邏輯，render prop 決定 UI
function MouseTracker({ render }) {
  const [pos, setPos] = useState({ x: 0, y: 0 });

  return (
    <div onMouseMove={e => setPos({ x: e.clientX, y: e.clientY })}>
      {render(pos)}  {/* 把資料吐給外部決定渲染 */}
    </div>
  );
}

// 使用端可隨意決定要顯示什麼
<MouseTracker render={({ x, y }) => <p>({x}, {y})</p>} />
「Render Prop」不一定要叫做 render，也常見 children 函式（Children as Function 模式）。
現代替代

Render Props vs Custom Hooks

方式優點缺點
Render Props與類別組件相容；UI 控制明確巢狀深時產生「wrapper hell」
Custom Hook簡潔、可組合；Hooks 時代首選只能用在功能組件
ℹ️

React Hooks 推出後，大多數 Render Props 場景都可以用自定義 Hook 取代，程式碼更簡潔。但在需要支援類別組件或需要明確控制渲染結構時，Render Props 仍有用武之地。

延伸追問

面試官可能再追

Render Props 和 HOC 解決同樣的問題嗎？

是，兩者都是共享邏輯的模式。HOC 在元件外包裹一層，Render Props 把控制權傳回給呼叫者。現代 React 首選 Custom Hook，但了解 Render Props 對讀懂舊程式碼仍重要。

Children as Function 是什麼？

把 children 當成函式傳入：<Tracker>{(data) => <span>{data}</span>}</Tracker>，組件內部 this.props.children(data) 呼叫它，本質和 Render Props 相同。

面試這樣答

30 秒版本

「Render Props 是傳一個值為函式的 prop，組件把資料傳給這個函式，由呼叫者決定如何渲染。好處是邏輯封裝在組件裡，UI 完全彈性。Hooks 出現後大多改用 Custom Hook 取代，因為更簡潔；但在需要明確控制渲染結構或搭配類別組件時，Render Props 仍是有效選擇。」
