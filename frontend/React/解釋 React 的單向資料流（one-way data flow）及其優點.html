REACT 架構

單向資料流：資料只能往下傳，訊息靠 callback 往上回

React 的資料流是嚴格的由上到下：父組件透過 props 傳資料給子組件，子組件只能讀。若子組件需要「通知」父組件，就呼叫父組件傳下來的 callback 函式。這讓資料流可預測、易追蹤。

資料流方向

Props 向下，Events 向上

Parent 持有 state（data），透過 props 往下傳，並把 handleChange callback 也傳下去
Child 從 props 讀取 data（唯讀），使用者操作時呼叫 props.onChange(newValue)
Parent 的 handleChange 被觸發，更新自己的 state，React 重渲子組件
ℹ️

「資料往下，事件往上」是 React 單向資料流的核心口訣。這也是為什麼 React 和雙向綁定（Angular）的思維方式不同。

優點

為什麼單向比雙向好

面向單向（React）雙向（ng1 style）
可預測性資料來源唯一，追蹤容易任何層都能改狀態，難以追蹤
除錯看 state 就知道 UI 會長什麼樣連鎖更新難以重現
效能React 可優化重渲策略過度觸發更新

面試官可能再追

prop drilling 是什麼？如何解決？

Prop drilling 是資料需要穿越多層中間組件才能到達目標子組件，中間層組件被迫傳遞不關心的 props。解法：Context API（避免逐層傳遞）或狀態管理工具（Redux、Zustand）。

單向資料流和 Flux/Redux 有什麼關係？

Flux 模式把單向資料流擴展到全域狀態管理層：所有狀態變更都必須透過 Action → Dispatcher → Store，而不是直接修改。Redux 繼承並簡化了這個模式。

面試這樣答

30 秒版本

「React 的單向資料流是：資料透過 props 由父往子傳遞，子組件只能讀取不能修改。子組件要影響父組件的狀態，只能呼叫父組件傳來的 callback 函式——『資料往下，事件往上』。好處是資料來源唯一、行為可預測，任何時刻都能透過 state 推導出 UI 長什麼樣，大幅降低除錯難度。」
