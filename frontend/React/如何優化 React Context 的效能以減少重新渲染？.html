Context 效能優化：三招讓只有真正需要更新的組件重渲

Context value 改變，所有 consumer 都重渲——這個問題有解。三個層級的解法：拆分 Context（按職責分開）、記憶 value 物件（useMemo）、選擇性訂閱（use-context-selector）。

解法一

拆分 Context：把高頻和低頻的分開

// ❌ 合在一起：user 改變時 theme 的 consumer 也重渲
const AppContext = { user, theme, count };

// ✅ 分開：各自 consumer 只訂閱自己關心的
const UserContext   = createContext();  // 登入資訊（低頻）
const ThemeContext  = createContext();  // 主題（極低頻）
const CountContext  = createContext();  // 計數（高頻，隔離）
解法二

useMemo 記憶 value 物件

function AppProvider({ children }) {
  const [state, dispatch] = useReducer(reducer, init);

  // 沒有 useMemo：每次 Provider 重渲都建立新物件
  // 有 useMemo：state 不變就用同一個引用
  const value = useMemo(
    () => ({ state, dispatch }),
    [state]   // dispatch 穩定，不需加
  );

  return <AppContext.Provider value={value}>{children}</AppContext.Provider>;
}
✅

狀態（state）和 dispatch（setter）分離成兩個 Context 也是常見進階模式：只需要 dispatch 的組件不因 state 改變而重渲。

解法三

use-context-selector：細粒度訂閱

import { useContextSelector } from 'use-context-selector';

// 只訂閱 user.name，其他欄位變不觸發重渲
const name = useContextSelector(UserContext, ctx => ctx.user.name);
延伸追問

面試官可能再追

React.memo 能擋住 Context 觸發的重渲嗎？

不能。React.memo 只比對 props，而 Context 是透過 useContext 訂閱，繞過 props 觸發重渲。React.memo 對 Context consumer 無效。

把 state 和 dispatch 分成兩個 Context 有什麼好處？

只 dispatch action 的組件（如按鈕）不需要訂閱 state，分開後這些組件不會因 state 變更重渲，在大型表單或頻繁更新的場景效能明顯更好。

面試這樣答

30 秒版本

「優化 Context 效能有三個層級：一是拆分 Context，按更新頻率把高頻和低頻資料分開，讓 consumer 只訂閱自己需要的；二是用 useMemo 記憶 value 物件，避免每次 Provider 重渲都建立新引用；三是用 use-context-selector 做細粒度訂閱，只訂閱 Context 裡特定的欄位。React.memo 對 Context 觸發的重渲無效。」
