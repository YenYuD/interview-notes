REACT 測試

三層測試金字塔：從組件單元到端對端流程的完整策略

React 測試以 Jest（測試執行器）+ React Testing Library（以使用者視角渲染組件）為主力，再搭配 Cypress 跑 E2E 流程。三層覆蓋讓你在速度與信心之間取得平衡。

測試工具

三個層次對應三種工具

層次工具測試目標速度
單元測試Jest + RTL單一組件渲染與邏輯最快
整合測試Jest + RTL多組件互動、狀態流動中等
E2E 測試Cypress完整使用者流程最慢
✅

React Testing Library 的核心原則：以使用者能感知的方式查詢元素（優先用 getByRole、getByText，而非 class 或 id），讓測試更貼近真實使用行為。

單元 ＋ 整合測試

Jest + React Testing Library

// 單元測試：確認組件正確渲染
import { render, screen } from '@testing-library/react';
import MyComponent from './MyComponent';

test('顯示正確文字', () => {
  render(<MyComponent />);
  expect(screen.getByText('Hello, World!')).toBeInTheDocument();
});

// 整合測試：模擬使用者互動後驗證 UI 更新
import { render, fireEvent, screen } from '@testing-library/react';

test('點擊按鈕後更新子組件', () => {
  render(<ParentComponent />);
  fireEvent.click(screen.getByText('更新子組件'));
  expect(screen.getByText('子組件已更新')).toBeInTheDocument();
});
E2E ＆ 快照

Cypress 與 Snapshot 測試

// Cypress E2E：模擬真實登入流程
describe('登入流程', () => {
  it('應導向 dashboard', () => {
    cy.visit('/login');
    cy.get('input[name="username"]').type('user');
    cy.get('input[name="password"]').type('password');
    cy.get('button[type="submit"]').click();
    cy.url().should('include', '/dashboard');
  });
});
快照測試（Snapshot）用 expect(tree).toMatchSnapshot() 記錄組件的渲染輸出，後續變更時會 diff 比對。適合防止意外的 UI 迴歸，但過多快照會讓測試維護成本上升。
延伸追問

面試官可能再追

React Testing Library 為什麼不建議用 class selector 查詢元素？

RTL 的設計哲學是「測試使用者能感知的行為，而不是實作細節」。用 class 或 data-testid 查詢，若組件重構但行為不變，測試可能誤報失敗。優先用 getByRole（ARIA role）、getByText、getByLabelText，讓測試更具韌性。

什麼情況下需要 mock？

當測試涉及外部依賴（API 呼叫、計時器、瀏覽器 API）時用 Jest 的 jest.mock() 或 jest.spyOn()。隔離外部依賴讓測試穩定、可重複。API mock 也可用 MSW（Mock Service Worker），更貼近真實 HTTP 行為。
