useEffect vs useLayoutEffect：差在瀏覽器畫面繪製的前後

兩者都處理副作用，但執行時機不同：useEffect 在畫面繪製後非同步執行，不阻塞 UI；useLayoutEffect 在 DOM 變更後、繪製前同步執行，適合需要「先量完再畫」的場景。

Hook適合場景注意
useEffect API 請求、訂閱、事件監聽器、日誌 預設首選，99% 的副作用都用這個
useLayoutEffect 讀取 DOM 尺寸/位置後立即調整樣式（防閃爍） 同步執行會阻塞渲染，謹慎使用
✅

如果 useEffect 造成視覺閃爍（先畫錯、再修正），才考慮換成 useLayoutEffect。典型例子：tooltip 位置計算、動畫起始點測量。

延伸追問

面試官可能再追

SSR 時 useLayoutEffect 有什麼問題？

伺服器沒有 DOM，useLayoutEffect 在 SSR 時會發出警告，並且不會執行。解法：改用 useEffect，或用 typeof window !== 'undefined' 包裹。

cleanup 函式在 useLayoutEffect 中的執行時機？

cleanup 在下一次 effect 執行前、或組件卸載時執行，時機和 useEffect 相同。差別只在 effect 本身的執行時機（繪製前 vs 後）。
