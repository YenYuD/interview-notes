REACT 最佳實踐

這六個 React 反模式，讓 bug 悄悄進門

寫 React 最常見的壞習慣：直接改 state、用索引當 key、在 render 裡寫函式……每一個看似無害，卻可能讓你的應用程式出現難以追蹤的 bug 或效能問題。

六大反模式

看一眼就能記住的對比

反模式問題正確做法
直接修改 state React 偵測不到變化，UI 不更新 用 setState 或 useState setter 建立新物件
用陣列索引當 key 重排/增刪時 key 錯位，狀態對應到錯的節點 用資料的穩定唯一 ID
render 裡定義內聯函式 每次渲染建立新函式引用，子組件 memo 失效 用 useCallback 或提到組件外
深度巢狀 state 更新時需手動深度複製，容易遺漏 扁平化 state 結構；或用 Immer
用已棄用生命週期 componentWillMount 等不安全，可能觸發兩次 改用 useEffect 或 componentDidMount
缺少 key 的清單渲染 React 只能用位置對比，效率差、容易出 bug 每個列表項必須有唯一 key
最危險的一個

直接 mutate state：看似沒事，其實很危險

反模式 state.items.push(newItem);
setState(state); // 同一引用，React 不重渲
正確 setState(prev => ({
  ...prev,
  items: [...prev.items, newItem]
}));
延伸追問

面試官可能再追

過度使用 useEffect 算是反模式嗎？

是的！React 官方文件特別指出，如果你只是根據 props 或 state 計算衍生值、或同步兩個 state，這些都不需要 useEffect。過度使用 Effect 是 React 最常見的現代反模式之一。

過度使用 Context 是反模式嗎？

Context 頻繁變動時，所有 consumer 都會重渲，可能造成效能問題。對頻繁更新的全域狀態（如表單輸入），Context 並非最佳選擇，應考慮 Zustand 等外部工具。

面試這樣答

30 秒版本

「React 常見反模式包括：直接修改 state（React 偵測不到變化）、用陣列索引當 key（重排時狀態錯位）、在 render 裡定義內聯函式（每次新建引用破壞 memo 優化）。核心原則是：state 要不可變、key 要穩定唯一、副作用只在 useEffect 裡做。」
