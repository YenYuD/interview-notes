i18n：用函式庫讓文字跟著語言走，不寫死在組件裡

在地化（Localization）的核心原則是：組件裡不寫死任何文字，改用翻譯鍵（key），再由 i18n 函式庫根據當前語言查找對應翻譯。react-i18next 是最常見的選擇。

核心流程

設定、注入、使用——三步驟

建立翻譯檔：各語言各一個 JSON，key 統一，value 是各語言的翻譯
初始化 i18n：在 i18n.js 設定語言資源和預設語言
在組件使用：const { t } = useTranslation();，然後 t('key')
// en.json
{ "greeting": "Hello, {{name}}!", "save": "Save" }

// zh-TW.json
{ "greeting": "你好，{{name}}！", "save": "儲存" }

// 組件裡使用
function Header({ name }) {
  const { t } = useTranslation();
  return <h1>{t('greeting', { name })}</h1>;
}
進階考量

切換語言與懶載入翻譯

// 切換語言（i18n 物件透過 useTranslation 取得）
const { i18n } = useTranslation();
<button onClick={() => i18n.changeLanguage('zh-TW')}>
  繁體中文
</button>
多語言應用建議把翻譯檔懶載入（Backend plugin 或動態 import），避免把所有語言的 JSON 打包進主 bundle，影響初始載入速度。
延伸追問

面試官可能再追

在地化（l10n）和國際化（i18n）有什麼差別？

i18n（Internationalization）是把應用程式設計成「可支援多語言」的過程（抽出文字、日期格式等）；l10n（Localization）是為特定語言/地區實際翻譯和調整內容（填入翻譯檔）。i18n 是基礎建設，l10n 是實際工作。

除了文字，i18n 還需要處理哪些？

日期/時間格式（Intl.DateTimeFormat）、數字/貨幣格式（Intl.NumberFormat）、複數形式（英文 1 item vs 2 items）、RTL 文字方向（阿拉伯語、希伯來語）。

面試這樣答

30 秒版本

「React 應用程式在地化通常用 react-i18next：每種語言準備一個 JSON 翻譯檔，初始化 i18n 實例後，組件裡用 useTranslation hook 取得 t 函式，把組件文字從寫死的字串改成 t('key')。切換語言呼叫 i18n.changeLanguage。實務上還需處理日期、數字格式、複數形式，以及懶載入翻譯檔避免 bundle 過大。」
