REACT STATE

直接改 state 是靜默的 bug：React 偵測不到、UI 不更新

React 用引用比較（reference equality）偵測 state 是否改變。直接修改物件或陣列的值，引用沒變，React 以為 state 沒動過，不觸發重渲——畫面顯示過時資料。

問題根源

為什麼直接 mutate 不行

// ⚠️ 直接修改：引用沒變 → React 不重渲
const [items, setItems] = useState([1, 2, 3]);

// 錯誤：修改了陣列內容，但 items 引用不變
items.push(4);
setItems(items);  // 傳入同一個引用，React 認為沒變化

// 正確：建立新陣列
setItems([...items, 4]);  // 新引用 → React 知道要重渲
⚠️

物件也一樣：state.count = 1; setState(state) ← 傳同一個引用，Object.is 比較結果是相等，React 跳過重渲。

正確做法

永遠建立新的值

操作錯誤（mutate）正確（新值）
陣列新增arr.push(x)[...arr, x]
陣列刪除arr.splice(i, 1)arr.filter((_, idx) => idx !== i)
物件更新obj.key = val{ ...obj, key: val }
深層物件直接修改巢狀屬性用 Immer 或手動逐層展開
✅

深層巢狀物件的不可變更新很繁瑣，推薦用 Immer（已整合在 Redux Toolkit 和 useImmer 中），讓你用「看起來是 mutate 的語法」得到不可變的結果。

延伸追問

面試官可能再追

不可變（immutability）除了讓 React 偵測變化，還有什麼好處？

1. 可以用 Object.is 快速比較，React.memo 和 useMemo 的優化才有效；2. 便於做 undo/redo（保留歷史快照）；3. 避免共享引用導致的意外副作用（pure function 的前提）。

直接 mutate state 然後強制 setState(newObj) 可以嗎？

即使你 setState({ ...state }) 建立了新物件，但如果你先 mutate 了 state 的屬性，React 的 devtools 和 time-travel debug 會記錄到被 mutate 的歷史快照，行為不可預測。永遠不要先 mutate 再 setState。

面試這樣答

30 秒版本

「React 用引用相等性（Object.is）判斷 state 是否改變。直接 mutate 物件或陣列，引用不變，React 不觸發重渲，UI 顯示過時資料。正確做法是永遠建立新值（展開運算子 ...、map、filter）。不可變性同時也讓 React.memo 和 useMemo 的優化得以生效。深層物件推薦用 Immer 簡化更新邏輯。」
