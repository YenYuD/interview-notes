useCallback：記憶函式引用，阻止子組件不必要的重渲

每次渲染都會建立新的函式實例，如果把這些函式當 prop 傳給 React.memo 包裹的子組件，子組件每次都會觸發重渲。useCallback 快取函式引用，只有在依賴項改變時才建立新函式。

核心概念

為什麼函式引用每次都不同？

function Parent() {
  const [count, setCount] = useState(0);

  // 沒有 useCallback：每次渲染都建立新函式 → 子組件每次重渲
  const handleClick = () => setCount(c => c + 1);

  // 有 useCallback：依賴不變就用同一個引用
  const handleClick = useCallback(() => {
    setCount(c => c + 1);
  }, []);  // 空依賴 = 永不重建

  return <Child onClick={handleClick} />;
}

const Child = React.memo(({ onClick }) => {
  console.log('子組件渲染');
  return <button onClick={onClick}>點</button>;
});
⚠️

useCallback 要和 React.memo 搭配才有意義——若子組件沒有用 memo 包裹，就算函式引用不變，子組件仍會隨父組件重渲。

何時使用

不要過度使用

適合用傳給有 React.memo 的子組件的 callback
適合用作為 useEffect 的依賴項的函式
不必用組件內純粹使用、不傳出去的函式
不必用子組件沒有 memo 優化時
延伸追問

面試官可能再追

useCallback 和 useMemo 有什麼差別？

useCallback(fn, deps) 等價於 useMemo(() => fn, deps)，前者快取函式本身，後者快取函式的回傳值。用途不同：useCallback 給「函式引用穩定」，useMemo 給「計算結果快取」。

空依賴陣列 [] 的 useCallback 會不會有 stale closure 問題？

會。如果函式內部用到了會變的 state 或 props，空依賴會讓函式永遠讀到初始值。解法：把需要的值加進依賴陣列，或改用 setter 的函式格式（setCount(c => c + 1)）繞過捕獲。
