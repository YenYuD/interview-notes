REACT 表單

受控 vs 非受控：真相之源（source of truth）在 React 還是在 DOM？

受控組件把表單值存在 React state，每次輸入都觸發 re-render 同步；非受控組件把值留在 DOM，用 ref 在需要時讀取。前者控制力強，後者實作簡單。

對比

兩種表單控制模式

受控組件（Controlled） value={state} + onChange={handler}
每次輸入都更新 state，React 是唯一資料來源
非受控組件（Uncontrolled） ref={inputRef}
DOM 自己管值，送出時 inputRef.current.value 讀取 
// 受控
const [value, setValue] = useState('');
<input value={value} onChange={e => setValue(e.target.value)} />

// 非受控
const ref = useRef();
<input ref={ref} defaultValue="初始值" />
// 讀取：ref.current.value
選用指南

何時選哪種

情境推薦
需要即時驗證、條件禁用按鈕受控
需要動態控制 input 值（如清空）受控
整合 React Hook Form 等表單庫非受控（register API）
簡單表單、只在 submit 時讀值非受控
需要與非 React 程式碼整合非受控
✅

React Hook Form 預設用非受控模式（register），效能更好（不因每次輸入重渲）；需要監看特定欄位時才用 watch（切換為受控模式）。

延伸追問

面試官可能再追

受控組件每次按鍵都 re-render，會有效能問題嗎？

對簡單表單影響極小。若表單很複雜（數十個欄位），可以用 React Hook Form（非受控）或把各個欄位的 state 隔離，避免整個表單因一個欄位輸入而重渲。

defaultValue 和 value 有什麼差別？

defaultValue 是初始值，之後 DOM 自己管（非受控）；value 綁定 React state，必須搭配 onChange（受控）。混用或忘記 onChange 會導致 React 警告 "uncontrolled to controlled" 切換。

「受控組件用 value={state} 把表單值存在 React state，React 是唯一資料來源，每次輸入都同步更新，適合需要即時驗證或動態控制值的場景；非受控組件把值留在 DOM，用 ref 在需要時讀取，實作簡單、效能更好，React Hook Form 等表單庫預設採用此模式。」
