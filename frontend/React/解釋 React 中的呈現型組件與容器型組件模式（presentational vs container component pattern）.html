REACT 設計模式

呈現型 vs 容器型：把「長什麼樣」和「怎麼運作」分開

這個模式把組件拆成兩個職責：呈現型組件只管渲染 UI（靠 props 拿資料）；容器型組件只管業務邏輯（獲取資料、管理 state，再透過 props 往下餵）。關注點清晰，測試也更容易。

對比

兩種組件的特徵

面向呈現型（Presentational）容器型（Container）
關注UI 外觀業務邏輯 / 資料
State幾乎沒有（最多 UI 狀態）有，管理資料狀態
資料來源全部從 props 來從 API、Redux、Context 等獲取
可複用性高（不綁邏輯）低（綁定特定資料源）
測試只需傳入 props，極易測試需要 mock API / store
範例

UserList：拆成兩個

// 呈現型：只管渲染，props 告訴我什麼就顯示什麼
function UserList({ users, onSelect }) {
  return <ul>{users.map(u =>
    <li key={u.id} onClick={() => onSelect(u)}>{u.name}</li>
  )}</ul>;
}

// 容器型：負責獲取資料和邏輯
function UserListContainer() {
  const [users, setUsers] = useState([]);
  useEffect(() => { fetchUsers().then(setUsers); }, []);
  const handleSelect = user => console.log(user);
  return <UserList users={users} onSelect={handleSelect} />;
}
ℹ️

Hooks 出現後，這個模式的邊界變得模糊——Custom Hook 可以把「容器型」的邏輯抽出來，讓單一組件同時有乾淨的 UI 和封裝好的邏輯。但模式本身仍是理解關注點分離的好框架。

延伸追問

面試官可能再追

Hooks 讓這個模式變得不必要了嗎？

部分是。Custom Hook 讓邏輯和 UI 可以在同一個函式組件裡乾淨共存。但模式背後的「關注點分離」原則仍有價值，只是實現方式從「拆成兩個組件」變成「Hook 抽邏輯 + 組件純 UI」。

Redux 的 connect() 和這個模式有什麼關係？

Redux 的 connect()(Component) 就是一個 HOC，自動把 Component 包成容器型組件（連接 store）。這是這個模式的典型實際應用。

面試這樣答

30 秒版本

「呈現型組件只管 UI，所有資料從 props 來，不關心資料從哪裡來；容器型組件負責獲取資料和業務邏輯，再透過 props 餵給呈現型組件。好處是關注點清晰、呈現型組件極易測試和複用。Hooks 時代改用 Custom Hook 抽邏輯，讓單一組件同時保持 UI 簡潔和邏輯封裝，是這個模式的現代演進。」
