useReducer：當 state 邏輯複雜時，把更新規則集中在一處

useState 適合簡單值，useReducer 適合多個子值相互影響、或更新邏輯複雜的場景。它引入 action → reducer → newState 的模式，讓狀態變更可預測、易測試。

API

dispatch action → reducer 決定新 state

const initialState = { count: 0 };

function reducer(state, action) {
  switch (action.type) {
    case 'increment': return { count: state.count + 1 };
    case 'decrement': return { count: state.count - 1 };
    case 'reset':     return initialState;
    default: throw new Error('未知 action');
  }
}

function Counter() {
  const [state, dispatch] = useReducer(reducer, initialState);
  return (
    <>
      <p>{state.count}</p>
      <button onClick={() => dispatch({ type: 'increment' })}>+</button>
      <button onClick={() => dispatch({ type: 'reset' })}>重置</button>
    </>
  );
}
何時選用

useState vs useReducer

情境推薦
單一、簡單的值（布林、數字、字串）useState
多個相關聯的狀態欄位useReducer
下一個 state 依賴多個條件useReducer
想把更新邏輯移出組件、方便測試useReducer
✅

Reducer 是純函式（pure function），可以完全脫離組件單獨測試，這是它比 useState 更容易維護的主要原因。

延伸追問

面試官可能再追

useReducer + Context 可以取代 Redux 嗎？

可以處理中小型應用。但 Redux 提供 DevTools（時間旅行除錯）、中間件（logger、thunk）、更嚴格的更新流程，大型應用仍有其價值。

useReducer 的 dispatch 函式是穩定的嗎？

是的，dispatch 函式在渲染之間保持穩定（引用不變），因此可以安全地放進 useEffect 的依賴陣列，或傳給子組件而不觸發不必要的重渲。

面試這樣答

30 秒版本

「useReducer 是 useState 的替代方案，適合狀態邏輯複雜或多個相關欄位的場景。它採用 dispatch(action) → reducer → newState 模式，把所有更新規則集中在 reducer 函式裡，讓邏輯可預測且易於單獨測試。搭配 Context 可以實現輕量級的全域狀態管理。」
