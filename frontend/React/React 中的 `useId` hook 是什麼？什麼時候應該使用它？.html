useId：產生唯一且穩定的 ID，再也不怕表單無障礙問題

表單的 <label htmlFor> 必須對應 <input id>，若組件被多次渲染就會 ID 衝突。useId（React 18+）自動產生在整個應用程式中唯一的 ID，且對 SSR 水合友善。

核心用法

表單無障礙 label-input 配對

import { useId } from 'react';

function PasswordField() {
  const id = useId();  // 每個實例得到唯一 ID

  return (
    <div>
      <label htmlFor={id}>密碼</label>
      <input id={id} type="password" />
    </div>
  );
}

// 同一頁放兩個 PasswordField，ID 各自不同，不衝突
<PasswordField />
<PasswordField />
一個組件裡可以呼叫多次 useId，或加後綴區分：const id = useId(); const nameId = `${id}-name`; const emailId = `${id}-email`;
為什麼不用亂數或計數器

SSR 水合要求伺服器與用戶端 ID 一致

Math.random()伺服器和客戶端產生不同值 → 水合不匹配警告
全域計數器元件樹渲染順序若不同 → SSR/CSR ID 不同
useId基於組件在樹中的位置，伺服器與客戶端保證一致
延伸追問

面試官可能再追

useId 可以用來當清單的 key 嗎？

不行，useId 是給單一組件實例用的，在每次渲染保持穩定。清單的 key 應使用資料本身的穩定 id，而不是 useId。

React 18 之前如何解決這個問題？

常見做法：用套件（如 nanoid）在 state 初始化時產生 ID；或用 useRef 加計數器；但這些方式在 SSR 都有水合不匹配的風險，useId 才是官方正解。

面試這樣答

30 秒版本

「useId 是 React 18 引入的 hook，用來產生全應用程式唯一且 SSR 友善的 ID。最常見的場景是表單無障礙：把 label htmlFor 和 input id 綁到同一個 useId 回傳值，即使組件被多次渲染也不會 ID 衝突。不能用 Math.random 或計數器，因為 SSR 和客戶端的值會不同，造成水合錯誤。」
