state 一變，React 只改有差的那一塊

虛擬 DOM 是真實 DOM 的輕量記憶體副本。state 變化時 React 建一棵新樹，跟舊樹比對（diff），再把差異最小化地套用到真實 DOM。

DEMO — 改一個字，動了幾個節點？

整棵樹重建，但 DOM 只改差異

function Card() {
  const [count, setCount] = useState(0);
  return (<div><h3>標題</h3><p>{count}</p></div>);
}

按按鈕讓 count 改變。整棵虛擬 DOM 會重建，但看 React diff 後實際只碰了哪個真實節點：

點擊更新 state
<h3>標題</h3>
<p>0</p>
React 比對後發現 <h3> 沒變、只有 <p> 的文字變了，所以真實 DOM 只更新那一個文字節點——這就是省效能的關鍵。
三步驟 + 取捨

運作流程

1

建新樹

state/props 變 → 重新執行組件，產生新的虛擬 DOM 樹。

2

Diff 比對

新樹 vs 舊樹，找出差異（協調 reconciliation）。

3

最小化更新

只把差異套到真實 DOM，並可批次合併多次更新。

優點宣告式、批次更新、跨平台(RN)
缺點有抽象開銷、極端優化場景不如手動操作
延伸追問

面試官可能再追

虛擬 DOM 一定比直接操作 DOM 快嗎？

不一定。它的價值是「自動算出最小更新 + 宣告式心智模型」，而非絕對最快。極簡頁面或高度手動優化的場景，直接操作可能更快。

diff 為什麼能很快？

React 用啟發式：同層比較、不同型別的節點直接整塊換、用 key 辨識清單項目，把 O(n³) 的樹比對降到接近 O(n)。

「虛擬 DOM 是真實 DOM 的記憶體輕量副本。state 變化時 React 建新樹、和舊樹diff，再把最小差異套到真實 DOM，並能批次更新。好處是效能與宣告式開發、還能跨平台到 React Native；代價是抽象開銷，極端優化場景不一定贏過手動操作。」
