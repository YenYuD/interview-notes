重新渲染 ≠ 重新操作 DOM

「重新渲染」只是 React 再執行一次組件函式、產生新的虛擬 DOM 拿去 diff。真正改不改真實 DOM，要看 diff 有沒有差異。搞懂這點，才知道怎麼優化。

三個觸發來源

  • 自己的 state 改變（useState setter / setState）
  • 收到新的 props
  • 父組件重渲染 → 子組件預設跟著重渲染
✅

優化工具：React.memo（props 沒變就跳過）、useMemo（記住值）、useCallback（記住函式引用），避免不必要的重渲染。

延伸追問

面試官可能再追

重新渲染一定會更新 DOM 嗎？

不會。重渲染只是重跑函式 + diff；若 diff 沒差異，真實 DOM 完全不動。所以重渲染本身沒那麼貴，貴的是大量重渲染累積的計算。

為什麼傳 inline function 給 memo 子組件還是重渲染？

因為每次渲染都建立新的函式引用，props 被視為「變了」。用 useCallback 穩定引用才能讓 memo 生效。

30 秒版本

「重新渲染是 React 再執行一次組件函式、產生新虛擬 DOM 去 diff，不等於一定改真實 DOM。觸發來源是 state 改變、收到新 props、或父層重渲染。我會用 React.memo / useMemo / useCallback 來避免不必要的重渲染，但只在實際有效能問題時才優化，避免過早優化。」
