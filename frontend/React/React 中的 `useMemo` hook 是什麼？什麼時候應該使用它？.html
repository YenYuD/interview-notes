useMemo：依賴沒變，就別再算一次

把昂貴計算的結果記憶（快取）起來，只有依賴改變時才重算。也能穩定物件/陣列的引用，避免下游組件被連累重渲染。

DEMO — 重算 vs 重用

無關的 state 變了，要不要重算？

const sorted = useMemo(() => expensiveSort(list), [list]);

組件有兩個 state：list（昂貴排序的來源）和不相關的 theme。切換有沒有用 useMemo，再點「只改 theme」：

沒 useMemo：每次渲染都重跑昂貴排序，即使 list 根本沒變。用了 useMemo：依賴 [list] 沒變就直接回傳上次結果。
什麼時候用

兩個時機

  • 昂貴計算：排序、過濾大陣列、複雜運算，避免每次渲染都重跑。
  • 穩定引用：把物件/陣列傳給 React.memo 子組件或當 useEffect 依賴時，保持引用不變。
⚠️

別過度使用。memo 本身也有成本，廉價計算硬包反而增加複雜度與記憶體。先量測，有問題再優化。記住值用 useMemo，記住函式用 useCallback。

延伸追問

面試官可能再追

useMemo 和 useCallback 差在哪？

useMemo(fn, deps) 記住 fn 的回傳值；useCallback(fn, deps) 記住函式本身。其實 useCallback(fn, d) === useMemo(() => fn, d)。

useMemo 保證一定不重算嗎？

不保證。React 可能在記憶體吃緊時丟棄快取重算，所以別把它當「只執行一次」的語意依賴，計算要是純函式。
