REACT 錯誤處理

Error Boundary：讓一個組件的爆炸，不拖垮整個應用程式

沒有錯誤邊界時，任何子組件的 JavaScript 錯誤都會讓整個 React 樹崩潰、畫面變白。Error Boundary 攔截子樹的渲染錯誤，改顯示備用 UI，其他部分繼續正常運作。

實作

需要類別組件：實作兩個生命週期方法

class ErrorBoundary extends React.Component {
  state = { hasError: false };

  // 捕獲錯誤，更新 state 顯示備用 UI
  static getDerivedStateFromError() {
    return { hasError: true };
  }

  // 記錄錯誤（送到監控服務）
  componentDidCatch(error, info) {
    errorTrackingService.log(error, info.componentStack);
  }

  render() {
    if (this.state.hasError) {
      return <h2>此功能暫時無法使用，請稍後再試。</h2>;
    }
    return this.props.children;
  }
}
ℹ️

目前 Error Boundary 只能用類別組件實作（官方尚未提供 Hook 版），但你可以用 react-error-boundary 套件的函式組件寫法。

捕獲範圍

什麼錯誤能捕獲？什麼不行？

能捕獲render、生命週期方法、constructor 裡的錯誤
不能捕獲事件處理器（用 try/catch 自行處理）
不能捕獲非同步程式碼（setTimeout、Promise）
不能捕獲SSR 期間的錯誤
不能捕獲Error Boundary 自身拋出的錯誤
延伸追問

面試官可能再追

Error Boundary 應該放在哪個層級？

視需求而定。可以在整個 App 放一個兜底邊界，也可以在每個功能模組放獨立邊界，讓局部錯誤不影響其他模組。顆粒度越細，使用者體驗越好。

如何在 Error Boundary 裡提供「重試」功能？

在 Error Boundary 的 state 加 retry 機制，或使用 react-error-boundary 套件的 resetErrorBoundary 回呼，讓使用者可以手動觸發重渲。

面試這樣答

30 秒版本

「Error Boundary 是特殊的類別組件，透過 getDerivedStateFromError 和 componentDidCatch 攔截子組件樹的渲染錯誤，改顯示備用 UI，防止整個應用程式崩潰。它無法捕獲事件處理器或非同步錯誤——那些要用 try/catch 自行處理。實務上建議在重要功能模組各放一個邊界，搭配錯誤監控服務（如 Sentry）記錄錯誤。」
