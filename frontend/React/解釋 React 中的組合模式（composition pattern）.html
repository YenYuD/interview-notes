REACT 模式

組合優於繼承：用小組件堆出複雜 UI

React 官方建議用組合（Composition）而非繼承（Inheritance）來重用組件邏輯。通過 children 或 slot props 讓組件保持開放，呼叫者決定填入什麼，實現高複用性與靈活性。

兩種組合方式

Children 和 Slot Props

// 方式一：children prop（最常見）
function Card({ children, title }) {
  return (
    <div className="card">
      <h2>{title}</h2>
      <div className="card-body">{children}</div>
    </div>
  );
}

// 方式二：具名 slot（傳 JSX 作為 prop）
function Layout({ sidebar, main }) {
  return (
    <div className="layout">
      <aside>{sidebar}</aside>
      <main>{main}</main>
    </div>
  );
}

// 使用：像樂高積木一樣組合
<Layout
  sidebar={<NavigationMenu />}
  main={<ArticleList />}
/>
為何優於繼承

繼承在 UI 組件的問題

繼承的問題父類改動影響所有子類；子類難以理解哪些是繼承來的
組合的優點依賴關係明確（props 可見）；組件獨立、可單獨測試
React 官方文件明確說：「如果你想在組件之間共享非 UI 功能，可以把它抽取成單獨的 JavaScript 模組，而不是用繼承擴展它。」
延伸追問

面試官可能再追

Compound Component 模式是什麼？

Compound Component 是組合的進階版：一組組件共享隱式 state，例如 <Select> + <Option>。通常透過 Context 在父組件和子組件間共享資料，使用者使用時組合自由但行為一致。

什麼時候還是需要繼承？

React 生態幾乎不需要用繼承。唯一的官方例外是 Error Boundary，必須繼承 React.Component。其他場景用組合 + Custom Hook 都能解決。

面試這樣答

30 秒版本

「React 推崇組合而非繼承，讓組件透過 children 或具名 prop 接收 JSX，呼叫者決定填入什麼內容。好處是依賴關係透明、組件獨立，修改一個組件不會意外影響其他組件。實務上 Card、Modal、Layout 等容器型組件都是組合模式的典型應用，比繼承更容易理解和維護。」
