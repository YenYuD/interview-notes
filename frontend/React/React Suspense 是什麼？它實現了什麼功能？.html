REACT 非同步

Suspense：宣告式地處理等待狀態，告別手寫 loading flag

以往要處理非同步載入，得手動管理 isLoading state。Suspense 讓你宣告「等待時顯示什麼」，子組件自行決定何時就緒，父層只負責 fallback UI。

兩大使用場景

程式碼分割 vs 資料獲取

場景搭配 API說明
程式碼分割 React.lazy() 懶載入組件，讓 bundle 更小、初始載入更快
資料獲取 use() hook（React 19）
或 react-query / Relay		 組件「懸停」直到資料就緒，由 Suspense 展示 fallback 
import { Suspense, lazy } from 'react';

const Chart = lazy(() => import('./Chart'));

function Dashboard() {
  return (
    <Suspense fallback={<div>圖表載入中...</div>}>
      <Chart />
    </Suspense>
  );
}
優點

為什麼比 isLoading flag 好

宣告式父層定義等待 UI，子層專注業務邏輯
可組合多個非同步組件可共用一個 Suspense 邊界
與 Concurrent Mode 整合React 可優先渲染就緒的部分
ℹ️

Suspense 的資料獲取功能在 React 18 後趨於穩定；搭配 use() hook（React 19）或 react-query v5 的 suspense: true 選項使用最順暢。

延伸追問

面試官可能再追

Suspense 和 Error Boundary 有什麼關係？

建議把 Suspense 搭配 Error Boundary 一起使用：Suspense 處理「載入中」狀態，Error Boundary 處理「載入失敗」狀態，兩者互補覆蓋所有非同步場景。

React.lazy 只能用在組件最上層嗎？

React.lazy 必須在模組頂層呼叫（不能在函式內部動態呼叫），因為它需要在渲染前就確定懶加載的目標。但 <Suspense> 邊界可以放在任何位置。

面試這樣答

30 秒版本

「Suspense 讓我用宣告式的方式處理非同步等待，搭配 React.lazy 做程式碼分割，或搭配支援 Suspense 的資料庫做資料獲取。當子組件尚未就緒，Suspense 顯示 fallback；就緒後自動切換到正式內容。好處是父組件只定義『等待時的 UI』，不需手動管理 isLoading flag，關注點更乾淨。」
