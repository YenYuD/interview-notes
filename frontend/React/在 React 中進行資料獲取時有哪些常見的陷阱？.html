REACT 非同步

資料獲取四個坑：記憶體洩漏、競態條件、缺少 cleanup…

在 React 裡 fetch 資料看似簡單，但每個坑都可能讓你的應用出現難以重現的 bug：組件卸載後 setState、搜尋框快速輸入時舊請求覆蓋新請求……這些在開發環境幾乎不出現、卻在正式環境爆炸的問題。

四大陷阱

一次看清

陷阱症狀解法
未處理載入 / 錯誤狀態 載入中 UI 閃白、錯誤時白屏 維護 loading 和 error state，分別渲染
組件卸載後仍 setState React 警告「can't perform a state update on unmounted component」 cleanup 函式設 isMounted = false，或用 AbortController
競態條件（Race condition） 快速切換 id 時，舊請求的回應覆蓋新請求 在 cleanup 中 abort() 上一個請求
在 render 裡直接 fetch 無限迴圈（fetch → setState → re-render → fetch…） 永遠在 useEffect 裡 fetch
解法範例

用 AbortController 同時解決記憶體洩漏和競態

useEffect(() => {
  const controller = new AbortController();

  fetch(`/api/user/${userId}`, { signal: controller.signal })
    .then(r => r.json())
    .then(setData)
    .catch(err => {
      if (err.name !== 'AbortError') setError(err);
    });

  return () => controller.abort();  // cleanup：取消舊請求
}, [userId]);
✅

實務上推薦用 TanStack Query（react-query）或 SWR 等資料獲取函式庫，它們已內建處理這些陷阱，並提供快取、重試、失效等功能。

延伸追問

面試官可能再追

為什麼 StrictMode 下 useEffect 會跑兩次，會影響 fetch 嗎？

會，Strict Mode 下 effect mount → unmount → remount，第一次 fetch 會被 cleanup abort，然後第二次 fetch 才是「真正的」請求。用 AbortController 的程式碼能正確處理這個情況。

什麼是 waterfall fetch 問題？如何解決？

父組件先 fetch，等資料回來才渲染子組件、子組件再 fetch，形成串行的瀑布效應，延遲很高。解法：並行 fetch（Promise.all）、或用 React Suspense 讓子組件各自並行 fetch。
