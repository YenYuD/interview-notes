REACT HOOKS

Hooks 讓邏輯可以脫離組件複用——這是類別組件做不到的

React 16.8 引入 Hooks，解決了類別組件的三個痛點：有狀態邏輯難以複用、複雜組件難以理解（生命週期方法把不相關邏輯混在一起）、類別語法對人和機器都不友善。

五大優點

為什麼 Hooks 比類別組件好

優點說明
邏輯可複用Custom Hook 把有狀態邏輯抽離，跨組件共用，告別 HOC 包裹地獄
按關注點組織程式碼相關邏輯放在同一個 Hook 裡，而不是分散在 componentDidMount/componentDidUpdate
消除 this函式組件不需要 this，不需要 .bind，邏輯更直覺
更好的 TypeScript 支援函式比類別更容易推斷型別
更容易測試Custom Hook 可以獨立用 renderHook 測試，不需要掛載完整組件
Custom Hook 的力量

把有狀態邏輯封裝成可複用的 Hook

// 自定義 Hook：封裝 fetch 邏輯
function useFetch(url) {
  const [data, setData]     = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError]   = useState(null);

  useEffect(() => {
    fetch(url)
      .then(r => r.json())
      .then(setData)
      .catch(setError)
      .finally(() => setLoading(false));
  }, [url]);

  return { data, loading, error };
}

// 任何組件一行取用
const { data, loading } = useFetch('/api/users');
延伸追問

面試官可能再追

Hooks 可以完全取代類別組件嗎？

幾乎可以。唯一的例外是 Error Boundary 目前仍只能用類別組件實作。其他所有場景（包含複雜 state、生命週期）都可以用 Hooks 取代。

Custom Hook 和普通函式有什麼差別？

Custom Hook 函式名必須以 use 開頭，且可以在內部呼叫其他 Hook。普通函式不能呼叫 Hook（違反 Hooks 規則）。
