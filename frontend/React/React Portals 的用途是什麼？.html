Portal：把子組件「傳送」到 DOM 樹的任意位置

Modal、Tooltip、Dropdown 常被 overflow: hidden 或 z-index 剪裁，因為它們被困在父組件的 DOM 節點裡。Portal 讓你把這些 UI 渲染到 #root 以外的目標節點，同時保留 React 的事件冒泡。

API

createPortal(child, container)

import ReactDOM from 'react-dom';

function Modal({ isOpen, children }) {
  if (!isOpen) return null;

  return ReactDOM.createPortal(
    <div className="modal-overlay">{children}</div>,
    document.getElementById('modal-root')  // 目標容器
  );
}
✅

記得在 index.html 加上 <div id="modal-root"></div>，與 #root 平行，這樣 Modal 就不受 #root 的 CSS 限制。

三大使用場景

什麼時候非用 Portal 不可

Modal 對話框需渲染在 body 頂層，避免 z-index 問題
Tooltip / Popover父元素有 overflow:hidden 時會被裁切
全螢幕元素需要脫離所有父層的 CSS 上下文
一個常見誤解

Portal 脫離 DOM，但事件仍冒泡到 React 父組件

Portal 只是「渲染目標」改變了。在 React 的組件樹裡，Portal 仍是父組件的子節點，所以在 Portal 內觸發的事件會冒泡到 React 的父組件。這個行為讓狀態管理保持一致。
延伸追問

面試官可能再追

Portal 內部的事件會冒泡到 React 組件樹的父組件嗎？

會。React 的事件委派（event delegation）是基於 React 組件樹的邏輯關係，而非實際 DOM 位置。Portal 內的點擊事件依然會冒泡到邏輯父組件。

Portal 和 CSS position:fixed 有什麼不同？

position:fixed 視覺上脫離文件流，但 DOM 節點仍在原位，仍受祖先 transform 影響。Portal 把 DOM 節點移到新位置，完全脫離原 DOM 上下文。
