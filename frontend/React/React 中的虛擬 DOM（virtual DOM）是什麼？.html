虛擬 DOM：React 用記憶體快照決定「最少要動哪裡」

直接操作真實 DOM 代價高昂。React 在記憶體中維護一棵虛擬 DOM 樹，狀態改變時先比對新舊兩棵樹（diffing），算出最小變更集，再一次性套用到真實 DOM。

流程

從 setState 到畫面更新的四個步驟

觸發：state 或 props 改變
渲染（Render）：React 建立新的虛擬 DOM 樹
比對（Diffing）：演算法比對新舊虛擬 DOM，找出差異
提交（Commit）：僅更新真實 DOM 中發生變化的部分
優點與限制

虛擬 DOM 不是萬能的

優點批量更新、最小化 DOM 操作；開發者不需手動操作 DOM
優點抽象層讓跨平台成為可能（React Native）
限制比 vanilla JS 直接操作目標 DOM 多一層計算開銷
限制極度頻繁的更新場景，虛擬 DOM diffing 本身也有成本
延伸追問

面試官可能再追

虛擬 DOM 和 Shadow DOM 是一樣的嗎？

完全不同。虛擬 DOM 是 React 等函式庫的 JS 技術，在記憶體中比對 UI 差異。Shadow DOM 是瀏覽器原生 API，用於 Web Components 的樣式和結構隔離。

key 在 diffing 時有什麼作用？

diffing 演算法預設用位置比對同層節點。加 key 讓 React 用 identity 而非 position 比對，清單重排時能正確識別節點，避免狀態錯位。

面試這樣答

30 秒版本

「虛擬 DOM 是 React 在記憶體中維護的 UI 輕量表示。狀態改變時，React 建立新的虛擬 DOM 樹並與舊樹 diffing 比對，算出最小變更集，最後一次性套用到真實 DOM——稱為協調（reconciliation）。好處是批量、高效地更新 DOM，開發者只需宣告式描述 UI，不用手動操作 DOM。」
