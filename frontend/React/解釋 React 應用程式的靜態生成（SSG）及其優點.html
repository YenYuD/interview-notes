REACT 渲染策略

SSG：在建置時就把 HTML 生成好，部署後直接從 CDN 秒速供應

靜態生成（Static Site Generation）在建置期預先把每個頁面的 HTML 算好，存成靜態檔案。請求來時直接從 CDN 回傳，零伺服器運算，速度最快、成本最低。

三種渲染策略比較

SSG vs SSR vs CSR

策略HTML 生成時機適合場景
SSG 建置時（build time） 部落格、文件、行銷頁、不常更新的內容
SSR 每次請求（request time） 個人化內容、即時資料、需要 SEO 的動態頁
CSR 瀏覽器（client time） 管理後台、需要大量互動、不需 SEO 的 App
Next.js 實作

getStaticProps：在建置期獲取資料

// pages/blog/[slug].js（Next.js Pages Router）
export async function getStaticPaths() {
  const posts = await getAllPosts();
  return { paths: posts.map(p => `/blog/${p.slug}`), fallback: false };
}

export async function getStaticProps({ params }) {
  const post = await getPost(params.slug);
  return { props: { post }, revalidate: 60 };  // ISR：60 秒後重新生成
}
✅

增量靜態再生（ISR）：在 getStaticProps 加 revalidate，讓靜態頁面在後台定期重新建置，兼顧速度與內容新鮮度。

延伸追問

面試官可能再追

SSG 的內容過期怎麼辦？

有三個策略：1. 重新 deploy（適合更新頻率極低的內容）；2. ISR（revalidate，定時在背景重建）；3. On-demand ISR（內容更新時手動呼叫 API 觸發重建）。

Next.js App Router 的靜態生成有什麼不同？

App Router 預設就是靜態的（Server Components），不需要 getStaticProps。若需要動態，加 export const dynamic = 'force-dynamic' 或使用 fetch 時不加 cache。
