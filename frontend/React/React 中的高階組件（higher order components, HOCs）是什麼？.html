REACT 模式

HOC：把組件丟進去，得到一個功能增強的新組件

高階組件（Higher Order Component）是接收組件、回傳增強組件的函式。命名慣例以 with 開頭。它解決「如何在不修改原組件的情況下複用邏輯」，但 Hooks 時代已有更簡潔的替代方案。

模式

HOC 的結構

// withAuth：檢查登入才渲染，否則跳轉
function withAuth(WrappedComponent) {
  return function AuthenticatedComponent(props) {
    const isLoggedIn = useAuth();

    if (!isLoggedIn) return <Redirect to="/login" />;
    return <WrappedComponent {...props} />;
  };
}

// 使用：包裹後得到需要登入的版本
const ProtectedDashboard = withAuth(Dashboard);
HOC vs Custom Hook vs Render Props

三種複用邏輯的方式比較

方式優點缺點
HOC可包裹類別組件；能包裹 JSX 結構多層包裹時組件樹深；props 命名衝突；難以追蹤來源
Custom Hook簡潔；組合自由；Hooks 時代首選只能用在功能組件
Render Props明確控制渲染結構巢狀深時「wrapper hell」
✅

Hooks 推出後，HOC 的主要使用場景已大量被 Custom Hook 取代。但在舊專案維護、或需要包裹整個組件（如 React.memo、connect）時，HOC 仍是有效工具。

延伸追問

面試官可能再追

HOC 有什麼常見的坑？

1. props 命名衝突（HOC 注入的 prop 覆蓋了原有的）；2. 靜態方法不會自動複製（需用 hoist-non-react-statics）；3. ref 無法穿透（需搭配 forwardRef）；4. DevTools 中組件名稱難以辨識。

React.memo 算是 HOC 嗎？

廣義上是，React.memo(Component) 接受組件回傳增強組件（加上淺比較 props 的優化）。這是 React 內建的 HOC 典型應用。

30 秒版本

「HOC 是接收組件回傳增強組件的函式，用來複用組件邏輯。典型用途有身份驗證保護、日誌注入、主題包裹等。命名以 with 開頭是慣例。Hooks 出現後大多數場景改用 Custom Hook 取代，因為更簡潔、沒有 props 污染問題；但 React.memo、connect（Redux）等仍是常見的 HOC 應用。」
