重置狀態：把初始值存起來，需要時呼叫 setter 傳回去

重置組件狀態的核心做法是把初始值定義成常數，並在重置時呼叫 setState(initialState)。如果初始值來自 props 或動態來源，改用函式包裝。

最常見做法

定義 initialState，重置時傳回去

import { useState } from 'react';

// ✅ 把初始值定義在組件外（穩定引用）
const initialState = { count: 0, text: '' };

function MyComponent() {
  const [state, setState] = useState(initialState);

  const resetState = () => setState(initialState);

  return (
    <div>
      <p>計數：{state.count}</p>
      <button onClick={resetState}>重置</button>
    </div>
  );
}
✅

把 initialState 定義在組件外部（模組頂層），可確保引用穩定，避免每次渲染都建立新物件造成不必要的比較問題。

動態初始值

初始值來自 props？用函式包裝

function MyComponent({ initialCount }) {
  // 函式形式：useState 只在首次渲染呼叫它（lazy initializer）
  const getInitialState = () => ({ count: initialCount, text: '' });
  const [state, setState] = useState(getInitialState);

  const resetState = () => setState(getInitialState());

  return (
    <div>
      <p>計數：{state.count}</p>
      <button onClick={resetState}>重置</button>
    </div>
  );
}
進階技巧

用 key prop 強制重置整個組件

除了手動呼叫 setState，還有一個更乾淨的方式：在父組件改變子組件的 key，React 會卸載舊實例、掛載全新組件——所有 state 都回到初始值，不需要寫任何重置邏輯。適合「對話框關閉後清空所有欄位」這類場景。
// 父組件：改變 key 即可完全重置 Form
const [formKey, setFormKey] = useState(0);
<Form key={formKey} />
<button onClick={() => setFormKey(k => k + 1)}>重置表單</button>
延伸追問

面試官可能再追

改 key 和手動 setState(initialState) 有什麼差別？

改 key 會讓 React 完全卸載再掛載組件，所有 state、ref、副作用都重設，適合「完全歸零」的情境。手動 setState(initialState) 只重設 state，組件實例和 DOM 保留，適合「保留組件生命週期但清空資料」的情境。

為什麼 initialState 建議定義在組件外部？

定義在組件內部時，每次渲染都會重新建立這個物件（新引用），雖然不影響正確性，但若把它放進 dependency array（如 useEffect、useMemo）會造成不必要的重新執行。放外部可確保引用穩定。

30 秒版本

「重置 React 組件狀態有兩種主要方式：一是把初始值定義為常數，呼叫 setState(initialState) 傳回初始值；若初始值來自 props，改用函式 getInitialState() 包裝。另一種更乾淨的方式是在父組件改變子組件的 key，React 會完全重新掛載組件，適合需要徹底歸零的場景，不需要在組件內寫任何重置邏輯。」
