REACT 開發工具

StrictMode：在開發期故意執行兩次，提早暴露潛在問題

<React.StrictMode> 是開發環境專用的工具組件，不渲染任何可見 UI，也不影響 production。它的主要手段是刻意雙重調用 render 和 effect，讓非純函式的問題立刻現形。

它做什麼

四種主動檢測

雙重調用 render 函式：在 React 18+，開發模式下 render 會被呼叫兩次，逼出不純的 render（如直接修改外部變數）。
雙重執行 Effect：React 18+ 在 Strict Mode 下，useEffect 會 mount → unmount → remount，確認 cleanup 正確。
偵測已棄用 API：如 componentWillMount、字串 ref、findDOMNode 等，在 console 發出警告。
警告 context 舊版 API：偵測使用 Legacy Context API 的組件。
✅

建議在根元件用 <React.StrictMode> 包裹整個 App，只在開發階段生效，不影響 production 效能。

常見誤解

Effect 執行兩次不是 bug

⚠️

React 18 Strict Mode 下，useEffect 的確會跑兩次（mount / unmount / remount）。這是刻意設計，用來測試你的 cleanup 是否完整。如果你的 effect 跑兩次結果不同，表示你的 cleanup 函式有問題，而不是 Strict Mode 有 bug。

延伸追問

面試官可能再追

Strict Mode 會影響效能嗎？

只在開發環境生效，production build 會自動移除 Strict Mode 的額外行為。所以對 production 效能零影響。

可以只對某個子樹啟用 Strict Mode 嗎？

可以，<StrictMode> 只影響其後代組件，你可以只包裹需要檢查的子樹。
