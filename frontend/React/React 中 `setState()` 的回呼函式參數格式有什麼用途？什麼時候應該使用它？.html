setState(fn)：用函式格式才能保證拿到最新狀態

React 的 setState 是非同步且可能被批次合併，如果你直接用目前的 state 值計算下一個值，可能讀到的是「過時的快照」。傳入函式（prevState => newState）才能保證永遠基於最新的狀態。

問題根源

直接寫 vs 函式格式的差別

可能出 bug setCount(count + 1);
setCount(count + 1);
// 兩次都讀同一個 count，結果 +1 而非 +2
永遠正確 setCount(prev => prev + 1);
setCount(prev => prev + 1);
// 串聯執行，結果 +2
⚠️

在同一個事件處理器或 useEffect 裡連續呼叫多次 setState，React 會批次處理（batching）。若直接寫值，每次都讀同一個 state 快照；改用函式格式，React 會把上一次的結果傳進來，保證串聯正確。

典型情境

什麼時候一定要用函式格式

  • 新狀態依賴舊狀態：計數器、toggle、陣列 push/filter
  • 同一個 handler 連續多次更新同一 state
  • 在 useEffect / setTimeout / Promise callback 裡更新 state（這些地方的 state 是閉包捕獲的舊值）
// 類別組件
this.setState((prevState, props) => ({
  counter: prevState.counter + props.step
}));

// 功能組件（useState）
setItems(prev => [...prev, newItem]);
延伸追問

面試官可能再追

React 18 的自動批次（auto batching）如何影響這個問題？

React 18 把批次更新擴展到 setTimeout、Promise 等非同步場景（之前只在事件處理器內批次）。這讓函式格式更重要，因為批次場景更多了。

useState 的 setter 和類別組件的 setState 行為一樣嗎？

不完全一樣：useState 的 setter 完全替換 state，而 this.setState 會做淺合併（shallow merge）。但兩者都支援函式格式，且語意相同。

面試這樣答

30 秒版本

「setState 的函式格式（prevState => newState）確保更新永遠基於最新的狀態。因為 React 可能批次處理多個 setState，如果直接寫 setState(count + 1)，連續呼叫多次都讀同一個舊值；改用函式格式，React 會把上一次的結果傳進函式，串聯更新正確。凡是新狀態依賴舊狀態，都應使用函式格式。」
