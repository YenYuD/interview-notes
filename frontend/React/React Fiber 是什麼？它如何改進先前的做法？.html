REACT 架構

Fiber：讓 React 從「一次跑完」變成可中斷、可優先排程的引擎

React 16 之前的協調算法是同步遞迴，一旦開始就無法中斷，複雜 UI 時容易卡住主線程。Fiber 把渲染工作拆成小單元，讓 React 能暫停、恢復，並根據優先級決定先處理哪些更新。

舊 vs 新

Stack 演算法 vs Fiber 演算法

面向舊 Stack 演算法Fiber（React 16+）
執行方式同步、一次跑完可中斷、分幀執行
主線程阻塞長任務會凍結 UI讓出控制權給瀏覽器
優先級無用戶互動 > 動畫 > 後台更新
啟用功能—Concurrent Mode、Suspense、時間分片
關鍵概念

Fiber 做了三件事

漸進式渲染（Incremental rendering）：把渲染工作拆成「fiber 節點」，每個節點是可暫停的最小工作單元。
時間分片（Time slicing）：高優先度任務（如鍵盤輸入、點擊）可以插隊，確保 UI 響應流暢。
錯誤邊界（Error boundaries）：Fiber 架構讓捕獲子樹錯誤成為可能，舊 Stack 演算法做不到。
✅

Fiber 是內部實作細節，對大多數開發者而言感知是：Concurrent Mode（React 18 的並行功能）和 Suspense 資料載入都建立在 Fiber 之上。

延伸追問

面試官可能再追

Fiber 的「Render 階段」和「Commit 階段」有什麼不同？

Render 階段（協調）可以中斷，計算出 effect 清單；Commit 階段不可中斷，一次性把 DOM 變更全部套用，確保畫面一致性。

Concurrent Mode 是什麼？跟 Fiber 有什麼關係？

Concurrent Mode 是建立在 Fiber 之上的模式，允許 React 同時準備多個版本的 UI、根據優先級中斷低優先度渲染。React 18 的 createRoot 即啟用此模式。

面試這樣答

30 秒版本

「React Fiber 是 React 16 對協調算法的完全重寫。舊版算法是同步遞迴，一旦開始就無法中斷，複雜 UI 會阻塞主線程。Fiber 把渲染工作拆成可中斷的小單元，引入優先級排程——用戶互動可以插隊低優先度更新，讓 UI 保持流暢。同時它也是 Concurrent Mode、Suspense 等新功能的基礎架構。」
