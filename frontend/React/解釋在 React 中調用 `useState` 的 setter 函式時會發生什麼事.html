REACT STATE

呼叫 setter 不是「立即更新」，而是排入更新隊列

呼叫 setCount(1) 後，count 的值不會立刻變。React 把更新排入隊列，在下一次渲染時才套用新值。這是理解 React state 行為的核心認知。

三個重要行為

呼叫 setter 後發生了什麼

排入更新隊列：React 標記此組件需要重渲，但不立即執行
批次處理（Batching）：同一事件處理器或 effect 裡的多個 setter 合併成一次重渲（React 18 自動批次擴展到所有非同步場景）
完全替換（vs setState 的淺合併）：setUser({ name: 'A' }) 會刪掉原本所有其他欄位
// 這兩行在同一個 handler 裡，只觸發一次重渲
setCount(count + 1);
setName('Yenyu');

// setter 是完全替換，要保留其他欄位必須展開
setUser(prev => ({ ...prev, name: 'Yenyu' }));
常見誤解

為什麼 setter 後立刻讀 state 還是舊值？

⚠️

在同一個 render 執行週期內，state 是「快照」（snapshot）。呼叫 setter 不改變目前這次執行週期的 state 值，下次渲染才有新值。若需要連鎖更新同一個 state，用函式格式：setCount(prev => prev + 1)。

// count 目前是 0
setCount(count + 1);  // 排入 1
setCount(count + 1);  // 還是排入 1！count 快照沒變
// 結果：count 變成 1（不是 2）

// 正確做法：函式格式串聯
setCount(prev => prev + 1);  // 1
setCount(prev => prev + 1);  // 2
延伸追問

面試官可能再追

React 18 的 auto batching 對舊有程式碼有影響嗎？

有影響。React 17 只在事件處理器批次，React 18 把 setTimeout、Promise、原生事件等也納入批次。大多數情況行為更一致，但若你的程式碼依賴「每次 setState 立刻重渲」的行為（不建議），需要用 flushSync 強制同步更新。

useState 的初始值函式（惰性初始化）是什麼？

useState(fn) 若傳函式，React 只在第一次渲染呼叫它，避免每次渲染都執行昂貴的計算。例如：useState(() => JSON.parse(localStorage.getItem('state')))。

面試這樣答

30 秒版本

「呼叫 setter 會把更新排入隊列，不立即更新——state 在當前渲染週期是快照（snapshot），下一次渲染才有新值。React 會批次合併多個 setter，減少重渲次數（React 18 擴展到所有場景）。useState 的 setter 是完全替換，不像 class 的 setState 會淺合併；連鎖更新同一 state 要用函式格式 prev => newValue。」
