REACT 核心

協調（Reconciliation）：React 如何算出最少要動哪裡

每次 state 或 props 改變，React 重新算出虛擬 DOM，再用 diffing 演算法比對新舊兩棵樹，只把真正改變的部分更新到真實 DOM——這個過程叫做協調。

Diffing 三規則

演算法如何比對節點

規則一：不同類型 → 整棵子樹替換
如果節點類型從 <div> 變成 <span>，React 直接卸載舊子樹、掛載新子樹（不保留狀態）。
規則二：相同類型 → 更新 props
同類型節點只比對 props 差異，更新必要的屬性，保留組件的 state。
規則三：子節點列表用 key 辨識
沒有 key 則按位置比對；有 key 則按 identity 比對，允許正確識別移動/增刪的節點。
複雜度優化

O(n³) 問題如何用 O(n) 解決

理論上比對兩棵樹的最優演算法是 O(n³)。React 用上面三條啟發式規則把複雜度降到 O(n)——代價是假設跨層級移動節點極少發生。這個假設在實際 UI 中幾乎成立。
✅

理解協調是理解「為什麼需要 key」「為什麼要避免改變元素類型」的根本原因。

面試官可能再追

協調（Reconciliation）和 Fiber 是什麼關係？

協調是「比對新舊虛擬 DOM、決定要做什麼更新」的算法概念；Fiber 是 React 16 實作協調的具體架構，把協調拆成可中斷的工作單元，支援優先級排程。

如果兩個組件 type 不同，舊組件的 state 會保留嗎？

不會。類型不同時 React 完全卸載舊組件（state 銷毀）並掛載新組件。這就是為什麼條件渲染要小心，用 type 改變會導致狀態重置。

30 秒版本

「協調是 React 比對新舊虛擬 DOM 並計算最小 DOM 變更的過程。核心是 diffing 演算法的三條規則：不同類型整棵替換、相同類型只更新 props、列表用 key 辨識節點身分。這讓複雜度從理論上的 O(n³) 降到 O(n)。Fiber 架構在 React 16 把這個過程拆成可中斷的小工作，支援優先級排程。」
