語法對照

Jest vs Mocha+Chai

Jest（內建斷言） 
test('adds 1+2', () => {
  expect(sum(1,2)).toBe(3);
});
Mocha + Chai（組合式） 
describe('sum', () => {
  it('adds 1+2', () => {
    expect(sum(1,2)).to.equal(3);
  });
});

Jest 自帶斷言（expect().toBe()）；Mocha 需額外引入 Chai（expect().to.equal()）。語法相近，換框架切換成本不高。

Cypress 特色

E2E 測試為何選 Cypress

1

真實瀏覽器執行

不是 jsdom 模擬，是真實 Chrome/Firefox，CSS、動畫、網路請求全都真的跑。

2

時間旅行（Time Travel）

每個指令執行後都有快照，可以倒帶查看每一步發生什麼，除錯超直覺。

3

自動等待

不需要手動 sleep，Cypress 自動等 DOM 出現、網路完成再往下走。

延伸追問

面試官可能再追

Jest 和 Vitest 差在哪裡？

Vitest 與 Vite 共用設定（vite.config.ts），不需要另外配 babel；速度更快（利用 esbuild）。Jest 生態更成熟，plugin 多。Vite 專案直接用 Vitest，非 Vite 專案沿用 Jest 即可。

Cypress 和 Playwright 怎麼選？

兩者能力相近。Playwright 原生支援多瀏覽器並行（Chromium/Firefox/WebKit）、速度稍快；Cypress DX（開發者體驗）和除錯介面更友善。看團隊偏好和 CI 環境。

面試這樣答

30 秒版本

「我依場景選工具：Unit / Integration 測試用 Jest，如果是 Vite 專案就換 Vitest；E2E 用 Cypress 或 Playwright。Jest 吸引我的是零配置和內建 mock；Cypress 的時間旅行除錯很省時。Mocha 和 Jasmine 我在老專案維護有用過，彈性更高但需要自己組工具鏈。」
