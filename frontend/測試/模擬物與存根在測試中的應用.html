Mock vs Stub：一個控制輸出，一個驗互動

Stub 是假資料的提供者；Mock 是行為的監視者。搞清楚你要隔離還是要驗證，才能選對工具——否則測試通過了卻什麼都沒保護到。

核心差異

Stub 隔離，Mock 驗證

Stub — 控制依賴的回應

給測試對象一個假的依賴，讓它回傳你指定的值。你不在乎這個假依賴有沒有被呼叫，只在乎被測程式碼的輸出結果。

const fetchStub = sinon.stub();
fetchStub.returns({ id: 1, name: 'Alice' });

const result = processUser(fetchStub);
expect(result.name).toBe('Alice');
Mock — 驗證互動行為

不只替換，還記錄「有沒有被呼叫」、「呼叫幾次」、「用什麼參數」。測完要 verify()。

const logMock = jest.fn();

sendNotification('hello', logMock);

expect(logMock).toHaveBeenCalledOnce();
expect(logMock).toHaveBeenCalledWith('hello');
決策流程

要用 Stub 還是 Mock？

1

只需要假資料讓被測程式碼跑起來

→ 用 Stub。目的是隔離外部依賴（DB、API），讓測試可控。

2

需要確認程式碼是否正確「呼叫」了某個依賴

→ 用 Mock（或 Spy）。例如確認「寄信函式有被呼叫一次」、「log 有收到正確參數」。

⚠️

過度使用 Mock 會讓測試與實作細節綁定太深，稍微重構就大量測試失敗。能用 Stub 或真實物件就不要用 Mock。

Jest 中的對應

Jest API 速查

需求Jest API
Stub：讓函式回傳固定值jest.fn().mockReturnValue(val)
Stub：非同步回傳jest.fn().mockResolvedValue(val)
Mock 整個模組jest.mock('module-path')
Spy：追蹤真實函式的呼叫jest.spyOn(obj, 'method')
驗有無被呼叫expect(fn).toHaveBeenCalled()
驗呼叫參數expect(fn).toHaveBeenCalledWith(...args)
延伸追問

面試官可能再追

Spy 和 Mock 有什麼不同？

Spy 包裹在真實實作外面，讓真實邏輯繼續執行但同時記錄呼叫資訊；Mock 則直接替換掉實作。jest.spyOn() 預設就是 Spy 行為，可以選擇是否覆寫實作。

什麼是「測試替身（Test Double）」？

Test Double 是所有替換真實依賴的統稱，包含 Stub、Mock、Spy、Fake（有簡化實作的替身，如 in-memory DB）、Dummy（不使用但需要傳入的參數）。Stub 和 Mock 只是其中兩種。

面試這樣答

30 秒版本

「Stub 是控制輸入，Mock 是驗證互動。如果我只需要讓被測程式碼收到假資料，我用 Stub（jest.fn().mockReturnValue()）；如果我需要確認程式碼有沒有正確呼叫某個依賴——比如確認 logger 被呼叫一次、email 有送出——我用 Mock 或 Spy。原則上我盡量少用 Mock，因為 Mock 過多會讓測試跟實作細節綁太死，重構時很容易大規模壞掉。」
