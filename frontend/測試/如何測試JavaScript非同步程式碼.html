非同步測試：讓框架等你的 Promise

測試非同步程式碼最常犯的錯是讓 test 函式在 Promise 還沒 resolve 前就結束。三種寫法都能處理，async/await 最推薦，最接近正常程式碼的閱讀感。

三種寫法

async/await 是首選

方法一：async/await（最直覺，現代標準寫法）

test('成功取得資料', async () => {
  const data = await fetchData();
  expect(data).toBeDefined();
});

方法二：回傳 Promise（Jest/Mocha 偵測到 return 後會等待）

test('成功取得資料', () => {
  return fetchData().then(data => {
    expect(data).toBeDefined();
  });
});

方法三：done callback（舊式 API 或無法 promisify 的情況）

test('callback 風格', (done) => {
  fetchData((err, data) => {
    expect(err).toBeNull();
    expect(data).toBeDefined();
    done(); // 告訴 Jest「非同步結束了」
  });
});
⚠️

忘記 return 或 await，測試會立刻通過（假陽性）。這是非同步測試最危險的坑。

測試錯誤路徑

也要測 reject / throw

// 用 rejects 測 Promise 失敗
test('API 失敗時拋出錯誤', async () => {
  await expect(fetchData('bad-url'))
    .rejects
    .toThrow('Network Error');
});
測試只有 happy path 等於沒測試，錯誤路徑往往是 bug 藏身的地方。

面試官可能再追

Jest 的 fake timers 是什麼？什麼時候用？

用 jest.useFakeTimers() 可以接管 setTimeout/setInterval，讓時間可以用 jest.advanceTimersByTime(ms) 手動推進，不需要真的等待。適合測試 debounce、polling 等時間相關邏輯。

測試非同步時如何避免假陽性（false positive）？

1. 永遠 return 或 await 非同步操作。2. 使用 expect.assertions(n) 指定預期斷言次數——若 callback 沒執行，Jest 會報錯而非靜默通過。
