測試

單元測試不只是assert 對不對，而是隔離、快速、可信

好的單元測試有三個特質：只測一件事、不依賴外部狀態、毫秒內完成。學會 describe/it 結構與 mock 依賴，才算真正入門。

基本結構

describe / test / expect

Jest（及 Vitest、Jasmine）的測試三元組：describe 群組、test/it 案例、expect 斷言。

// sum.test.js
describe('sum 函式', () => {
  test('正數相加', () => {
    expect(sum(1, 2)).toBe(3);
  });

  test('負數相加', () => {
    expect(sum(-1, 1)).toBe(0);
  });
});
💡

toBe 用 === 嚴格比對純值；物件/陣列要用 toEqual（深比較）。

常用斷言

Jest Matcher 速查

Matcher用途
toBe(val)嚴格相等（===），純值用
toEqual(obj)深比較物件/陣列
toBeTruthy() / toBeFalsy()truthy/falsy 判斷
toContain(item)陣列或字串包含某值
toThrow()函式是否拋出例外
toHaveBeenCalledWith()mock 是否以特定參數被呼叫
Mock 依賴

隔離外部依賴是單元測試的核心

單元測試不應真的打 API 或寫 DB。用 jest.fn() / jest.mock() 取代外部依賴：

// 整個模組都換成 mock
jest.mock('node-fetch');

test('fetchData 回傳 mock 資料', async () => {
  fetch.mockResolvedValueOnce({
    json: async () => ({ data: '42' })
  });

  const result = await fetchData('https://api.example.com');
  expect(result).toEqual({ data: '42' });
});
⚠️

忘記 mock 外部依賴會導致測試在沒有網路的 CI 環境失敗，也讓測試速度暴增。

延伸追問

面試官可能再追

beforeEach / afterEach 什麼時候用？

每個 test 執行前後需要重置狀態時使用：例如 beforeEach(() => jest.clearAllMocks()) 清除 mock 呼叫記錄，避免測試互相污染。

單元測試應該測到 100% 覆蓋率嗎？

不必追求 100%。覆蓋率是指引，不是目標。應優先測邊界條件（邊界值、null、錯誤路徑），而非追求每行都跑到。有時候 80% 有意義的測試比 100% 形式測試更有價值。

面試這樣答

30 秒版本

「我寫單元測試會遵守三個原則：只測一個行為、mock 所有外部依賴、讓測試在毫秒內完成。用 Jest 的話，describe 群組、test 定義案例、expect 斷言結果。依賴 API 或 DB 的地方用 jest.mock() 替換，確保測試在沒有網路也能跑。我也會用 AAA 模式（Arrange、Act、Assert）讓測試邏輯一眼清楚。」
