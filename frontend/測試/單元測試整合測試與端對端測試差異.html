測試金字塔：粒度不同，成本不同

Unit、Integration、E2E 三層測試各有職責。越靠塔底越快越便宜，越靠塔頂越貼近真實使用者但越慢。好的測試策略是把大量預算投在底層，少量投在頂層。

🔵 Unit 單元測試

範圍：單一函式或元件。與外部完全隔離（依賴全 mock）。
工具：Jest、Vitest、Mocha。
特性：毫秒級執行、可大量鋪，是迴歸防線第一道。

建議比例：70%

程式碼範例

三層各長什麼樣

Unit：函式輸入輸出直接斷言

// sum.test.js
test('adds 1 + 2 to equal 3', () => {
  expect(add(1, 2)).toBe(3);
});

Integration：多模組串起來，只 mock 外部 I/O

// API route + DB layer 整合測試
const response = await request(app).get('/users');
expect(response.status).toBe(200);
expect(response.body).toEqual(expect.arrayContaining([...]));

E2E：真實瀏覽器操作，驗使用者流程

// Cypress 登入流程
cy.visit('/login');
cy.get('input[name="username"]').type('testuser');
cy.get('button[type="submit"]').click();
cy.url().should('include', '/dashboard');
💡

E2E 找不到問題，不代表 bug 不存在；Unit 先找好，E2E 只確認流程通。

延伸追問

面試官可能再追

測試金字塔比例建議是多少？

業界常見參考：Unit 70%、Integration 20%、E2E 10%。E2E 越多，CI/CD 越慢且越脆。

什麼情況下 E2E 最有價值？

跨多個服務的關鍵使用者流程（結帳、登入、送出表單）。這些場景光靠 Unit 無法保障端到端正確性。

整合測試和 E2E 怎麼抉擇？

整合測試不需要瀏覽器，速度快 10x 以上；如果後端 API 本身正確已足夠，就不需要跑 E2E。E2E 留給前後串起來才能驗證的流程。

面試這樣答

30 秒版本

「我會用測試金字塔來分配：底層大量 Unit test，快速驗函式邏輯；中層 Integration test 驗模組串接，例如 API route 加 DB；頂層少量 E2E 驗關鍵使用者流程，像登入或結帳。越往上越貼近真實，但也越慢越貴，所以比例大約是 7:2:1。」
