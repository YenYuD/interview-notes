Design Patterns

複製既有物件，不從零建立

原型模式以現有物件為藍圖複製出新物件，跳過昂貴的初始化流程。JavaScript 的原型鏈（Prototype Chain）本身就是這個模式的語言層實作。

兩種實作方式

Object.create vs 建構函式 prototype

// 方式一：Object.create（最直接）
const animalProto = {
  speak() { return `${this.name} says ${this.sound}`; }
};
const dog = Object.create(animalProto);
dog.name  = 'Rex';
dog.sound = 'woof';
dog.speak(); // "Rex says woof"

// 方式二：建構函式 + prototype（共享方法節省記憶體）
function Animal(name, sound) {
  this.name = name; this.sound = sound;
}
Animal.prototype.speak = function() {
  return `${this.name} says ${this.sound}`;
};
💡

ES6 Class 的本質：class 語法糖底層仍是 prototype；extends 建立的繼承鏈就是原型鏈的延伸。理解原型模式有助於解釋為何 instanceof 和原型鏈查找是 JavaScript 的核心機制。

原型鏈查找

屬性存取沿著鏈往上找

1

先查自身屬性

存取 obj.prop 時先找 obj 本身是否有 prop。

2

再查 [[Prototype]]

找不到則往 Object.getPrototypeOf(obj) 查，一路到 null。

3

回傳 undefined 或找到

到達鏈尾仍未找到則回傳 undefined；找到即停止。

延伸追問

面試官可能再追

淺複製 vs 深複製，原型模式怎麼選？

原型模式的「複製」可以是淺複製（只複製一層屬性參考）或深複製（遞迴複製所有嵌套物件）。Object.assign 和展開運算子 {...obj} 是淺複製；需要深複製時用 structuredClone()（現代瀏覽器支援）或 JSON.parse(JSON.stringify())（不支援函式、undefined、循環參考）。

Object.create(null) 和 Object.create(Object.prototype) 的差異？

Object.create(null) 建立一個沒有任何原型的「純淨」物件，不繼承 toString、hasOwnProperty 等，常用做 dictionary（純 key-value map）；Object.create(Object.prototype) 等同 {}，繼承所有 Object 方法。

面試這樣答

30 秒版本

「原型模式透過複製現有物件來建立新物件，適合物件初始化成本高的場景。JavaScript 天生就是原型語言，每個物件都有 [[Prototype]] 鏈，屬性存取沿鏈查找。Object.create(proto) 是最直接的原型模式實作；ES6 的 class 底層也是 prototype，extends 就是建立原型鏈繼承。使用時要注意淺複製與深複製的差異，避免多個實例共享同一個嵌套物件參考。」
