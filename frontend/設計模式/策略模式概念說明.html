Design Patterns

把演算法抽換自如，不動呼叫端

策略模式將一組可互換的演算法各自封裝，讓 Context（環境） 在執行時動態切換策略，而不是靠一堆 if/else 分支決定行為。

核心結構

Context 持有策略，隨時可換

// 每個策略只負責自己的演算法
const sortAsc  = { sort: arr => [...arr].sort((a,b) => a-b) };
const sortDesc = { sort: arr => [...arr].sort((a,b) => b-a) };

class Sorter { // Context
  constructor(strategy) { this.strategy = strategy; }
  setStrategy(s) { this.strategy = s; }
  execute(data)  { return this.strategy.sort(data); }
}

const sorter = new Sorter(sortAsc);
sorter.execute([3,1,4]); // [1,3,4]

sorter.setStrategy(sortDesc); // 切換策略，Context 不變
sorter.execute([3,1,4]); // [4,3,1]
✅

JavaScript 中更輕量的寫法：直接用函式當策略，不一定要包成類別。const strategies = { asc: ..., desc: ... }，然後 strategies[type](data)，簡潔又 functional。

面試官可能再追

策略模式 vs 工廠模式，怎麼分？

工廠模式關注「如何建立物件」；策略模式關注「如何執行行為」。工廠解決的是建立邏輯的封裝，策略解決的是行為切換的彈性。兩者常搭配使用：工廠負責根據類型建立對應的策略物件。

策略模式如何符合 SOLID 原則？

主要符合 OCP（開放封閉原則）：新增策略時只需新增類別，不修改 Context；也符合 SRP（單一職責原則）：每個策略只負責一種演算法的實作。

面試這樣答

30 秒版本

「策略模式把一組可互換的演算法各自封裝成獨立策略，Context 只持有介面參考，執行時動態切換。這樣新增策略不需要修改 Context，符合開放封閉原則。前端我最常在表單驗證和排序功能用到它：把每種規則封裝成策略物件，動態組合而不是寫一堆 if/else 分支。JavaScript 裡甚至直接用函式物件就夠了，不一定要包成 class。」
