四種模式

讀寫策略

  • Cache-aside（最常見）：讀先看 cache、miss 就讀 DB 再回填；寫 DB 後讓 cache 失效。
  • Write-through：寫 DB 同時也寫 cache → 永遠最新，但寫變慢。
  • Write-behind：先寫 cache、之後非同步寫 DB → 快，但掛掉有掉資料風險。
  • Refresh-ahead：TTL 過期前主動更新，避免使用者撞上 miss。
熱資料短 TTL（30秒~5分）+ 寫入主動失效
冷資料長 TTL（1小時~1天）
快取失效難題

電腦科學兩大難題之一

💬

「Cache invalidation 是電腦科學兩大難題之一（另一個是命名）。」策略：盡量短 TTL + 寫入時主動 invalidate + tag-based invalidation（給快取打標籤，一次失效一整組）。

Redis 常見用途：Session store、rate limiting、熱資料快取（車輛即時位置）、分散式鎖（SET NX EX）、queue、Pub/Sub。

面試這樣答

30 秒版本

「最常用 cache-aside：讀先看 cache、miss 就回填，寫則更新 DB 再讓 cache 失效。要更即時可以 write-through（寫變慢）；要極快可接受掉資料風險用 write-behind。TTL 熱資料短 + 主動失效、冷資料長。最難的是失效時機，我會用短 TTL 加寫入時主動 invalidate，必要時用 tag-based。車輛即時位置這種我會放 Redis、TTL 約 10 秒。」
