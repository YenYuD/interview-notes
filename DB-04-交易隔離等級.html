多個交易同時進行可能互相干擾出現「怪現象」。隔離等級就是設定「我這個交易要被保護到什麼程度，不被別人的併發操作影響」—— 越嚴格越安全，但效能成本越高。

怪現象

①

Dirty Read 髒讀：讀到別人還沒 commit（可能等下會 rollback）的資料。

②

Non-Repeatable Read 不可重複讀：同一筆資料讀兩次，值卻不一樣（別人中途改了並 commit）。

③

Phantom Read 幻讀：同一查詢條件讀兩次，筆數變了（別人插了符合條件的新列）。

重點

PG 的特別之處

  • PG 的 REPEATABLE READ 比 SQL 標準更強：用 MVCC snapshot，連幻讀都擋掉了。
  • SERIALIZABLE：保證結果等同「交易一個一個跑」，但偵測到衝突會 abort 交易，應用層要準備 retry。
  • PG 沒有真正的 READ UNCOMMITTED，設了也當 READ COMMITTED。
一般 OLTP→ READ COMMITTED（預設就夠）
金流結算 / 預訂衝突→ SERIALIZABLE 或 SELECT ... FOR UPDATE
面試這樣答

30 秒版本

「隔離等級擋三種異常：髒讀、不可重複讀、幻讀。PG 預設 READ COMMITTED 擋髒讀；REPEATABLE READ 用 MVCC snapshot 連幻讀都擋（比標準強）；SERIALIZABLE 最嚴格但衝突會 abort 要 retry。一般 OLTP 用預設就好，金流或預訂衝突我會用 SERIALIZABLE 或 SELECT FOR UPDATE。」
