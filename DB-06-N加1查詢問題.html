查清單 1 次，
每筆又各查一次

查一個清單（1 次 query），然後對清單裡每一筆又各自查一次關聯資料（N 次），總共打了 1+N 次 DB，量大時超慢。常因 ORM 的 lazy loading 不小心觸發。

問題長相

為什麼是 1+N

-- 1 次：
SELECT * FROM users LIMIT 10;          -- 拿到 10 個 user
-- 然後對每個 user 各跑一次：
SELECT * FROM orders WHERE user_id = ?;   -- 跑 10 次！

總共 1 + 10 = 11 次。100 個用戶就 101 次。每次查詢都有來回網路開銷，量一大就拖垮效能。

解法

把 N 次併成 1 次

  • SQL：用 JOIN，或一次 WHERE user_id IN (1,2,3,...)。
  • ORM eager loading：Prisma include: { orders: true }、TypeORM relations: ['orders']。
  • GraphQL：用 DataLoader —— 把同一 tick 內所有「查 user 的 orders」收集起來合併成一次 batch query，並 cache。
🔍

怎麼發現它：看 DB log / APM trace 出現「同一句 query 被打了好幾十次只差參數」。

面試這樣答

30 秒版本

「N+1 是查清單 1 次、再對每筆各查 1 次關聯、總共 1+N 次，通常是 ORM lazy loading 造成的。解法是 JOIN、或 IN (...) 批次查、或 ORM 的 eager loading；GraphQL 場景用 DataLoader 把同一 tick 的請求 batch + cache。我會在 APM 看到『同一句 query 重複幾十次』就知道中了。」
