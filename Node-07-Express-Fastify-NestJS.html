三框架一覽

框架風格適合
Express極簡，以 middleware 為核心，什麼都自己組小型專案、原型
Fastify高效能，內建 JSON schema 驗證注重吞吐量
NestJS像 Angular 後端版：DI、模組化、TS 優先大型團隊、長期專案
NestJS 為什麼適合大型專案

架構自帶紀律

  • 強制模組化（Controller / Service / Module）→ 自然達到高內聚低耦合（MOOVO JD 關鍵字）。
  • DI 依賴注入 container → 容易替換、容易測試（mock 依賴）。
  • Decorator 寫法清晰：@Controller('bikes')、@Get(':id')。
  • 內建支援 Swagger、Validation、GraphQL、WebSocket、MQTT、microservices。
⚠️

何時不用 NestJS：簡單 API 用 Express / Fastify 就好，NestJS 的架構 overhead 太大；團隊不熟 DI / OOP 模式時也不適合。

面試這樣答（Emily 可能被問「為什麼選 NestJS」）

30 秒版本

「Express 極簡彈性、適合小專案；Fastify 主打效能與內建 schema 驗證；NestJS 像 Angular 後端版，用 DI 和模組化強制高內聚低耦合，內建一堆企業功能，適合大團隊長期維護。我主力是 Express 和 Next.js Route Handlers，NestJS 的 DI、模組、decorator-based controller 我研究過設計理念，可以快速上手。」

💡

誠實應對：沒 production 用過 NestJS 沒關係，講得出「Module / Controller / Service / Provider 怎麼搭」+「它解決什麼問題」就很加分。
