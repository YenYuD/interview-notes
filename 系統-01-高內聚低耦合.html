高內聚 = 相關的東西放一起；低耦合 = 模組之間盡量少互相依賴。這樣改一處不會牽動全身。

分層 + 依賴反轉 + 按業務切

  1. 分層架構：Controller（HTTP 邊界）→ Service（業務邏輯）→ Repository（資料存取）→ Domain model（核心實體）。
  2. 依賴反轉：Service 依賴 Repository 的介面，不是具體實作 → 換 DB 或 mock 測試都不用改 Service。
  3. 以「業務能力」切模組，不是以「技術層」切。
  4. 不跨模組偷叫對方的內部，要走公開 API。
✅ 按業務切bikes/ payments/ subscriptions/ 各自完整
❌ 按技術切controllers/ services/ repos/ 全混在一起

30 秒版本

「高內聚是把一件事的相關程式碼聚在一起，低耦合是模組間透過介面溝通、不碰彼此內部。我會分層（Controller / Service / Repository / Domain），用依賴反轉讓 Service 依賴 Repository 介面方便測試與換實作，並且以業務能力切模組（bikes、payments 各自完整）。NestJS 的 Module 天生就在強制這個邊界。」
