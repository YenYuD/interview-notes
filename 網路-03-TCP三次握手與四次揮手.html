網路協定

建線握手 3 次，
斷線揮手 4 次

TCP 建連線要「握手」三次確認雙方收發都正常；斷線要「揮手」四次，因為兩個方向要各自關閉。

三次握手

為什麼是三次不是兩次？

  1. Client → Server：SYN「喂，聽得到嗎？」
  2. Server → Client：SYN+ACK「聽得到，那你聽得到我嗎？」
  3. Client → Server：ACK「聽得到，開始吧。」
  • 要確認雙方的收與發都正常（兩次只能確認單向）。
  • 防止「舊的、延遲很久的 SYN」突然抵達，造成 server 開了沒人用的假連線。
四次揮手

為什麼是四次？

  1. Client → Server：FIN「我講完要掛了。」
  2. Server → Client：ACK「收到。」
  3. Server → Client：FIN「我這邊也講完了。」
  4. Client → Server：ACK「收到，掰。」

TCP 是雙工，兩個方向要分別關閉。Server 收到 FIN 後可能還有資料要傳完，所以先回 ACK、等傳完才送自己的 FIN —— 中間兩步分開，所以四次。

常見追問

TIME_WAIT 與 CLOSE_WAIT

TIME_WAIT 為什麼等 2MSL？

主動關閉一方最後進入 TIME_WAIT，等 2 倍 MSL。① 確保最後那個 ACK 對方有收到（沒收到對方會重送 FIN）；② 讓舊封包在網路上消散，不干擾下一條同 port 的連線。

TIME_WAIT 太多怎辦？

重用 port（SO_REUSEADDR）、調 kernel 參數。

為什麼 server 容易堆 CLOSE_WAIT？

App 收到對方 FIN 後忘了呼叫 close()，是程式 bug。

面試這樣答

30 秒版本

「三次握手是為了確認雙方收發都正常、並防止舊 SYN 造成假連線；四次揮手是因為 TCP 雙工、兩個方向要各自關，而且 server 收到 FIN 後可能還有資料要傳完，才把 ACK 和 FIN 分兩步。TIME_WAIT 等 2MSL 是確保最後的 ACK 送達並讓舊封包消散。」
