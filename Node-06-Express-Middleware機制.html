請求跑過
一條輸送帶

Express 把每個請求丟進一條「處理管線」，管線上每一節就是一個 middleware，靠呼叫 next() 把棒子交給下一節。

DEMO — 請求在管線上跑

next() 傳棒、不呼叫就卡住

選一種情境，按「送出請求」看那顆球怎麼在管線上跑：

選情境
每個 middleware 的長相

(req, res, next)

  • 呼叫 next() → 把控制權交給下一個 middleware。
  • 不呼叫 next() 也不回應 → 請求永遠卡住（hang）。
  • 直接 res.send() → 提前結束，不再往下。
🔴

錯誤 middleware 簽名是四個參數 (err, req, res, next) —— Express 靠「參數數量」判斷這是錯誤處理器。任何 middleware 呼叫 next(err) 就會跳過一般 middleware、直接進到它。

順序很重要

標準排法

app.use(cors());          // 1. CORS 最先（OPTIONS 預檢要先過）
app.use(helmet());        // 2. 安全 header
app.use(express.json());  // 3. 解析 body
app.use(logger);          // 4. log
app.use('/api', auth);    // 5. 驗證
app.use('/api', routes);  // 6. 業務邏輯
app.use(notFound);        // 7. 404 兜底
app.use(errorHandler);    // 8. 錯誤兜底（一定最後）
⚠️

順序錯會出 bug：例如 auth 放在 cors 前面，OPTIONS 預檢會因為沒帶 token 被擋。

延伸追問

面試官可能再追

為什麼 middleware 能串接？

next 是個 closure，包著「下一個 middleware 的 reference」。

Express vs Koa 差在哪？

Koa 用 async/await + await next()，可以「在 next 之後再做事」，形成洋蔥模型（請求進去一層層、回來再一層層）。

面試這樣答

30 秒版本

「Express 把請求送進一條 middleware 管線，每個 middleware 是 (req,res,next)，呼叫 next() 往下傳、不呼叫就卡住。錯誤 middleware 用四個參數簽名來辨識，next(err) 會直接跳過去。順序很關鍵：cors → 安全 header → body parser → log → auth → 路由 → 404 → 錯誤兜底放最後。」
