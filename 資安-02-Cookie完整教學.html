Cookie 的每個旗標
都在擋一種攻擊

Cookie 是 server 放在瀏覽器、之後每次請求都自動帶回的一小段資料，最常用來記住「你是誰」（session / token）。但「自動帶回」這個特性正是資安風險的來源 —— 所以每個設定旗標，其實都在補一個洞。

先搞懂

Cookie 是什麼？怎麼運作？

登入成功後，server 回一個 Set-Cookie header；瀏覽器存起來，之後對同一個網域的每次請求都自動在 Cookie header 帶上它。server 看到就知道「喔，是剛剛登入的 Emily」。

// server 回應：
Set-Cookie: sessionId=abc123; HttpOnly; Secure; SameSite=Lax

// 之後瀏覽器每次請求自動帶：
Cookie: sessionId=abc123
💡

關鍵理解：cookie 的「自動帶回」很方便，但也代表惡意網站可能借用你的 cookie（CSRF），或 惡意 JS 可能偷讀你的 cookie（XSS）。下面每個旗標就是在堵這些。

先認識兩個攻擊

XSS 與 CSRF 是什麼？

cookie 的安全設定主要在防這兩種攻擊，先用白話搞懂它們，後面才看得懂旗標在擋什麼。

🦠 XSS（Cross-Site Scripting，跨站腳本）

攻擊者想辦法把惡意 JavaScript 塞進你的網頁，讓它在別人的瀏覽器裡執行。

最典型的例子：留言板沒有過濾輸入，攻擊者把暱稱填成 <script>偷cookie送走</script>。之後任何人打開這個頁面，那段 script 就在他們瀏覽器裡跑起來，偷走他們的 cookie / token。

🎯

一句話：「壞人的 JS 在你網站上跑」。所以重點是「別讓使用者輸入變成可執行的程式碼」+「就算被執行了，也讓它偷不到 cookie」（這就是 HttpOnly 的用途）。

🎣 CSRF（Cross-Site Request Forgery，跨站請求偽造）

攻擊者不偷你的 cookie，而是借用它。因為 cookie 會自動帶回，攻擊者只要騙你在登入狀態下，去觸發一個對目標網站的請求即可。

典型例子：你登入了銀行（cookie 還在），這時收到一封信，點了裡面的圖片或連結，那其實是 evil.com 偷偷對 bank.com/transfer 送出的轉帳請求。瀏覽器一看是打 bank.com，自動把你的銀行 cookie 帶上去，銀行就以為是你本人操作。

🎯

一句話：「壞人借你還沒登出的身份，替你發請求」。所以重點是「跨站來的請求別自動帶 cookie」（這就是 SameSite 的用途）。

⚖️

一句話分清楚：XSS 是偷 cookie（讀），CSRF 是借用 cookie（送）。前者靠 HttpOnly 防、後者靠 SameSite 防。

每個旗標擋什麼

🔒 HttpOnly — 擋 XSS 偷 cookie

加了 HttpOnly，JavaScript 就讀不到這個 cookie（document.cookie 看不見它）。所以就算網站中了 XSS、攻擊者的 JS 在你瀏覽器裡跑，也偷不走你的 session。放 token / sessionId 的 cookie 一定要加。

🔐 Secure — 只走 HTTPS

加了 Secure，cookie 只會在 HTTPS 連線時送出，不會在 http 明文裡裸奔被中間人攔截。正式環境必加。

🛡️ SameSite — 擋 CSRF

控制「跨站請求要不要自動帶這個 cookie」。這是 CSRF 防禦的核心：

值跨站時帶 cookie？說明
Strict完全不帶最安全，但從外部連結點進來也不帶 → 會「看起來像沒登入」
Lax
預設		只有「頂層導航 GET」帶平衡點：點連結進站 OK，但跨站 POST/表單不帶
None都帶必須同時加 Secure，否則瀏覽器拒收。用於真的需要跨站的場景

🌐 Domain / Path — 限制範圍

Domain 決定哪些子網域收得到、Path 決定哪些路徑收得到。範圍開越小越安全（最小權限原則）。

⏰ Expires / Max-Age — 存活時間

不設 → session cookie（關瀏覽器就消失）；有設 → 持久 cookie（到期前都在）。敏感 cookie 設短一點。

✨ __Host- / __Secure- 前綴

cookie 名稱用 __Host- 開頭，瀏覽器會強制它必須有 Secure、Path=/、且不能設 Domain —— 等於把安全設定鎖死，防止被攻擊者用較寬鬆的設定覆蓋。

面試這樣答

30 秒版本

「存 token 的 cookie 我一定加三件套：HttpOnly 讓 JS 讀不到、擋 XSS 偷 cookie；Secure 只走 HTTPS、防中間人；SameSite=Lax（或 Strict）擋 CSRF 的跨站自動帶 cookie。範圍用 Domain/Path 收到最小、敏感 cookie 設短 TTL，講究一點用 __Host- 前綴把安全設定鎖死。如果是行動端或跨站場景，才會用 SameSite=None + Secure 並另外加 CSRF token。」
