翻頁 vs 接著看

資料太多不能一次全回，要分頁。Offset 像「翻到第幾頁」，Cursor 像「從上次那筆繼續往下」。差別在資料變動時誰會出錯。

兩種分頁的本質

SQL 差在哪

Offset 分頁（翻頁式）

GET /bikes?page=2&limit=20
SQL: OFFSET 20 LIMIT 20

像書本「跳到第 3 頁」。能跳頁、能顯示總頁數，但 OFFSET 很大時 DB 要先數過前面所有列才能跳過 → 越後面越慢；資料變動時還會跳重複或漏資料。

Cursor 分頁（接續式）

GET /bikes?cursor=abc&limit=20
SQL: WHERE id > 'abc' LIMIT 20

像「我看到 abc 這筆了，給我之後的 20 筆」。穩定、效能好（直接用索引定位），但不能跳頁、要設計穩定排序鍵。

怎麼選

即時車輛列表 → Cursor

因為車輛資料一直在變，使用者通常只往下滑「下一頁」，不會跳到第 50 頁。關鍵：用 (updated_at, id) 這種複合 cursor，避免「同一秒插入兩筆」造成排序不穩、漏資料。

後台報表資料穩定、要跳頁 → Offset
即時動態列表資料變動、只看下一頁 → Cursor
延伸追問

面試官可能再追

Cursor 要加密嗎？

一般明文 base64 編碼即可；只有 cursor 內含敏感資訊時才加密。

要回總筆數嗎？

Cursor 分頁通常不回 —— 要算總數得另外下一次 query，很貴。

✕

用 id 當 cursor 但排序卻用 created_at → 同秒兩筆會出錯。
