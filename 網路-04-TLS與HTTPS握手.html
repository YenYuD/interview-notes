三個關鍵概念

SNI / 憑證鏈 / 前向保密

🏷️

SNI：一個 IP 可能掛很多網域，client 在握手時告訴 server「我要哪個網域」，server 才知道出示哪張憑證。

🔗

憑證鏈：你的網站憑證 ← 中介 CA ← Root CA。瀏覽器內建信任一批 Root CA，從你的憑證一路驗到 Root 都有效才信任。

🔐

ECDHE → 前向保密：每次連線用「臨時」金鑰協商。即使將來 server 私鑰外洩，過去側錄的流量也解不開，因為當時的 session key 是臨時算的、沒存下來。

延伸追問

面試官可能再追

自簽憑證 vs Let's Encrypt 差在哪？

信任鏈在不在瀏覽器內建的 Root CA 清單裡。自簽的瀏覽器會跳警告。

mTLS 是什麼？

雙向驗證 —— 不只 client 驗 server，server 也要求 client 出示憑證。常用於 B2B 機敏 API 與 IoT 裝置認證。

面試這樣答

30 秒版本

「使用者打 https，先 DNS 拿 IP、TCP 三次握手、再 TLS 握手。TLS 1.3 一個 RTT 就完成：Client Hello 帶 SNI 和臨時金鑰，Server 回憑證和它的臨時金鑰，client 驗憑證鏈到 Root CA，雙方用 ECDHE 算出 session key，之後內容都加密。用 ECDHE 是為了前向保密 —— 私鑰外洩也救不回過去流量。」
